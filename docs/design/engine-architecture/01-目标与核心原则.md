# 目标与核心原则

## 目标定位

本项目目标是一个 **AI 原生游戏生产引擎**。

正式目标用户：

```text
没有编程基础的游戏创作爱好者。
只有少量编程基础的游戏创作爱好者。
```

这两个群体共同构成默认产品用户，不把熟练程序员、Technical Artist 或专业引擎工程师作为完成主流程的前置条件。

默认用户体验必须满足：

```text
用户可以用自然语言描述目标，用可视化编辑器检查和精修结果。
用户不需要编写 Rust、手工修改项目 JSON 或理解 ECS / RHI / RuntimePackage internals。
AI 和引擎负责把意图转成可审查、可验证、可恢复的工程修改。
界面、诊断和报告使用用户能理解的游戏与产品语言，并在需要时渐进展示技术细节。
少量编程基础用户可以进入高级视图检查项目逻辑或受控代码 Patch，但这不是主流程要求。
专家代码入口作为扩展和逃生通道保留，不能反向增加零基础用户的默认认知成本。
```

用户通过自然语言完成：

```text
生成资源
生成逻辑
修改资源
修改逻辑
生成场景
验证项目
导出可发布游戏
```

它不是单次 prompt-to-game 玩具，而是面向真实生产的工程型引擎：

```text
自然语言 -> 功能规格 -> 修改计划 -> 验证补丁 -> 可维护游戏工程 -> 多平台发布
```

定位优先级：

```text
无编程基础和少量编程基础的爱好者优先
中小型游戏优先支持
架构上预留大型游戏能力
长期目标支持桌面、移动端、Web 和更复杂生产流程
```

“预留大型游戏能力”只表示模块、数据、构建和运行边界可以扩展，不表示默认编辑体验提前暴露大型项目的全部复杂度。

## 核心原则

### 1. AI 不能直接乱改文件

AI 不应该绕过权限、审阅和验证直接修改工程文件、脚本或资源配置。所有自然语言需求必须经过工程化流程。

对于零基础用户，AI 可以生成或修改项目侧资产和项目侧代码，但必须表现为受控 Patch，并经过 scope、diff、验证、用户确认和失败恢复；底层 Engine Core 不属于普通项目修改范围。

标准流程：

```text
User Intent
  -> Project Context Scan
  -> AI Feature Spec Draft
  -> User Confirm / Adjust
  -> Patch Plan Generation
  -> Engine Validation
  -> Auto Fix Loop
  -> User Decision if Needed
  -> Apply Patch Transaction
  -> Run Tests / Build Check
  -> Result Report
```

这个流程是 AI 原生引擎的核心。

### 2. 所有工程对象 schema-first

所有核心对象都必须有 schema：

```text
Project Schema
Scene Schema
Entity Schema
Component Schema
Prefab Schema
Asset Schema
Script Schema
Input Schema
Render Schema
Quality Profile Schema
Export Schema
```

schema 的作用：

```text
限制 AI 输出
验证工程合法性
支持 diff / review / rollback
支持自动修复
支持跨平台导出
```

### 3. AI 输出 patch，不输出最终黑盒结果

AI 输出应该是可审查的 patch 或 patch plan。

不推荐：

```text
AI 直接重写 scene 文件
AI 直接重写整段 runtime 代码
AI 直接生成不可解释的最终工程
```

推荐：

```json
{
  "op": "attach_component",
  "entity": "player",
  "component": {
    "type": "DashAbility",
    "cooldown": 2.0,
    "distance": 3.5,
    "duration": 0.18
  }
}
```

### 4. 引擎负责验证，AI 负责修复建议

验证由引擎执行，不由 AI 自己说了算。

验证类型：

```text
Schema Validation
Dependency Validation
Script Compile Validation
Asset Validation
Render Validation
Platform Capability Validation
Performance Budget Validation
Automated Tests
Build Check
```

AI 可以根据验证错误自动修复，但必须区分：

```text
可确定自动修复的问题
需要用户决策的问题
```

用户决策必须以玩法、视觉、平台、成本和风险语言表达；不能要求零基础用户根据编译器错误、类型系统或引擎内部对象做产品决策。
