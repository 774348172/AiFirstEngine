# AI功能生成流程

## AI 功能生成流程

本流程默认服务没有编程基础和只有少量编程基础的用户。AI 负责补齐工程细节，用户只需要确认玩法、表现、平台、成本和风险；技术细节可以展开查看，但不能成为完成主流程的必答题。

以“给玩家加一个冲刺技能”为例。

### 1. 用户意图

```text
给玩家加一个冲刺技能
```

这句话不完整，AI 不能在未形成可审查规格前直接应用项目修改。

缺失信息包括：

```text
目标玩家是谁
输入按键是什么
冲刺距离
持续时间
冷却时间
是否无敌
是否消耗能量
是否需要 VFX / 音效 / UI
移动端如何触发
是否影响多人同步
```

### 2. 项目上下文扫描

AI 先扫描当前项目：

```text
当前 active scene
玩家 entity
已有输入系统
已有移动组件
已有资源
目标平台
当前性能预算
当前 gameplay scripts
```

### 3. 生成功能规格草案

AI 根据项目生成默认方案，并让用户确认。

默认方案必须使用玩家能理解的产品语言。`Component`、`RuleSlot`、`RuntimeModule`、`Shader Variant` 等术语只在高级详情中出现。

示例：

```text
检测到当前玩家使用 PlayerPlaneController，项目是 3D 空战模板。
建议冲刺设计：
- 触发：Shift / 手柄 B / 移动端 Dash 按钮
- 方向：当前移动方向，没有输入时向前
- 距离：3.5 单位
- 持续时间：0.18 秒
- 冷却：1.2 秒
- 冲刺期间：不提供无敌
- 视觉：蓝色拖尾
- 音效：短促 whoosh
是否按这个方案生成？
```

用户可以继续自然语言修改：

```text
不要无敌，冷却改成 2 秒。
```

### 4. 固化 Feature Spec

确认后形成正式功能规格。

```json
{
  "featureId": "player_dash",
  "target": {
    "scene": "scene-shooter",
    "entity": "player"
  },
  "design": {
    "input": {
      "keyboard": "Shift",
      "gamepad": "B",
      "mobile": "DashButton"
    },
    "movement": {
      "direction": "current_input_or_forward",
      "distance": 3.5,
      "duration": 0.18
    },
    "cooldown": 2.0,
    "invincibleDuringDash": false
  },
  "presentation": {
    "vfx": "blue_dash_trail",
    "audio": "dash_whoosh",
    "uiCooldown": true
  },
  "tests": [
    "dash_moves_player",
    "dash_respects_cooldown",
    "dash_does_not_grant_invincibility"
  ]
}
```

### 5. 生成 Patch Plan

AI 从 Feature Spec 生成 Patch Plan。

```json
{
  "planId": "patch_player_dash_001",
  "fromFeatureSpec": "player_dash",
  "operations": [
    {
      "op": "add_component_schema",
      "component": "DashAbility"
    },
    {
      "op": "attach_component",
      "entity": "player",
      "component": {
        "type": "DashAbility",
        "cooldown": 2.0,
        "distance": 3.5,
        "duration": 0.18,
        "invincible": false
      }
    },
    {
      "op": "add_input_binding",
      "action": "dash",
      "bindings": ["Keyboard.Shift", "Gamepad.B", "Touch.DashButton"]
    },
    {
      "op": "add_vfx_preset",
      "id": "blue_dash_trail"
    },
    {
      "op": "add_audio_event",
      "id": "dash_whoosh"
    },
    {
      "op": "add_runtime_system",
      "system": "DashAbilitySystem"
    },
    {
      "op": "add_tests",
      "tests": [
        "dash_moves_player",
        "dash_respects_cooldown",
        "dash_does_not_grant_invincibility"
      ]
    }
  ]
}
```

### 6. 引擎验证

引擎检查：

```text
DashAbility schema 是否存在
player entity 是否存在
输入 action 是否冲突
VFX preset 是否存在
音效是否存在
移动端 UI 是否有位置
runtime 是否支持 DashAbilitySystem
目标平台性能预算是否允许拖尾效果
```

### 7. AI 自动修复

可确定问题自动修复：

```text
缺少 VFX preset -> 生成默认 blue_dash_trail
缺少音效 -> 使用默认 whoosh
schema 字段缺失 -> 补齐默认字段
测试缺失 -> 生成测试
```

自动修复必须记录：

```json
{
  "autoFixes": [
    {
      "issue": "missing_vfx_preset",
      "fix": "created default blue_dash_trail"
    }
  ]
}
```

### 8. 用户决策

不可自动决策的问题必须交给用户。

示例：

```text
检测到 Shift 已绑定“锁定目标”。
请选择：
1. 改用 Ctrl 作为冲刺
2. 覆盖 Shift 绑定
3. 保留 Shift，取消冲刺快捷键
```

### 9. 应用补丁

用户确认后，补丁以事务方式应用。

要求：

```text
支持 diff preview
支持 rollback
支持 undo / redo
支持 patch history
支持生成变更报告
```

### 10. 结果报告

示例：

```text
已添加冲刺技能：
- 玩家按 Shift / B / Dash 按钮触发
- 距离 3.5，持续 0.18 秒
- 冷却 2 秒
- 已添加蓝色拖尾和 whoosh 音效
- 已生成 3 个测试
- 已通过 runtime 验证
- 移动端 UI 已添加 Dash 按钮
```
