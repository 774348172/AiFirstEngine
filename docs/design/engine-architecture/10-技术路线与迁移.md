# 技术路线与迁移

## 技术路线总览

技术路线必须服务 `01-目标与核心原则.md` 的目标用户：没有编程基础和只有少量编程基础的游戏创作爱好者。Native Rust、ECS、RHI、IR、AOT 和 Build Graph 是实现手段，不是默认用户操作面。

### 编辑器

当前 legacy 过渡实现：

```text
React
Electron
TypeScript
Three.js preview
```

长期方向：

```text
Native Rust Editor Host
Schema-driven Editor Core
自研 UI Schema / Command / Layout Model
可替换 UI Backend
UI Backend v1 使用 winit + wgpu + 自研 UI renderer
egui / eframe 不进入正式窗口主线，只允许作为 headless compatibility test adapter
Viewport / Graph / Inspector / Dock 逐步 native 化
强化 AI patch review / diff / validation UI
编辑器预览与 runtime 共享 Runtime Package / schema / trace
```

编辑器路线规则：

```text
Electron / React 只作为 legacy transition shell。
不再围绕 Electron 设计 Runtime Bridge / Sidecar 主线。
Rust Runtime 与编辑器优先采用 Native Editor Host direct boundary。
编辑器采用 C-lite 长期路线：第一版窗口底座就使用 winit + wgpu + 自研 UI renderer，功能慢慢加。
editor_ui_backend_egui 仅保留为 headless compatibility test adapter，不作为真实窗口后端。
```

## 渲染架构纳入总设计

渲染系统不作为孤立模块，而是 AI 原生架构的一部分。

渲染底层工程路线参考 Unreal 的核心分层：

```text
Renderer Feature Layer
  -> RDG / Render Dependency Graph
  -> RHI / Render Hardware Interface
  -> Backend
```

本项目与 Unreal 的核心区别不在底层工程方向，而在上层控制方式：

```text
Unreal：人类专家通过编辑器、材质图、C++ 和项目设置控制渲染
本项目：AI 通过 Schema / Graph / Preset / Patch / Validation 控制渲染
```

AI 不直接写 shader，而是输出：

```text
Visual Style Patch
Material Graph Patch
Lighting Preset Patch
PostFX Preset Patch
Quality Profile Patch
Asset Optimization Patch
```

渲染验证包括：

```text
Render feature contract validation
Material schema validation
Material graph validation
Shader IR / WGSL compile validation
RDG pass dependency validation
Platform capability validation
Performance budget validation
Fallback generation
```

## Editor Viewport 与 Runtime Renderer 边界

编辑器里的 Scene 面板不是由单一渲染器完成。

正式规则：

```text
Scene 面板外壳、Tab、Toolbar、按钮、面板边框、Overlay UI
  -> Editor UI Renderer

Scene / Game 世界内容、模型、灯光、阴影、粒子、地图、角色
  -> Runtime Renderer
```

Scene Viewport 是组合点：

```text
Runtime Renderer
  -> EditorViewport Render Mode
  -> Editor Camera
  -> Editor-only Pass: grid / gizmo / selection outline / debug draw
  -> render target / viewport texture

Editor UI Renderer
  -> 绘制 Scene 面板外壳
  -> 预留 Viewport Rect
  -> 合成 Runtime Renderer 输出的 viewport texture
  -> 绘制编辑器 overlay / hit region
```

禁止规则：

```text
Editor UI Renderer 不负责画游戏世界。
Runtime Renderer 不负责画编辑器面板。
Scene View 不复制一套 3D 渲染器。
Game View 使用 Runtime Renderer 的 GameCamera / GameView mode。
Scene View 使用 Runtime Renderer 的 EditorCamera / EditorViewport mode。
```

渲染详细设计见：

```text
框架设计/渲染技术路线/README.md
```

## 大型游戏能力预留

本项目优先支持中小型游戏，但不能在架构上堵死大型游戏能力。

大型能力预留不能给中小型项目和零基础用户增加默认复杂度。大型世界、多人同步、Build Farm 等能力应通过可选 Module、Profile 和按需展开的高级界面进入，而不是成为每个新项目的必配概念。

需要预留：

```text
World streaming
Asset bundle / package system
Large scene partition
LOD / HLOD
Occlusion culling
Multiplayer replication
Save / load system
Quest system
Dialogue system
Inventory / economy system
Team collaboration
Version control integration
Build farm / cloud build
```

短期不实现全部，但 schema 和 runtime 架构应允许扩展。

## 当前项目迁移路径

当前状态：

```text
React / Electron legacy editor shell
Three.js editor preview
TypeScript runtime prototype（已冻结为 transition code，Rust Runtime MVP 后退役）
JSON project data
Electron export MVP
```

建议迁移：

```text
1. 固定项目 schema
2. 固定 AI Feature Spec / Patch Plan / Validation Report 格式
3. 抽出当前 runtime 行为规则
4. 建立 Rust Native Runtime MVP
5. 建立 Native Rust Editor Host MVP
6. 让编辑器预览和导出游戏读取同一份 Runtime Package / schema
7. 建立 patch review UI
8. 建立自动验证和自动修复闭环
9. 删除 TypeScript Runtime 运行路径
10. 冻结并逐步退役 Electron legacy shell
```

Runtime 迁移规则：

```text
Rust Native Runtime 是唯一正式 runtime。
TypeScript Runtime 只作为过渡 prototype。
Rust Runtime 的正确性由 Golden Scenario Test 验证。
不做 TypeScript Runtime vs Rust Runtime 长期等价测试。
```

## 总结

本引擎的核心不是“AI 直接生成一堆文件”，而是：

```text
AI 生成可审查的工程计划
引擎验证计划
AI 自动修复确定性问题
用户决定产品性问题
引擎以事务方式应用补丁
最终导出可发布游戏
```

这套机制是区别于传统 Unity / Unreal 工作流的核心竞争力。
