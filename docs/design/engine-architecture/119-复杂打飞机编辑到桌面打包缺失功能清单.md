# 119-复杂打飞机编辑到桌面打包缺失功能清单

## 1. 目标

本文回答一个具体问题：

```text
用户能否在编辑器里创建 / 编辑 / AI 生成一个复杂打飞机游戏，
然后打包成 Windows 桌面程序，
最终打开 exe 就能玩。
```

本文不是打飞机玩法设计文档，也不允许把 `Player / Enemy / Bullet / Health / Score / Wave` 做成引擎内置 API。

这些概念属于项目侧：

```text
Project Schema
Project Rule
Project Prefab
Project Data Asset
Project UI State
Sample Project
```

引擎侧只补齐通用能力：

```text
编辑器创作
资源导入与 cook
项目保存
RuntimePackage 构建
RuntimePackage 校验
项目规则编译 / 运行接入
RuntimeScene -> ECS World
Asset -> GPU Resource
World -> Projection -> Renderer -> RHI
Windowed Player
Desktop Package
Trace / Report / Golden Scenario
```

## 2. 当前真实结论

当前引擎已经具备很多底座能力，但还不能完成用户可见的完整链路。

已经比较稳定的是：

```text
headless runtime gate
ECS / Dynamic Component / Generic Write
RuntimePackageBuilder C-min
RuntimePackageLoader
RuntimeScene World Hydration
Runtime Asset Loader
Physics2D Foundation
SpriteRenderer2D / RenderProjection 基础
RuntimeRenderer -> RenderGraph -> RhiCommandPlan
EngineRHI trait
RealWgpuBackend smoke
Native Editor Window / UI / FontSystem / WGPU present
Scene Editing C-min
PlaySession headless gate
Complex Project Validation fixture
```

还没有完成的是：

```text
真实编辑器项目 -> RuntimePackageBuilder 的产品化入口
真实 Project Rule Authoring / Compile / Runtime Execute 链路
真实 RuntimePackage -> Native Windowed Player exe 链路
真实纹理 / sprite / mesh / material cook 后的 GPU 上传和绑定
真实桌面 package layout
真实复杂打飞机样例从编辑器创作到导出运行的验收门禁
```

所以当前状态应该判断为：

```text
引擎底座验证已经走通一部分。
编辑器生成复杂游戏并打包桌面可玩，还没有走通。
```

## 3. 完整目标链路

完整链路必须是：

```text
用户自然语言 / AI 生成请求
  -> Project Schema / Project Rule / Prefab / Scene / Asset / AUI
  -> Editor Authoring UI 可查看、可编辑、可保存
  -> Project Saved Document
  -> Asset DB / Importer / Cook
  -> RuntimePackageBuilder
  -> RuntimePackageValidationReport
  -> Desktop Package Builder
  -> Native Windowed Player exe + data
  -> OS window / input / time / frame loop
  -> RuntimePackage load
  -> RuntimeScene World Hydration
  -> Project Rule Execute
  -> Physics2D / Input / AUI / RenderProjection
  -> RuntimeRenderer / EngineRHI / WgpuBackend
  -> Surface Present
  -> Trace / Report / Golden Scenario
```

这条链路中任何一段靠 fixture、手写测试数据、临时 smoke、或只返回 report，都不算用户完整可玩闭环。

## 4. 与成熟引擎对比

| 引擎 | 成熟做法 | 对我们的启发 | 我们当前缺口 |
|---|---|---|---|
| Unity | Scene / Prefab / AssetDatabase / Importer / BuildPipeline.BuildPlayer / PlayerLoop / SpriteRenderer / Physics2D | 用户从编辑器保存的内容可以直接进入 BuildPlayer，Player 是独立产物 | 我们还缺 Editor Saved Project 到 RuntimePackageBuilder 的正式入口，以及 Build And Run |
| Unreal Engine | Editor / Content Browser / Blueprint 或 C++ / Cook / Stage / Package / GameViewport / RenderThread / RHI | Cook 和 Package 是正式流水线，PIE/Standalone/Package 有清晰边界 | 我们已有 engine-side gate，但还缺真实 Windowed Player 和 Desktop Stage |
| Godot | Scene / Node / Resource / Export Preset / DisplayServer / RenderingServer | Scene/Resource 是统一创作和运行数据入口，Export Template 生成可运行程序 | 我们的项目保存、资源 cook、运行时加载还没有形成用户级一键导出 |
| Bevy | ECS / Schedule / Assets / wgpu / Examples | Rust ECS 和 wgpu 路线可参考，但编辑器与打包链路较弱 | 我们不能只停留在 ECS 示例和 headless gate，需要补编辑器产品链路 |

结论：

```text
我们的技术方向没有错。
真正缺的是 Unity / UE 都已经产品化的“编辑器内容进入 Player 构建”的完整流水线。
```

## 5. 缺失能力总表

| 编号 | 缺失能力 | 所属层 | 当前状态 | 为什么阻塞复杂打飞机桌面可玩 | 优先级 |
|---|---|---|---|---|---|
| M1 | Editor Saved Project -> RuntimePackageBuilder Integration | Editor / Build | 有局部编辑器和 RuntimePackageBuilder，但连接不完整 | 用户在编辑器里放的飞机、敌人、资源、UI 不能稳定进入运行包 | P0 |
| M2 | Project Rule Authoring / Compile / Runtime Execute Gate | Logic / Build / Runtime | ProjectLogicRunner 有 Rust fixture，IR/RustAOT 生成链路未产品化 | 子弹移动、碰撞后扣血、生成敌机、得分等项目规则无法从编辑器/AI 进入桌面 Player | P0 |
| M3 | RuntimePackage -> Native Windowed Player exe | Runtime / Platform | `118` 完成 engine-side gate，不是真实用户 Player | 不能从包启动真实窗口并连续运行完整游戏 | P0 |
| M4 | Desktop Package Layout / Build And Run | Build / Platform | 有构建报告和 package 概念，缺正式 exe + data 输出 | 用户无法得到一个可分发、可双击运行的桌面游戏目录 | P0 |
| M5 | Runtime Asset Cook -> GPU Resource Binding | Asset / Render / RHI | 有 descriptor 和 smoke，真实纹理/mesh/material 上传绑定不足 | 打飞机需要真实图片、特效、UI 贴图显示，而不是测试几何体 | P0 |
| M6 | Sprite2D 产品级运行链路 | Render / Runtime | SpriteRenderer2D 基础存在，但产品级相机、排序、材质、纹理绑定仍需补齐 | 飞机、子弹、敌机、背景、爆炸都依赖稳定 2D 渲染 | P0 |
| M7 | Editor Asset Browser / Inspector / Prefab Workflow 补齐 | Editor | 有 C-min 场景编辑和资源放置，仍不够完整 | 复杂打飞机需要批量资源、Prefab、组件参数、复用对象编辑 | P1 |
| M8 | Input Mapping Authoring -> Runtime | Editor / Input / Runtime | ActionSnapshot 和 InputMapping 基础存在，编辑器 authoring 不完整 | 用户需要在编辑器里设置键盘/手柄/鼠标输入，并进入 Player | P1 |
| M9 | Physics2D Collider Authoring / Visualization | Editor / Physics | Physics2D Foundation 存在，编辑器可视化不足 | 子弹命中、敌机碰撞、拾取物触发需要可编辑可调试碰撞体 | P1 |
| M10 | AUI HUD Authoring / Binding / Runtime Present | UI / Runtime | AUI C-min 存在，产品工作流不完整 | 血量、分数、暂停、结算、弹药等 UI 需要可编辑、可绑定、可运行 | P1 |
| M11 | Golden Scenario 覆盖导出 exe | Test / QA | 有复杂项目验证 fixture，缺导出产物级验收 | 现在能测引擎模块，不能证明导出的游戏真的可玩 | P1 |
| M12 | Build / Runtime Report 用户级诊断 | Build / Runtime / Editor | 有 report 基础，缺完整串联展示 | 打包失败、资源缺失、规则错误、渲染缺失时 AI 和用户需要定位层级 | P1 |
| M13 | Save / Undo / Reload / Rebuild 一致性门禁 | Editor / Build | 有局部 undo/redo，缺完整项目循环门禁 | 编辑器改完、保存、重开、打包后的结果必须一致 | P1 |
| M14 | AI 生成项目补丁入口 | AI / Editor | 有 AI 资源生成和命令基础，缺完整项目 patch 入口 | 用户自然语言生成复杂打飞机，需要 AI 修改 Schema/Prefab/Rule/Asset/UI | P2 |
| M15 | 复杂样例项目资产与规则集 | Sample / QA | 有验证 fixture，没有真实可编辑样例项目 | 没有一个真实项目持续验证所有系统组合是否还能工作 | P2 |

## 6. P0 必须先打通的四条链

### 6.1 编辑器内容进入 RuntimePackage

第一优先级不是再做一个玩法系统，而是让编辑器保存的内容成为 RuntimePackageBuilder 的正式输入。

目标：

```text
Editor Project Document
  -> Asset DB records
  -> Scene Document
  -> Prefab Document
  -> Project Schema
  -> Project Rule Manifest
  -> RuntimePackageBuildRequest
  -> RuntimePackage
```

验收：

```text
在编辑器中创建一个 sprite entity
保存项目
构建 RuntimePackage
加载 RuntimePackage
World Hydration 后能看到同一个 entity / component / asset ref
```

### 6.2 项目规则进入 Runtime

复杂打飞机的玩法不能写成引擎 API，但项目规则必须能进入运行时。

目标：

```text
Project Rule Source
  -> Rule Manifest
  -> Compile / Register
  -> ProjectLogicRunner
  -> FrameLoop
  -> ECS Query / Write / CommandBuffer
  -> Trace
```

第一版可以只支持 Rust AOT registered rule gate，但必须按长期规则保留 IR/RustAOT 边界，不再靠测试 fixture 模拟玩法。

验收：

```text
项目规则定义“按 fire action 生成一个 projectile-like prefab”
Runtime 执行规则
World 新增 entity
Trace 能说明规则、输入、写入和命令
```

注意：

```text
projectile-like 只是测试项目里的 schema 名称。
引擎 API 仍然只能看见 entity / prefab / component / command。
```

### 6.3 RuntimePackage 进入真实 Windowed Player

`118` 已经完成 engine-side gate，但用户要的是能运行的桌面程序。

目标：

```text
WindowedPlayerHost native entry
  -> OS window / event loop
  -> RuntimePackage load
  -> EngineHostLoop
  -> Input / Time / FrameLoop
  -> Render / RHI / Surface Present
```

验收：

```text
给定一个 RuntimePackage 目录
启动 player exe
打开 OS 窗口
连续运行多帧
能看到 package 中的 sprite
能接收输入并改变 World
```

### 6.4 Desktop Package Layout

不能只停留在 cargo run 或测试命令。

目标：

```text
Build And Run
  -> build/player/windows/
      Game.exe
      data/runtime_package/
      data/assets/
      reports/build_report.json
      reports/runtime_validation_report.json
```

验收：

```text
用户打开输出目录
双击 exe
不依赖编辑器进程
游戏能运行
错误能写入 report
```

## 7. P1 需要补齐的产品化能力

P0 打通后，复杂打飞机还需要以下能力达到可编辑、可修改、可调试。

```text
Schema-driven Inspector：编辑任意项目组件字段。
Prefab Editor：创建、保存、更新、实例化通用 Prefab。
Asset Browser：真实图片 / 音频 / prefab / scene / rule 资源管理。
Sprite2D Scene Tools：拖拽 sprite 到场景、排序、相机、背景层。
Collider2D Visualization：可视化碰撞体和碰撞 pair。
Input Mapping Editor：编辑 action 和设备绑定。
AUI HUD Workflow：编辑 HUD、绑定 ProjectUiState、运行时显示。
Play / Stop / Build And Run UI：编辑器里能触发完整构建和运行。
Report Panel：Build / Runtime / Asset / Rule / Render 错误统一展示。
Golden Scenario Runner：对编辑器项目和导出 exe 做验收。
```



规则：

```text

```

## 9. 推荐实施顺序

不要继续一小点一小点散着讨论。下一步应该生成一份大的施工文档，按 gate 一个一个施工和测试。

推荐顺序：

```text
1. EditorSavedProjectToRuntimePackageBuildGate
2. ProjectRuleAuthoringCompileRuntimeExecuteGate
3. RuntimePackageToNativeWindowedPlayerGate
4. DesktopPackageLayoutAndBuildRunGate
5. RuntimeAssetCookToGpuBindingGate
6. Sprite2DVisibleGameSceneGate
7. EditorAuthoringProductWorkflowGate
8. ExportedShooterGoldenScenarioGate
```

每个 gate 的施工规则：

```text
先写最小测试。
实现一个 gate。
跑该 gate 测试。
跑相关 workspace 回归。
更新阶段完成记录。
再进入下一个 gate。
```

## 10. 当前最重要判断

```text
现在不应该优先继续细化玩法。
现在也不应该先做更漂亮的编辑器 UI。

最应该先补的是：
编辑器保存内容 -> RuntimePackage -> 真实 Player exe -> 桌面运行 -> 可验证报告。
```

只要这条链闭合，复杂打飞机的项目内容就可以逐步由 AI 通过 Project Schema / Rule / Prefab / Asset / AUI 生成和修改。

如果这条链不闭合，继续补局部系统会让引擎看起来能力很多，但用户仍然不能得到一个可玩的桌面游戏。
