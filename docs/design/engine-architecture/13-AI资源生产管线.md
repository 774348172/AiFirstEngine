# AI 资源生产管线

本文档定义 AI 原生游戏引擎的资源生产规则。

资源生产不是“调用一个模型生成文件”，而是：

```text
用户自然语言 / 图片 / 视频 / 音频参考
  -> Asset Spec
  -> Asset Generation Plan
  -> Generation Graph
  -> Candidate Variants
  -> Asset Edit Plan
  -> Quality Gate
  -> Asset Graph 注册
  -> Prefab / Scene / UI / DSL 绑定
  -> Cook / Bundle / Hot Update
```

## 核心定位

传统 AI 资源工具主要生成文件：

```text
prompt -> image / mesh / audio
```

本引擎的目标是生成工程资产：

```text
prompt / reference
  -> 可追踪、可修改、可验证、可接入游戏系统的 Asset
```

资源生产管线属于 Core Engine 的 AI 工程流程和 Asset System 能力。
具体生成模型可以外接，资源生产流程、资源验证、资源引用、资源版本和资源接入必须由引擎自研。

## 与 Unity AI 的关系

Unity AI / Muse 的方向是：

```text
给传统 Unity 工作流增加 AI 能力
```

本引擎的方向是：

```text
从底层把项目结构设计成 AI 可理解、可生成、可修改、可验证
```

共同点：

```text
自然语言生成资源
自然语言修改资源
编辑器内 AI 助手
项目上下文理解
生成 Sprite / Texture / Material / Animation / Audio / UI
允许接入外部模型
```

关键不同：

```text
Unity AI = AI 辅助专业开发者更快使用 Unity
本引擎 = AI 作为主要生产者，让用户持续生产、修改、维护完整游戏项目
```

Unity AI 更偏：

```text
AI 操作已有 Unity 工程对象
```

本引擎必须偏：

```text
工程对象本身就是给 AI 读写和验证设计的
```

因此本引擎必须提供：

```text
Asset Spec
Asset Edit Plan
Asset Source Graph
Asset Revision
Style Bible
AssetSlot
Asset Graph
Quality Gate
Generation Graph
AI Build Report
```

这些不是普通编辑器插件，而是引擎底层规则。

## 模型接入策略

不一开始自研完整基础生成模型。

推荐路线：

```text
引擎自研：资源生产流程、资源理解、资源验证、资源接入、资源可修改系统
生成模型：先接入外部模型 + 本地开源模型
长期自研：垂直小模型 / 适配器 / LoRA / 风格模型 / 验证模型
```

正式架构：

```text
External / Local / Own Models
        ↓
Model Router
        ↓
Asset Generation Graph
        ↓
Asset Spec / Edit Plan / Source Graph
        ↓
Quality Gate
        ↓
Asset Graph
        ↓
Prefab / Scene / UI / DSL / Build Graph
```

模型 Provider：

```text
Image Provider
Image Edit Provider
3D Provider
Material Provider
Animation Provider
Audio Provider
Video Understanding Provider
Text / LLM Provider
Local Model Provider
Own Fine-tuned Provider
```

上层流程不能绑定具体模型。
模型可以替换，Asset Spec、Asset Graph、Quality Gate、Build Graph 不能替换。

## 自研模型边界

长期可以自研，但优先自研小而关键的模型：

```text
项目风格识别模型
资源可用性评分模型
资源引用理解模型
局部修改规划模型
项目专属 LoRA / Adapter
自动标注模型
质量检查模型
```

不建议早期自研：

```text
通用图片基础模型
通用 3D 基础模型
通用音乐基础模型
通用视频基础模型
```

因为这些模型成本高、变化快、竞争强，不应成为引擎早期护城河。

## 资源连续修改规则

AI 资源必须支持连续修改。
一次性生成不是核心流程。

正式流程：

```text
生成候选
  -> 用户指出不满意
  -> AI 理解修改意图
  -> Asset Edit Plan
  -> 局部修改 / 参数修改 / 重新生成变体
  -> 保持风格、引用、尺寸、平台约束不变
  -> Quality Gate
  -> Asset Revision
  -> Asset Graph 更新
```

AI 不能只拿最终图片继续反复喂模型。
必须保留：

```text
Asset Spec
Asset Source Graph
Reference Asset
Mask
Seed
Model Provider
Prompt
Style Bible
Generation Parameters
Edit History
```

用户说：

```text
这个敌机太像玩具了，改得更有压迫感，但不要改变红色阵营风格。
```

AI 应生成：

```text
Asset Edit Plan:
  target_asset: enemy_aircraft_medium
  preserve:
    - red_faction_palette
    - top_down_readability
    - sprite_size
    - existing_prefab_slot
    - mobile_texture_budget
  change:
    - sharper_silhouette
    - darker_metal_material
    - larger_weapon_shapes
    - stronger_cockpit_contrast
  edit_mode:
    - image_to_image
    - mask_body_only
  validation:
    - transparent_background
    - same_pivot
    - same_collision_bounds
    - readable_at_128px
```

## 核心数据对象

### Asset Spec

资源需求真相。描述：

```text
要生成什么
为什么生成
用在哪里
风格是什么
目标平台是什么
验收标准是什么
和哪些系统有关
```

### Asset Generation Plan

资源生成计划。描述：

```text
生成哪些候选
调用哪些模型
需要哪些参考
如何后处理
如何验证
如何接入项目
```

### Generation Graph

资源生成源图。记录：

```text
prompt
reference
mask
model
seed
style
generation step
postprocess step
validation step
```

### Asset Edit Plan

资源修改计划。描述：

```text
保留什么
修改什么
修改范围
修改方式
修改后如何验证
会影响哪些引用
```

### Asset Revision

资源历史版本。每次生成和修改都必须可追踪、可比较、可回滚。

### Style Bible

项目风格规范。约束：

```text
色板
比例
镜头
材质
UI 风格
阵营规则
角色规则
特效强度
音频气质
```

### AssetSlot

系统需要的资源槽位。例如：

```text
enemy_small_sprite
skill_fire_icon
shop_panel_bg
boss_intro_bgm
impact_vfx
```

用户和 AI 应优先操作 AssetSlot，而不是到处手写动态路径。

### Quality Gate

资源质量门禁。检查：

```text
尺寸
透明
pivot
碰撞
LOD
贴图通道
音频响度
平台预算
风格一致性
引用合法性
版权和来源
```

## 资源等级

资源生成分三档：

```text
Level 1: Single Asset Generation
生成单个图、模型、音效、材质。

Level 2: Asset Set Generation
生成一套同风格资源，例如一组敌人、一套 UI、一组技能图标。

Level 3: System Asset Generation
围绕一个玩法系统生成资源 + Prefab + DSL + UI + 音效 + 测试场景。
```

真正的核心卖点是 Level 3。

例如用户说：

```text
给我做一个火焰法师技能
```

普通 AI 工具可能生成一张图。
本引擎应生成：

```text
skill_icon
casting_vfx
impact_vfx
projectile_prefab
sound_effect
animation_marker
damage_rule_dsl
cooldown_ui_binding
mobile_low_quality_vfx
test_scene
```

并且全部进入：

```text
Asset Graph
DSL / IR / Rust AOT Rule
Prefab
Build Graph
Quality Gate
```

## 2D Sprite / 图标 / 道具图

适用：

```text
飞机
子弹
道具
技能图标
敌人
UI 小图
```

Asset Spec 必须包含：

```text
asset_kind
camera_view
silhouette
palette
transparent_background
pivot
size
animation_frames
target_platform
usage_slot
```

生成输出：

```text
main_sprite
damaged_sprite
icon
shadow
optional_animation_frames
thumbnail
```

验证规则：

```text
透明背景
尺寸符合平台预算
pivot 不变
碰撞区域可推导
小尺寸可读
和当前阵营色板一致
不能和玩家 / 敌人轮廓混淆
```

修改规则：

```text
允许修改 silhouette / 明暗 / 细节 / 颜色
不能默认改变 pivot / 尺寸 / 引用槽位 / 平台预算
```

## UI 资源

UI 资源必须可组合，不能只生成单张图。

Asset Spec 必须包含：

```text
ui_component_type
layout_role
state_list
theme_token
scale_mode
text_safe_area
input_mode
platform
```

按钮至少需要：

```text
normal
hover / focused
pressed
disabled
selected
icon_slot
text_style
nine_slice_rule
```

验证规则：

```text
文字不会溢出
九宫格拉伸不变形
触控尺寸符合手机端
状态齐全
颜色符合 UI Theme
和现有 UI Token 一致
```

修改规则：

```text
修改颜色和风格时，优先修改 Theme Token / Palette
不要逐张图片孤立修改
```

UI 资源必须接入：

```text
UI Theme
Design Token
Component Slot
```



修改规则：

```text

不能破坏任务目标、导航和玩法触发点
```

## Prefab / Entity 模板

Prefab 是资源和逻辑的交界点。

Asset Spec 必须包含：

```text
entity_type
components
asset_slots
logic_binding
stats_schema
runtime_lifetime
pooling_rule
```

生成输出：

```text
prefab
component_config
asset_slot_bindings
test_scene_instance
```

验证规则：

```text
组件齐全
AssetSlot 已绑定
DSL 引用合法
生命周期明确
对象池规则明确
移动端不会频繁实例化
```

修改规则：

```text
用户要求新增能力时，应同步修改 stats、component、vfx slot、ui binding、behavior DSL
不能只替换单个视觉文件
```

## 视频 / 图片 / 音频参考

参考素材不是运行资源，但必须进入 Asset Graph。

Reference Asset 必须包含：

```text
reference_type
source
user_note
style_tags
usable_scope
license_status
linked_asset_specs
```

用途：

```text
风格参考

配色参考
构图参考

```

验证规则：

```text
来源记录
授权状态
是否允许训练 / 参考 / 商用
和哪些生成资源有关
```

## DSL / IR / Blueprint 作为资源

Prefab / Scene / DSL / IR / Blueprint 都算 Asset。
它们也必须走资源规则。

DSL Asset：

```text
feature_spec_id
domain
system_contract
source_map
test_cases
```

IR Rule Asset：

```text
ir_hash
ir_version
native_operation_list
source_map
signature
```

验证规则：

```text
DSL 覆盖需求
IR 可追踪
IR operation 合法
Native operation 白名单
测试通过
```

修改规则：

```text
AI 修改 Feature Spec / DSL
确定性编译器生成 IR
不能直接修改 Rust AOT 产物
```

## 版权和来源

每个 AI 生成或参考资产都必须记录：

```text
source_type
provider
model
prompt
reference_asset_ids
license_status
commercial_usage
generated_at
owner
```

没有来源记录的资源不能进入正式发布 Build。

## 最终规则

```text
AI 资源生成不以文件为中心
AI 资源生成以 Asset Spec 为中心
```

```text
生成模型可以外接
资源生产系统必须自研
```

```text
单资源生成是基础能力
系统级资源生成是核心卖点
```

```text
资源必须可连续修改
资源必须可追踪
资源必须可验证
资源必须可接入 Asset Graph / Build Graph / Hot Update
```
