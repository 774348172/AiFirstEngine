# 长期主义实现路径

本文档定义当前项目从 Electron 编辑器原型，逐步进入 Native Rust Editor Host 与 AI-first engine 底层实现的长期主义路线。

它不是新的架构设想，而是后续开发的施工顺序。

## 核心原则

本路线的产品约束来自 `01-目标与核心原则.md`：默认用户没有编程基础或只有少量编程基础，目标项目以中小型游戏为主，同时保留大型游戏扩展能力。每个阶段除了技术 Gate，还必须证明新增能力能被自然语言、可视化编辑或可理解的报告使用，不能只证明底层类型已经存在。

```text
一个模块一个模块做。
每个模块先固定最小正式规格。
每个模块实现后立刻写测试。
测试通过后更新文档。
模块未达到完成标准，不进入下一个模块。
```

禁止的短期路线：

```text
继续围绕打飞机模板堆功能。
继续把所有编辑器逻辑塞进 App.tsx。
继续在 TypeScript runtime 里无限增加玩法系统。
继续把 Three.js preview 当成正式 runtime。
在 Project Schema / Runtime Boundary 未稳定前直接写 Rust 大 runtime。
在 IR v1 未稳定前直接做 Rust AOT。
```

允许的过渡路线：

```text
TypeScript runtime 仅作为 Rust Runtime MVP 出现前的临时 prototype。
Three.js 继续作为编辑器 preview backend。
Electron / React 继续作为 legacy transition shell。
当前 Build Graph 继续作为导出 MVP。
```

但这些都必须被明确标记为 prototype / transition，不允许误认为最终 runtime 架构。

Runtime 硬规则：

```text
Rust Native Runtime 是唯一正式 runtime。
TypeScript Runtime 冻结为 transition code。
Rust Runtime MVP 跑通后，TypeScript Runtime 进入退役和删除流程。
不做长期 TypeScript Runtime vs Rust Runtime 等价测试。
Rust Runtime 的正确性用 Golden Scenario Test 验证。
Rust Runtime 与编辑器主线不再围绕 Electron sidecar 设计。
Native Rust Editor Host 是正式编辑器主线。
Electron / React 只维护现有 legacy shell。
```
