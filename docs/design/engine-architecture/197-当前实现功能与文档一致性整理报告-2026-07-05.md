# 197-当前实现功能与文档一致性整理报告-2026-07-05

## 1. 整理目标

本报告按 `195` / `196` 的当前规则，对现有 Rust 实现做一次功能与文档一致性整理。

判断基准：

```text
用户心智是 Rust Project Framework + Project Assets。
IR 只存在于 Contract-bound RuleSlot 中，是受限规则数据。
复杂 gameplay 流程、复杂算法、复杂 UI 工作流默认由 Rust Project Module / Rust Framework 承担。
AUI Document 是 UI 结构真相；Binding 只读 ProjectUiStateSnapshot。
RuntimePackage 是发布运行输入真相。
```

本轮不重构大系统，只修复会误导后续实现方向的小偏差，并把仍需后续施工的缺口标出来。

## 2. 总体结论

当前实现总体没有偏离 `195` / `196` 的主方向。

```text
RuntimePackage 加载链路成立。
AUI Document -> package -> load -> binding -> overlay -> render pass 链路成立。
Runtime rule manifest 正式执行路径已经只允许 RustAot。
ProjectRuntimePackageAssembler 已经是 DesktopExportPipeline 的项目装配入口。
旧 Bridge / Extract / Hydration 模块名仍存在，但主要报告和语义已按 Projection 理解。
```

需要注意的偏差：

```text
ProjectLogicRunner 曾公开 RuleCall::ir_interpreter 构造，容易被误读成正式 runtime 执行路径。
render_extract / render_asset_bridge / runtime_scene_hydration 文件名仍是历史旧称。
AUI package_smoke_snapshot 仍是 C-min 验证快照，不是完整 Project UI State Producer。
ProjectRuleAsset 仍直接保存 canonical_ir 字段，当前可接受，但用户/AI 产品化入口不应暴露为默认编辑对象。
```

本轮已修：

```text
RuleCall 的 executor_hint 改为 crate 内部字段。
RuleCall::ir_interpreter 改为 crate 内部 validation_only_ir_interpreter。
IrInterpreterExecutor 改为 crate 内部 validation-only 占位。
trace 文案改为 ValidationOnlyIrInterpreter。
旧命名模块补充 module doc，说明它们是 Projection 旧名兼容，不是新架构层。
```

## 3. 功能对照

| 功能域 | 文档要求 | 当前实现 | 判断 |
|---|---|---|---|
| RuntimePackage | Runtime 只加载 RuntimePackage，不扫描项目源目录 | `load_runtime_package` 读取 manifest / scene / assets / rules / AUI / input；player 和 runtime_run 走 package | 一致 |
| ProjectPackage Assembly | 项目目录进入 RuntimePackageBuildInput 应走 `ProjectRuntimePackageAssembler` | `DesktopExportPipeline` 先 `ProjectRuntimePackageAssembler::assemble`，再 `RuntimePackageBuilder::build` | 一致 |
| AUI Document | AUI Document 保存 UI 结构，不保存运行时值 | `AuiDocument` 保存 canvas / nodes / binding_refs / action_refs；运行时值在 `ProjectUiStateSnapshot` | 一致 |
| AUI Binding | Binding 只读 `ProjectUiStateSnapshot`，不读 ECS / Project Rule | `AuiRuntimeResolver::resolve_bindings(document, snapshot)` 只消费 snapshot | 一致 |
| AUI Present | Renderer 只接收解析后的 overlay，不读 binding path | `AuiRuntimePresenter` 产出 `AuiOverlayFrame`，`RuntimeRenderer` / `RenderThread` 接收 overlay | 一致 |
| Rule 执行 | C-min 正式运行路径只允许 Rust AOT | `RuntimeRuleExecutor` 只有 `RustAot`；`RuleModuleRegistry` 拒绝非 `StaticRegistry` / 非 `RustAot` | 一致 |
| IR 定位 | Canonical IR 是内部规范语义 / 构建输入 | `ProjectRuleAsset` 仍包含 `canonical_ir`，并由规则资产生成 manifest / artifact id | 基本一致，产品化入口需继续隐藏内部 IR |
| Projection | 旧 Bridge / Extract / Hydration 名称只作历史命名 | `runtime_scene_hydration` 和 `render_asset_bridge` 已输出 `ProjectionReport`；本轮补充旧名说明 | 已标注兼容 |
| Complex Shooter | 项目语义不能进入通用 Core API | 样例名主要出现在 `samples`、测试、e2e gate 和 fixture 中 | 基本一致 |

## 4. 已修复偏差

### 4.1 Rule interpreter 旁路

问题：

```text
ProjectLogicRunner 公开 RuleCall::ir_interpreter。
虽然 RuntimeRuleManifest 正式路径只允许 RustAot，但外部代码仍可能绕过 manifest 手动构造解释器 RuleCall。
```

修复：

```text
RuleCall::ir_interpreter -> pub(crate) validation_only_ir_interpreter。
RuleExecutorHint / executor_hint 改为 crate 内部。
IrInterpreterExecutor 改为 crate 内部。
LogicResult unsupported 文案明确解释器是 validation-only，不是 runtime execution path。
```

效果：

```text
外部 crate 只能通过 RuleCall::rust_aot 或 RuleModuleRegistry / RuntimeRuleManifest 构造正式规则执行。
解释器占位只保留为 engine_runtime 内部测试和结构化 unsupported 证据。
```

### 4.2 旧 Projection 命名

问题：

```text
文件名仍有 render_extract / render_asset_bridge / runtime_scene_hydration。
如果后续 AI 只看文件名，容易误以为这些仍是独立 Bridge / Extract 架构。
```

修复：

```text
render_extract.rs 增加说明：当前按 RenderProjection / RenderProjectionAdapter<SpriteRenderer2D> 理解。
render_asset_bridge.rs 增加说明：当前按 AssetProjection 理解。
runtime_scene_hydration.rs 增加说明：当前按 HydrationProjection / HydrationProjectionAdapter<RuntimeScene> 理解。
```

## 5. 保留但需要继续治理的点

### 5.1 AUI ProjectUiStateSnapshot 生产者仍是 C-min

当前：

```text
AuiRuntimePresenter::package_smoke_snapshot 使用固定样例路径：
game.score_text
player.hp_ratio
game.paused
player.ship_icon
```

判断：

```text
这不违反 AUI Binding 规则，因为 Binding 仍只读 ProjectUiStateSnapshot。
但它还不是完整项目 UI state producer。
```

后续方向：

```text
由 Rust Project Framework / Project Rust Module 生成 ProjectUiStateSnapshot。
复杂 UI 交互状态和业务工作流不进入 IR。
```

### 5.2 ProjectRuleAsset 暴露 canonical_ir 字段

当前：

```text
ProjectRuleAsset { canonical_ir: ProjectRuleIr }
```

判断：

```text
当前实现作为工程内部资产格式可接受。
但产品化编辑入口不能把 canonical_ir 当作普通用户默认编辑对象。
```

后续方向：

```text
编辑器展示 Gameplay Rule Asset / Rule Graph / DSL 视图 / RuleSlot。
Canonical Rule IR 继续作为内部规范语义和构建输入。
```

### 5.3 RuntimePackageBuilder 在测试和验证里仍可直接使用

当前：

```text
engine_runtime 测试、complex_project_validation 和 builder 自测会直接构造 RuntimePackageBuildInput。
正式 DesktopExportPipeline 已走 ProjectRuntimePackageAssembler。
```

判断：

```text
测试 fixture 直接用 builder 可以保留。
项目目录导出路径不能绕过 ProjectRuntimePackageAssembler。
```

## 6. 后续建议

优先级从高到低：

```text
1. 继续保持 RuntimeRuleManifest 只允许 RustAot，避免解释器成为默认 runtime 路径。
2. 后续做 UI 系统时，先补 ProjectUiStateSnapshot Producer，而不是把复杂 UI 逻辑放入 IR。
3. 后续 Rule Authoring Productization 应隐藏 canonical_ir 默认编辑面，突出 Gameplay Rule Asset / RuleSlot。
4. 后续如有时间，可逐步新增 projection facade 名称，减少旧文件名对 AI 的误导；但不需要为了改名大重构。
```
