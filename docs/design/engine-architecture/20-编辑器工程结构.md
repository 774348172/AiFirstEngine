# Current Status Notice

本文档记录 Electron / React legacy editor shell 的过渡期工程结构。TypeScript / Electron 原型层现已归档到 `legacy/typescript-prototype/`；新编辑器能力默认进入 Native Rust Editor Host / Editor Core。

# 编辑器工程结构

本文档定义当前 Electron / React legacy editor shell 的工程结构和第一轮拆分规则。

它不是最终 Native Editor Host 设计文档，也不是 UI 视觉设计文档。  
它的作用是把当前 `src/App.tsx` 从超大入口逐步拆成可维护、可测试、可迁移的 legacy shell 模块，并为 Native Editor Host / Editor Core 迁移降低成本。

当前主规则：

```text
Native Rust Editor Host 是正式编辑器主线。
Schema-driven Editor Core 是编辑器业务真相层。
Electron / React 只作为 legacy transition shell。
本文档只约束 legacy shell 的维护、拆分和过渡。
新编辑器底层能力默认进入 Native Editor Host / Editor Core，不继续塞进 Electron / React。
```

## 当前问题

当前代码已经有正式化的底层边界：

```text
Project Schema
RuntimeBackend
Patch Plan
Asset DB
Build Graph
Replay Debug Store
AI Asset Generation
```

但编辑器入口仍然集中在：

```text
src/App.tsx
```

风险：

```text
UI、项目状态、AI Patch、Runtime Tick、Asset Import、Build Export、Replay Debug 混在同一个文件。
后续接入 Rust Runtime、Build Report Panel、真实 Asset Importer 时容易继续堆逻辑。
AI 修改 UI 或逻辑时难以定位边界。
测试粒度过粗，容易出现局部改动导致整体行为漂移。
```

## 目标

第一阶段目标：

```text
App.tsx 只负责应用装配。
面板组件从 App.tsx 拆出。
服务层承载项目修改、Patch、Validation、Runtime、Build、Replay 等流程。
拆分不改变现有用户行为。
每次拆分都能跑测试。
```

长期目标：

```text
Legacy React UI
  -> Editor Core / Services
  -> Engine Core / RuntimeBackend / Build Graph / Asset DB

Native Editor Host
  -> Editor Core / Services
  -> Engine Core / Rust Runtime / Renderer / Build Graph / Asset DB
```

而不是：

```text
Editor UI
  -> 直接改 Project / 直接调 Runtime 内部函数 / 直接写 Build Graph
```

## Asset Pipeline State 所有权

正式规则：

```text
Asset Pipeline State 属于 Editor Core / Native Editor Host。
React / Electron App 只作为 legacy transition shell 读取 Snapshot / ViewModel。

ProjectDock 不持有 AssetRegistry。
ConsoleDock 不持有 ImportReport / BatchImportReport / RegistryReport。
Inspector 不持有 Asset Pipeline 真相。
AI 不读取 UI 内部状态作为资源真相。
```

长期数据流：

```text
AssetPipelineController
  -> AssetPipelineState
  -> AssetPipelineSnapshot
  -> EditorAssetPipelinePanelViewModel
  -> ProjectDock / ConsoleDock / Inspector / AI Debug View
```

AssetPipelineState v1 边界：

```text
AssetPipelineState 是 Editor Core / Native Editor Host 内部状态。
AssetPipelineSnapshot 是 UI / AI 的只读输入。
AssetPipelineEvent 是刷新通知，不是资源真相。
EditorAssetPipelinePanelViewModel 是面板展示模型，不是资源真相。
```

AssetPipelineState v1 数据流：

```text
Importer / ImportWorker / FileChangeBatch
  -> AssetPipelineController
  -> AssetPipelineState
  -> AssetPipelineSnapshot
  -> ProjectDock / ConsoleDock / Inspector / AI Debug View

AssetPipelineController
  -> AssetPipelineEvent
  -> UI refresh / AI recent-change explanation
```

第一版过渡限制：

```text
legacy App 可以临时派生或读取 AssetPipelineSnapshot。
legacy App 不能长期成为 AssetRegistry / reports 的所有者。
新增资源系统能力默认进入 Editor Core / Native Editor Host 边界。
如果为了现有 React UI 临时接线，必须保留明确的迁移边界和测试。
active import 期间 legacy App 只能读取 progress / busy，不读取半成品 registry。
Snapshot 不能反向写回 AssetPipelineState。
Event 不能被当作数据库。
```

### inspector

职责：

```text
显示 Project / Scene / Entity Inspector
显示 Asset Editor / Asset Inspector D-min
显示 Component 字段
触发字段修改
```

长期规则：

```text
Inspector 字段应逐步由 Component Schema / Project Schema 驱动。
Inspector 不直接绕过 validation。
Inspector 修改必须通过 Patch / Project mutation service。
Asset Inspector 不持有 AssetPipelineState。
Asset Inspector 只读 AssetPipelineSnapshot / AssetInspectorViewModel。
Asset Inspector 不直接写 Asset DB / AssetRegistry。
Asset Inspector 可以直接触发 Editor Command，但不直接执行资源写入。
Locate / Copy guid / Open report / Switch tab 等低风险动作可以直接执行。
资源重导入、Importer setting 修改、AI 修复、删除、移动、重命名、引用替换、批量操作等高风险动作必须生成 AssetActionRequest / AssetActionPlan，由 Controller / Patch / ImportTransaction / Patch Transaction 执行。
Request / Plan / Transaction 只用于高风险资源动作，不允许扩散成所有 UI 操作的强制规则。
ProjectDock 选中资源后只写入 EditorSelectionState 的 asset target。
Inspector target = asset 时，必须通过 AssetPipelineSnapshot 派生 AssetInspectorViewModel。
Inspector 不允许从 ProjectDock props、ImportWorker 或文件系统扫描结果直接拼资源详情。
第一版 Asset Inspector 只展示 identity / importer 摘要 / dependencies / referencers / reports / actions，不做完整资源预览器、真实 importer setting 修改、Apply / Revert、多资源同时编辑或专用资源编辑器。
```

## 第一轮拆分顺序

第一轮只做无行为拆分，禁止顺手重构业务流程。

推荐顺序：

```text
1. RuntimeTracePanel
2. ConsolePanel
3. ProjectPanel
4. HierarchyPanel
5. InspectorPanel
6. AICommandPanel
7. ViewportShell
```

原因：

```text
RuntimeTracePanel 和 ConsolePanel 多数是展示逻辑，风险低。
ProjectPanel / HierarchyPanel 有选择和少量操作，风险中等。
InspectorPanel 修改项目字段，风险较高。
ViewportShell 涉及渲染和 RuntimeBackend，最后拆。
```

## 拆分规则

必须遵守：

```text
每次只拆一个面板或一个服务。
拆分前后用户可见行为不变。
先移动代码，再整理类型。
不要在拆分过程中改变 Patch / Runtime / Build 语义。
不要在 UI 组件中新增底层 import。
```

允许：

```text
提取 props type。
提取只读 view model。
提取纯 UI 子组件。
提取小工具函数。
```

禁止：

```text
顺手重写状态管理。
顺手换 UI 框架。
顺手改 Project Schema。
顺手改 RuntimeBackend。
顺手改 Build Graph。
```

如果拆分过程中发现必须改变架构设计，应暂停实现，先回到架构文档讨论。
