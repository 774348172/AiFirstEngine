# 201-热更新方案收敛与当前实现基线

## 1. 一句话结论

当前代码还没有真正的线上热更新系统。

当前已经实现的是：

```text
RuntimePackage manifest / hash / load
本地 RuntimeAssetIndex / Bundle mount / asset load / release
RuntimeAssetLoader.mount_patch_index 的资源索引覆盖原语
Rust AOT rule manifest / StaticRegistry / ProjectLogicRunner 执行
RuleArtifact / RuntimeRuleManifest 校验
```

当前没有实现的是：

```text
远程热更包下载
热更包签名校验
Hot Update Staging Area
安全 Apply Point 切换
完整资源 Delta / Full Content Update
IR RuleSlot hotfix 运行时执行
Project UI Hot Logic Module / Rust-authored WASM
Rust native dylib 热替换
```

正式口径：

```text
热更新不是任意代码替换。
热更新只承诺受控内容在可验证、可回滚、可审查的边界内更新。
当前实现只完成了热更系统需要的一部分底座，不应对外说已经支持完整热更。
```

## 2. 为什么之前看起来乱

当前文档里有三类说法混在一起：

```text
09 / 05 / 06 / 07：
  长期架构边界，描述未来应该支持什么。

186 / 187：
  当前规则执行 C-min / B-min，明确第一版只执行 Rust AOT + StaticRegistry。

195 / 199 / 200：
  最近新增项目逻辑和复杂 UI 边界，加入 Project UI Hot Logic Module / Rust-authored WASM 作为未来受控 UI 热逻辑路线。
```

因此统一理解为：

```text
长期方案可以讨论热更能力。
当前实现不能被描述成已经完成热更。
新方案必须写清楚是 current implemented、foundation primitive、future planned 还是 rejected。
```

## 3. 当前正式热更分层

| 层级 | 内容 | 当前口径 | 当前实现 |
|---|---|---|---|
| Level 1 | 数据 / 配置 / 文案 / 数值 | 应优先支持可验证热更 | 未形成完整热更包；可随 RuntimePackage / Project Assets 重构建 |
| Level 2 | 资源 / Bundle / AUI Document | 应支持 Delta / Full Content Update | 本地 asset index、bundle mount、load/release 已有；真实热更包未实现 |
| Level 3 | Contract-bound IR RuleSlot hotfix | 长期支持，走 IR Interpreter | 当前未实现；IrInterpreterExecutor 是 validation-only unsupported |
| Level 3.5 | Project UI Hot Logic Module | 未来受控 UI 热逻辑路线，Rust -> WASM | 当前未实现；无 host interface / wasm runtime / patch apply |
| Level 4 | Rust AOT rule artifact | 正式发布性能路径，不属于热更 | RustAot + StaticRegistry 已实现；变更需要重新构建 / 重新打包 |
| Level 5 | Rust native engine / project module | 不承诺热更 | 无 native dylib hot reload；DynamicValidationHost 仅占位 |

## 4. 当前代码实现矩阵

| 能力 | 状态 | 代码证据 | 说明 |
|---|---|---|---|
| RuntimePackage 加载 | 已实现 | `rust/crates/engine_runtime/src/runtime_package.rs` | 读取 manifest / scene / asset / rule / input / aui |
| RuntimePackage 构建 | 已实现 | `rust/crates/engine_runtime/src/runtime_package_builder.rs` | 写入 manifest、rule-manifest、asset-manifest、aui-manifest、diff report |
| 构建 diff report | 已实现，非热更 | `runtime_package_builder.rs` | 只报告 manifest hash changed，不生成 patch package |
| RuntimeAssetIndex | 已实现 | `rust/crates/engine_runtime/src/runtime_asset.rs` | guid / id resolve、cooked asset、dependency table |
| Bundle mount / unmount | 已实现，基础能力 | `runtime_asset.rs` / `runtime_asset_loader.rs` | 本地 mount table，不含远程下载和签名 |
| Asset load / release | 已实现，基础能力 | `runtime_asset_loader.rs` | 支持依赖加载、decoded cache、handle generation、diagnostics |
| mount_patch_index | 已实现，原语级 | `runtime_asset_loader.rs` | 能合并新的 RuntimeAssetIndex，让下一次 load 命中新版本；不是完整热更 |
| Rust AOT rule execution | 已实现 | `logic_executor.rs` / `project_logic.rs` / `rule_registry.rs` | RustAotExecutor + ProjectLogicRunner |
| RuntimeRuleExecutor | RustAot only | `runtime_package.rs` | enum 只有 `RustAot` |
| StaticRegistry | 已实现 | `rule_registry.rs` | 当前唯一可执行 module kind |
| DynamicValidationHost | 只校验 / 占位 | `runtime_package.rs` / `rule_registry.rs` / `rule_artifact.rs` | registry 明确拒绝执行 |
| IR Interpreter runtime hotfix | 未实现 | `logic_executor.rs` / `project_logic.rs` | 当前返回 `unsupported_executor` |
| Project UI Hot Logic WASM | 未实现 | `rg wasm` 结果 | 只有依赖锁文件里有 wasm 生态依赖，没有本系统代码 |
| Rust native dylib hot reload | 未实现 | 全局搜索 | 没有 libloading / dylib reload / module swap |
| Hot Update Package | 未实现 | `07` / builder 代码 | 文档中为可选长期输出，当前 Bundle Pack v1 不生成热更补丁包 |

## 5. 当前实现的准确说法

可以说：

```text
当前实现具备 RuntimePackage、RuntimeAssetIndex、本地 Bundle mount、资源加载释放、资源索引 patch 原语、Rust AOT 静态规则执行和 manifest 校验。
这些是未来资源热更、规则热更和 UI 热逻辑热更所需的底座。
```

不能说：

```text
当前已经支持完整热更。
当前已经支持 IR RuleSlot 热更执行。
当前 Rust 项目模块可以热更。
当前 UI Rust 逻辑可以热更。
当前可以下载补丁包并安全切换线上版本。
```

## 6. 正式方案收敛

### H0：当前基线

当前运行方式：

```text
Project / Editor
  -> RuntimePackageBuilder
  -> RuntimePackage
  -> RuntimeAssetLoader local mount
  -> Rust AOT StaticRegistry
  -> ProjectLogicRunner
```

变更方式：

```text
修改项目资源 / AUI / 规则
  -> 重新构建 RuntimePackage / Player
  -> 重新运行或重新发布
```

### H1：资源热更 C-min

目标：

```text
Hot Update Package
  -> manifest / changed bundle / removed assets / dependency list
  -> hash / signature / rollback target
  -> staging area
  -> safe apply point
  -> RuntimeAssetIndex patch + bundle mount switch
```

第一步可以复用：

```text
RuntimeAssetIndex.merge_patch
RuntimeAssetLoader.mount_patch_index
Bundle mount / unmount
AssetLoadDiagnostics
```

但必须补齐：

```text
补丁包 schema
下载 / 本地导入
签名 / hash
依赖兼容检查
旧 handle / 新 handle 生效规则
Apply Point
Rollback
Report
```

### H2：IR RuleSlot hotfix

目标：

```text
base rule = Rust AOT
hotfix rule = IR Interpreter
active rule = hotfix if exists else base
```

限制：

```text
只允许 Contract-bound RuleSlot。
不允许任意脚本。
不允许对局中静默替换。
State Rule 实例运行期间不替换。
```

当前缺口：

```text
真实 IR Interpreter runtime backend
IR hotfix package schema
RuleRegistry active version overlay
Apply Point
Interpreter vs Rust AOT equivalence / determinism test
Rollback
Trace source map
```

### H3：Project UI Hot Logic Module

定位：

```text
项目侧 UI 热逻辑的受控热更载体。
它不是 AUI Core 热更，也不是 Rust native dylib 热更。
```

推荐路线：

```text
Rust source
  -> wasm hot module
  -> stable host interface
  -> batch ProjectUiStateInput
  -> ProjectUiStateSnapshotPatch / ProjectCommand / Diagnostic
```

适用：

```text
tooltip 文本和属性差值生成
装备 / 商店 / 背包 UI 展示数据转换
panel state patch
AuiAction 到 ProjectCommand 的受限映射
```

不适用：

```text
AUI layout / hit test / drag drop framework
ECS 直接读写
renderer / file / network / platform API
长期 unmanaged state
完整 ProjectUiStateSnapshot 聚合算法
```

当前缺口：

```text
WIT / host interface schema
wasm runtime host
module manifest / hash / signature
import whitelist
batch input/output protocol
deterministic / performance test
Apply Point / rollback
diagnostic source map
```

### H4：Rust AOT / Native 变更

正式口径：

```text
Rust AOT rule artifact 是发布性能路径。
Rust Project Module / Engine Native Module 是 native 代码。
两者变更都走重新构建 / 重新打包 / 重新发布。
```

允许未来评估：

```text
Windows editor dev-only native fast reload
```

但它不能成为跨平台发布热更承诺。

## 7. 自走棋 / 复杂 UI 口径

以复杂自走棋装备 UI 为例：

| 内容 | 归属 | 热更口径 |
|---|---|---|
| 装备图标、稀有度框、文案 | Data / Resource / AUI Asset | 未来资源热更 |
| 装备面板布局、绑定路径、按钮 action id | AUI Document | 未来资源 / AUI 文档热更 |
| can_equip、equip_cost、显示条件 | IR RuleSlot | 未来 IR hotfix；当前需要重构建 |
| drop_on_slot -> equip_requested 受限编排 | Transaction RuleSlot | 未来 IR hotfix；当前需要重构建 |
| 背包排序算法、槽位事务、经济账本一致性 | Rust Project Module | 不热更，重新构建 / 发布 |
| tooltip 文本转换、局部 display transform | Project UI Hot Logic Module | 未来 Rust -> WASM 热更；当前未实现 |
| drag/drop 命中、pointer capture、layout | Rust AUI Core | 不热更，重新构建 / 发布 |

关键边界：

```text
复杂项目可以有热更空间，但不能为了热更把 IR 扩成脚本语言。
需要热更的自由 UI 业务逻辑，不进入 AUI Core，也不进入 Rust native dylib，而进入受控 Project UI Hot Logic Module。
需要强一致性和复杂算法的系统，继续留在 Rust Project Module。
```

## 8. 红线

不承诺：

```text
任意代码热更
Rust native dylib 跨平台热更
AUI Core 热更
Editor / Runtime core 热更
对局中静默替换 gameplay 逻辑
用 Lua / HybridCLR 作为本引擎主路线
用 WASM 替代全部项目逻辑
```

必须坚持：

```text
Hot update package 必须可验证、可签名、可回滚。
热更必须发生在 Apply Point。
帧同步项目一局内锁定 rulesetVersion / logicHash / dataHash / assetHash。
用户和 AI 不直接手写最终 Bundle、RuntimePackage internals、Rust AOT 派生产物。
```

## 10. 下一步施工建议

建议按真实价值排序：

```text
Step 1: Resource Hot Update C-min
  先把 Hot Update Package / signature / staging / apply point / rollback 跑通。
  这是最基础、最容易验证、也最接近商业项目需求的热更。

Step 2: IR RuleSlot Hotfix C-min
  只覆盖 Function Rule / Transaction RuleSlot。
  先不要做复杂 State Rule 热更。

Step 3: Project UI Hot Logic Module C-min
  只覆盖 tooltip / display transform / AuiAction -> ProjectCommand mapping。
  先不承载完整 UI framework 或完整 producer。

Step 4: Dev-only Native Fast Reload Research
  只限 Windows editor 开发提效，不作为发布承诺。
```

当前如果要进入施工，必须先生成独立施工文档，不能直接从本文开始改代码。
