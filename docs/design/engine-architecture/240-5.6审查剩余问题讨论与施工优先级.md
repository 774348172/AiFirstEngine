## 2. 状态定义

讨论状态与施工状态必须分开：

| 状态维度 | 可选值 | 含义 |
|---|---|---|
| 讨论状态 | 待讨论 | 尚未开始正式方案讨论 |
| 讨论状态 | 讨论中 | 已开始证据复核和方案比较，但用户尚未确认方案 |
| 讨论状态 | 已完成 | 用户已明确确认方案，正式方案文档已落盘并完成方案审查 |
| 施工状态 | 未施工 | 没有当前施工文档，或方案尚未进入施工 |
| 施工状态 | 待执行 | 施工文档已生成并自审，位于 `施工文档/待执行/`，尚未激活且禁止施工 |
| 施工状态 | 施工中 | 唯一当前施工文档已激活；可标明“未开工”或正在执行的 Gate |
| 施工状态 | 已完成 | Gate、整体回归、完成记录、入口同步和施工归档全部闭环 |
| 任一状态 | 阻塞 | 有明确外部阻塞，本文必须记录证据、责任边界和恢复条件 |

“讨论完成”必须同时满足：

```text
当前代码证据与审查结论已重新核对。
成熟引擎/工具的官方文档和源码做法已研究。
已给出 2-3 个可选方案及本项目推荐结论。
用户已明确选择或确认方案。
正式方案文档已落盘并完成方案审查。
```

只在对话中提到过、只写了审查建议、只存在旧方案、或 AI 自己推荐但用户未确认，都不算 `讨论状态=已完成`。

```text

2. 校验本文状态是否与正式方案/施工归档一致；不一致时先修本文状态。

4. 若该项目为“讨论中”，继续原讨论，不新开另一套方案。

6. 用户明确点名其它项目时可以讨论，但先声明它跳过了哪些未完成高优先级项目。
```

用户说“开始施工/执行下一步”时，不按讨论状态或待执行状态直接猜：只以 `54` 和 `施工文档/当前/` 的唯一施工文档为准。没有当前施工文档时，先对最高优先级待执行文档做激活前复核并移动一份到 `当前/`；没有待执行文档时才生成并自审新施工文档。
