## 1. 目标与完成定义

提供面向 AI 创作、能承载大型效果的正式引擎粒子系统。AI 用普通项目文件表达效果，用代码处理特殊行为，用现有 Engine tools 运行、观察和修改。人工不必创建节点、拖动曲线或操作粒子编辑器。

完整目标同时包含：可编程创作、真实 GPU 模拟、批量渲染、运行生命周期、大规模运行边界，以及 AI 实际制作效果的闭环。仅实现组件、通过编译、渲染若干点或返回活跃计数，均不构成完成。

本方案必须交付两个实际可运行效果：

1. **火花与烟雾爆炸**：证明常见参数、多个发射器和不同绘制方式能简洁组合。
2. **吸附、螺旋上升与爆开**：证明 AI 能通过公开粒子函数编写非预置行为，并修改行为，无需新增引擎特效模块。

两者都必须经过需求记录、首次制作、真实画面复看、两轮有目的的修改、修改后复验和最终交付。源码集成通过只是中间状态；不得把样例制作与复验留为“施工完成后可选事项”。

## 3. 选定方案 B 与架构边界

采用**结构化效果描述＋可选 WGSL 粒子行为函数＋引擎托管 GPU 执行**。常见行为可直接配置，特殊行为可编程；两种输入使用同一粒子运行合同。自定义函数必须在本版真实编译、运行和交付，不能只预留入口。

```text
AI 编写效果描述、可选行为源与项目触发代码
  → 既有 Compiler：校验、派生、源码定位和增量准备
  → RuntimePackage
  → Runtime 粒子播放与 GPU 模拟
  → 既有 RenderGraph / RHI / WGPU 的粒子批量绘制
  → 现有 playtest / observe：时间采样画面、行为与按需性能证据
```

AI 根据证据自行选择下一步。内部生成、更新、排序和绘制不是新的 AI 工具，也不是强制逐步调用流程；九项独立工具保持。Skill 只给可跳过的使用建议，不增加引擎内 AI、第二个 Agent 或统一 MCP 调度工具。

### 3.1 本次明确修订的下层边界

允许 AI 在项目资产中编写符合公开粒子函数合同的 WGSL。它确实是 GPU 程序源，不能通过改名规避旧文档的“AI 不写 Shader”。[渲染技术路线](../渲染技术路线/README.md)和[技术路线与迁移](10-技术路线与迁移.md)中相应表述按本方案限定适用范围。

引擎继续拥有 GPU handles、缓冲绑定、RenderGraph/RHI 命令、同步、资源分配与释放。项目不手写生成的管线代码或最终 RuntimePackage；本次不开放任意自定义 Render Pass，也不改造通用材质图系统。顶层 v1.1 无需换版。

## 4. AI 创作合同

### 4.1 作者源与唯一真相

一个效果以一个 `*.particle-effect.json` 为主要描述；特殊行为引用项目内 `*.particle.wgsl` 源文件。文件合同已由A落实，公开SDK控制由D落实，具体字段与命名见施工文档及第4.3节；实际双效果制作和交付资格仍待E/F。

| 描述内容 | 确定语义 |
|---|---|
| 身份 | 版本化 schema、稳定 Asset ID/GUID；按既有 AssetRef 规则引用纹理、材质和网格 |
| 发射器 | 有稳定名称、各自容量、发射速率/爆发、延迟与循环策略；可在一个效果内组合 |
| 时间与空间 | 秒为时间单位，明确 local/world 空间、坐标轴、效果时钟和参数单位；作者不推测隐藏单位 |
| 行为 | 常见初始化/更新行为、曲线、种子，以及可选自定义函数源引用 |
| 外观 | 颜色/透明度、尺寸、旋转、序列帧、绘制方式、混合与排序需求 |
| 参数与输入 | 显式类型、默认值、必要范围和声明的只读数据输入；项目可通过公开 SDK 修改 |
| 容量与可见性 | 粒子及事件上限、合理包围范围、质量/重要程度与离屏策略 |

未知字段、无效引用、非有限数、错误单位或参数类型必须能定位。合理默认值用于减少输入；不要求 AI 同时维护效果描述、节点图、绑定表和生成 Shader 四份同义内容。描述中的参数定义是类型真相，函数看到的参数布局由引擎生成。

源文件进入现有 SourceView、Asset Graph 和唯一 Compiler/Assembler。常规模块是可组合数学与行为能力，不是“爆炸/龙卷风”等封闭玩法目录；需要特殊公式时不强迫修改 Engine Core。

### 4.2 可编程行为

公开两个语义入口：粒子出生初始化、每模拟步更新。函数读写自己的位置、速度、颜色、尺寸、旋转、寿命和声明的自定义状态，读取效果参数、步长、种子以及已声明环境输入。允许正常 WGSL 数学和函数组合，不另造通用 DSL 或把 Canonical Rule IR 扩成 GPU 语言。

必须固定行为执行次序：引擎初始化基础状态 → 已声明初始化行为 → 自定义初始化；每步更新年龄与步长 → 描述中有序的更新行为 → 自定义更新 → 根据提交状态判断存活。移动积分须有显式约定：默认由标准积分行为负责；自定义位置函数可选择接管，不能两层都隐式积分。碰撞/子发射的阶段与粒子结束时的事件顺序进入同一公开合同和测试。

发射、结束或碰撞可向引擎托管的有界事件通道请求子粒子；不允许绕过容量直接写其它粒子的内存。自定义函数无需声明 GPU binding 编号、分配缓冲或控制 dispatch。代码验证只能证明语法/类型与合同，不保证任意程序的耗时；复杂函数还须接受实际 GPU 成本测试。

WGSL 使用成熟编译/验证链。任意 Rust 函数不会自动在 GPU 上执行；本版也不承诺任意 GPU 程序具有等价 CPU 回退。无所需 GPU 能力时明确失败或使用作者显式声明、已验证的替代效果，不静默改用 CPU 并宣称同等能力。固定种子用于控制复看条件，不承诺跨 GPU 浮点结果逐位一致。

### 4.3 项目控制与播放状态

Scene/Prefab 中的效果组件保存引用和初始参数，保持纯数据。项目 SDK 提交播放、设置参数、暂停/恢复、停止发射和清空等 typed intent。正式名称、组件 schema 和现有 ABI consumer 改动在施工文档中落实，不新增每种特效专用 API。

D已落地：组件名`engine.particle_effect`，字段`effectRef / playOnAwake / paused / parameters`；SDK入口`writer.particle_effect(&entity)`，方法`play / restart / stop_emitting / clear / set_paused / set_parameter`。暂停/恢复分别为`set_paused(true/false)`，命名参数使用`ParticleParameterValue::{Float, Uint, Vec3, Vec4}`；效果描述仍为参数类型/范围/作用阶段的唯一定义。

- 同一播放源重复 play 默认保持当前播放；restart 显式从零重播，避免持续状态导致每帧重新爆炸。
- stop-emitting 停止新粒子并让旧粒子自然结束；clear 立即清除粒子和待消费视觉事件；两者不得混用。
- 不同源可并行播放；单源重播不隐式累积无限实例。命令按既有成功提交通道只消费一次，NoOp/失败不生效。
- 参数生效于下一个约定的模拟步；发射初值变化作用于新粒子，更新参数变化作用于活跃粒子，需在参数合同中可辨认。
- 局部/世界空间分别验证跟随源移动和发射后脱离源移动。暂停冻结效果时间和粒子更新，不在恢复时追赶暂停期间的发射。
- 组件移除、实体销毁、Scene 实例卸载和 session 结束均由 Runtime 清理；句柄带运行实例身份/世代，旧命令不能命中新实体。GPU 资源退役须考虑在途帧，不能提前释放。

## 5. 正式运行与渲染范围

### 5.1 数据与执行责任

效果/发射器是场景控制对象，粒子使用专用连续数据或 GPU 缓冲，不逐颗创建 ECS Entity、RenderProxy 或普通 Sprite 命令。Runtime 拥有播放、时间和生命周期；GPU 粒子执行接入既有 Renderer 功能与 RenderGraph/RHI，跨域使用既有 Projection 规则，不另造同步总线、独立 DLL、Compiler 或缓存服务。

GPU 模拟、存活回收、实例准备和绘制形成真实链路。按需要生成活跃索引、排序数据和间接绘制参数；缓冲在容量不变时持续使用，不每帧从 CPU 重建全体粒子顶点。默认不逐颗读回 GPU，必要统计异步读取并标明采样帧；不得为生成报告强迫每帧等待 GPU。

模拟使用明确的步长与效果时钟；同一模拟步不因多次 Present 重跑。运行落后时采用有界追赶并记录降级事实，暂停、重播和生命周期不依赖本帧恰好有 Fixed Tick。

### 5.2 本版必须落地的功能面

| 范围 | 本版能力 |
|---|---|
| 效果组织 | 多发射器、连续/爆发发射、延迟/循环、固定种子、有界子发射 |
| 运动与变化 | 常用发射形状、速度/重力/阻力/噪声、颜色/大小/旋转随寿命变化、自定义初始化与更新 |
| 绘制 | 2D 与 3D billboard、序列帧、网格粒子、拖尾；Alpha/Additive 混合和需要时的深度排序 |
| 环境交互 | 平面/球体等简单显式碰撞输入、反弹/结束及事件；不借用项目玩法实体做逐粒子刚体 |
| 生命周期与规模 | 播放控制、资源退役、发射器/效果容量、离屏处理、质量与重要程度预算、可观察的超限处理 |

这些能力是本版完成范围，不以“以后可扩展”替代实现。GPU 主线、自定义函数、批量绘制和两个真实效果不能被挪到后续版本。功能可依赖顺序分段施工，但整体完成必须有第8节覆盖。

材质、透明叠加和粒子运动共同影响画面；仅有模拟吞吐不代表烟雾或火焰表现合格。3D 验收须有实际相机下的粒子绘制、遮挡/排序证据，不以二维截图推断完整 3D 游戏能力。

D的普通资源合同：保留`.asset`的`schemaVersion / assetId / assetGuid`元数据，用`runtimeData`保存mesh的`positions / uvs / indices`或unlit material的`baseColor`和可选纹理AssetRef `texture`。Compiler沿现有Assembler提取纯运行字节、校验并维护依赖；粒子draw显式texture优先于material的texture，颜色相乘。未知材质图/Shader字段不静默接受，不声称已具备通用模型导入或光照材质系统。

明确不包含：粒子编辑器/节点图 UI、资源复用库、引擎内效果生成 AI、任意 GPU 计算框架、流体/体积求解、全局邻域算法、完整动态光照/Bloom、复杂场景 SDF 烘焙、全功能 CPU 镜像和所有平台同时资格化。单粒子程序的公开边界不能被宣称支持任意多阶段流体算法。

## 6. 编译、交付与 AI 反馈

效果描述、行为源、引用资源、编译合同版本与目标能力参与既有摘要和依赖失效。参数默认值修改重新准备效果数据；行为源修改校验并准备相关 GPU 程序；只失效受影响产物，不要求重编 Engine DLL。Shader/管线创建仍可能有耗时，分别记录，不能承诺零编译成本。

RuntimePackage 包含真实运行所需效果数据、程序和资源，不依赖项目源目录或编辑器缓存。变更 GPU 属性布局时重新准备对应实例并明确重启/迁移策略，不用旧布局继续执行；本版可采用明确重启，未要求无缝热更新。普通项目迭代不自动触发完整 export/verify。

沿现有 check/run/playtest/observe 输出以下证据，具体字段并入既有结果合同：

- 编译：效果文件、发射器、阶段、字段或作者代码行、首因及局部修复提示；生成代码错误必须映射回作者源。
- 运行：未触发、发射停止、活跃、完成、被裁剪、超容量丢弃、后端不支持和执行失败等可区分事实。
- 可视：效果身份、源摘要、种子、相机、模拟时间与真实关键帧序列对应；视频可作为补充，关键帧序列是本版必需交付。
- 性能：活跃/发射/丢弃计数、效果与发射器数量、CPU/GPU 时间、缓冲内存和回读采样身份。无法获取的指标明确 unavailable，不用 CPU 提交耗时代替 GPU 时间。

Off/Summary/Trace 延续既有规则，常规运行不写逐粒子日志。完整性能采样和捕获按测试请求启用。语义计数只辅助定位，不能替代真实画面审阅。

## 7. 两个效果的实际制作与修改流程

### 7.1 一个小型验证项目，两个真实效果

在后续施工中建立一个普通项目 `samples/particle_effects_project`，容纳两个效果、必要相机/背景、触发和重播入口。此路径为拟建，当前不存在不影响方案状态。它是公开 SDK 的消费者，不是独立粒子引擎或第三个完整游戏。必要纹理按正常资产链进入项目，不建设资源复用系统。

两个案例使用同一套公开能力，效果命名和特殊轨迹不能进入 Engine Core。引擎集成测试可以使用最小夹具，但真实制作阶段必须从需求与可运行项目起步，不能把引擎内部测试 Shader 原样包装成“AI 制作完成”。

### 7.2 效果 A：火花与烟雾爆炸

任务：在指定位置产生一次短促爆炸，火花快速向外飞散，烟雾较慢扩散消退，少量碎片落下；背景应保持可辨认。源移动后旧烟雾不被拖走，重播不残留上一轮效果。

实现以结构化参数为主，组合火花、烟雾和碎片发射器。覆盖 Additive/Alpha 混合、烟雾序列帧、网格碎片、少量拖尾和简单碰撞；子发射可用于首次碰撞后的短火花，必须有数量上限。

基准时序：首次播放后 `0.10 / 0.35 / 0.80 / 1.60 / 3.20` 秒采样。到3.20秒可见粒子应全部结束；火花运动快于烟雾，烟雾连续淡出，碎片方向与重力一致。采样时刻可在创作开始前依据最终需求统一调整，不得在发现失败后删去失败时刻。

两轮修改任务：

1. 调整火花方向与速度范围，使爆炸明显偏向上方；保留烟雾行为。
2. 缩短烟雾消退时间并降低遮挡；保留已改好的火花方向。

每轮保留相同条件的前后关键帧、源差异、检查结果和视觉判断。不能只改文件后声明效果应当变化。

### 7.3 效果 B：吸附、螺旋上升与爆开

任务：粒子先从外围向中心吸附，随后绕轴螺旋上升，最后向外爆开并淡出。阶段之间位置连续，可从不同相机观察空间轨迹。

基准时序：`0–0.8s` 吸附、`0.8–2.2s` 螺旋、`2.2s` 开始爆开、`4.0s` 内清空。关键帧选 `0.20 / 0.70 / 1.20 / 1.90 / 2.35 / 3.00 / 4.00s`，另保留能辨认旋转方向的相邻帧序列。

必须使用项目自定义粒子初始化/更新函数表达轨迹与阶段变化，不允许为案例新增命名的引擎内置“吸附螺旋爆炸”行为。效果参数可控制半径、上升速度和阶段时长。

两轮修改任务：

1. 反转旋转方向、扩大螺旋半径；使用相同相机和种子证明变化。
2. 修改行为代码，让爆开速度随粒子高度变化，并调整爆开时机；必须体现作者程序变更进入最终 GPU 产物，不能只改一个未消费的代码文件。

检查阶段顺序、轨迹连续、方向、高度关系、颜色/透明度变化和最终消失。证明自定义行为无需改引擎，并记录这一轮只准备了哪些产物。

### 7.4 每个案例必须执行的闭环

1. **记录输入**：保存效果需求、初始项目身份、模型/宿主、相机、种子、时间线和评价标准；正常人工文字反馈允许，若发生人工编辑效果文件或节点必须如实记录，不能计为 AI 独立制作通过。
2. **制作首版**：AI 编写效果文件和必要项目控制代码，经现有 check/run 获取真实结果；失败在对应责任层修复。
3. **审阅首版**：打开真实关键帧序列，逐项判断需求；记录实际看到的表现与不足，不以计数或编译成功代替。
4. **执行两轮修改**：按各案例指定任务形成局部差异，重新运行受影响效果，在相同条件下比较；保留前后身份和结论。
5. **复验最终版**：普通窗口播放与有界 playtest/observe 使用同一最终交付身份。验证暂停/恢复、重复触发、重播清空和退出。
6. **交付与留存**：按正常 build/export 产生独立产物，原样复制到独立目录，在无法使用作者源路径的条件下运行两个效果，保留运行与视觉证据；提供用户可直接打开的产物及关键帧位置。

这六项是本次验收的结果要求，不把固定工具顺序写入公共 Skill。AI 可以自主选择先查证据、局部修改还是运行；不为每次小修改强制完整导出。最终交付复验集中执行一次，失效或失败时才定向重做。

修改阶段时长或方向前，先记录变更后的预期。复验保留相同时间点的对照帧，并补充新阶段边沿的帧；只更新本轮有意改变的断言，其余要求继续保持。不能因改了爆开时机仍套用首版时序而误判，也不能删除失败断言来制造通过。

每个案例至少记录：首次可见用时、两轮修改到复看的用时、人工干预、失败原因、修复次数、作者文件数量、引擎源码是否被迫修改。分开列出构建/准备/运行/审阅耗时，不只给一个模糊总数；未做同条件对照不宣称快于 Godot/Unity。

### 8.2 大型效果测量

使用同一验证项目的参数化负载，不再另写性能游戏。施工文档须在测量前固定设备/GPU/驱动、构建 profile、分辨率、相机、材质、可见覆盖、采样长度、目标帧预算和粒子增量预算；不能看到结果后调低通过门槛。没有预算或未达到预算，P8 不得标为通过。

必需负载方向：

- 同一简单程序的 `1千 / 1万 / 10万` **实际活跃**小面片粒子，区分模拟与绘制成本；不是仅分配容量或把粒子藏到屏幕外。

10万粒子是规模验证点，不预先承诺任何显卡在任意材质下60FPS；要区分简单面片吞吐与大面积烟雾的像素成本。通过范围绑定设备与效果条件。计时不可得或窗口无法运行必须说明未完成的证据，不能把 headless 成功转换为画面/性能资格。
