## 2. 选定路线与排除边界

选择A：模块化美术资源＋Sprite透明叠层＋局部渐变光晕＋既有GPU粒子＋真实AUI。环境固定明暗可绘入模块贴图；光束亮芯/宽柔光分层；动态火花、出口和死亡反馈沿343公开SDK控制。

B（通用发光/Bloom）和C（动态2D灯光/阴影）未选用，不进入本施工。普通Sprite尚无公开加法混合，不把修改Sprite材质接口偷偷纳入A；若现有素材/透明叠层/粒子无法达到明确验收项，先保存失败对照并做缺口分析，再讨论是否改变方案。

本轮不新增工具、ABI、通用Shader图、Scene加载/卸载系统、联网、Android/release导出、安装升级或宿主绑定修改。保留338的关卡地形、碰撞、跳跃、平台速度与激光周期；可修改项目视觉绑定、动画资源和HUD状态消费，不为匹配截图改动玩法时序。

## 3. 视觉规范与资产拆分

色彩以深蓝黑墙体、低饱和青灰设备、青绿色安全灯和红粉色危险激光为主。白色/浅青用于小面积亮芯、角色细节和正文；背景明度低于角色与机关。场景材质由大形、面板缝、窄描边和少量磨损建立层次，避免噪点掩盖轮廓。

| 资产组 | 必须分开的内容 | 编辑与呈现要求 |
|---|---|---|
| 远景与墙体 | 可拼接墙板、立柱、通风口、设备舱、管线、非交互标识 | 单个模块内可合并装饰，不能把整房间、角色、UI或机关烘成一图；覆盖整个相机移动范围 |
| 地形与机关 | 地板顶边/侧面、平台、踏板、门框/门体、激光发射器 | 视觉对齐既有碰撞面；移动平台装饰随平台统一运动 |
| 角色 | 面罩、身体、轮廓统一的透明背景动画帧 | 复用Animator2D；待机、移动、跳跃/下落、受伤状态可辨，脚底锚点和帧外框稳定 |
| 固定灯具 | 灯条、局部柔光、低透明光锥 | 明暗可烘入背景模块；分离光晕须固定世界位置，避免变成贴着摄像机的蒙版 |
| 激光 | 亮芯、红束、宽柔光、上下发射器、少量火花 | 开启/预警/关闭同步真实机关状态；发光范围不扩大危险判定；关闭后不能残留像开启的亮束 |
| 出口与反馈 | 门灯、方向箭头、出口/通关爆发、死亡消散 | 沿既有事件驱动；暂停停止动态效果，重开/换房清理旧效果 |
| UI | 顶栏面板、房间进度、计时/失败数、提示、暂停按钮、底部键位、状态浮层 | 使用AUI与真实运行状态；可用装饰面板图片，文字/按钮/进度不烘入图片 |

以1280×720作为现有主验收分辨率，参考图约16:10的构图按比例重新排版而非拉伸截图；另用1600×1000检查接近参考图比例的布局。具体顶部/底部面板高度以不遮挡跳跃轨迹和落脚点为约束。中文标题、字号层级、按钮点击框与显示一致；房间数字与标题、计时/失败数使用真实状态，缺少绑定时只补项目侧状态生产。

精确几何件、描边和UI面板优先采用可编辑矢量/程序绘制源并离线导出PNG；需要AI生成角色或纹理时使用imagegen流程，保留源图、透明处理和裁切记录，不以AI生成整张场景代替资产制作。资产保存到项目Assets，沿现有texture-asset/AssetRef/meta/GUID机制登记，保持已有引用身份或显式更新引用，进入正常Compiler/RuntimePackage消费路径。记录尺寸、采样方式、锚点、动画帧顺序和来源；不在Runtime生成或改写纹理文件。

## 4. 渲染与状态消费

继续通过既有Sprite/RenderProjection和UiProjection呈现，不增加类型专用Bridge。按背景、设备、地形/机关、角色、适当位置的透明光效、HUD组织排序；实际粒子/世界深度关系用截图验证，不能仅根据作者层号推断。

局部光晕用带平滑透明边缘的纹理，避免黑边、矩形边框和大面积发白；激光亮芯保留清楚窄线。动态加法效果使用343已有纹理粒子，其数量按可见密度控制，不把固定墙体和静态UI转换成粒子来绕过Sprite能力。若持续光束能用透明Sprite达到标准，优先用该方式。

保持公开SDK边界：RuntimeModule只驱动游戏语义对应的可见状态/动画/粒子，不接触GPU或RenderProxy。HUD走active binding path/dirty cache，不增加每帧全量镜像或常驻Trace。危险预警和UI进度从同一项目计时状态读取，不另起墙钟。

## 5. 参考实现的采纳与限制

前一轮已核对本地Godot源码 `I:/godotcode/godot-master/godot-master`：

- `scene/resources/canvas_item_material.cpp::CanvasItemMaterial::_update_shader`按blend_mode生成blend_mix/blend_add等render_mode，随后由渲染服务消费。采纳“资产形态与混合方式明确分工”，不声称本引擎普通Sprite已有同等材质接口。
- `drivers/gles3/effects/glow.cpp::Glow::process_glow`从源颜色经过亮部过滤、降采样、上采样形成Glow。该链路解释B的额外渲染成本与边界，本轮不照搬或实现。
- 本引擎 `rust/crates/engine_runtime/src/particle_render.rs`已使用SrcAlpha/One加法混合；`render_asset_bridge.rs::SpriteBlendMode`仅Opaque/AlphaBlend；338已有`house-laser-sparks.particle-effect.json`消费纹理加法粒子。

在线尝试Godot官方2D lights/shadows与CanvasItem shader文档返回403，GitHub文档源请求超时；不把网络失败记为已完成在线核验。本轮依据用户图与已读本地源码，不宣称参考图来自某个引擎或采用真实Bloom。已有Godot源码参考与其它AI源码参考只作索引；未发现本344专属外部审查结论。
