# 93-复杂打飞机验证所需引擎侧缺失能力清单

## 当前归属说明：Projection 术语

本文中如果出现以下历史名称：

```text
RenderExtract
RenderAssetBridge / Render Asset Bridge
Physics2DBridge
RuntimeScene Hydration
AuiRenderExtract / AuiRendererBridge
SpriteRenderer2D ECS-to-RenderProxy Bridge
```

统一按 `110-World-Projection-Adapter统一跨域同步规则.md` 理解为：

```text
RenderProjection
AssetProjection
Physics2DProjection
HydrationProjection
UiProjection
RenderProjectionAdapter<SpriteRenderer2D>
```

这些名称可以作为历史实现名保留，但不再作为新增架构概念扩展。后续新增类型只新增对应 `ProjectionAdapter`，不新增独立 Bridge。

## 1. 文档目的

本文承接 `92-当前功能盘点与打飞机游戏可行性评估.md`。

92 的结论是：当前引擎已经能做打飞机技术 demo，但还不能自然制作稍微复杂、可玩、可编辑、可测试的打飞机游戏。

这里需要修正一个边界：下一步不应该做 `Shooter Gameplay C-min` 这种听起来像“引擎内置打飞机玩法”的系统，而应该做：

```text
Engine Gameplay Foundation C-min
```

也就是补齐引擎侧通用游戏运行能力。打飞机只作为验证场景，不作为引擎内置玩法。

## 2. 引擎侧与项目侧边界

### 2.1 引擎侧负责

引擎提供通用、可复用、和具体游戏玩法无关的基础能力：

```text
ECS 查询
通用 Component 读写
CommandBuffer
Entity spawn / despawn
Prefab instantiate / despawn
输入 Action 运行时
Runtime Time Service C-min
Physics2D Foundation / 2D 空间查询与碰撞对
Sprite / 2D 渲染
AssetRef / Runtime Package
Trace / Replay / Golden Scenario
编辑器 Authoring 工作流
```

### 2.2 项目侧负责

项目定义具体玩法概念和规则：

```text
Player
Enemy
Bullet
Health
Damage
Score
WaveSpawner
DropTable
BossPhase
WeaponLevel
```

这些不应该成为引擎内置类型。它们应该来自：

```text
Project Schema
Project Data Asset
Prefab / Blueprint
Project Rule / IR / Rust AOT
```

## 3. 成熟引擎对比

### Unity

Unity 内置的是：

```text
GameObject / Component
Transform
SpriteRenderer
Physics2D / Collider2D
Prefab
Input
AssetDatabase / Importer
Scene / Game View / Inspector
```

Unity 不会内置“Bullet / Enemy / Score”作为引擎基础概念。它们通常由项目脚本、Prefab、ScriptableObject 和场景对象定义。

### Unreal Engine

UE 内置的是：

```text
Actor / Component
World / Level
SpawnActor
Collision / Trace
Input
Asset Registry
Blueprint / C++
Render Thread / RHI
```

UE 有 Gameplay Framework，但具体游戏里的子弹、敌人、血量、分数依然是项目层定义，不是引擎底层必须理解的东西。

### Bevy

Bevy 内置的是：

```text
ECS World
Query
Commands
Schedule
Events
Assets
Sprite / Camera
Input
```

Bevy 的 `Health`、`Bullet`、`Enemy` 都是项目自己定义的 Component。

### Godot

Godot 内置的是：

```text
Node / Scene
Resource
Sprite2D
Area2D / CollisionShape2D
Signal
Input
Editor workflow
```

Godot 项目会用脚本和 Scene 组合出子弹、敌人、血量、分数等玩法对象。

## 4. 明确不做成引擎内置的内容

以下内容不进入引擎内置能力：

```text
Health
Damage
Score
Bullet
Enemy
Player
WaveSpawner
DropTable
BossPhase
WeaponLevel
WeaponUpgrade
EnemyAI
ProjectileRule
```

引擎可以提供让这些东西高效运行和方便编辑的底层能力，但不理解它们的玩法语义。

## 5. 缺失的引擎侧能力清单

### 5.1 Engine Gameplay Foundation C-min

这是最优先需要补齐的基础系统。

目标是让项目规则可以自然地查找、读取、修改和创建 Entity / Component，而不是只能改 Transform。

第一版能力：

```text
ECS Query API
Generic Component Read
Generic Component Write
CommandBuffer
SpawnEntity
DespawnEntity
AddComponent
RemoveComponent
SetComponentField
CommandBuffer apply point
Trace every write
```

关键规则：

```text
引擎只保证内存安全和结构一致。
玩法顺序、扣血顺序、得分规则由项目层规则决定。
所有写入必须能被 Trace 追踪。
AI 生成规则时优先生成少量清晰 Query + Command，而不是隐藏流程。
```

### 5.2 Physics2D Foundation C-min

打飞机、平台跳跃、塔防、ARPG 都需要基础空间查询。

本系统不再命名为单纯 `2D Spatial Query / Collision C-min`，正式收敛为：

```text
Physics2D Foundation C-min
```

原因是：后续需要升级到完整 Physics2D 类似系统时，不能重新补第二套物理入口。第一版只实现查询和碰撞对，但架构上按完整 Physics2DWorld / Physics2DBridge 预留。

第一版能力：

```text
Collider2D
Physics2DWorld
Physics2DBridge
AABB
Circle
Layer / Mask
overlap_aabb
overlap_circle
collision pair report
query trace
```

边界：

```text
ECS World 是游戏对象与组件真相。
Physics2DWorld 是引擎内部物理计算世界。
Physics2DBridge 负责 ECS 与 Physics2DWorld 同步。
第一版只做查询和碰撞对，不做完整刚体求解。
引擎不理解 Enemy / Bullet / Damage。
项目规则根据查询结果决定发生什么。
```

### 5.3 Sprite / 2D Rendering C-min

当前 RenderProxy / Renderable 已有雏形，但还不是完整 2D 游戏可用能力。

第一版能力：

```text
SpriteRenderer typed component
Sprite AssetRef
Texture AssetRef
sortingLayer
orderInLayer
sortZ
color / alpha
flipX / flipY
orthographic camera
transparent blending
sprite bounds
```

边界：

```text
SpriteRenderer 是引擎通用渲染组件。
飞机、子弹、敌机只是项目 Prefab 使用 SpriteRenderer。
```

Sprite2D 排序第一版只保留一个确定性规则：

```text
Sprite2D draw order =
  render_domain(Sprite2D)
  sortingLayer
  orderInLayer
  sortZ / Transform.z
  stable_entity_id
```

边界规则：

```text
Sprite2D C-min 只负责 2D 可见顺序，不负责完整透明深度排序。
透明深度排序属于 Renderer Core / Camera / Material pass 后续能力。
摄像机距离排序属于 Renderer Core / Camera 模式，2D 第一版默认不使用。
材质批处理排序属于 Renderer 内部优化，不暴露给项目规则和 AI patch。
材质批处理不能打乱 Sprite2D 的可见排序，只能在相同排序桶内合并。
多 Canvas 排序属于 AUI Runtime UI 系统，不属于 Sprite2D Rendering。
```

### 5.4 Runtime Prefab Instantiate / Despawn C-min

当前 Runtime 已经有 Prefab instantiate / despawn 基础，但项目规则调用链还需要补齐。

第一版能力：

```text
LogicContext instantiate_prefab request
LogicContext despawn request
return root EntityId
dependency asset loading
instantiate trace
despawn trace
diagnostic report
```

边界：

```text
引擎负责实例化 Prefab。
项目决定什么时候生成子弹、什么时候生成敌人、什么时候销毁。
```

### 5.5 Runtime Time Service C-min

第一版能力：

```text
RuntimeTime
TimeContext
time
delta_time
unscaled_time
unscaled_delta_time
fixed_time
fixed_delta_time
time_scale
maximum_delta_time
frame_count
fixed_frame_count
in_fixed_step
Timer helper
Cooldown helper
TimeTraceSummary
```

边界：

```text
引擎提供 Unity-like Time 和基础 helper。
FrameLoop 推进 RuntimeTime。
项目逻辑通过只读 TimeContext 读取时间。
项目规则自己保存和修改 cooldown / timer 状态。
Timer / Cooldown 只是 helper，不是全局系统。
第一版不做全局 Timer Manager。
第一版不做 Coroutine。
第一版不做 Schedule。
第一版不做 Delayed Command。
第一版不做 InvokeRepeating。
发射频率、敌人波次、技能冷却由项目规则决定。
```

### 5.6 Input Mapping Asset C-min

当前 Input Action runtime 有基础，但 Input Mapping 还不是完整项目资源。

第一版能力：

```text
InputMapping asset schema
InputMapping importer
InputMapping runtime load
keyboard / mouse / gamepad abstraction
platform override placeholder
```

边界：

```text
引擎负责把设备输入转成 ActionSnapshot。
项目规则读取 action.move / action.fire 等项目自定义 action。
```

### 5.7 AUI Runtime UI C-min

稍微复杂的可玩游戏需要最小 Runtime UI。

正式命名采用 AUI：

```text
AUI = AI-first Runtime UI System
```

AUI 不是打飞机 HUD 的临时功能，而是面向所有游戏的正式运行时 UI 系统。
HUD 只是 AUI 的一种使用场景。

第一版能力：

```text
AuiDocument
AuiCanvas ScreenOverlay
AuiNode Panel / Image / Text
AuiRect anchor / offset
AuiLayoutEngine headless
AuiDrawList
AuiRenderReport
AuiHitTest pointer
AuiBinding StaticValue / ProjectUiState
RuntimeRenderer 接收 AUI draw list
```

边界：

```text
引擎提供 AUI 基础结构、布局、绘制列表、命中测试、最小绑定和渲染接入。
分数、血量、弹药、背包、任务等显示内容由项目 UI 数据绑定决定。
Canvas / Panel / ZOrder 只影响 AUI 系统内部排序，不参与 Sprite2D 排序。
AUI 不直接查询 Gameplay ECS，而是读取 ProjectUiState / RuntimeSnapshot。
AUI 交互通过 AuiCommand / Project Command 返回项目层。
```

### 5.8 Editor Authoring 补齐

要让 AI 和用户自然制作小游戏，编辑器侧也要补齐。

第一版能力：

```text
Sprite drag to Scene -> Entity + Transform + SpriteRenderer
Prefab create / save / update
Schema-driven Inspector
InputMapping editor
Collider2D visualization
Scene View 2D camera / grid / gizmo
```

边界：

```text
编辑器提供通用 authoring。
项目具体对象仍由 Project Schema / Prefab / Data Asset 定义。
```

### 5.9 Build / Runtime Package 补齐

当前打通了部分 Build / Runtime Package，但还需要让游戏项目可重复构建。

第一版能力：

```text
persistent Project Asset DB
cook sprite / texture
cook input mapping
cook prefab
cook schema
cook project rules
package validation
runtime package diff report
```

边界：

```text
引擎负责打包和校验。
项目负责资源内容和规则内容。
```

### 5.10 Trace / Replay / Golden Scenario

这是 AI-first 引擎区别于普通引擎的重要能力。

第一版能力：

```text
ActionSnapshot trace
Rule execution trace
ECS write trace
Collision query trace
Spawn / despawn trace
Render extract trace
Replay script
Golden Scenario baseline
Golden Scenario diff
```

打飞机只作为一个 Golden Scenario：

```text
输入移动和发射
生成子弹
子弹移动
碰撞查询命中
项目规则扣血
项目规则销毁实体
项目规则加分
渲染状态更新
Trace 可解释每一步
```

## 6. 推荐讨论顺序

后续建议按系统讨论，不再按玩法细节讨论：

```text
1. Engine Gameplay Foundation C-min
2. Physics2D Foundation C-min
3. Sprite / 2D Rendering C-min
4. Runtime Prefab Instantiate / Despawn C-min
5. Runtime Time Service C-min
6. Input Mapping Asset C-min
7. AUI Runtime UI C-min
8. Editor Authoring 补齐
9. Build / Runtime Package 补齐
10. Trace / Replay / Golden Scenario
```

## 7. 下一步讨论入口

下一步建议讨论：

```text
Engine Gameplay Foundation C-min
```

需要确认的问题：

```text
Query API 第一版长什么样？
Generic Component read/write 如何保持简单？
Spawn / despawn 是否统一走 CommandBuffer？
CommandBuffer 在 FrameLoop 的哪个点 apply？
是否所有项目 Component 写入都必须 Trace？
AI 生成这些调用时如何让用户能看懂和排查？
```

## 8. 核心结论

```text
缺的不是 Shooter Gameplay。
缺的是引擎侧通用 Gameplay Foundation。

打飞机是验证场景，不是引擎内置方向。
Bullet / Enemy / Health / Damage / Score 属于项目侧。

引擎下一步要补齐的是：
ECS Query / Generic Component Write / CommandBuffer / Physics2D Foundation / Sprite2D / Prefab Instantiate / Time / Input Asset / AUI Runtime UI / Trace Replay。
```
