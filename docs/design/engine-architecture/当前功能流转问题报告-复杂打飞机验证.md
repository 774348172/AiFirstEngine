
## 2. 已真实跑通的链路

当前引擎已经可以跑通：

```text
Runtime Package 构建
Runtime Package 读取
输入映射解析为 ActionSnapshot
ECS 动态组件与 Transform 字段写入
通过 CommandBuffer 延迟创建 Entity
Physics2D 从 ECS 同步 Collider 并检测碰撞对
碰撞后通过项目动态组件修改状态字段
ECS dirty 记录提取成 RenderCommand
RenderCommand 应用到 RenderSceneState
RuntimeRenderer 生成 headless RenderGraph / RHI command plan
AUI 文档生成 DrawList 并接入 RuntimeRenderer overlay
AI 可读 JSON 验证报告序列化
```

## 3. 暴露出的真实缺口

### 3.1 Project Rule Pipeline 还没有接入

当前复杂样例里的“项目规则”由 Rust 验证 fixture 模拟执行。

缺口：

```text
自然语言 / Project Rule / IR / Rust AOT 还没有进入这个端到端验证门禁。
```

建议下一个系统：

```text
Project Rule Authoring / Compile / Runtime Execute Gate
```

### 3.2 SpriteRenderer2D 还没有贯通 ECS -> RenderProxy

当前已有：

```text
ComponentTypeId::sprite_renderer2d
SpriteRenderer2D struct
RenderProxyPayload::Sprite
RuntimeRenderer sprite draw
```

但缺少中间桥：

```text
ComponentValue::SpriteRenderer2D
World 存取 SpriteRenderer2D
RenderExtract 把 SpriteRenderer2D 转成 RenderProxyPayload::Sprite
RuntimeScene / Package 对 Sprite2D 的正式表达
```

本次验证为了跑通，用 `Renderable + quad` 作为替代。

建议下一个系统：

```text
SpriteRenderer2D ECS-to-RenderProxy Bridge
```

### 3.3 Editor Saved Project 没有驱动验证 fixture

当前 RuntimePackageBuildInput 是验证代码直接构造的。

缺口：

```text
真实 Editor 保存的 Scene / Prefab / Asset Authoring Document
还没有直接作为 RuntimePackageBuilder 的输入来源。
```

建议下一个系统：

```text
Editor Saved Project -> RuntimePackageBuilder Integration Gate
```

### 3.4 RuntimeScene 到 World Hydration 不完整

当前 `load_runtime_package` 能读取 `RuntimeScene`，但复杂验证仍然手动创建 `World`。

缺口：

```text
RuntimeScene entity / transform / mesh / dynamic component
还没有完整 hydration 到 World / typed component / dynamic component。
```

建议下一个系统：

```text
RuntimeScene World Hydration C-min
```

## 4. 一个施工中发现的重要规则

RenderExtract 只消费 `World` 的 dirty records。

这意味着：

```text
初始 RuntimeScene 加载到 World 后，必须有明确的 initial render sync / initial dirty mark。
否则初始可渲染对象不会自动进入 RenderSceneState。
```

这个规则是合理的，但需要在后续 `RuntimeScene World Hydration C-min` 中正式处理。

## 5. 下一步优先级建议

优先级最高：

```text
RuntimeScene World Hydration C-min
```

原因：

```text
它是 Runtime Package -> World -> Logic / Physics / Render 的真正入口。
不补它，端到端验证仍然需要手写 World fixture。
```

第二优先级：

```text
SpriteRenderer2D ECS-to-RenderProxy Bridge
```

原因：

```text
复杂打飞机验证需要真实 Sprite2D，而不是 Renderable quad 替代。
```

第三优先级：

```text
Editor Saved Project -> RuntimePackageBuilder Integration Gate
```

原因：

```text
它能把编辑器产物和 runtime package 真正接起来。
```
