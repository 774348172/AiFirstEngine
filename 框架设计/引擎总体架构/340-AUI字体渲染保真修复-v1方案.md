# 340 AUI 字体渲染保真修复 v1

状态：用户确认采用方案 A；2026-09-14 方向定位、内置 FontPack 产物修复及 Windows 新交付验收全部通过。完成记录见 [340 字体窗口验收](阶段完成记录/2026-09-14-340-AUI-Font-Window-Acceptance-v1/00-总览.md)。338 仍为当前施工，未归档；本次未安装 Provider。

## 目标

统一字体 Cook、glyph metrics、UV 和 AUI quad 的坐标约定，消除字号和字体模式相关的上下倒置；保留现有 RuntimePackage 字体 schema 与 AUI 工具边界。

## 最小实现

- 以字体图集实际像素原点为准，明确 `pixel_rect` 与 `uv_rect` 的方向。
- bitmap 与 MSDF 使用同一套 glyph quad 方向。
- Renderer 只执行一次必要的纹理坐标映射，不针对字号或字符猜测翻转。
- 增加非对称字形（A、g、p、y、2）、多字号、bitmap/MSDF 的定向测试和真实窗口截图。
- 非法 glyph rect、缺页、越界和缺字继续在字体 Cook/Load 阶段结构化报告。

## 边界

不升级字体资源 schema，不新增坐标字段，不改 AUI 文档格式，不做字体编辑器、排版系统、Animator2D、音频或材质重构。方案 B 仅在多来源字体和多坐标协议确实出现后再评估。

## 自审

2026-09-14 非对称 A/g/p/y/2 实测：新鲜 Cook 的 bitmap/MSDF 一致，Renderer 屏幕顶点方向测试通过；sealed 内置 FontPack 的五个 MSDF 字形全部垂直镜像，bitmap 正常。责任收敛到内置 Cook 产物，使用现有 `build_builtin_font_pack` 生成器重新生成并封装，不修改 Renderer 或 Cook 算法。原始失败见 `.artifacts/340-orientation-complete-font.log`。重新封装后的同一测试必须通过，不能通过翻转参考或弱化断言过验收。
