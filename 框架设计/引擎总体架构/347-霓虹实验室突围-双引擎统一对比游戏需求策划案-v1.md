## 2. 游戏定位与实验目的

**一句话游戏：**操控维护机器人穿过三间失控实验室，射击无人机、冲刺穿越危险区、取回能源核心并关闭防御系统，最终逃离设施。

类型为2D俯视角动作闯关；单人、单局、无随机地图。目标首次体验3–6分钟是体验目标，不通过强制等待凑时长；通关过快或过慢均记入体验评审，调整必须形成共同版本。

本次重点不是功能数量，而是验证：

| 问题 | 用什么游戏内容暴露 |
|---|---|
| AI能否快速建立完整游戏 | 输入、战斗、关卡目标、HUD、结算与交付 |
| 逻辑和表现能否一致 | 受击、冲刺、敌人死亡、激光开关、暂停 |
| 同一功能能否复用 | 三房间共用玩法结构，但有不同敌人组合和视觉主题 |
| 局部需求是否容易修改 | 警戒行为、蓄力攻击、局部运动规则 |
| 是否容易定位真实错误 | HUD过期、特效残留、音效生命周期 |
| 质量是否一次到位 | 同构图参考、同状态截图、实际操作与试听 |

本试验只能说明本游戏及这些任务上的结果，不据此宣称全面超过Godot、Unity或UE。

## 3. B0内容与排除范围

B0包含：3间固定房间、1种玩家、3类敌人、1种普通枪、1种冲刺、每房1核心和1控制台、生命与目标HUD、暂停/失败/通关界面、四类声音、三类粒子表现，以及Windows独立交付。

B0没有警戒侦测模式、蓄力、惯性移动、移动平台、跳跃、背包、成长树、随机掉落、联网、寻路网格、刚体推动、存档、3D或移动端。原讨论中的“低重力”作为后续变更题，俯视角中具体解释为低牵引惯性，不能自行实现成平台跳跃。

最多同时存活12敌人是安全上限；实际布置最多7个。B0敌人不刷新，无复活或隐藏波次。所有影响玩法的参数由共同表确定，不能通过降低敌人数、减少视觉反馈或省略状态来赶进度。

## 4. 操作与玩家规则

| 输入 | 唯一含义 |
|---|---|
| WASD | 世界平面移动；斜向归一化，不加速 |
| 鼠标 | 瞄准；不控制角色移动，无自动瞄准 |
| 鼠标左键按住 | 普通射击 |
| Shift按下 | 冲刺；按下沿触发，不因长按连续发动 |
| E按下 | 与最近的可交互对象交互 |
| Esc | 游戏中暂停/恢复；失败/通关时不恢复游戏 |
| Enter | 暂停/失败/通关面板中从第一房重新开始；游玩中不生效 |
| UI按钮 | 真实鼠标点击继续、重新开始或退出；退出关闭游戏 |

窗口失去焦点时自动暂停；重新获得焦点后保持暂停，玩家主动恢复。窗口关闭按钮可正常退出。UI打开时鼠标射击被屏蔽；重新开始/恢复后，按键和鼠标必须释放再按下才产生射击、冲刺或交互，防止点击穿透。

统一逻辑采用每秒60步；秒数按游戏时间计算，不用墙钟推进。实现可不同，但相同输入、初始状态应得到相同事件顺序；时序允许1逻辑步误差，位置比较容差0.05单位。

| 参数 | B0值 |
|---|---|
| 玩家碰撞 | 圆，半径0.30单位；装饰不改变碰撞 |
| 移动速度 | 5单位/秒，松开即停 |
| 生命 | 上限3，初始3，无回血或房间间补血 |
| 玩家子弹 | 速度14单位/秒，半径0.08，伤害1，寿命1.5秒 |
| 普通射击 | 首次按下立即发射；间隔0.20秒；不限弹药 |
| 子弹命中 | 每颗只命中一个目标；击中敌人/边界后消失，无穿透、无友伤 |
| 冲刺 | 速度15单位/秒，持续0.16秒，方向发动时锁定 |
| 冲刺方向 | 有移动输入取该方向；无移动输入取瞄准方向；鼠标与玩家重合时用上次有效朝向，初始向右 |
| 冲刺冷却 | 从发动起1.20秒；冷却中按键无效 |
| 冲刺交互 | 可受边界阻挡，不能穿墙；可穿过不阻挡移动的敌人和激光；期间免疫伤害且不射击、不交互 |
| 受击 | 每次扣1；0.80秒无敌；同时多种伤害只扣一次；无击退 |
| 交互距离 | 玩家中心到对象中心不超过1.0单位 |

玩家子弹使用路径命中检测，避免高速穿透；相同路径多目标取最近者，同距按固定ID排序。敌人不阻挡玩家移动，接触只造成伤害。生命降为0立即进入失败，无负生命、无死后射击。相同步内先结算命中/伤害，再交互，最后房间出口；死亡优先于通关。

## 5. 敌人和环境危险

| 类型 | 参数与B0行为 | 可见反馈 |
|---|---|---|
| 追踪无人机 | 生命2，半径0.35，速度2.2；房间启用后直接追玩家；接触伤害1 | 圆形青灰机体、红色核心；移动朝向与实际一致 |
| 定点炮台 | 生命3，半径0.45；每2秒发射一次；射前0.4秒锁定当时玩家方向并预警 | 底座固定、枪口旋转；锁定线琥珀，发射时短闪 |
| 巡逻无人机 | 生命2，半径0.35，速度1.8；在规定两端点间往返；接触伤害1；B0不追踪、不警戒 | 与追踪型轮廓不同，有路线方向灯 |

炮台子弹速度6、半径0.12、伤害1、寿命4秒；撞边界或命中玩家后消失。攻击冲刺/无敌玩家时子弹仍消失，不扣血。炮台被击毁时取消未完成预警，但已发出的子弹继续存在，直到寿命结束或退出房间。敌人死亡即失去碰撞/攻击能力，随后0.25秒解体表现结束；不掉血包。

激光是固定线段危险，宽度0.12单位；玩家碰撞圆与激光相交时可受伤，遵守无敌规则。每个4秒周期：前1.8秒开启，随后0.2秒衰减且无伤害，再安全1.4秒，最后0.6秒琥珀预警且无伤害。进入房间时相位为0。预警不得使用与安全状态相同的颜色；关闭防御后全部激光立即安全且不再循环。

每次进入房间提供0.75秒入场保护；敌人移动、预警、子弹与激光时钟在保护结束后从零开始。玩家可移动但不能攻击/交互；HUD显示“系统连接中”。B0无内部阻挡地形，避免把寻路能力混入本轮比较；机柜、管线和地板全部为不碰撞装饰，房间外墙碰撞。

## 6. 三房间与关卡布局

逻辑场地统一24×12单位，左上为(0,0)，x向右、y向下，外墙厚0.5；玩家圆完整留在内边界。每房玩家入场(2,6)、核心(18,6)、控制台(21,3)、出口中心(23,6)。出口有效区为x=22–23.5、y=5–7，未解锁时不触发切换。

| 房间 | 主题和教学目的 | 固定敌人位置/路线 | 激光线段 |
|---|---|---|---|
| 01 入口控制室 | 青绿供电柜；学移动、瞄准和交互 | 追踪D1(10,3)、D2(13,9)；巡逻P1(15,3)↔(20,3) | 无 |
| 02 激光试验室 | 琥珀警示、地面实验轨迹；学冲刺和激光时机 | 追踪D1(10,2)、D2(18,10)；炮台T1(20,2)；巡逻P1(14,9)↔(20,9) | (12,4)–(12,8)，上下保留绕行空间 |
| 03 核心反应堆 | 紫青反应炉、环形装饰；组合战斗 | 追踪D1(9,2)、D2(14,10)、D3(19,6)；炮台T1(19,2)、T2(19,10)；巡逻P1(8,3)↔(11,3)、P2(14,9)↔(17,9) | (10,4)–(10,8)、(16,4)–(16,8)，第二条相位偏移2秒 |

敌人固定ID包含房号，巡逻从表中第一端点向第二端点出发。不使用随机初始位置或随机命中率。背景允许精修，但不能改变碰撞、遮挡玩家或改变危险区。

每房流程：入场 → 清除全部敌人 → 核心解除锁定 → E取核心 → E启用控制台 → 防御关闭/出口解锁 → 进入出口。核心不可提前收集，控制台不可重复消费，累计核心数从0增至3。核心收集是永久本局状态，不消耗。交互目标同距时核心优先，触发条件不满足显示原因而不改变状态。

房01/02出口进入下一房，保留生命/累计核心/总游戏时间；清空子弹、特效、房间音效和上一房敌人，冲刺恢复可用，受击无敌由新房入场保护替代。房03进入出口才通关，不能在拿到第三核心时提前通关。过场统一0.25秒淡出＋0.25秒淡入，玩法和总计时冻结。

## 7. 状态、HUD和完整闭环

游戏从标题界面开始，按钮为“开始实验”“退出”。标题内显示基本操作；首次点击开始进入房01。顶栏显示房号/名称、3格生命、核心n/3、剩余敌人、累计时间；底栏显示操作与冲刺冷却。场内上下文提示仅在靠近核心/控制台时出现。

统一阶段提示：

| 阶段 | 主提示 |
|---|---|
| 入场 | 系统连接中 |
| 敌人未清除 | 清除守卫，解除能源核心锁定 |
| 核心已解锁未收集 | 靠近能源核心，按 E 收集 |
| 已收集未关防御 | 靠近控制台，按 E 关闭防御 |
| 出口解锁 | 防御已关闭，前往出口 |
| 失败 | 实验中断；显示房间、时间、核心数 |
| 通关 | 突围成功；显示总时间、剩余生命、3/3核心 |

暂停按钮“继续”“重新开始”“退出”；失败/通关按钮“重新开始”“退出”。重新开始总是回房01：生命3、核心0、计时0、默认位置/朝向、冲刺可用、所有房间和效果初始状态；不续关。失败、通关时世界计时与玩法冻结，仅允许限定结算反馈结束，之后静止。

暂停冻结位置、敌人、所有冷却、预警、激光、粒子、动画及游戏时间；正在播放的游戏声音暂停，恢复从原进度继续，不能重播。UI悬停可继续响应，不算游戏时间。失败/通关停止原游戏声音，再播放一次结算声音；重开/切房立即清除旧声音。

观察事实至少包括：阶段、房号、位置、生命、敌人数、核心数、核心/控制台/出口状态、冲刺剩余时间、无敌剩余时间、激光相位、游戏时间、活动子弹/粒子/游戏声音、失败/胜利/重开次数。验证“清理为零”指旧房间/上一局拥有的对象，不把新房初始敌人或新事件声音计为残留。

## 8. 统一美术与声音目标

基准窗口1280×720。逻辑画布固定16:9；其它比例等比缩放并留边，鼠标必须逆变换到逻辑画布。验收1280×720及1600×1000，留边点击不触发场内操作。不要求自适应重新排版。

共同构图：顶栏y=0–80；场地画布x=64–1216、y=96–672，1世界单位=48逻辑像素；底部操作条y=680–720。标题/暂停/结算使用中间面板，长提示有足够宽度。文字以14/18/24/32逻辑像素四档组织，统一字体来源、字号和行距参考，允许各引擎按真实度量实现，不比较逐像素完全相等。

风格为精细扁平科幻：背景深蓝灰#101B26，主要交互青绿#76EADC，预警琥珀#EDBC70，危险红#FF526E，正文浅灰#E4EEF2。三房沿同一材质语言改变设备与主辅色。不能用同一张墙壁贴图冒充三个主题，也不靠一张整屏背景烘焙玩家/敌人/UI。

必须可见：玩家朝向、发射反馈、受击闪白0.12秒、冲刺残影、敌人解体、核心拾取光点、控制台状态切换、出口开锁。粒子分枪口/命中解体/拾取三类；冲刺残影可用帧动画或绘制实现，不规定特定粒子API。光晕应局部衰减，无明显矩形边缘，不遮挡弹道和文字。可用原生光照、shader或透明素材，但不得提高一边素材分辨率或改需求；实现方法与成本如实记录。

声音按四类管理：射击、受击/击毁、核心拾取、系统提示。共六个统一音频文件：shot、hit、core、unlock、failure、victory；无背景音乐/循环环境音首期要求。场景音量和同时发声数量在共同素材表冻结。正常运行必须实际可听、无持续爆音；自动触发日志与实际试听分别验收，单纯触发计数不证明有声。

美术审阅使用同输入、同房间、同状态的截图/短录像，并检查移动中轮廓、文字、反馈时序；不能只展示最好看的一帧。最终风格质量需要人工对照参考，不用图片相似度百分比代替。

## 9. 共同素材与起跑包

B0所需角色/三类敌人、三房模块、核心/控制台/出口、子弹/光晕/粒子、UI图标、字体和六个音频文件，由348制作同一套共用源素材。每项列出来源/许可、尺寸、透明方式、锚点、帧数/顺序、默认音量、字体授权及摘要；两边自行导入，导入工作属于开发成本。

起跑包包含本案B0部分、上述素材、三房布局数据、普通/受击/暂停/失败/通关/标题的共同构图参考，以及功能验收清单。参考必须是共享输入，不得拿某一方完成画面倒推另一方目标。348产物位于`samples/neon_lab_shared`：参考均为离线设计图，不是游戏实机证据；游戏验收清单尚待执行。

两边可使用已存在的官方/项目通用SDK、文档和模板；起跑前登记版本和清单。不得单方提供为本题定制的完整玩法模板、既有答案或另一引擎的成品代码。正常引擎工具差异本身属于比较对象，无需强制相同工具数/文件结构/语言。

引擎版本、Codex模型/推理配置、机器、访问权限、允许的外部资源及总任务预算，在施工前写入一次共同实验清单。若预算耗尽仍未完成，记录未完成项，不取消质量要求后报成功。

## 10. 后续改动题（B0验收后逐项发放）

M1–M3按固定顺序施加到各自已验收版本；两边同时得到同一段任务文本，各次单独记录起止版本和成本。施工执行者做B0时只获得B0材料，不获得本节详细答案；已看过完整策划的会话不作为盲测执行者。无隔离条件则明确标为开放题对比。

| 任务 | 统一变更 | 验收重点 |
|---|---|---|
| M1 警戒机制 | 仅巡逻机改变：距玩家≤5且连续可见0.30秒后警戒，以2.6速度追踪；距离>7连续2秒后回最近巡逻端点再恢复巡逻。无内部遮挡，视线按直线处理。HUD显示警戒敌人数；进入警戒一次琥珀闪光，用unlock音提示，不逐帧重播 | 进入/脱离阈值、暂停计时、HUD和提示一致；追踪机/炮台行为不变 |
| M2 蓄力射击 | 替换普通枪：按下积累、松开发射；不足0.25秒取消，0.25–不足0.75秒伤害1，达到0.75秒伤害3；1秒封顶不自动发射。弹速/寿命/非穿透保持；发射间隔最少0.20秒。HUD显示蓄力；开始冲刺、暂停、死亡、切房或重开取消蓄力且不发射 | 临界时长、输入释放、满蓄力视觉及原敌人生命合同 |
| M3 低牵引区 | 只在房02矩形x=4–10、y=2–10改变普通移动：每秒以8单位速度变化量趋近目标速度(输入归一化×5)，无输入目标为0，斜向加速度归一化；区域外恢复B0即停。冲刺保持锁定规则，结束时普通速度归零；边界阻挡清除法向速度。用共同冷蓝地面标识和提示显示区域 | 局部影响、惯性与停止距离、离区恢复、冲刺结束、暂停/重开状态 |

M3不包含垂直重力、漂浮高度或跳跃，不改变敌人、子弹和关卡目标。必要的新提示文本/素材同时发放；不能一边做M3、一边仅比较B0成品。

## 11. 修复题与比较方法

修复轮从各自已验收的B0独立副本开始，三个题各自还原，避免前题泄漏答案或污染后题。不修改用户已验收主项目。评测准备者在适合各实现的位置注入同等外显缺陷，不要求删掉同样一行代码；先复现并确认已有正确测试能变红，然后只提供复现现象、预期与可用证据，不提供根因。

- R1：收集首个核心后逻辑数量增加，但HUD仍显示0/3。
- R2：带受击或拾取效果重开后，上一局残影/粒子继续存在。
- R3：游戏声音播放期间切房，旧房间声音仍继续播放；测试夹具共用较长的系统提示片段以稳定复现，两边同样使用。

验收修复时仍使用原预期，不能删除断言或屏蔽反馈绕过；保留失败首证、修复差异与相关回归结果。故障注入准备成本单列，不与AI修复时间混算。

两边从独立上下文开始，模型配置一致；不互相读取实现/聊天/修复记录。按共同规则登记已知引擎文档和技能。先做哪一边须记录；如复测可交替顺序，首轮单次结果不提供统计显著性结论。用户中途反馈形成统一需求澄清；只给一方的额外帮助计人工干预并披露。

可以使用Godot Editor、命令行、引擎工具和普通文件工具；AI操控Editor同样计开发工作，人工代操作也计干预。禁止为了结果好看排除一方的必要操作。两边都应能从交付包验收，不依赖作者临时修改的运行状态。
