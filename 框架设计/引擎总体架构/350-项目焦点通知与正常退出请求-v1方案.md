## 1. 问题与目标

Neon Lab 的退出动作目前只设置 `exit_requested = true`，没有向 Player 传递退出控制。Winit 收到 `Focused(false)` 后仅发送输入释放事件，没有把焦点变化交给项目，也未处理 `Focused(true)`。

项目已有暂停与恢复逻辑，但 SDK 缺少窗口生命周期输入和宿主退出输出，导致项目无法通过正式接口闭合两个行为。最小修复是在现有 SDK、会话执行和宿主循环间补齐这两条通道。

目标：

1. 游戏可在标题、游戏中或暂停菜单请求正常结束当前游戏会话。
2. 项目可收到真实焦点变化，Neon Lab 失焦自动暂停，重新获得焦点后由玩家手动继续。
3. 生命周期处理不依赖 fixed tick、玩法时间推进、UI 输入是否被消费或诊断采样级别。
4. 复用现有 Compiler、Generated Glue、RuntimePackage、Engine DLL 和 Player，不新增工具、Provider、生命周期管理器或通用事件总线。

## 2. 方案选择与参考

| 方案 | 结果 |
| --- | --- |
| 引擎统一规定失焦自动暂停 | 未选。不同游戏可能需要后台运行，不能把 Neon Lab 的策略固化为 Core 行为。 |
| 引擎通知焦点并接收退出意图，项目决定暂停 | 已选。窗口事实、游戏策略和宿主退出职责分别有明确 owner。 |

参考官方源码：

- [Bevy 0.16.1 Winit runner](https://github.com/bevyengine/bevy/blob/v0.16.1/crates/bevy_winit/src/state.rs)：将焦点变化转成窗口事件，并由 runner 消费应用退出意图。
- [Bevy 0.16.1 App](https://github.com/bevyengine/bevy/blob/v0.16.1/crates/bevy_app/src/app.rs)：`AppExit` 表达应用退出结果。
- [Godot 4.4 Window](https://github.com/godotengine/godot/blob/4.4/scene/main/window.cpp)：明确区分获得焦点、失去焦点和关闭请求。
- [Godot 4.4 SceneTree](https://github.com/godotengine/godot/blob/4.4/scene/main/scene_tree.cpp)：`quit()` 设置退出意图，由主循环结束运行。

只吸收职责划分，不移植完整事件框架。禁止项目直接 `process::exit()`、轮询平台窗口 API、注入 Esc，或以观察报告中的布尔字段控制宿主退出。

## 3. 通道与职责

```text
OS Focused(false/true)
  -> Player / 宿主焦点适配
  -> EngineHostLoop 生命周期分派
  -> Generated Glue / Project Game SDK
  -> 项目暂停策略与既有受控输出

AUI 退出动作
  -> 项目 SDK request_exit()
  -> 会话成功提交 typed host control
  -> EngineHostLoop 返回退出控制
  -> 所属宿主正常结束游戏会话
```

| 层 | 职责 |
| --- | --- |
| Player / Editor 宿主 | 提供焦点事实，消费已提交的退出控制，负责窗口与会话资源清理。 |
| EngineHostLoop | 保存会话焦点状态、分派有序变化、组织回调与玩法执行顺序，返回 typed 控制结果。 |
| Project Runtime Session | 执行回调、校验输出，沿现有提交机制应用 mutation 与退出意图。 |
| SDK / Generated Glue | 提供小型可选生命周期回调和退出方法，自动生成注册、序列化与能力声明。 |
| Neon Lab | 决定哪些状态失焦暂停、怎样显示暂停菜单、暂停哪些媒体及何时允许恢复。 |

## 4. 最小 SDK 合同

下列名称为设计名称，落地时按现有命名规范统一，语义必须保持。

### 4.1 生命周期输入

- 增加可选 `lifecycle` 注册，v1 事件仅包含 `FocusChanged { focused: bool }`。
- 宿主初始化时提供当前焦点状态；若平台尚未给出可靠状态，按未获焦处理，后续以真实事件更新。Headless 默认 focused，并允许测试显式注入变化。
- 回调上下文可读取当前焦点及现有游戏状态，使用既有受控 mutation/media 输出；不向项目暴露 Winit 或 OS 句柄。
- 同一会话有序处理变化；相邻相同状态可去重，但同帧 `false -> true` 不得合并为最终 `true`，否则会漏掉暂停。
- 生命周期在该批 AUI/玩法分派之前处理。没有 fixed tick、玩法暂停、窗口不绘制时仍须有控制处理机会；不能只把字段塞进 fixed-update 请求。
- 焦点输入不经过 AUI 的 consumed 过滤。保留 `engine_input` 失焦释放按键、指针 Cancel 等行为。
- SDK 焦点状态以宿主事件为真相，不能复用“收到按键或鼠标按下就视为 focused”的输入设备启发式。
- 未注册生命周期回调的项目继续运行，不被引擎自动暂停。

### 4.2 正常退出输出

- SDK 在 `GameCallContext` 提供 `request_exit()`，仅表达成功结束当前游戏会话；v1 不增加任意退出码、强杀、重启或关闭确认对话框。
- 保持项目侧 `SessionOutput` 原有字段及字面量构造方式，退出请求由 context writer 保存，生成胶水转换为内部协议输出。在内部 `ProjectRuntimeSessionOutput` 中承载独立 typed host-control 输出，与实体 mutation 和 diagnostics 分开。它不是 ECS 组件写入，也不是 observe fact。
- 仅在产生请求的回调成功、相关输出校验及现有提交成功后发布退出控制。Rejected、NoOp、panic 或提交失败不能产生退出副作用；仅有退出请求的有效回调应返回成功状态。
- 重复请求幂等；一旦提交退出，不再启动后续玩法阶段，转入宿主收尾。不得在模块回调或 FFI 栈内销毁宿主。
- 普通帧、生命周期分派和现有 immediate AUI dispatch 都必须返回该控制，暂停菜单退出不等待 fixed tick。
- 退出不消除已经记录的运行错误，也不能把提前退出的测试当成所有后续断言通过。

### 4.3 宿主消费

| 消费端 | 退出语义 | 焦点来源 |
| --- | --- | --- |
| Windows 独立 Player | 复用正常 finish / 清理路径，再由 event loop 退出；无既有错误时进程返回成功。 | Winit 主游戏窗口的真实焦点事件。 |
| Editor Play / Preview | 结束所属 Play 会话，清理其资源，不关闭 Editor 或 Provider。 | 游戏视图焦点；失去应用焦点也必须映射为 false。 |
| Headless | 返回会话正常结束状态，由调用者决定进程寿命。 | 确定性默认状态及显式测试注入。 |

合同保持跨消费端一致；本次真实窗口资格限 Windows。移动端后台/前台生命周期、多窗口焦点聚合不在 v1 范围，不将桌面焦点直接宣称为移动端生命周期支持。

## 5. Neon Lab 接入策略

1. `Play` 失焦调用已有暂停行为，显示暂停菜单；连续失焦不得重复播放暂停音效或反复改变 UI revision。
2. 转场失焦须保留暂停意图及转场进度；暂停期间冻结转场，手动继续后恢复原阶段，不得因转场完成而自动开始玩法。
3. 标题、失败和胜利页面保持其原有状态，不能由焦点变化误跳到 Play。已经暂停时失焦保持暂停。
4. 重新获得焦点只更新焦点状态，不自动恢复。未获焦时拒绝“继续”，同批失焦与继续动作也必须遵守这一条件。
5. 恢复时保留既有 release-before-press 输入门控，避免失焦前按住的移动、射击或交互残留。
6. 暂停冻结玩法计时、角色、机关、转场及属于玩法的动画/粒子；通过既有媒体命令暂停相应音源。暂停 UI 仍可更新、点击继续或退出。单独将 timeScale 置零不能替代这些行为。
7. 退出按钮调用 SDK 请求；`exit_requested` 如保留，仅作项目测试/观察事实，不作为宿主控制依据。

## 6. 影响面与兼容

预期直接修改范围：

- `rust/crates/project_game_sdk`：生命周期注册与退出 writer。
- `rust/crates/project_runtime_sdk`、`project_runtime_abi`：请求/输出合同、能力与 ABI 适配。
- 现有 GameProjectCompiler Generated Glue：自动生成新增回调及描述，不允许项目手写 ABI。
- `rust/crates/engine_runtime/src/project_runtime_session.rs`、`engine_host_loop.rs`：回调提交、分派与控制返回。
- `rust/crates/runtime_player_winit/src/lib.rs`：双向焦点事件与正常退出消费。
- Engine DLL 边界、Headless 与 Editor 现有消费路径：核对并贯通实际经过的输入/输出，不能只修 source-linked Player。
- `samples/neon_lab_project/RuntimeModule`：项目状态机、AUI 退出及相应测试。

沿用现有 serialized byte transport、contract digest 和 capability 机制。严格反序列化合同变更必须同步生产者、消费者与生成器；不假设添加可选字段即可兼容旧二进制。如果新增 callback 改变 C function table 布局，按现有 ABI 版本规则升级，加载时先检查版本与大小，再访问新增槽位；不要仅为 JSON 字段变更另造协议版本体系。

旧项目源码不注册新回调仍应由新 Compiler 正常生成。旧二进制与新合同不兼容时明确拒绝混装，不静默忽略新请求。缓存身份必须覆盖合同与实际产物变化。

安装版 346 不会因修改游戏源码就获得新能力。后续交付必须使用彼此匹配的 Compiler/Provider、Generated Adapter、项目模块和 Engine DLL/Player；复用仍然兼容的固定 Host，不把升级解释为所有产物无条件全量重编译。候选构建可先独立验证；生产安装、宿主接入及配置变更另按实际授权执行。

| 风险 | 最小验证 |
| --- | --- |
| 焦点变化漏送或顺序错误 | 初始状态、重复事件、同批失焦再获焦、零 fixed tick、暂停状态分派测试。 |
| 退出意图丢失或越过提交边界 | 成功请求、重复请求、失败/NoOp/panic 无副作用，覆盖 immediate AUI 与普通路径。 |
| 暂停策略错误 | 项目测试覆盖 Play、转场、已暂停、标题/失败/胜利，获焦不自动恢复，未获焦拒绝继续。 |
| 玩法或媒体继续推进 | 暂停前后推进至少 2 秒，比较计时/位置/转场/动画/粒子状态及音源暂停命令；UI 保持可操作。 |
| 宿主误关闭或合同混装 | Player 退出控制、Headless 终态、Editor 会话边界与合同不匹配拒绝测试；未注册回调的项目兼容测试。 |
| 导出产物缺少新能力 | 使用匹配候选工具链导出 Windows dev，在完整交付副本中实测点击退出、Alt+Tab、返回与继续；保存产物身份和结果。 |
