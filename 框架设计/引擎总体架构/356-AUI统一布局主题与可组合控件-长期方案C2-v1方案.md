### 1.1 目标

建立能够长期支撑菜单、HUD、背包、设置、复杂表单、弹窗及大量数据列表的 AUI 基础设施。内容、字体、主题、窗口尺寸变化后，布局、绘制和交互保持一致；AI 能生成、修改、解释和验证这些界面。

霓虹实验室是首个回归与迁移样本，不决定通用系统能力上限。横竖排只是布局家族中的基础策略；Flex、Grid、主题资源、复杂控件和虚拟列表属于本长期计划的交付范围，不能以基础菜单通过为由宣布全系统完成。

### 1.2 方案选择依据

| 选项 | 组织方式 | 结论 |
| --- | --- | --- |
| C1 | 容器类型 + 主题，接近 Godot 心智 | 容器思想采纳，但公共协议需能容纳更多算法和复杂控件 |
| C2 | 统一测量/安排协议 + 多布局策略 + 结构化主题 | 用户已选择；作为长期主架构 |
| C3 | 选择器、层叠样式表驱动的 UI 框架 | 不引入完整 CSS 语言；Flex/Grid 能力不依赖 CSS 选择器 |

完整性以本文能力矩阵和可验证行为定义，不承诺逐项复制 UE、Unity、Godot 的所有功能或达到未经测量的性能同等水平。

## 3. 成熟引擎研究与采纳结论

### 3.4 研究结论

长期稳定的核心是统一尺寸与失效协议，具体布局算法和主题写法建立在它之上。本方案按 C2 组织；借鉴外部源码不等于直接复制代码。第三方代码的采用必须核对许可证与再分发要求。

本轮未发现专门针对 356 的外部 AI 审查材料；历史其它系统审查不自动成为 356 的新要求。后续收到针对本方案的审查，应先分类处理并回填本文。

## 4. 架构与唯一事实链

```text
Project AUI Document + Theme/Template/Font/Image Assets
  -> Project Game Compiler / Asset Graph
  -> ProjectRuntimePackageAssembler
  -> RuntimePackage（版本化描述 + cooked 资源 + source map）
  -> active ProjectUiStateSnapshot / Binding Resolve
  -> Resolved Style / Control Composition
  -> Measure under Constraints / Arrange
  -> AuiLayoutSnapshot + ParagraphLayout
  -> Hit / Focus / Navigation / Clip + AuiDrawList
  -> UiProjection / AuiOverlayFrame
  -> RuntimeRenderer UI Pass / Present
```

1. AUI 文档和资源为工程真相；运行时布局树、样式、字形计划都是派生产物，不写回源文档。
2. Runtime 只读 RuntimePackage 和运行态 snapshot，不扫描项目源文件，不访问 Editor 内存真相。
3. Renderer 消费已解析样式、几何、资源和 glyph，不读取主题继承、binding path 或 ECS。
4. 输入、导航与绘制使用相同布局 revision 和坐标映射；反馈的 present-only 变换按 277 保留，不能误称其视觉缩放改变命中。
5. 默认 No-Editor、九项独立工具保持；诊断接入现有 inspect/check/observe 能力，具体 typed 扩展由施工合同冻结，不新增重复工具入口。
6. 复杂项目 UI 流程由项目 Rust Module 承担；本系统提供控件协议，不把业务流程加入 IR 或 Core。

## 6. 统一测量与安排协议

### 6.1 尺寸模型

- 尺寸策略：固定逻辑尺寸、随内容、填充剩余空间、相对确定父内容框的比例。
- 各轴支持 min/max；约束必须满足 `0 <= min <= max`，内部无界约束使用明确枚举，不向源文档写 Infinity/NaN。
- 布局单位为逻辑单位。DPI、物理像素和窗口映射由既有 presentation owner 转换，避免重复缩放。
- 明确 border box/content box：尺寸限制作用于 border box；padding 与保留的 border inset 扣除后得到内容框。可用内容尺寸不小于零。
- 内容原始需求与被约束后的最终尺寸分别保存，以便报告溢出，不通过直接 clamp 掩盖内容不足。
- 文本、图片、容器、复合控件实现同一测量协议；图片使用资源尺寸和显式比例策略。

### 6.2 所有权与求解

父容器控制参与布局的子节点位置和指定轴尺寸。手工锚点节点通过显式脱离流或独立子树参与，禁止同一轴同时由锚点与容器竞争写入。

先解析影响尺寸的内容/样式；获取内在尺寸需求；分配宽度；按最终可用宽度完成段落与高度测量；安排节点。Flex/Grid 按各自规则处理多轮冻结与轨道分配，不强行统一为固定两遍遍历。

对不确定父尺寸：比例尺寸不得偷偷读取上一帧；普通 Fill 在无界轴不创造无限空间，按内在需求处理；Flex 的剩余空间分配只在主轴可用尺寸确定时执行。真正的约束循环需诊断并终止候选布局，不能以无界迭代“直到稳定”。M1 固定具体枚举、回退与诊断测试表。

同一输入身份应产生确定的布局与顺序。迭代上限、节点/深度预算和容差在 M1 实验后写回；超限报告节点链和约束，不默默丢弃部分控件。

### 6.3 可见性、溢出与发布

- 三种布局参与状态：显示且参与；隐藏但保留空间；折叠且不占空间。隐藏/折叠均不接收输入。
- 旧 `visible` 行为保持，通过明确版本迁移映射，不能把既有隐藏节点突然改为折叠。
- 内容溢出可选择可见、裁剪、滚动等明确策略；省略号属于文本策略。不能承诺任意内容都在任意空间内无溢出。
- 新 snapshot 通过完整校验后原子发布，绘制与命中同步切换。失败沿既有 last-good 机制保留一致的旧帧并暴露错误；不可让新输入目标匹配旧绘制。
- 已失效/销毁节点即使存在旧快照，也必须经过生命周期有效性检查，避免向失效 action target 发送事件。

## 7. 布局家族与长期边界

| 策略 | 本计划必需行为 | 明确边界 |
| --- | --- | --- |
| Row / Column | 内容尺寸、gap、padding、交叉轴对齐、基线 | 使用统一尺寸协议 |
| Flex | direction、wrap、basis、grow/shrink、min/max、justify/align、多行间距 | 定义 engine 子集和差异，不宣称浏览器 CSS 全兼容 |
| Grid | 固定/内容/fr 轨道、minmax、显式位置、跨行列、自动放置、gap | 稳定放置顺序；subgrid/masonry 不在本版承诺 |
| Overlay | 层叠、对齐、内容槽位 | 命中与绘制排序使用既有统一顺序 |
| Anchor | 固定/拉伸、HUD 定位、脱离流 | 旧项目默认模式与行为不变 |
| Scroll | 有限 viewport、内容范围、滚动条、焦点可见性 | 保留原输入消费 owner，明确嵌套滚动交接 |
| Virtual List | 稳定 item key、固定与可变高度、overscan、回收、scroll-to-item | 不把全部离屏内容实例化来伪装虚拟化 |

跨策略嵌套必须验证：Grid 内 Flex、多行文字撑开 Row、Overlay 中滚动列表、锚点 HUD 内的自动布局面板。统一树有稳定 ID/source map，不以新增 ECS entity 表达每个控件。

## 8. 文本与本地化

### 8.1 段落产物

复用 345 的字体字节、fallback、shaping 和 glyph 数据，加入段落布局。宽度、字体指标、行高、字间距、方向、语言和溢出策略共同决定结果。

支持显式换行、常用中英文断行、长词处理、水平/垂直对齐、最大行数、clip/ellipsis 和 inline 富文本 span。富文本样式边界、连字与组合字符需要参与分段；不能切断 UTF-8 字节或任意拆 glyph cluster。

按合法断行机会选边界，必要时重新整形行片段，保证测量结果与实际行首/行尾字形一致。行宽、行高和基线来自实际字体，不用字符计数估算。

同一 ParagraphLayout 供控件尺寸、绘制、选区、光标和文本命中使用；显式 text alignment 逐步替代以节点 `:label` 后缀推断居中的行为，旧语义通过兼容路径保留。

### 8.2 完整能力与资格

多向段落重排、RTL/LTR 混排及 Arabic/Indic 等复杂脚本属于长期文本阶段的明确交付项，需要语言夹具与实际字体证据；不继承 345 为“已经全部支持”。纵向文字、完整国际化消息系统与系统屏幕阅读器桥接为后续独立范围。

布局树保留语义角色、标签和稳定身份扩展点，避免未来可访问性接口依赖装饰子节点；这不等于本方案已交付平台可访问性桥。

输入控件沿现有文本输入 owner 扩展光标/选区与段落坐标。IME 的 OS composition 事件、候选窗定位与取消行为需在复杂控件阶段实测；不能用直接设置字符串证明 IME 完成。

## 9. 主题与默认视觉体系

### 9.1 资源与覆盖

主题包含 typed tokens（颜色、字体、字号、尺寸、间距、圆角等）、控件 role 样式、命名变体和状态外观。主题允许单一基础主题引用，构建时检测循环并生成可追溯的解析结果。

覆盖顺序：内置版本化默认主题 → 项目主题 → 显式子树主题作用域 → 节点命名样式/变体 → 节点显式覆盖。作用域必须在文档中可见；资源与样式继承均无环。

节点旧内联样式保持最高兼容优先级。继承字段采用白名单（例如文本颜色、字体），padding、尺寸和 border 不从父节点隐式继承。tokens 引用必须类型匹配，未解析引用在 check/build 阶段失败，不静默回退。

状态样式只覆盖 paint 字段，默认布局指标独立于 hover/pressed/focus。复合状态顺序为 base → hover → pressed → focus 装饰，disabled 分支替代 hover/pressed；disabled 不再接收激活，焦点按既有规则迁移。显式尺寸变体切换走正常 relayout，不能借反馈动画隐藏布局变化。

### 9.2 默认主题

提供 Panel、Title、Body、Caption、Primary/Secondary Button、TextInput、Toggle、Slider、Progress、ListItem、Modal 等现有或待扩展控件的默认样式。包括字体层级、内外间距、最小交互尺寸、焦点指示、禁用可辨识度。

通用主题不内置霓虹项目语义；项目通过 tokens/变体制作霓虹主题。默认主题本身版本化，旧文档不会因全局默认升级而无提示改变外观。

主题切换和开发期热更新使用现有资源失效链。发布 Runtime 不读取外部源主题文件；仅颜色变化不能触发段落重排。

## 10. 可组合控件与模板

控件分为语义/行为根和可组合显示子树，支持内容槽位与命名部件。Button 可包含 icon/content/shortcut；TextInput 可包含 prefix/editor/clear/validation；列表项可替换内容而保留选择和焦点协议。

基于 211 展开式模板增强 typed 参数、槽位填充、必要部件校验与 source map。展开后的 ID 根据实例身份与模板局部身份稳定生成，避免只因兄弟顺序改变而全部重建。装饰子节点不自动成为独立激活目标。

行为 owner 保持原输入/焦点/action 系统。复杂项目 UI workflow 使用项目代码，不在主题文件加入任意脚本或事件执行表达式。

本计划不顺带实现完整 Prefab linked instance、反向 apply 和跨 domain variant 编辑器；控件模板可复用不依赖这些功能。

虚拟列表用稳定 item key 保存选择/焦点，回收节点必须清理输入捕获、订阅与临时状态。未实例化项可被逻辑导航定位，随后滚动/实例化并转移真实焦点。可变高度测量修正需保持可见锚点，防止滚动跳动；非可见项使用估算值时，诊断标记其估算身份。

## 11. 绘制与屏幕适配

### 11.1 装饰能力

本计划包括纯色背景、独立边框、圆角、图片九宫格及有限的阴影装饰。装饰按统一 paint order 排列，通过现有 UiProjection 扩展已解析的数据；具体 GPU 实现比较解析 shader 与 tessellation 等方案后冻结。

圆角背景绘制不等于圆角裁剪子内容。两者具有独立属性和验收：矩形 clip 复用旧实现；圆角 clip 需要真实 mask/scissor/stencil 等可行技术路径验证。命中默认采用布局矩形与有效 clip，若启用形状命中必须显式声明并与遮罩语义一致。

边框默认向内绘制并预留稳定 inset；状态边框变化不得挤动内容。九宫格保留 source slice、目标尺寸、UV、边缘钳制规则；测试小于边角总宽度的情况。阴影不扩大布局需求，paint bounds 可扩展但仍受父 clip 管理。

### 11.2 适配模式

- ReferenceCanvas：保留现有参考分辨率与 Contain/Stretch 行为。
- ViewportLayout：根约束来自逻辑可用视口，宽高比改变时真实重排。
- 安全区域由平台输入提供并转换到同一逻辑坐标，不能在项目中硬编码设备型号。
- 如需响应式变体，使用显式、互不歧义的视口条件表；条件依赖根视口，不能依赖其自身计算尺寸造成循环。

DPI/窗口事件由平台适配层提供；headless 可注入确定视口进行布局测试。Windows 实窗、DPI、移动平台安全区域各自验收，任何模拟通过都不能自动宣称真实平台通过。

## 12. 失效、缓存与性能

继承 294/299，不重建第二套 full-frame identity/缓存链。至少区分内容/结构、样式指标、样式绘制、测量、安排、clip/scroll、glyph/paint 失效。

| 变化 | 必要更新 |
| --- | --- |
| 仅颜色/透明度 | 样式绘制与 paint；不重做布局/文字整形 |
| 文本/字体/字号/行高 | 段落与控件测量，向尺寸依赖祖先传播 |
| 容器宽度/间距/子节点结构 | 相关布局子树及依赖祖先，按宽度失效段落 |
| 滚动偏移 | 可见区域、安排/clip、虚拟范围；不无条件重整所有文本 |
| hover/pressed 反馈 | 既有 present-only 路径 |
| 资源替换或主题指标切换 | 根据依赖 revision 更新相应缓存 |

缓存键包含实际文本、字体内容身份、宽度约束、排版参数和算法版本；不仅使用 node ID。缓存有容量/生命周期边界，销毁文档释放资源引用。clean frame 不重复整形、全树测量或构造 Trace。

性能资格记录节点数、脏节点数、测量/布局/shape 次数、缓存命中、CPU 时间与内存趋势。M1 记录基准环境并冻结预算；不在设计阶段虚构 FPS 数字。至少覆盖 100/1,000/10,000 节点与 10,000 数据项虚拟列表，分别测试静态、局部更新、整主题指标变更。虚拟列表实例化规模应与可见项及 overscan 相关。

## 13. 诊断与自动验收

诊断包含 source path/domain/stage、稳定 node/asset ID、代码、原因与 next action。重要类别：约束冲突、循环依赖、迭代超限、内容溢出、主题引用错误、缺失字体/部件、虚拟列表身份冲突、布局与交互 revision 不一致。

- Off：保留功能必需状态和失败信息，不生成全树字符串/JSON。
- Summary：计数、耗时、溢出/失效概要。
- Trace：按请求解释某节点的约束、测量、最终矩形、样式来源、祖先传播路径。

按需通过现有工具读取布局树与样式解释；Editor 面板只是可选消费端。自动验收沿 353 注入事件并沿原 observe 读取结果，不调用新造的内部旁路绕过真实 RuntimePackage。

| 验收域 | 必须捕获的失败 |
| --- | --- |
| Schema/构建 | 非法数值、循环资源、缺资源、旧版不支持新能力却静默加载 |
| 布局 | min/max、剩余空间、嵌套、换行、Grid span、无界约束和确定性 |
| 文本 | 同一测量/绘制行宽与基线、组合字符、长词、CJK、富文本、RTL 阶段夹具 |
| 状态/主题 | 覆盖来源正确；hover 不重排；指标变体正确失效 |
| 交互 | 重排后点击/焦点/导航/滚动一致，旧快照不激活销毁对象 |
| 绘制 | 真实 glyph、圆角边框、九宫格、嵌套 clip、不同缩放，无占位框冒充 |
| 列表 | 大数据、复用泄漏、稳定焦点、可变高度滚动锚点 |
| 性能 | 静态帧缓存复用、局部变化更新范围、缓存有界和反复创建销毁 |
| 交付 | 脱离源目录加载包，默认主题/字体/图片资源齐全 |

headless 几何、属性测试与交互测试优先；绘制结果还需真实 GPU 捕获。截图固定字体、分辨率、后端与容差，几何断言补充截图，避免只有像素对比无法定位问题。实际 Gate 命令由施工文档按冻结后的文件与测试目标编写，不在本文虚构测试命令。

## 14. 布局算法与文本依赖选型

架构已选 C2。2026-09-20 M1实验后选定引擎协议+Taffy 0.12.2低层Flex/Grid混合实现，详见[合同附录](356-M1-技术选型与合同冻结附录.md)。以下是选型要求；已执行范围、局限与文本/绘制后续资格在附录明确，不把实验dev-dependency误当成生产接入。

评估需要真实小型原型与相同夹具：

1. Flex/Grid 行为覆盖、固有尺寸、百分比/无界处理、基线和多行文字回调。
2. 增量失效、缓存复用、确定性、资源预算与异常诊断。
3. 与 Anchor/Overlay/Scroll 和现有树 ID 的映射。
4. 依赖体积、编译成本、Rust/平台兼容、许可证、维护记录。
5. 与 UE/Godot/Unity 可比用例的行为差异；差异写入 engine 规范，不盲目判外部引擎为 oracle。

文本的断行、双向算法等同样优先评估已有实现。适配层隐藏依赖类型，但只封装真实需求，不为了“可替换”复制所有第三方接口。M1 必须把版本、选型结果、预算、schema 键和行为差异写回本文或同编号受控附录后，才能冻结 M2 施工范围。

## 15. 兼容、迁移与失败处理
