# 356 M1 技术选型与合同冻结附录

日期：2026-09-20。上位：[356 长期方案 C2](356-AUI统一布局主题与可组合控件-长期方案C2-v1方案.md)。施工：[归档分阶段施工文档](施工文档/已完成/356-AUI长期方案C2-分阶段施工文档.md)。

本附录记录 M1 的选型实验、公共合同与 M2 必须遵循的边界。实验源码仅在 `engine_runtime/tests/`，三项新增依赖目前均为 dev-dependency；尚未接入生产 AUI、RuntimePackage 或默认安装。下文冻结的是实现合同，不把设计字段宣称为当前 API。

## 1. 选型结论

采用混合实现：**Taffy 0.12.2 负责 Flex/Grid 求解，引擎拥有布局树、尺寸协议、文字排版、缓存生命周期和诊断；Anchor/Overlay/Scroll 由同一协议下的引擎策略负责。**

| 候选 | 证据 | 结论 |
| --- | --- | --- |
| 全自研 Flex/Grid | 独立加权空间 oracle 可核对简单 Flex；不能代表完整 Grid、min/max 冻结、基线和跨轴规则 | 不选；不得用简单 oracle 的通过声称完整自研求解器已验证 |
| 直接用高层 TaffyTree | 嵌套、换行、约束、文本与缓存实验通过；测量回调只返回 Size | 不作为最终协议：不能从回调提供文字 baseline |
| 引擎协议 + Taffy 低层算法 | 低层 `LayoutOutput.first_baselines` 实验在 Flex/Grid 都通过 | 选用；M2 在引擎内部实现适配，不暴露 Taffy 类型到项目 schema |

仓库可选 Editor 已使用 Taffy（声明0.12.1兼容范围、实际锁0.12.2），不是新引入另一家算法库。但现有 `editor_ui_renderer::widget_layout` 每次构建 TaffyTree、使用只返回尺寸的测量协议，不适合作为长期 Runtime owner 直接复用。Editor 和 Runtime 可共用依赖，不合并 UI 真相或生命周期。

## 2. 可重复实验与结果

环境：Windows、Intel Core i5-12490F、rustc/cargo 1.96.0、test debug profile。字体为已有 `samples/neon_lab_shared/assets/fonts/NotoSansSC-Regular.ttf`，测试调用现有 `text_shaping::shape_text/layout_line`，不使用按字数估宽。

测试：`rust/crates/engine_runtime/tests/aui_layout_c2_selection.rs`；低层基线支持：`tests/support/aui_c2_baseline_probe.rs`。

| 实验 | 结果/意义 |
| --- | --- |
| 加权Flex与独立算式对照 | 通过；核对剩余空间、gap与位置 |
| min/max限制后再分配 | 通过；上限冻结后剩余空间进入另一项 |
| Grid固定/fr轨道、span、嵌套Flex | 通过；同一几何链成立 |
| Flex wrap | 通过；换行后容器高度增加 |
| 真字体宽度→多行高度→按钮位置 | 通过；窄变宽后父高度降低 |
| clean-frame与局部文本失效 | 通过；clean无测量回调，改变一项不测独立兄弟项 |
| 无界Fill→内在需求 | 通过；不产生Infinity |
| 百分比与padding | 通过；确定父内容框作为比例基准 |
| 折叠与border box | 通过；布局参与和内容边距明确 |
| 树循环、悬空、多父、深度 | 通过实验preflight；反向节点顺序也检查深度 |
| 内容父宽+百分比子宽循环 | 通过实验策略负例；求解前拒绝无确定基准的比例 |
| 实际字体差异/组合字符 | 通过；WWW与iii宽度不同；组合字符保持完整，超窄时保留溢出 |
| 双向顺序/Unicode断行候选 | 通过小夹具；不等于RTL/IME产品资格 |
| 自定义baseline传入低层Flex/Grid | 通过；不同控件基线对齐，不借bottom伪装 |
| 圆角填充与父clip分离 | CPU几何探针通过；不等于GPU圆角裁剪实现 |
| 确定性重建 | 通过；同输入重建矩形相同 |

终态17项普通实验通过；1项显式规模实验通过。去重18项，不叠加中间重复执行次数。实验中的简单grapheme折行helper只验证测量接线，正式段落必须用合法断行、cluster和行片段重整形；不得把helper搬入产品当作完整排版实现。

### 2.1 规模测量

同次debug测量，单位微秒。节点数为子项数，另有一个根；单次样本，不是P95或release预算资格。全脏更新使用每项高度10→12模拟主题指标变化，只测布局，不包括真实主题解析。

| 子项 | 首次布局 | clean（带整树取整） | 单项改变 | clean关闭取整 | 全脏关闭取整 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 100 | 465 | 18 | 241 | <1 | 268 |
| 1,000 | 2,872 | 162 | 3,014 | 1 | 2,959 |
| 10,000 | 34,597 | 2,601 | 26,699 | 2 | 29,468 |

结论：测量缓存成立，但高层整树取整仍线性遍历；长Column单项变高影响后续位置，不能承诺O(1)布局。正式实现保留逻辑浮点几何，不在clean frame运行整树取整/再构图；必要物理像素对齐由现有presentation边界负责。10,000数据项走虚拟列表，不能据这张表承诺10,000真实控件每帧布局达到目标FPS。

### 2.2 首因与修复记录

首次实验编译失败：Taffy NodeId 不实现 Ord，误用于BTreeMap；Size::ZERO是Size<f32>而非尺寸策略。已改测量计数为HashMap、尺寸策略用显式zero；不改变测试期望。低层实验首次误用AlignItems::Baseline，按0.12.2 API改为BASELINE。两份失败日志均保留。3项production dead_code警告属已有源码，不作为本轮新增失败或扩大修复范围。

## 3. 数据合同冻结（M2实现依据）

所有新增结构使用camelCase、拒绝未知字段；可选字段缺省不改变旧文档。新增能力通过现有包兼容机制声明；具体包外壳版本由M2检查消费者后确定，不能私加未经消费的capability字段。第三方Style/NodeId绝不直接序列化。

### 3.1 布局节点

| 字段 | 合同与默认 |
| --- | --- |
| `layout.mode` | `anchor/row/column/flex/grid/overlay`；旧文档缺省anchor |
| `layout.padding` | `{left,right,top,bottom}`非负逻辑长度，默认0 |
| `layout.gap` | `{column,row}`非负逻辑长度，默认0 |
| `layout.direction` | flex的row/rowReverse/column/columnReverse；默认row |
| `layout.wrap` | noWrap/wrap/wrapReverse；默认noWrap |
| `layout.justifyContent` | start/end/center/spaceBetween/spaceAround/spaceEvenly |
| `layout.alignItems` | start/end/center/stretch/baseline；默认stretch |
| `layout.alignContent` | start/end/center/stretch/spaceBetween/spaceAround/spaceEvenly |
| `layout.gridColumns/gridRows` | 轨道数组；fixed/content/minContent/maxContent/fr/minmax；递归minmax拒绝 |
| `layout.gridAutoFlow` | row/column；默认row，稳定源顺序；dense不在初版 |
| `slot.width/height` | `{kind: fixed/content/fill/percent, value?}`；值只在fixed/percent出现 |
| `slot.minWidth/minHeight/maxWidth/maxHeight` | 非负有限值；max缺省表示无界，不序列化Infinity |
| `slot.margin` | 四边非负长度，初版不支持负margin和auto margin |
| `slot.flexBasis/flexGrow/flexShrink` | basis为content/fixed/percent；grow默认0，shrink默认1，均非负 |
| `slot.alignSelf` | inherit或alignItems同集，默认inherit |
| `slot.gridColumn/gridRow` | `{start?,span}`，start/span从1计，默认自动位置、span=1 |
| `slot.participation` | flow/outOfFlow；默认flow；outOfFlow使用既有rect/anchor |
| `layoutVisibility` | visible/hidden/collapsed；旧visible=false映射hidden保留位置 |
| `overflow` | visible/clip/scroll；复用原Scroll/List与clip owner，禁止生成第二滚动状态 |

Row/Column是Flex约束预设而非另一求解器。Overlay的自动参与子项按统一尺寸/对齐安排，独立定位使用outOfFlow；Anchor子树内可嵌套自动容器。旧 `rect` 对新flow节点仅在迁移期间保留数据，不同时写同轴；验证器对冲突给出source path。

### 3.2 内部测量接口

`MeasureConstraints`含每轴`min/max`、`AvailableSpace = definite/minContent/maxContent`；无界与内在测量意图区分。`MeasureResult`含border-box期望尺寸、content需求、firstBaseline与依赖标记。`Arrange`接收最终border box，生成统一snapshot；图片比例、padding/border和段落使用相同逻辑单位。

引擎负责有限数/范围/树校验。父轴确定时percent以父content box计算；父轴只由该子项决定时返回`indefinite_percentage_basis`，不读旧帧、不采用库的隐式百分比回退。无界Fill按Content；确定轴Fill映射剩余空间分配。超宽不可分cluster保留需求并报告overflow。

布局snapshot/paragraph产物作为不可变revision原子发布。原interaction读取同revision；反馈present-only变换保留277边界，不能宣称实际反馈缩放后的像素边界就是命中矩形。

### 3.3 文本接口

`textLayout`：wrap=none/word/graphemeFallback；align=start/center/end/justify；verticalAlign=start/center/end；lineHeight为正倍数或固定逻辑长度；maxLines可选正整数；overflow=visible/clip/ellipsis；direction=auto/ltr/rtl；language可选语言标签。

`ParagraphLayout`：文本/字体/参数/宽度身份、逻辑范围、行范围、visual run顺序、glyph cluster、baseline、ink与advance bounds。测量/绘制/选区/命中复用产物。断行候选与grapheme和shaping cluster共同约束；Bidi按段落解析、按行重排，不能将视觉字符串再次整形来伪装复杂脚本正确。

M2交付基本多行；M4继续富文本、RTL/Arabic/Indic、IME与caret资格。语言/字体缺口在矩阵保留；候选库的小测试不替代完整文本资格。

## 4. 主题、控件和绘制合同

### 4.1 主题资源

`ThemeAsset`逻辑字段：schemaVersion、assetId、extends（可选一个AssetRef）、tokens、styles。token为tagged color/font/length/number；字体值为AssetRef。style以稳定styleId引用，可有单一baseStyle、role、metrics、paint、states。禁止同一继承链循环、错类型token与悬空引用。

metrics含字体、字号、行高、padding、最小尺寸及稳定border inset；paint含颜色、background、border、radius、image brush、shadow。states只覆盖paint，范围base/hover/pressed/focus/disabled，顺序遵循356第9节。字体变化不能藏在状态paint里。节点`themeRef/styleRef/variant/overrides`显式选择；旧内联样式最高兼容优先级。

主题层级沿正式方案；词法子树作用域编译为明确依赖。默认主题需版本身份，旧文档继续旧路径，新主题不会悄悄改变旧界面。M3实现资源装配时复用GUID/Asset Graph/assembler，不创建旁路文件加载器。

### 4.2 控件组合

模板保留211展开真相，扩展parameters（typed）、slots（名称/允许角色/是否必需）、parts（名称→局部节点ID）。实例化映射稳定instance ID+template local ID，source map保留来源。语义根拥有input/action/focus，装饰节点不自动接收激活；项目业务继续在Rust Module。

虚拟列表输入稳定item key，内容由项目snapshot按需提供；离屏项保留逻辑身份、不创建全量节点。固定高度和可变高度分别验证；焦点/捕获/选择随key而非回收槽索引。此合同由M4实现，不随M2基础列表通过而视为完成。

### 4.3 绘制技术方向

圆角/边框优先解析距离场quad；保留渲染适配内部实现，不向AUI暴露shader对象。CPU探针已验证圆角包含函数与父clip独立；候选tessellation的代价是几何随半径/缩放增加，不能替代精确子内容mask。M3需实际比较GPU抗锯齿、batch和嵌套clip后冻结最终后端，M1不宣布GPU选型资格完成。

冻结跨层合同：draw item携带已解析rect、radius、border width/color、background、clip引用、paint bounds和资源句柄引用；Renderer不解析主题。背景圆角与子内容圆角clip独立，矩形scissor不能冒充圆角clip。未通过GPU验证前新装饰不得作为生产可用能力公布。

## 5. 预算、失效与兼容验收

### 5.1 确定性与资源边界

首版引擎安全上限：单文档65,536节点、树深128；单段落64KiB UTF-8、最多4,096行；单次更新最多1,000,000次measure调用。达到上限返回明确诊断并保留一致旧帧。这些是保护上限，不是流畅运行承诺；生产接入时以边界负例验证。

外部反馈式迭代不开放：输入内容与视口固定后一次布局事务完成；内部Flex/Grid按库算法求解，不能读取上次布局形成跨帧自适应循环。循环树与无基准percent在入口拒绝。将来若增加滚动条反馈迭代，需单独冻结有限次数与稳定判据，不能静默新增重排循环。

逻辑几何使用f32，测试近似比较容差0.01逻辑单位；相同算法/平台/输入按确定次序计算。同输入跨CPU不承诺未经验证的bitwise一致。正常snapshot保持未取整逻辑值，实际像素转换由273既有owner执行。

文字缓存默认32MiB、最多4,096条，按实际存储容量计费并淘汰；单条超过预算只本次使用、不驻留。font bytes由资源owner共享，不为每条重复持有副本。缓存上限是M2实现要求，M1尚无产品内存资格。

### 5.2 性能验收合同

- clean frame：零重新shape、零measure、零全树layout/round，复用294/299已有帧缓存。
- paint-only：零段落/几何重排。
- 局部内容：不得重测约束未变的独立兄弟段落；因父尺寸变化造成的位置传播仍允许。
- 100/1,000/10,000规模都记录冷/热/单脏/全脏与调用计数；M1表为debug定位基准，M2/M5需在相同profile、机器、字体下对照，不能跨profile声称加速倍数。
- 10,000数据项虚拟列表的活动实例数受viewport+overscan控制；M4冻结overscan策略并验证内存回收。
- 不把M1单次测量换算成FPS。产品release CPU预算需按实际composition采样冻结；这项资格在M5，不属于M1已完成范围。

### 5.3 兼容与风险

新能力显式启用；旧文档缺字段保留anchor/visible/label与内联样式。M2必须验证check/build/loader拒绝不支持的新能力，不能只在JSON里写版本号。当前三库仅dev使用，默认产品无新增运行时行为。

测试中的preflight、约束与段落probe用于证明可行性；生产版本必须落入正式owner并通过真实consumer验证。低层probe目前无缓存实现，不能套用高层缓存实验证明低层生产适配已经完成；M2同时实现`compute_cached_layout`接入并复验。

## 6. M1自审与下一阶段约束

M1选型/合同阶段已具备实测依据：选择混合Taffy低层方案、文本候选、明确几何和绘制边界、冻结数据与资源预算。正式方案方向不变，补充本附录即可。M1不要求交付生产schema或GPU效果；这些分别由M2/M3实施。

下一阶段M2需要实际落地：schema/validator → 低层adapter与cache → 正式段落产物 → 现有layout/draw/hit链 → compiler/package消费者。首先按本合同核对旧AUI schema、版本和完整调用链，再细化当前施工文档的M2 Gate。完整356尚未完成，施工文档保持当前；安装与OS状态未变。
