### 1.1 一句话目标

让 AI 使用普通项目文件、Scene/Prefab、类型化组件、资产引用和 Project Game SDK，创建、运行、修改、检查并交付一个具有真实透视、遮挡、静态模型和 AUI 的 3D 场景。

“静态”指网格拓扑与模型内容，不限制实体移动、旋转、显隐、Prefab 实例化和相机控制。相机操控、演示交互和 UI 业务在项目代码中实现。

### 1.2 本方案结束时应交付什么

1. 普通 Scene/Prefab 中的 Transform3D、MeshRenderer3D、Camera3D 进入正式 Compiler、HydrationProjection、World 和 RenderProjection。
2. cube/plane 声明生成真实 Mesh 资产，不要求项目手写顶点字节或调用 GPU API。
3. glTF 2.0 / GLB 静态模型通过明确支持的导入子集，产生稳定可引用的 Mesh、Material、Texture 和 Prefab。
4. 一个普通 3D 样例通过源码候选工具链完成 check、run、playtest、observe、capture、build 和独立交付复验。
5. 可执行的项目模板、SDK 示例、错误修复示例和能力边界说明，供后续 AI 直接使用。

默认安装接入是独立后续操作。359 的源码/候选交付验收不自动更换当前 357 Provider，也不自动获得真实宿主新版连接资格。

## 4. 范围与长期接缝

### 4.1 本轮必需范围

- 右手、Y 向上、米制、相机朝 -Z 的 3D Scene/Prefab；显式 Transform3D、Camera3D、MeshRenderer3D。
- cube/plane、静态 triangle-list 网格、多个 submesh、命名材质槽、颜色/基础纹理 Unlit。
- 一个主 World3D 相机，Perspective 必需，Orthographic 复用 U2 并验证；同一输出可组合既有 2D 与 AUI。
- 父子变换、启用/可见性继承、稳定 ID、实例化/销毁、资产/材质替换后的正确失效。
- 静态 glTF/GLB 的明确导入子集、可解释降级、重导入与依赖追踪。
- 项目侧确定性相机/对象控制，3D 语义验收、真实窗口画面与 Windows dev 独立交付。

### 4.2 本轮不交付的能力

PBR/Light3D/阴影/环境光照、骨骼动画/蒙皮/morph、Physics3D/碰撞/角色控制器、Navigation3D、3D Picking、场景编辑器/gizmo、后处理、LOD/instancing 优化、大世界流送、Android/非 Windows 资格不在本轮。

透明材质仅使用 U2 的对象排序和 alphaBlend；不承诺相交透明面的逐三角形正确排序。原粒子继续原合同，不承诺与新 Mesh 共用相机深度。多相机堆叠、跨相机共享深度、World-space UI 和 2D/3D 互相遮挡不在本轮。

### 4.3 长期方向

| 后续能力 | 本轮保留的接缝 | 本轮不预埋的假能力 |
| --- | --- | --- |

## 5. 唯一生产链与 owner

```text
普通项目文件 / Rust Project Module / Scene / Prefab / 资产描述
  -> AuthoringProjectContext（snapshot / revision / mutation / rollback）
  -> GameProjectCompiler
       -> Import/Cook + Asset Graph
       -> ProjectRuntimePackageAssembler
       -> Generated Runtime Glue
  -> RuntimePackage + 固定 Host / Engine DLL / Project Module
  -> HydrationProjection -> World / Hierarchy / Spatial propagation
  -> RenderProjectionAdapter<MeshRenderer3D / Camera3D>
  -> U1 Asset Prepare + U2 RenderView / GeometryFrame
  -> 原 RuntimeRenderer / RenderGraph / RHI / WGPU
  -> 既有 Semantic Outcome / observe / capture / Delivery Verify
```

| 职责 | 既有 owner 与计划改动位置 |
| --- | --- |
| 项目 schema、身份、字段 patch、导入清单提交 | `authoring_project_context`；沿用 CAS/receipt/rollback，不另造 3D 项目数据库 |
| 解析、导入、Cook、派生 Prefab、包依赖 | `project_authoring_execution`；扩展 `neutral_assembler` / `render_asset_cook` 及内部 importer，不建第二 Compiler |
| typed component、空间传播、Hydration | `engine_runtime` 的 components/World/Hierarchy/runtime hydration；共用 entity 生命周期 |
| 渲染投影、Prepare、帧构造 | 现有 RenderProjection / RenderResourceManager / `render_geometry` / RuntimeRenderer |
| 项目编程面 | `project_game_sdk` / `project_runtime_sdk` / Generated Glue / Native Adapter，各自只承担原职责 |
| 执行与观测 | `engine_runtime_host`、`runtime_player_winit`、既有 observation/outcome；Engine DLL 路径必须真实消费新能力 |
| 工具与知识 | `engine_tool_provider` 的既有独立工具及版本化模板/示例，不增加 3D 专用大工具 |

Renderer 不读取项目目录或导入设置；Runtime 不解析 glTF 源文件；项目不持有 RenderProxy/GPU handle。Import/Cook 的内部函数拆分可以调整，不能改变这些 owner。

## 6. 场景与组件合同

以下是本方案冻结的语义和拟定 wire 名称，不是当前 357 已接受的输入。A0 施工需把它们落实为严格 schema、可执行 fixture 和兼容矩阵，随后示例必须从已实现 schema 验证。新组件/资产入口拒绝未知字段、版本和 tag；除明确可选字段外不靠缺省值吞掉错误。模板默认值必须写入生成文件，旧 decoder 保持原兼容规则。

### 6.1 空间域与 Transform3D

新增 `Transform3D` authoring component，data 使用 `transform3d.v1`：

| 字段 | 合同 |
| --- | --- |
| `translation` | 三个有限数，米；模板默认 `[0,0,0]` |
| `rotation` | tagged union：`eulerDegrees { xyz }` 或 `quaternion { xyzw }`，仅能存在一个分支 |
| Euler 定义 | 对列向量依次应用局部 X、Y、Z；矩阵 `Rz * Ry * Rx`，角度制；不得依赖库的默认 Euler 顺序 |
| quaternion | xyzw 单位四元数；超出 A0 固定容差的输入拒绝，容差内规范化并采用固定等价符号规则 |
| `scale` | 三个有限非零数；模板 `[1,1,1]`；支持负缩放，拒绝产生不可逆 world transform 的值 |
| 派生值 | runtime canonical rotation、local/world matrix、previous world matrix、world bounds，由引擎计算，项目不可独立写入 |

authoring 一份 rotation 真相；RuntimePackage canonicalize 成四元数，不同时保存两份可独立修改的 Euler/quaternion。投影矩阵沿用 U2 列主序、RH、clip depth `[0,1]`。

每个空间实体恰有一个位置来源：既有 top-level legacy `transform` 或新 Transform3D。二者并存、3D renderer/camera 没有 Transform3D、3D 实体附带旧 Sprite/Collider2D 均报明确 domain conflict，不偷偷挑一个生效。

3D 子树只能拥有同域空间父节点，允许挂在 Scene 结构容器根（该容器不是带隐藏 transform 的 World 实体）；不允许直接以 legacy 2D transform 作 3D 父坐标。UI 继续独立 Document。兼容项目无需迁移既有 2D transform。

### 6.2 层级传播与可见性

- `world = parent_world * local`，以既有 Hierarchy 的拓扑顺序传播。新增类型扩展共同传播 owner，不另建每帧全 World 扫描器。
- 重挂父节点、父 transform/enable/visibility 改变时，后代 dirty 必须传播；循环、孤儿和已销毁 parent 失败，Scene/Prefab 加载不能半成功留残存实体。v1 重挂默认保留 local transform，world 随新父节点变化；不隐式承诺 keep-world 分解任意仿射矩阵。
- 渲染对象可见性区分 authored、inherited 和 U2 的逐 view 结果。Hierarchy 的 enabled 继续影响整个子树；`Visibility3D` 使用 `visibility3d.v1`，只有 `visible:bool`，可用于 Transform3D 分组节点或渲染实体。父节点该值参与后代继承，本节点该值与 MeshRenderer3D.visible 取 AND；未挂 Visibility3D 表示没有额外隐藏约束，不要求分组节点伪装 Mesh。
- world bounds 由真实 Mesh local bounds 和 world matrix 派生；U2 八角保守剔除继续有效。非均匀父缩放产生的合法 mesh 仿射矩阵不强行分解回 TRS。
- CameraPose 使用传播后的刚体姿态；相机层级只接受可明确提取刚体姿态的变换，A v1 拒绝其祖先链的非单位 scale/shear，不从任意 matrix 猜旋转。
- 负 determinant 的 Mesh world transform 必须派生相反 front-face 策略，避免镜像模型被错误剔除；不能通过全局关闭背面剔除掩盖问题。
- previous world matrix 在帧提交时更新，首次创建等于当前；资产替换或重导入不能改写实体身份。

### 6.3 MeshRenderer3D

data 使用 `mesh-renderer3d.v1`：

| 字段 | 合同 |
| --- | --- |
| `mesh` | `AssetRef<Mesh>`，沿用 `id/type/guid/sub_asset`；路径仅作来源 |
| `materials` | `materialSlotName -> AssetRef<Material>` 映射；每个使用中的 submesh 槽必须可解析 |
| `visible` | bool，模板 true；与继承可见性共同生效 |
| `layers` | 稳定命名集合，模板 `['world']`；不暴露 raw mask |

材质槽缺失、拼错或多余均诊断，防止 AI 以数组位置误改另一材质。导入 Prefab 先填好完整绑定，实例可显式覆盖；解析后每个 submesh 的单一最终绑定才交给 U2。

同一 Mesh/Material 可被多个实体引用；GPU buffer/纹理按资源身份共享。通过现有 Projection identity 派生实例和 submesh draw identity，不按遍历顺序或资产数组位置制造运行实体 ID。

### 6.4 Camera3D 与主视图选择

data 使用 `camera3d.v1`：

- `projection` 为 `perspective { fovYDegrees, near, far }` 或 `orthographic { size, near, far }`。取值、size 定义和非法参数继承 U2。
- 模板提供 Perspective `60° / 0.1m / 1000m`；这些是模板明确写入的值，不是 decoder 遇错自动修复。
- `viewport` 首批支持整个窗口；aspect 来自当前有效 drawable extent。resize 后更新 view version、投影、viewport 和深度尺寸；窗口最小化零尺寸标记 suspended，不提交非法几何帧。
- `clearColor`、命名 `layers`、组件 enabled 由项目声明；World3D 深度使用 U2 TestAndWrite view policy，材质可选择 TestOnly。
- 场景渲染设置显式引用 `mainCamera` 的稳定 scene entity identity；至少有可渲染 3D 对象时必须解析为一个有效 Camera3D。多个 camera 可以存在，但 A v1 只执行被选择的一台。
- 没有相机、选中禁用/已销毁相机、引用歧义均报错；不从首个实体或 Editor 视角猜主相机。项目切换主相机通过受验证的 deferred intent，帧边界原子提交。
- 相机实体作为普通 Prefab 内容可实例化；实例化不自动夺取主相机，必须用实际生成的稳定运行 handle 显式选择。

### 6.5 版本与拒绝旧消费

现行 RuntimeEntity 对 schemaVersion 有检查，且 hydration 强制 legacy Transform。359 采用以下兼容方向：

1. 新增 `runtime-entity.v2` 表达显式 spatial 域和 3D typed 数据；legacy v1 继续原样读取。v2 不同时存放可写的 legacy transform 和 Transform3D。
2. 新 runtime 按实体版本解码后进入共同 World/Hydration owner，允许同场景的独立 2D/3D 子树；不隐式重写旧项目或全部旧包。
3. 3D scene 设置同样使用显式版本化扩展；承载新设置的场景/Prefab 若旧 reader 会忽略字段，必须升级其 envelope，并保留新 runtime 的旧版本 reader。
4. 新包要求旧 runtime 在加载阶段拒绝 unsupported schema/capability，不能成功加载后忽略 3D。A0 要验证旧 Provider、旧固定 Host/DLL 与新包的负向组合。
5. RuntimePackage 总 envelope、九工具协议、SDK/ABI 分别评估。只升级发生不兼容变化的合同；不得仅靠一个全局 engineVersion，也不能以“不升级”为目标省略必要版本变化。

A0 源码复核确定的最小边界：新 3D 项目显式选择 `aife-project.v3`，旧 v2 项目保留原格式；旧 Compiler 在 manifest 处拒绝 v3，避免将未知 3D 组件作为普通数据静默通过。新增 `authoring-scene.v2` / `authoring-prefab-asset.v2`、`runtime-scene.v2` / `runtime-prefab.v2`；任一新 spatial Prefab 所在交付也必须输出 v2 活动场景，因为旧 Prefab reader 本身不检查版本。RuntimePackage 外壳保留 v2，由已有旧 Scene 版本检查阻断旧 Runtime。A0 只有合同检查资格，实际 prepare/load 明确拒绝尚未接入的执行消费；后续按 A1/A2 接通。

A1.1实际消费现见[World/Hierarchy/Camera完成记录](阶段完成记录/2026-09-22-359-A11-World-Hierarchy-Camera/00-总览.md)：typed prepare/hydration与Projection已接通，generated资产、普通窗口及SDK仍按后续Gate实施；下文A0资格描述保留其阶段身份。

具体wire字段、模板、单位四元数一次规范化/包值只校验、版本矩阵、导入预算与consumer边界见[359-A0实际合同附录](359-A0-3D场景资产与版本合同附录.md)；[A0完成记录](阶段完成记录/2026-09-22-359-A0-Spatial-Contracts/00-总览.md)提供源码验证，不替代后续运行资格。

## 7. AI 易编写的原生资产

### 7.1 图元来源

新增高层 `mesh-asset.v2` 的 `source` tagged union。首批 `generated` 支持：

| primitive | 参数与几何定义 |
| --- | --- |
| `cube` | `size:[x,y,z]`，均为正数，中心原点，轴对齐；尺寸表示完整边长，模板 `[1,1,1]` |
| `plane` | `size:[x,z]`，均为正数，中心原点，位于 XZ 平面，正面朝 +Y；模板 `[1,1]` |

图元 cook 输出 position/normal/uv、真实 vertex/index、bounds、具名默认槽 `surface`。v1 不暴露无实现的细分/圆角参数；所需 count、winding、UV 和 byte digest 由确定性 generator 验证。

`source` 与 U1 低层 `renderData` 不得并存；U1 `mesh-asset.v1` 继续可读，不强制既有测试/资产改写。AI 普通创作使用高层声明，不手写二进制数组。generated mesh 也进入 Asset DB/Graph 和 Package，不在 runtime 特判 primitive 生成测试几何。

### 7.2 高层 Unlit 材质

新增易编写的 `material-asset.v2`：`preset='unlit'`、`baseColor`、可选 `baseColorTexture`、`blend`、`cull`、`depth`。参数约束来自 U1，透明缺省策略由模板明确写为 alphaBlend/TestOnly；不透明为 opaque/TestAndWrite。

颜色定义为线性 RGBA，基础颜色纹理按 sRGB 解码，alpha 为线性；sampler 设置影响纹理/绑定身份。颜色空间不是取决于文件扩展名的猜测。shaderSource/pipeline identity 由 Compiler 派生，普通项目不复制源码路径常量。

没有 texture slot 表示纯色材质；已声明纹理丢失必须失败。Unlit 不受灯光影响，不用环境灯或假阴影制造 PBR 完成的印象。

### 7.3 Cook、缓存与失效

继续复用 U1 原生 cooked payload、RuntimeAssetIndex、Loader、Prepare 与 ResourceManager。新增 source 入口扩展既有 Cook owner，不增加第二资产表或第二 GPU 上传链。

派生 identity 至少覆盖：source bytes/descriptor、import settings、generator/importer recipe version、所有依赖内容摘要、目标/profile 和实际输出。source digest、cooked digest、package digest 各自保留，不能互相冒用。

资源变更按依赖图失效：纹理修改影响相应材质绑定和包；纯材质颜色修改不重建 Mesh buffer；相机/transform 修改不重做资产导入。新资产完全验证/准备后才提交替换；预算不足沿用 U1 Deferred，失败必须显式报告，不把旧画面当作新 revision 成功。

## 8. glTF/GLB 静态导入合同

### 8.1 来源与产物

项目增加 `model-import.v1` 描述资产，包含源文件引用、选定 scene、坐标/单位转换设置、材质策略、稳定子资产映射及输出范围。源文件和外部依赖进入现有 Project Library / source inventory / Asset Graph。

```text
model-import.v1 + glTF/GLB + buffers/images
  -> source dependency scan + schema/feature validation
  -> importer intermediate data（内部临时产物）
  -> 原生 Mesh/Material/Texture cooked assets + generated Prefab
  -> 原 RuntimePackage asset manifest / dependency graph / source mapping
```

generated Prefab 保留选中 scene 的节点层级和可支持的 transform、Mesh/Material 绑定，沿用现有 Prefab 装配入口。它是 Library 派生产物；实例覆盖和项目逻辑放在源场景/项目文件。项目不得通过手改生成文件实现永久修复。

### 8.2 v1 支持矩阵

| 输入 | v1 行为 |
| --- | --- |
| glTF 2.0 `.gltf`、`.glb` | 必须支持；解析 version/minVersion，非法或不兼容版本拒绝 |
| buffers/images | GLB 内嵌、bufferView、有限 data URI、项目内相对路径；统一收集并摘要 |
| 外部网络/绝对路径/根外依赖 | 不在导入时下载或读取；给出 source path 与具体 URI 诊断 |
| primitive | triangle-list；多个 mesh/primitive，索引与非索引几何；非索引输入 cook 成确定性索引 |
| accessor | 正确处理 offset、stride、component type 和 normalized；索引 u8/u16/u32 规范到 U1 u16/u32；检查范围、溢出与有限值 |
| 顶点 | POSITION/NORMAL 为 FLOAT VEC3；UV0 为 FLOAT 或 normalized unsigned byte/short VEC2；COLOR_0 为对应 FLOAT/normalized VEC3/VEC4，VEC3 补 alpha=1；输出规范到 U1 float32 布局。POSITION 必需，Unlit 可无 NORMAL，带纹理但无所需 UV 必须诊断 |
| sparse accessor / Draco / meshopt | v1 明确 unsupported，不假定连续 buffer，不静默跳 primitive |
| 节点变换 | TRS 或可无损表示的 affine matrix；不能转换为本方案空间合同的 shear/奇异矩阵拒绝并定位 node |
| 材质 | `KHR_materials_unlit` 的 baseColorFactor/baseColorTexture、OPAQUE/BLEND、doubleSided；映射现有 Unlit |
| 纹理 | PNG/JPEG、UV0，wrapS/T 的 repeat/clampToEdge/mirroredRepeat、min/mag 的 nearest/linear；省略 sampler 时采用本导入 profile 明确的 linear/repeat，报告 resolved 设置。采样语义必须由既有纹理/绑定 owner 传到后端 |
| MASK / UV1 / KHR_texture_transform / mipmap filter | v1 明确 unsupported，或要求源文件先转换到已支持子集；不擅自删参数或把 mipmap filter 当普通 linear |
| skin / morph / animation / 灯光 | 选中消费范围内默认拒绝；v1 不承诺静态烘焙或动画导入 |
| camera | 不自动导入并替换项目主相机；发现源相机时报告未导入，项目显式提供 Camera3D |

默认只导入描述中选定 scene 的依赖闭包；未引用内容记录为未消费，不能把未消费对象中的能力宣传为支持。未知 `extensionsRequired` 必须拒绝；未知可选扩展也应标记其出现位置与处理结果。导入结果有 `accepted/degraded/unsupported`，诊断不能只输出成功文件数。

### 8.3 材质降级必须显式

glTF 默认材质模型是 PBR；“格式可解析”不等于“外观等价”。设置提供两个明确策略：

- `strictUnlit`：默认；只接受可准确映射到本方案 Unlit 的材质，PBR 返回 `material.model_unsupported`。
- `baseColorOnly`：项目显式选择；保留基础颜色/基础纹理、可支持透明与双面设置，报告每个丢弃的金属度、粗糙度、法线、遮蔽、自发光或扩展语义，结果标记 degraded。

`baseColorOnly` 不能绕过损坏文件、缺纹理、未知 required extension 或结构不支持。它只允许已列明的材质外观降级，不是“尽量吞掉所有错误”。

### 8.4 坐标、负缩放与纹理方向

glTF 的 RH/Y-up/米制与新合同相符，默认转换是 identity；不得额外套一次 Unity/UE 式坐标翻转。用户显式设置单位/轴转换时，统一应用到节点、顶点、bounds、normal 和 winding，记录转换 identity，避免节点和几何各做一次。

UV 与 image row origin 只在统一导入/纹理 owner 做一次转换，用非对称方向纹理验收。负缩放、非均匀缩放、面绕序和双面材质各有正反例。

### 8.5 稳定子资产与重导入

文件名、node name、mesh/material 数组下标、source digest 都不能单独成为长期引用身份。沿用 GUID/meta/AssetRef，为每个输出分配并持久化稳定子资产 GUID/key；source locator 与内容指纹是匹配信息，不是唯一身份。

首次导入规划输出/映射，跨资产写入通过现有 mutation 事务提交。后续 check/build 只消费已提交描述并生产 Library，不能悄悄改写 source meta。源文件变化需要新增/删除/重映射子资产时，先生成影响预览，再提交对应导入映射修改。

重导入遵循：

1. 未变对象保持 GUID；对象重命名/路径移动仍以持久映射为准。
2. primitive/node 重排或匹配歧义不可自动绑定到另一个对象；返回候选来源和影响引用，要求显式映射更新。
3. 删除仍被场景/材质/Prefab 引用的输出必须报告依赖，不能制造悬空引用或默默删实例覆盖。
4. 导入失败不发布半套输出；上一个完整派生集可保留，但其 revision 不代表新源文件成功。
5. mesh、material slot、generated Prefab 节点与实例 override 的稳定映射一起维护；不能只稳定 Mesh GUID 却让 override 因 slot 重排落到错误材质。

解析器优先选择成熟 Rust glTF 库，限构建侧依赖，禁用无关默认特性；A0/A2 施工文档需核对实际 API、许可、锁文件、输入限制与支持矩阵。源字节、解码图像像素、顶点/索引数、节点数/深度、总派生字节必须有可检查预算，整数运算检查溢出；超预算或取消在原子发布前终止并保留原结果。不得让库的“parse 成功”代替上述引擎合同验证。

## 9. Runtime 接入与资源生命周期

### 9.1 帧次序

```text
Fixed Tick 项目回调 / 输入
  -> 受验证的 deferred command 提交
  -> Hierarchy / world transform / inherited visibility 更新
  -> 现有 dirty RenderProjection（含 Camera3D / MeshRenderer3D）
  -> Prepare 资产与当前资源状态检查
  -> 主 RenderView + GeometryFrame
  -> 原 RuntimeRenderer::build_with_geometry
  -> 原 RenderGraph / RhiCommandPlan / Backend
  -> 按需观察与同帧 capture
```

项目驱动的相机和 transform 变化必须在同一已提交 tick 的派生帧生效；观察报告区分 simulation tick 和 presented frame。不能一边读新 World，一边复用旧相机截图还标为同一帧。

### 9.2 同输出 2D/3D/AUI

保留 U2 的实际 composition 顺序：native view 初始化在全局 clear 之后、BeforeWorld 之前；native world draw 在旧 Particle 和 ScreenOverlay/Modal 之前，旧 Sprite/UI consumer 保留既有分支。

本轮主 3D view 只清理自己的 viewport；AUI 继续独立 overlay。混合 2D/3D 样例必须断言实际 pass 顺序和像素，不能将“共用 RenderGraph”解释为旧 Sprite 自动进入新相机或共享世界深度。

### 9.3 生命周期和失败

- 相同 Mesh 跨实例/帧共享 U1/U2 几何数据与后端缓存；draw-specific uniform 不计为重新上传 Mesh。
- 资产替换、相机销毁、scene unload、Prefab despawn、resize、预算 Deferred、stale generation 均由既有 owner 处理。
- prepared 不等于 GPU resident；绑定在提交前仍要验证。声明纹理存在但 GPU 资源缺失时不得继续画纯色并报告成功。
- 3D 显式激活的项目加载失败应停在首因，不回退 legacy MeshBasic 测试三角形。设备/表面丢失沿用现有恢复或终态错误合同，不新承诺无条件自动恢复。
- Renderer 只消费不可变/共享派生产物；Trace 关闭时不每帧复制顶点、序列化完整场景或扫描全部 asset source。

## 10. SDK、AI 工具与知识交付

### 10.1 小而明确的 SDK 面

在既有 `WorldRead` / `DeferredMutationWriter` 上增加 typed helper，语义包括读取 Transform3D、写入局部 Transform3D、设置 Mesh 可见性/材料槽、选择主相机；继续使用既有 EntityHandle + generation。具体 Rust 符号由 A0/A3 的可执行 API fixture 冻结。

写入通过相同 deferred 校验与提交 owner。旧 `WriteTransform` 和 SDK Transform 只保留 legacy 语义；不能把它们解释为新的 quaternion 数据。复用通用字段写入时，reserved 3D component 必须经过专属校验，不允许 `ReplaceDynamicComponent` 绕过空间不变量。

确需增加 typed command 或 ABI payload 时，必须由 Compiler/SDK/Native Adapter/Engine DLL 成对接入并验证版本协商。固定 Host/DLL 缓存身份纳入新代码与合同，禁止新 Project Module 意外加载不兼容旧 DLL。

项目实现 camera orbit/移动、对象显隐、材质切换和 reset；本轮不把 orbit 控制器、射击、胜负等样例逻辑放入 Engine Core。没有 Physics3D 的移动明确为 transform 控制，不宣称碰撞或重力已生效。

### 10.2 现有工具承载的能力

| 现有接口 | 3D 输出或扩展 |
| --- | --- |
| `engine_project_inspect` | schema/support、主相机、实体/Prefab、typed asset refs、导入设置与来源映射 |
| `engine_project_check` | transform/domain、相机、材质槽、依赖、import/cook/package/binding 的阶段结果；静态检查不宣称 GPU 成功 |
| `engine_project_mutate` / rollback | 原 CAS/事务处理 3D 字段和导入映射；普通文本编辑仍是一等输入 |
| `engine_runtime_run` / playtest | 普通项目实际运行；353 有序输入驱动项目控制，必要 tick 的语义断言与捕获 |
| `engine_runtime_observe` | 读取已有 run 的 3D Summary/Trace 与视觉证据；capture 仍在其 typed 请求/既有 playtest 合同中，不新增独立 capture tool |
| build / delivery verify | 源码候选构建与同一交付的依赖、身份、实际启动验证 |

需要扩展的请求/结果采用版本化 domain 数据。既有调用和 2D outcome 继续兼容，九项独立工具不被折叠成字符串路由的大工具。

### 10.3 结构化观察与诊断

引擎提供可按稳定 entity/view/asset 过滤的 3D 观察投影：

- 实体：source identity、runtime handle/generation、local/world transform、真实 bounds、authored/inherited visibility。
- 相机：实际选中实体、projection 参数、pose、viewport/target extent、view version、suspended 状态。
- 逐 view：included/domain/layer/frustum 等状态；“在视锥内”和“实际未被遮挡的像素”分开，frustum included 不叫 occlusion visible。
- 资源：Mesh/submesh、材质槽、texture refs、cooked identity、prepared/deferred/failed、降级与失败原因。
- frame：tick、frame sequence、submitted/presented/captured 阶段、viewport、backend、交付身份及采样时间。

复用 312 Semantic Outcome owner，把引擎生成的 3D 数据投影到可断言的类型化路径；不要求样例 Rust 自报“模型已渲染”作为唯一事实。项目自定义业务观测仍保留。

运行/捕获结果绑定 project revision、package/delivery digest、runRef、operationId 和 frame/tick；check/inspect 没有运行实例时不伪造 runRef，而是在后续构建/运行时关联相同 revision。observe 回读封存结果不得重跑当前项目并冒充旧 run。

诊断继承 U0/U1：code、domain、stage、source path + field、entity/asset、expected/actual、dependency chain、fallback、retryability、next action。优先帮助 AI 区分“无相机”“剔除”“深度遮挡”“资源未就绪”“材质不支持”“旧工具链”，而非只返回黑屏。

### 10.4 Off / Summary / Trace

默认 Runtime Off，仅保留正确执行必需状态与 compact failure；按需 Summary 输出有界计数/选中对象/首因；Trace 才展开指定范围的逐实例 culling、绑定与命令来源。

过滤、条目上限、截断和分页/采样语义必须显式。Off 不执行诊断 closure、不生成长 JSON、不写文件；Summary 不隐式升级为全场景 Trace。截图使用真实渲染结果，headless hash 不能当图片证据。

### 10.5 AI Development Pack

至少交付：空 3D 场景、cube/plane 场景、Unlit 材质、静态模型导入、项目相机控制、3D+AUI、playtest/observe 和错误修复示例。示例由真实 schema/SDK/Compiler 测试消费，包含工具链能力要求与不支持项。

展示一条实际修复闭环：故意错误相机 near/far 或材质槽 → check 返回明确字段 → 字段 patch → 同 revision 的新候选运行 → 语义与像素双证据。无需为每个字段注册一个工具，也不要求每次小修改先写完整方案。

窗口截图使用固定分辨率和已记录 backend；关键 ROI/像素加几何/身份断言，容差事先写入施工文档。验证透视缩放、前后遮挡、背面/镜像、纹理朝向、near/far 与 AUI overlay，不以“一张不黑的截图”通过。

Windows dev 交付必须由默认的 Compiler/Export/Engine DLL 路径产生，在项目源路径不可用的独立副本中运行；source glTF、编译缓存和 Editor 不能成为隐含运行依赖。delivery verify 与截图/观察必须绑定同一成功交付。

## 12. 分阶段实施路线

本节划定方案交付阶段。A0–A4 的文件范围、实际命令、成本、前置条件和归档规则统一放入[方案 A 总施工文档](施工文档/已完成/359-3D静态场景与AI项目闭环-方案A-总施工文档.md)，在同一文档内按 Gate 推进和记录进度，不再逐阶段生成施工文档。执行状态以54为准。

| 阶段 | 交付目标 | 必须证明 | 依赖 |
| --- | --- | --- | --- |
| A0 合同与版本 | 3D component/spatial/scene camera、资产 source、导入/观察支持矩阵，兼容与 owner 落定 | 严格正反 schema fixture、legacy 无隐式迁移、旧 consumer 拒绝新格式、必要 SDK/ABI 影响清单 | 358 U0–U2 |

### 12.1 验收要求矩阵

| ID | 风险/要求 | 能捕获失败的证据 |
| --- | --- | --- |
| A-01 | 3D 与 legacy transform 冲突或语义漂移 | 两域输入 fixtures、dual transform/跨域 parent 拒绝、旧 2D decode 与行为回归 |
| A-02 | 层级旋转/可见性/bounds/dirty 错误 | 独立算例的 parent-child 世界结果，隐藏/重挂/销毁后的逐 view 状态，循环/奇异输入负例 |
| A-03 | 无相机或错误矩阵被静默接受 | mainCamera 缺失/禁用/切换、near/far、FOV/正交、resize/最小化、坐标约定投影点 |
| A-04 | 仍在画默认三角形 | 更换源图元尺寸/模型顶点后 buffer/cooked identity 与窗口轮廓同时改变，缺 payload 必须失败 |
| A-05 | 遮挡/cull/纹理方向错误 | 真实窗口的深度互换、镜像 front-face、方向纹理、双面/透明受限案例与像素断言 |
| A-06 | importer 漏依赖或越界 | glTF/GLB、indexed/nonindexed、stride/offset/u8 indices、图片依赖；破损/越界/缺依赖/sparse/required extension 负例 |
| A-07 | PBR 偷偷降级或 asset identity 漂移 | strictUnlit 拒绝、baseColorOnly 逐项 degraded；重排/同名/重命名/删除被引用输出的映射与回滚 |
| A-08 | SDK 写入绕过语义或 stale handle | 正常控制、销毁后旧 handle、非法 rotation/主相机、reserved component 旁路均有断言 |
| A-09 | 观察伪报画面或混淆版本 | 引擎源 3D 状态、真实 capture、run/delivery/frame 关联，修改当前源后回读旧 run，故意错误期望必须失败 |
| A-10 | 2D/AUI/粒子组合回归 | 受影响旧 consumer suite + 新候选混合画面，UI 不进 world depth，旧粒子深度边界明确 |
| A-11 | 资源或报告每帧无界增长 | 同资产多实例/多帧只上传必要几何，scene unload/reload/resize 后资源退休，Off 零详细报告、Summary 有界 |
| A-12 | 只有源码测试能运行 | 固定 Host/Engine DLL 与项目 ABI 实际配套、普通工具构建、独立副本在源路径不可用时启动与复验 |
| A-13 | 缓存忽略真实变更或无关重建 | 修改 texture/材质/几何/相机分别断言依赖失效范围与未变 mesh 复用，旧 cooked digest/旧 DLL 候选不得被误命中 |
| A-14 | 导入留下半套产物或无界分配 | 预算超限、取消、解码失败、发布中断负例；输出集合和 source 映射保持完整事务身份 |

开发反馈以确定性 owner 测试为主，跨 owner 改动覆盖真实 consumer。已有 U0–U2 证据按身份和影响面复用，不能因生成方案或文档变动机械重跑全 workspace。

Headless 测试可以证明合同、生命周期和 hash，不能证明实际 GPU 画面；A1/A4 指定的 Windows 图形验收需要真实设备成功运行。无设备时记录资格未完成，不把 skip 算 pass；这不意味着把所有普通 CI job 都改成 GPU 必需。

A4 测量有限实例规模下的 prepare/upload/draw 数量、CPU 时间和资源占用，报告环境与上限；预算在施工前冻结，不凭开发配置时间推导显示 FPS，不声称大场景或 release 性能已达标。

## 13. 风险、失败处理与范围控制

| 风险 | 处理 |
| --- | --- |
| 把本轮扩大成重写整个场景/ECS | 新增分域 schema 与共享传播实现，保持旧输入/consumer；超出必要接缝先回填设计 |
| 用通用动态 component 掩盖没有 consumer | reserved typed 注册、专门验证、Hydration/World/Projection/包/工具逐层可追溯 |
| glTF 范围膨胀或默认外观不一致 | 支持矩阵和 strictUnlit 默认；显式 degraded 与 unsupported，不以“支持 glTF”省略限制 |
| GUID 在每次 cook 重新生成 | 映射是 source/meta 的稳定输入，check/build 只生成派生内容，冲突通过事务修订 |
| 多 view 和旧粒子遮挡被误认为已统一 | A v1 一台活动主相机；旧 composition 与 depth 合同保留，混合测试限定声明 |
| 新 SDK/资产误配 357 Host/DLL | 独立版本/能力检查、缓存 identity 和旧 consumer 负例；不自动使用默认安装当候选 |
| AI 能写却无法诊断黑屏 | 按阶段的 compact 首因、按需 3D Summary/Trace、真实捕获和修复负例 |
| 默认报告/资源开销失控 | dirty + Arc 共享 + 原缓存/生命周期，Off 与有界 Summary；性能证据按实际规模解释 |

如果施工发现当前 owner 无法满足上述合同，先修订本方案与对应施工范围，再扩大实现；不能在代码中悄悄新增第二资产 authority、第二 Runtime 或独立 3D 工具入口。
