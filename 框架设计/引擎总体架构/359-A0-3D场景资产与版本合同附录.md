## 2. 空间与组件

owner：[spatial_contract](../../rust/crates/engine_runtime/src/spatial_contract.rs)、[document](../../rust/crates/engine_runtime/src/spatial_contract/document.rs)。

| 数据 | 序列化与规则 |
| --- | --- |
| Transform3D | `schemaVersion: transform3d.v1`、`translation:[f32;3]`、`rotation`、`scale:[f32;3]`；所有数有限；translation 米制 |
| rotation | `{kind:eulerDegrees, xyz:[x,y,z]}` 或 `{kind:quaternion, xyzw:[x,y,z,w]}`；不允许两个分支字段共存 |
| Euler | 角度制，列向量先 X 后 Y 后 Z，`Rz*Ry*Rx`；大角度先按360°归约；模板零旋转 |
| quaternion | source `abs(length-1) <= 1e-4`，归一化一次；w 优先取正，w=0 按 x/y/z 首个非零分量取正；清除负零；包只存 `rotationXyzw`。canonical 包值检查单位长度误差不超过 `2*f32::EPSILON` 和规范符号，拒绝不规范输入，不重复归一化导致末位漂移 |
| scale | 有限非零，倒数及局部 determinant 必须可表示；负缩放可用；World 数值、shear/镜像消费由 A1 验证 |
| Visibility3D | `visibility3d.v1`、唯一行为字段 `visible:bool`；可用于分组节点；未挂表示无额外隐藏约束 |
| MeshRenderer3D | `mesh-renderer3d.v1`、`mesh:AssetRef`、`materials:{slot:AssetRef}`、`visible`、`layers:[name]` |
| Camera3D | `camera3d.v1`、U2 `projection`、`viewport:fullWindow`、`clearColor:[f32;4]`、`layers`、`enabled`；拒绝 LegacyMatrix |
| project data | 新3D实体的 `components` 只容纳 `project.*` 纯数据；空间组件不能藏在此通道。旧 v1 decoder 的无关扩展行为不变 |

坐标固定 RH、Y up、米、camera -Z；矩阵列主序，clip depth `[0,1]`。模板显式写 `[0,0,0]`、`[1,1,1]`、Perspective `60/0.1/1000`、`world`、true；decoder 不用模板值掩盖漏写或坏输入。projection 数值规则沿用 U2；颜色保持 U1/U2 的有限线性 RGBA 合同，不在 A0 暗加颜色裁剪。

一个空间实体只有一份 transform。旧 transform/mesh/Sprite/Collider2D 不能与 Transform3D 共存；3D renderer/camera/visibility 缺 Transform3D 失败。父子同域，Scene 是结构容器；重复 identity、孤儿、循环失败。A0 已检查 camera 自身和祖先为单位 scale，选中的 camera/祖先 enabled；A1 执行层继续验证运行期变化。

source 中的组件形式仍为 `{componentType, data}`。内置新类型严格区分大小写，重复或未知内置组件失败；未知字段和重复 JSON 对象键不能被 Value 中转吞掉。source 的错误路径映射回 `/entities/i/components/j/data/...`，不向 AI 返回仅存在于派生运行数据的路径。

`mainCamera` 为稳定 scene entity id，可为空的前提是场景无 MeshRenderer3D。存在 renderer 时必须显式选中有效 Camera3D，不猜第一台。Prefab 可携带 camera，但不能声明/抢占场景主相机。

## 3. 源资产与引用

owner：[three_d_contract](../../rust/crates/project_authoring_execution/src/three_d_contract.rs)。可直接审查且由测试消费的普通 JSON：[场景](../../rust/crates/project_authoring_execution/tests/fixtures/three_d_a0/scene.json)、[图元](../../rust/crates/project_authoring_execution/tests/fixtures/three_d_a0/mesh.json)、[Unlit](../../rust/crates/project_authoring_execution/tests/fixtures/three_d_a0/material.json)、[导入描述](../../rust/crates/project_authoring_execution/tests/fixtures/three_d_a0/import.json)。它们是合同 fixture，不是已经可运行的 3D 游戏样例。

新资产共同字段：`schemaVersion/assetId/assetGuid/displayName`。新声明要求非空持久 id/GUID；资产与导入计划输出之间的 id/GUID 冲突失败。

- Mesh v2：`source:{kind:generated,geometry:{primitive:cube,size:[x,y,z]}}` 或 `plane/size:[x,z]`。尺寸为正的完整边长；cube 中心原点，plane 位于 XZ、正面 +Y；具名槽固定 surface。source 与 renderData 不得共存，未知细分等字段拒绝。A0 不生成顶点。
- Material v2：`preset:unlit`、`baseColor`、可选 `baseColorTexture`、`blend/cull/depth`，使用 U1 枚举；World3D 不接受 disabled depth。不透明模板 opaque/testAndWrite，透明模板 alphaBlend/testOnly。shader/pipeline 由 A1 派生。
- baseColorTexture：`texture:AssetRef`、`minFilter/magFilter:nearest|linear`、`wrapS/wrapT:repeat|clampToEdge|mirroredRepeat`。高层声明显式填参数；缺少整个纹理项表示纯色，已经声明但引用丢失失败。base color texture 固定 sRGB、alpha 线性；A1 负责实际采样传输。
- AssetRef 原键 **`id/type/guid/sub_asset`** 保持；不引入 path-only 引用或 `subAsset` 新拼法。类型/id/guid/sub-asset 解析复用 RuntimeAssetIndex + RenderAssetReference；临时 source 视图只是现有索引的检查输入，不是另一套数据库。
- renderer 使用的具名槽必须与 Mesh source/renderData/已提交 import 映射完全对应；漏槽、多槽、大小写拼错均失败。A0 检查可解析身份，不宣称纹理已解码、资产已 Cook 或 GPU Ready。

## 4. 导入设置、预算与长期映射

`model-import.v1` 字段为共同资产元数据、`source`（项目内 gltf/glb 相对路径）、`scene:u32`、`coordinates:{upAxis:y|z,handedness:right|left,metersPerUnit}`、`materialStrategy`、`budgets`、`outputs`、`nodes`。选定 scene 是导入范围，未消费内容不等于支持。

省略 materialStrategy 使用 `strictUnlit`；只有显式 `baseColorOnly` 才允许已列明的外观降级。省略 budgets 使用下表，配置只可收紧，0或扩大 profile 失败；部分预算对象漏字段也失败。

| 字段 | v1 上限 | 执行检查阶段 |
| --- | --- | --- |
| sourceBytes | 268,435,456 | A0 检查主源是否已经超限；A2 检查全部依赖闭包 |
| imagePixels | 16,777,216 | A2，单图解码前 |
| decodedImageBytes | 268,435,456 | A2，总图像预算 |
| vertices / indices | 2,000,000 / 6,000,000 | A2，分配前溢出和数量检查 |
| nodes / depth | 10,000 / 128 | A2，节点遍历前/中 |
| cookedBytes | 536,870,912 | A2，派生分配和发布前 |

`outputs[]` 每项含稳定 `key/assetId/assetGuid`、`kind:mesh|material|texture|prefab`、`sourceLocator/sourceFingerprint`，Mesh 可声明 `materialSlots:[{key,name,sourceLocator}]`。`nodes[]` 含稳定 `key/entityId` 与 locator/fingerprint。fingerprint 为 sha256 摘要。稳定 key/GUID 是 source 真相；locator/index/name/fingerprint 只辅助匹配，不能独自决定长期 identity。check/build 只读这些映射，首次生成与重映射由 A2 在既有 mutation 事务中明确提交。

CanonicalSourceInventory 已覆盖 glTF/GLB、bin、图像及描述文件，并拒绝源根之外/reparse 路径；A0 已用真实 snapshot 检验 gltf/bin 无需新增 inventory owner。A2 的 URI 解码、安全相对引用、预算和取消仍需单独验证，不能因文件已进入 inventory 就视为导入成功。

## 7. A2.3 实际消费补充（2026-09-23）

- `model-import.v1` 的 key/GUID/entityId/materialSlots 数据合同保持不变。`engine_project_inspect` 可选 `modelImport:{descriptorPath,maxEntries}` 返回 `model-import-inspection.v1`，提供 revision、源对象及 fingerprint、匹配候选/歧义、持久身份/cooked 路径、结构化引用与源实例位置。`maxEntries` 默认 256、上限 4096，结果明确标 truncated。候选不分配或继承长期身份；相关材质映射变化也触发槽复核提示。

- 覆盖以持久 entityId 和具名材质槽定位，支持 MeshRenderer3D 的 `materials.<完整槽名>`、Transform3D 的 translation/rotation/scale、Visibility3D.visible、已有 project.* 点路径字段。缺失目标/槽、重复覆盖、错误引用、ID 碰撞均失败；两个实例不修改共享派生 Prefab。根位置不能另用 override 定义；嵌套空间实例与混合域 Prefab 源实例明确拒绝。公开 source canonicalize 拒绝未展开的实例，真实 Compiler 的同一 neutral assembler 展开后才生成 RuntimeScene v2。

- Compiler `prepare_cancellable` 在操作开始、模型/primitive/image 和返回 prepared 包前安全点响应；RuntimePackageBuilder `build_cancellable` 在 staging 完成/校验后、rename 临界区前响应，替换临界区由原 atomic owner 完成或回滚。九工具尚不声明异步取消，新增源码接口不等于安装能力更新。

## A3.2观察合同收口（2026-09-23）

A0冻结的future_api.rs仍保留原字节和预留fixture身份；以下是A3.2正式consumer的组织方式，不把A0当时的fixture声明为已部署接口。

- 情景仍用playtest-scenario.v1/v2，新增可选domain请求`spatialObservation:{schemaVersion:"spatial-observation-request.v1",level,entities}`。无显式请求时只对引擎断言选择的实体采样Summary；无引擎断言则保持Off。
- 断言使用保留路径`engine.spatial/<entityId>/<field>`，`engine.*`不得由ProjectObservationContract声明。字段为number类型x/y/z、bool类型visible/mainCamera/inView/resourceReady，以及string类型`material/<slot>`；具名槽不固定为样例的surface。未知字段或类型错误拒绝。
- `spatial-observation.v1`由World/Projection/Prepare派生；local/world、runtime index/generation、authored/inherited visibility、mesh、材质、真实bounds、culling和cooked资源来源在entities中。相机pose/projection、view/version/viewport和suspended在同一快照。
- A0的revision/deliveryDigest/runRef/operationId沿用既有Provider/Compiler外层，不在每个实体复制。tick分别由SemanticPlaytestReport.simulationTicks与captureEvidence.simulationTick携带；frameSequence落为spatial.committedFrame；mainCamera/viewVersion分别落为view.sourceCameraEntityId/view.version。resourceState保留prepared/deferred/failed区分。
- World未投影或Projection不同步时matchesProjection=false，不能产生成功引擎断言。报告显式记录submittedFrame/presentedFrame；捕获验证实际RHI帧号和view/version/矩阵/viewport，并将快照frameStage标记captured。提交/呈现/捕获不会由项目自报或headless占位生成。
- Summary最多64个显式选中实体、16条诊断；Trace最多4096个实体/每帧4096子网格细项，超限truncated或请求拒绝。Trace只展开请求对象；正常Runtime不生成详情闭包/JSON，报告只保留末帧及有上限的捕获点。
- inspect/check通过authoring owner提供`spatial-project-inspection.v1`支持矩阵、mainCamera、实体/Prefab及稳定资产槽引用；校验首因仍来自原三维合同、模型导入和Compiler。Provider只转发，不另建解析器。
