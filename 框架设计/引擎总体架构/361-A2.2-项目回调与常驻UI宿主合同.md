# 361 A2.2：项目回调与常驻UI宿主合同

日期：2026-09-25。范围：SDK/生成Glue/原生模块宿主与会话属性owner。接续[A2.1传输合同](361-A2.1-有界属性传输与Glue安全合同.md)，不包含增量排版、窗口呈现和性能交付。执行结果见[本段记录](施工文档/证据/361/A2.2-执行记录.md)。

## 项目使用方式

普通ProjectGameSDK的生命周期、AUI动作和fixed-update回调可执行：

```rust
let ui = ctx.ui()?;
let title = ui.text("settings", "label")?;
title.set_text(ui, "骑兵")?;
let start = ui.button("settings", "button")?;
start.set_interactable(ui, false)?;
```

项目返回Applied，Glue自动结束本段暂存并调用host stage，不要求项目提交batch、维护revision、生成snapshot或手工dirty。UiTextRef/UiButtonRef可保存在会话中，访问时校验实例身份与generation；借用的UiContext不能逃出回调。`UiError`可通过`?`转换到GameError。`GameCallContext::new`保持兼容，默认无UI；规则、observe及绑定producer没有UI写权限，ui()返回Unavailable。

这里实现按document/node解析typed ref；编译生成整组命名View字段尚未实现，留A2.3。Text/Button不代表圆形进度、自定义测量/绘制已完成。

## ABI与有界调用

HostApi新增ui_query、ui_stage两个原有HostCall形状的函数指针，ABI minor由2升到3，主版本1不变；ABI/SDK摘要一起变化。旧minor/摘要与短host表拒绝，不读取不存在的尾字段。新的`copy_validated_host_api`先读取size前缀，检查后复制函数表，Glue不保存宿主表裸引用。

| 调用 | 输入 | 输出与约束 |
| --- | --- | --- |
| ui_query | Resolve(document,node)、NodeType(handle)、Read(handle,property) | Result(Handle/NodeType/Value,UiError)，请求≤16KiB；只读结果可重试一次，客户端拒绝超过4MiB的所需容量 |
| ui_stage | A2.1的version=1属性批次 | Result(unit,UiError)，先保证4096字节回复缓冲，再执行stage；SDK不重试stateful请求 |

stage载荷≤4MiB、≤4096属性、≤256KiB原始UTF-8文本。与原有256KiB项目回调结果是不同通道，不能把两者误认为同一容量。读取过大源文本返回容量错误；模块不接受无限resize。错误仍走紧凑UiError，宿主回调token仅在当前调用栈有效。每个回调最多接受一次stage，第二次拒绝并清除前一次pending，不能用分批绕过总容量。

空变更跳过host stage；重复setter按handle/property合并，首次节点类型查询缓存。同值仍可进入wire并由实例层消除，不宣称所有setter零跨DLL访问或零分配。

## 会话所有权与提交顺序

Bootstrap从RuntimePackage.aui_documents挂载AuiSession，每会话独立实例；不扫描项目源目录。挂载只在初始化时读取/复制源资产，不按帧全量复制。文档ID映射到实例ID，handle查找实例和slot。销毁会话丢弃实例及pending；重新挂载产生新的实例身份，旧引用不可复用。

流程：

1. lifecycle/AUI/fixed回调开始时清空上一段pending。
2. 模块通过有界查询读取必要值，setter暂存在模块侧；Glue只为Applied且无拒绝动作的输出发送stage。
3. 宿主按实例分组，利用现有AuiEdit验证全部相关文档，验证阶段不提交任何实例。
4. 回调结果成功解码/转换后，既有session executor处理玩法命令。
5. 仅Applied、非terminal、零拒绝命令、零拒绝动作时，executor调用finish_ui_updates(true)。其它结果、回调panic均调用false或提前丢弃。

多文档批次全部验证后才提交；AuiSession不暴露实例可变访问，stage到finish之间身份、绑定owner、节点类型与属性容量不变，因此重放已验证稀疏写集合不会出现晚到校验失败。新增内部mutation入口必须保持这个前提，不能直接暴露可变实例后仍沿用此证明。

UI失败不会回滚项目已经修改的Rust会话状态，也不把已发生的玩法命令升级为全局事务。原生callback失败沿用既有terminal-fault策略；错误不能留下已提交的一半UI。直接调用session方法的host消费者也必须遵循finish接受边界，不能仅看到Applied就认为属性已生效。

真实DLL负例发现并修复了既有Glue的共享锁poison：项目回调panic现在在sessions锁仍存活时捕获，只将对应StoredSession标记faulted，外层FFI边界继续保护其它异常。出错会话不再分发业务回调；销毁仍可进行，新会话和已存在的其它会话保持可用。没有用忽略PoisonError继续访问未知状态的方式掩盖故障。

只读retained_ui访问为后续布局consumer保留同一实例owner；本轮Player/Renderer仍未消费这些新属性，不能用本段测试宣称拖拽、动画帧率已改善。安装仍为360，新的host和module需要匹配重建，不能只替换其中一个。
