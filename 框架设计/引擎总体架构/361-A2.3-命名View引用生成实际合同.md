# 361 A2.3 命名View引用生成实际合同

日期：2026-09-25。依据361 R2第5节；承接A2.2的SDK/Glue/常驻实例链，运行时和ABI无需新增协议。验收结果见[执行记录](施工文档/证据/361/A2.3-执行记录.md)。

## 项目输入与用法

普通项目可选添加`RuntimeModule/ui.views.json`，不填写时保持原有按document/node解析方式。声明使用严格JSON，未知字段拒绝，不从Rust源码猜测需要哪些控件：

```json
{
  "views": [{
    "name": "SettingsViewRefs",
    "document": "settings",
    "fields": [
      {"name": "title", "node": "label", "kind": "Text"},
      {"name": "start", "node": "button", "kind": "Button"}
    ]
  }]
}
```

`document`/`node`引用AUI源资产的稳定ID，不是文件路径。`name`是公开Rust类型/字段名称；允许ASCII字母、下划线及非首位数字，拒绝关键字、单独下划线、重复名称，不静默重命名。节点ID仍可使用中文等字符串。`kind`只有`Node`、`Text`、`Button`：Node接受所有节点类别，仅暴露通用属性；Text/Button必须精确匹配。不暗示其它控件typed专有属性已经实现。

```rust
mod views {
    include!(concat!(env!("CARGO_MANIFEST_DIR"), "/../RuntimeGlue/ui_views.rs"));
}

// 在UI挂载后的可写回调中解析一次，保存在该会话的Controller/Session。
let ui = ctx.ui()?;
let view = views::SettingsViewRefs::resolve(ui)?;
view.title.set_text(ui, "骑兵")?;
view.start.set_interactable(ui, false)?;
```

生成结构只有typed handles，支持Copy；不克隆View树、属性快照或玩法状态。resolve经过A2.2的host查询和节点类型验证，整组成功才返回。之后直接使用缓存字段；跨实例/卸载旧句柄仍由A1/A2.2合同拒绝。不能把引用跨会话复用；模板多实例、结构变更与生命周期便利接口仍属于C。

## 编译与诊断

owner是`project_authoring_execution::generated_runtime_glue::ui_views`。所有输入来自同一不可变CompilerSourceView，AUI复用neutral_assembler的既有cook转换，支持扁平AUI及既有legacy树；运行时不读源目录。

构建/检查在调用Cargo前验证缺失document/node、节点类型错误、重复document/node及非法名称。错误带源文件和JSON字段路径；报告source_map分别记录生成字段到声明、到AUI节点的映射。扁平文档用`/nodes/index`，legacy用稳定`nodeId:ID`。引用错误定位到声明，并在消息中保留AUI源文件。

生成文件是`RuntimeGlue/ui_views.rs`，通过已有PreparedRuntimeGlue::materialize写入Compiler持有的派生目录；不修改项目源，不新增crate依赖。check与Windows生产暂存均保持RuntimeGlue和RuntimeModule/RuntimeModuleBuild同级，故上述include可在现有两种manifest布局下解析。仅直接在未prepare的原始项目上执行cargo不能凭空得到该文件；应通过现有引擎check/build入口生成，不手工复制派生源码。本段不新增IDE生成命令，也不声明Android导出资格。

派生源码纳入既有generation_digest，引用变更使Glue缓存身份变化；即使声明删除，materialize也覆盖为空文件，不残留旧字段。新增/修改字段的Rust编译错误由现有Compiler check诊断路径处理，不另造UI编译器。
