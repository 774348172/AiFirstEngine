## 1. 确认的设计决定

1. View 定义外观和节点结构；Controller 处理界面交互；Model 保存玩法状态和规则。
2. 项目可以通过有类型的节点引用直接设置文字、位置、显隐、样式和控件值。简单界面不必额外编写三个空壳类。
3. 数据绑定是可选便利能力。普通控件使用者不必生成整份 UI 状态快照、手写 Delta、维护 UI revision 或手动标记 dirty；自定义控件作者可通过受控接口申请局部重绘或重新测量。
4. 引擎保存常驻节点树；setter 比较新旧值并自动登记必要更新，内部合并处理。
5. 布局、绘制、命中几何的一致性是引擎内部责任，不增加面向项目的“整帧 UI 快照层”。渲染线程需要的只读绘制数据也不等于整份 UI 状态镜像。
6. AI 友好保留在结构化源资产、稳定标识、生成式类型引用、局部修改、诊断和验证能力上，不通过每帧序列化大文档实现。
7. 公开开发体验以Unity UGUI的控件引用、事件、模板实例和生命周期为主要参照；运行内核以Unity UI Toolkit的常驻树、分类失效与绘制缓存为主要参照。Godot/Slate用于交叉验证，不同时引入四套公开对象模型。不承诺Unity源码或资产兼容，也不复制完整GameObject/MonoBehaviour体系。

## 2. 问题依据与改造边界

[塔防实测](../../samples/tower_defense_project/Projects/hezi_shoucheng/Evidence/fps-diagnosis.md)记录：Windows dev、180 帧、预热 60 帧、采样 120 帧。403 节点/757 绑定引用时 CPU 平均 125.93 ms，其中更新 112.79 ms；临时缓存 UI revision 后 CPU 为 98.11 ms；进一步停用玩法 tick 为 94.33 ms；恢复玩法并缩减至 117 节点/307 引用为 43.04 ms。原包 GPU 平均 0.257 ms。

这支持“UI 规模相关的 CPU 工作和全量更新是重点”，不支持把全部耗时归因于某一个函数，也不是与 Godot 的等条件速度比。dev 构建会放大成本，但不能解释为什么缓存命中后仍存在如此大的规模成本。

已定位的源码接缝（行号以调查时为准，函数语义用于后续定位）：

| 路径（相对 rust/crates） | 当前问题 | 新职责 |
| --- | --- | --- |
| engine_runtime/src/aui.rs | resolve_bindings、C2 layout、反馈处理存在全文档扫描/比较/克隆；反馈分支可在缓存命中后再次做主题、draw、composition、glyph 工作 | 实例状态、事件和局部失效协调 |
| engine_runtime/src/aui_theme.rs、aui_viewport.rs | 解析阶段复制/遍历文档 | 编译索引与明确依赖失效 |
| engine_runtime/src/aui_layout_runtime.rs | 验证、构树及结果复制重复进入运行路径 | 常驻布局对象与受影响布局根更新 |
| runtime_player_winit/src/lib.rs、editor_core/src/editor_gameview_play.rs | 分别维护呈现缓存，路径易分叉 | 消费同一 AUI 运行时实现 |
| engine_runtime/src/runtime_renderer.rs | ui_projection_ordered_batches 重建字形映射、解析颜色和生成裁剪顶点 | 消费增量更新后的绘制缓存 |

固定逻辑时钟也存在独立问题：每个呈现帧默认只推进一次 1/60 秒，低 FPS 会让游戏时间变慢。AUI 改造必须验收表现时钟与模拟时钟边界，不能靠 UI 提速掩盖该问题；通用 fixed-step 调度修复归属 Runtime 调度器。

## 3. 项目侧结构：View / Controller / Model

```text
UIBattle                         战场界面根节点/组合 View
├─ Battlefield                   自由定位容器
│  ├─ DeploymentGrid             布阵点排列
│  │  └─ DeploymentSlot          接收点击和拖放
│  ├─ UnitLayer                  自由定位，不受 Grid 逐帧排版
│  │  └─ UnitView                兵种文字、血条、选中状态
│  └─ EffectLayer                局部表现
├─ CardGrid                      字牌布局
│  └─ CardView                   字牌，支持点击/拖动
└─ Controls
   ├─ StartButton
   └─ PauseButton

BattleController → typed View references
BattleController → BattleModel / gameplay commands
BattleModel      → 不依赖 AUI
```

UIBattle 是界面根，不是按钮类型；Grid 负责子节点排列，不负责点击或合成规则。CardView 是组合控件，UnitView 是显示单位状态的视图。“骑”只是骑兵的呈现文字，骑兵属性和移动、战斗、合成规则仍属于 Model。

引擎负责按下/悬停/焦点/捕获/拖动预览；项目 Controller 将落点翻译为部署或合成命令，Model 判断“人+马”等合法性。失败时 Controller 显示原因并恢复字牌位置。Core 不出现塔防专用兵种和格子规则。

世界实体无需全部 UI 化：真正参与世界相机、空间遮挡的单位可以走 World/RenderProjection；屏幕字牌与 HUD 走 AUI。此处 UnitLayer 是文字塔防的项目选择。

## 4. 作者资产与运行实例

```text
AUI 源资产 + Theme + Template + 字体资源
    ↓ Project Compiler / 既有 Package Assembler
RuntimePackage：编译节点描述、依赖索引、样式、资源引用、源映射
    ↓ 加载并实例化一次
常驻 AUI 实例 ← Controller setters / 可选 Binding / 控件内部状态
    ↓ 自动局部更新
布局结果 + 命中结构 + UiProjection 绘制缓存
    ↓ 既有 Renderer UI Pass
屏幕
```

源资产保存初始属性、层级、布局、主题、绑定声明和稳定 ID，不保存游玩中不断变化的状态。运行时 setter 只改实例；保存/修改源资产是另一个明确的作者操作。

字符串路径解析、schema 校验、静态样式编译和绑定目标解析尽量在构建/加载时完成。Runtime 不扫描项目源目录；Editor Play 与 Player 使用相同运行产物与内核。

静态节点使用稳定 NodeId；重复模板以实例身份和稳定 item key 区分。句柄包含实例身份与 generation，移除、卸载、热重载后旧引用可诊断失效，禁止复用到新节点。

## 5. 项目接口与 ABI

以下是拟议接口语义示意，并非已有可编译 API：

```rust
view.gold_label.set_text(gold.to_string());
view.pause_button.set_interactable(can_pause);
view.card_preview.set_translation(pointer_in_overlay);
view.error_label.set_visibility(Hidden);
```

资产编译器生成 `BattleViewRefs` 等有类型引用；节点类型不匹配或必需 ID 缺失在构建/实例化阶段诊断。项目不必每帧查找字符串路径。简单事件可直接由项目回调处理，不强制引入通用 MVC 框架或全局消息总线。

直接 setter 是项目编程体验，不代表 Project Module DLL 能访问引擎内部对象。跨 ABI 遵循现有 `project_runtime_abi`：不传 Rust Vec/String/Arc 所有权、裸节点指针或 GPU 对象；使用版本化 POD、opaque handle、调用方拥有的字节缓冲及生成 Glue。

SDK 在回调内收集变更，按回调结束或明确 flush 边界批量交付；同一回调读回刚写属性必须可见。布局结果读取只保证最近一次已提交布局，不能悄悄触发全树同步排版。需要测量新布局的操作走明确受控提交边界。

非法句柄/类型、非法数值和缓冲超限必须有明确失败结果；一次提交先校验，再应用有效事务，禁止留下不可说明的半更新。实现前须冻结 wire schema、容量、错误码、模块/引擎版本协商及 Glue 同步用例。

### 5.1 Unity风格的日常操作合同

下表定义必须具备的语义，方法名为拟议名称；实际Rust借用方式和签名由SDK合同冻结，不能将示例宣称为现有接口。

| Unity习惯 | AUI合同 | 关键行为 |
| --- | --- | --- |
| Button/Text/Image字段引用 | 生成typed View refs，也支持按类型查询动态节点 | 静态引用生成一次；不要求逐帧字符串查找 |
| onClick.AddListener/RemoveListener | subscribe返回订阅token，可显式取消，并可归入生命周期scope | 同一token取消幂等；不因反复启用重复注册 |
| Instantiate UI Prefab | 从已打包Template Asset实例化，返回实例handle与实例内refs | 允许同一模板多个实例；局部ID互不冲突 |
| SetParent/SetSiblingIndex | 修改父节点、兄弟顺序 | 拒绝环及跨不兼容UI根；同步布局、绘制顺序与命中 |
| RectTransform | Rect布局、anchor、pivot、offset/size，以及post-layout transform | 锚点和坐标合同见5.2；不是单纯改字段名称 |
| LayoutGroup | Grid/Flex/Stack等父布局策略 | 同一轴只有一个布局owner |
| SetActive、interactable | 分别提供active、interactable、visibility | 停用、禁止交互和隐藏严格分开，见9.1 |
| Awake/OnEnable/OnDisable/OnDestroy | on_mount/on_enable/on_disable/on_dispose | 不要求每个控件实现空回调，不默认逐帧Update |
| SetValueWithoutNotify | set_value与set_value_without_notify | 同值均不通知；前者产生带来源的Changed，后者仅更新值及表现 |

Changed事件携带old/new与User/Programmatic/Binding来源。绑定回填默认使用无通知赋值，避免控件与数据相互回写；显式通知在当前回调返回后排队，不递归调用监听器。业务Submit/Click与Changed分开，赋值不能伪造一次用户点击。

事件监听顺序在同一阶段按注册顺序稳定。分发中的新增订阅从下一次事件起生效；取消立即阻止尚未执行的对应监听器。节点删除/停用请求在当前回调后提交，后续分发检查存活与active状态；路由路径在本次事件开始时确定，新父节点不接收该次事件。低层指针事件支持捕获/目标/冒泡及停止传播；Button的Click是一次确定的高层事件。

### 5.2 布局所有权与坐标

沿用356的LayoutSpec/ChildSlotSpec与统一测量内核；Unity风格Rect能力映射到该内核，不能增加第二套排版器。

- UI局部坐标以左上为原点，x向右、y向下，单位为逻辑UI单位；OS像素、DPI、viewport和画布缩放只由既有统一映射转换。
- 自由布局下，anchor_min/anchor_max为父内容矩形的归一化锚点；pivot为自身归一化轴心。尺寸为锚点跨度对应尺寸加size_delta；轴心位置为两锚点按pivot插值得到的位置加anchored_position，左上位置再减pivot乘自身尺寸。公开接口拒绝非有限数及负有效尺寸，不能生成失效命中几何。
- Grid/Flex等父容器控制的轴，其布局位置/尺寸为只读计算结果；项目改变ChildSlotSpec中的尺寸偏好/约束，不能靠setter与布局器每帧抢写。post-layout translation仍可设置，不改变父布局占位。
- reparent必须显式选KeepLocal或KeepScreen，不隐式猜测；KeepScreen在下一安全布局提交时转换。进入受控布局且无法保持屏幕位置时返回明确错误，项目可选自由定位拖动层。
- 提供screen_to_local/local_to_screen，考虑祖先transform与clip；不可逆变换返回错误。布局读取返回最近已提交几何及状态；普通事件不要求项目主动flush。

这保留Unity的锚点/轴心操作习惯，但坐标原点、布局所有权和层级变更语义由本合同明确，不宣称与RectTransform逐字段兼容。

### 5.3 三类扩展接口

扩展优先采用组合；只有已有节点不能表达时才使用自定义测量/绘制。运行时扩展通过Project Module与生成Glue接入，不要求项目修改Core或为每种控件新增Projection通道。

| 扩展层 | 项目能做什么 | 引擎负责什么 |
| --- | --- | --- |
| 组合View | 模板、命名子节点、插槽、typed属性与事件，例如CardView/HealthBar | 实例化、资源和引用校验、统一布局与生命周期 |
| 行为 | 持有局部状态，响应事件，可选定时/动画订阅 | 事件路由、取消、启停、捕获；无默认逐节点Update |
| 自定义测量/布局/绘制 | 实现固有尺寸、子项排列、圆弧/网格等局部图形 | 约束、调度、失效、clip、缓存、合批与后端提交 |

自定义类型以稳定type_id、schema版本、typed属性描述和所需回调注册；Package声明依赖，模块加载时校验，缺失/不兼容时诊断到源节点。属性描述声明影响Measure/Layout/Paint/Hit等类别；SDK生成setter负责同值检查和自动失效。项目私有算法状态无法由属性系统观察时，控件作者可以调用request_repaint/request_measure；重复请求合并，普通使用者不需要了解dirty位。

自定义测量输入为有限尺寸约束、布局相关属性及只读资源度量，返回尺寸/基线；相同输入必须有确定结果。自定义布局接收受影响容器的子项约束和测量访问接口，输出子矩形；两者均不能修改UI树或玩法状态。使用已有测量协议扩展，不暴露Taffy内部节点指针。内容依赖环按7.2的迭代上限诊断。

自定义绘制接收只读已提交布局、相关属性和受控PaintContext，输出局部坐标的图元/顶点索引、资源引用及绘制范围。初次创建或相关失效时调用；固定尺寸圆形进度值变化只重建该节点几何。纯transform变化复用局部几何。不得在绘制回调中改树、改变布局属性、推进玩法、主动提交GPU命令或嵌套触发绘制。

v1提供复用现有材质能力的局部网格、矩形/图片及既有文字路径；自定义圆弧由项目生成局部网格。自定义布局以径向布局样本验证。任意shader、外部GPU对象、运行时加载未打包插件不纳入本轮。

默认命中由布局矩形和clip决定；非矩形控件可选择引擎支持的局部命中形状。复杂自定义hit_test只在粗筛后调用，必须无副作用，并声明形状失效依赖，不能每帧遍历全部自定义控件。

### 5.4 跨DLL扩展与更新成本

项目保留自定义控件状态；引擎保留通用节点属性、布局与绘制缓存。跨DLL传递不携带Rust trait object或闭包：生成Glue以type/instance/callback ID分发，输入输出通过版本化POD和有界缓冲交换。调用上下文仅在回调期间有效；卸载模块前停止调度并清理所有回调、订阅和实例，禁止留存悬空函数地址。

自定义measure/paint只按失效调用；同阶段独立节点可按模块批量调用，有依赖的测量按实际依赖顺序执行。不得承诺任意复杂布局仅一次跨DLL调用。报告必须能区分事件、measure、paint、命令提交各类调用数和耗时。

setter本地暂存以“已触及的handle+property”作为稀疏写集合，禁止克隆整个View或snapshot。读操作优先读本回调写集合，再读取必要已提交属性；不隐式复制整树。同值写入在SDK已知值或引擎接收端消除，不要求为比较而逐setter同步往返DLL。

同一提交段内纯属性赋值可合并；可观察的Changed通知、创建/删除、reparent、生命周期和事件形成顺序屏障，不能跨屏障合并。事务验证覆盖所有关联操作，失败整段拒绝；SDK撤销该段暂存状态并报告失败，不能让读后值与引擎状态永久分叉。已经发生的玩法操作不由UI事务回滚，Controller不得把UI提交当成玩法事务。

## 6. 可选绑定与属性所有权

绑定用于金额、血量、列表等数据呈现；Controller setters 用于事件流程和直接控制。可以同界面混用，但同一属性只能有一个明确 owner。

- 默认由 Controller 管理的属性可直接设置。
- 绑定占用的属性，直接 setter 默认报所有权冲突；显式解绑/转移后才允许接管。
- 控件内部 pressed/hover 状态独立于项目属性，通过主题状态合成表现，不覆盖项目的基础值。
- 动画覆盖层必须声明属性、优先级和结束后的恢复策略，禁止隐式最后写入者获胜。

已有绑定读取 `ProjectUiStateSnapshot` 的纯数据边界保留，禁止绑定直接读 ECS 或执行玩法。已有 snapshot producer 是兼容/可选绑定源，不再是所有 UI 更新的强制入口。新绑定支持按字段通知和按需刷新；不要求项目每帧构造全量状态。公开 Delta 与 revision 不是使用 UI 的前置条件。

## 7. 常驻状态、失效传播与缓存

引擎将变化分类并自动合并，同值 setter 不产生工作。局部失效按真实依赖传播，不能承诺一切 O(1)。

| 变化 | 必须更新 | 通常应复用 |
| --- | --- | --- |
| 无变化 | 输入接收、必要呈现提交 | 样式、布局、字形、几何、节点索引 |
| 文本改变 | 该文本 shaping/测量/绘制；影响尺寸时传播布局 | 无关文本和子树 |
| 固定尺寸节点文字颜色 | 材质/顶点颜色等绘制数据 | 字形 shaping、布局 |
| post-layout translation | 世界变换、受影响裁剪/命中、渲染变换 | 原始测量与布局 |
| 宽高、字体大小、自动尺寸 | 节点及必要祖先/子节点的布局与绘制 | 无关布局根 |
| 新增/删除/重排子节点 | 受影响结构索引、布局、命中与绘制顺序 | 其它稳定子树 |
| 主题/DPI/字体资源改变 | 由依赖索引确定的受影响集合 | 与变化无关的资源和节点 |

布局位置与布局后的视觉变换分离。拖动和移动优先改 translation；Grid 内元素脱离排版拖动时使用拖动层预览，并保留来源占位。落下后一次更新真实布局或数据。

真实变换必须同步命中与裁剪；按钮装饰性的按下缩放可按控件合同保留稳定命中区域，避免边缘抖动。旋转、嵌套裁剪和复杂布局仍可能扩大更新范围。

文本缓存分层：字体资源、shaping、段落/换行、glyph atlas、绘制几何；缓存键包含真实字体身份、字号、语言/方向、宽度及相关样式。颜色变化不能清空字体缓存；字体替换不能继续误用旧 glyph。容量与淘汰规则须可测量，不能以无限缓存换性能。

UiProjection 必须贯通增量语义，复用节点绘制片段、字形索引与几何。清洁帧不能在后端再次全文扫描、解析颜色并重建顶点。绘制顺序、透明混合和裁剪限制批处理，不能为合批改变视觉结果。缓存 CPU 构建结果不意味着 GPU 不需要每帧绘制可见界面。

### 7.1 更新职责与隔离范围

| owner | 常驻内容 | 工作触发条件 |
| --- | --- | --- |
| UI实例 | generation、层级、属性、订阅索引 | setter、结构变化、事件/生命周期 |
| 样式解析 | 样式结果、继承/主题依赖索引 | 对应属性、状态或主题依赖变化 |
| 布局运行时 | 测量结果、子项排列、脏布局根 | 约束、文字度量、结构等尺寸依赖变化 |
| 输入运行时 | 命中索引、焦点、capture | 几何、顺序、visibility/active等变化 |
| 文本运行时 | shaping、段落、atlas等分层缓存 | 相应文字/字体/排版输入变化 |
| UiProjection/Renderer | 局部绘制片段、排序关联、GPU几何/变换缓存 | Paint、transform、clip、资源与结构变化 |

失效仅由一个协调器归并；Player/Editor不各自重做一套缓存规则。布局根由尺寸依赖决定：固定约束的独立子树可阻断向上尺寸传播，自动内容尺寸的父节点不能假装隔离。绘制缓存分区不等于布局根或离屏纹理；父transform/clip变化仍须更新受影响引用。保留全局透明顺序，结构变化可重排受影响绘制范围，不以每个UIBattle都拆成独立Render Pass实现隔离。

### 7.2 阶段顺序、合并与重入

1. 接收当前可用的项目变化、绑定通知及UI动画变化，记录脏集合。
2. 按时间顺序分发输入；事件前只补齐影响本次命中的待处理状态，事件回调后提交变更。下一个事件需要新几何时执行局部样式/布局/命中更新。
3. 输入处理后处理其余属性与样式，合并脏布局根，完成必要测量/排列；再更新transform/clip和命中索引。
4. 只为失效节点执行文字/自定义绘制与UiProjection更新，生成或更新对应GPU数据；每个呈现帧统一提交最终UI绘制。

去重队列使用节点身份与失效类别；祖先布局根覆盖后代时合并工作。事件间确有几何依赖时允许同帧多次局部布局，不能为了“每帧只一次”返回错误命中。纯paint工作尽量留到最终阶段。

普通事件回调可写属性；measure/layout/paint回调为只读输入和结果输出，UI写入请求立即拒绝并诊断，不能任意重入。几何变化通知在当前布局完成后排队，回调产生的新布局变化进入下一有界更新轮。

单根每轮帧内稳定化最多8轮；持续改变尺寸、非有限输出或非法子矩形视为控件错误。超限停止该根的更新循环，保留最近一次有效几何供绘制和命中共同使用；首次无有效结果时隔离该故障子树，记录节点及失效原因。不能进入死循环，也不能只更新绘制不更新命中。应用持续产生事件/变更时按时间顺序延期，不能合并丢失down/up。

绘制回调输出错误或超出容量时不安装半份几何；复用仍与当前布局/资源有效匹配的旧绘制片段，否则跳过故障节点绘制并诊断。UI线程不接受后台直接写节点；异步结果通过既有项目调度进入安全回调，再校验实例generation。

### 7.3 清洁帧成本和缓存预算

清洁帧允许输入索引查询、活跃动画/定时器工作和可见绘制提交，不允许为了检测变化而扫描全部节点/绑定/自定义状态。不做全树字符串解析、哈希、克隆或字节序列化。资源清理采用有界增量维护，不能每帧全缓存扫描。

稳定清洁帧AUI更新路径以零新增堆分配为目标；平台事件/驱动提交等成本分开记录。缓存池以高水位复用并有明确容量/淘汰策略。设备丢失、atlas迁移、字体/主题全局变化可能合法造成大量失效，必须记录原因；不能把每帧全局失效包装成缓存实现。

性能报告增加：各阶段visited_nodes、dirty_nodes、measure/shape/paint次数、跨DLL调用数、交换字节数、CPU分配次数/字节数、GPU上传字节数、命中索引更新量和缓存占用。计数在Summary/测量模式启用，详细原因仅Trace；统计本身不得让正式Off热路径产生字符串或文件写入。

## 8. 事件、拖放与帧内一致性

1. 保留时间有序的 down/move/up、键盘和文字输入事件；不能仅取最后状态而吞掉点击或拖放。
2. 命中并沿节点路径分发，支持停止传播；明确指针捕获、键盘焦点、模态遮挡。
3. 控件即时更新 pressed/hover/drag 等内部状态；业务意图交给项目回调，同一次操作业务动作至多触发一次。
4. 回调变更在安全边界提交；若影响下一个事件的命中，必须先更新相关几何。不能等整批输入结束后才更新所有命中。
5. 最终呈现消费该轮已提交状态，避免重复全树构建；线程间如需只读 draw 数据，由内部缓存/缓冲管理。

捕获源和 drop target 分离；拖动预览跟随鼠标且不参与 drop 命中。源节点删除、隐藏、卸载、窗口失焦和取消操作都要释放捕获并结束拖动。接受、拒绝和取消必须有可见反馈与确定状态。

输入框保留 selection、caret、composition 与系统 IME 接入；不能把提交文字和预编辑文字混为一体。系统候选窗的真实 OS 验收单独记录，不能用 headless 输入替代。

## 9. 生命周期、列表与时钟

实例创建后mount一次，active状态控制enable/disable，visibility控制显示，最终dispose一次；dispose取消订阅、定时回调、动画、焦点和捕获。隐藏不自动销毁，重新显示必须获得最新数据。精确语义见9.1。

Visible 正常布局绘制；Hidden 保留布局空间但不绘制/命中；Collapsed 不占布局、不绘制/命中。绑定订阅是否暂停由明确策略决定；恢复时必须补齐状态。隐藏子树不能每帧重复生成绘制结果。

长列表采用可见区加 overscan 的虚拟化和回收；稳定 item key 保证选择、焦点和数据身份，回收时必须解除旧绑定和事件。固定高度列表优先，变高列表需维护测量缓存及滚动锚点，不能套用固定高度假设。

UI 动画与拖动使用呈现时间/真实输入位置，不等待 fixed tick。游戏模拟使用独立固定步累计器、最大补步上限和明确过载策略；暂停界面仍可响应。单位表现允许在相邻模拟状态间插值，不能由 UI 擅自推进玩法时间。

### 9.1 启停、显隐与订阅

| 状态 | 布局/绘制/命中 | 项目行为 |
| --- | --- | --- |
| active=false（含祖先停用） | 不参与布局、绘制、命中，保留实例 | on_disable一次，暂停该实例UI调度和active-scope订阅 |
| active=true + Hidden | 保留布局，无绘制和命中 | 行为与订阅保持；需要停用必须显式改active |
| active=true + Collapsed | 不占布局，无绘制和命中 | 行为与订阅保持 |
| interactable=false | 保留布局、绘制与禁用样式；不接受激活、拖动和键盘输入 | 普通项目数据更新继续；低层遮挡由hit_test_enabled决定 |
| hit_test_enabled=false | 不作为指针目标，不改变绘制 | 子节点是否命中按各自状态；父clip和模态规则仍适用 |
| dispose | 从所有索引移除并释放资源引用 | 先disable（若需要），再dispose一次；句柄generation失效 |

active有效值为自身与祖先active共同决定；重新启用先补齐当前绑定数据，再发on_enable，首次交互前准备有效布局。instance-scope订阅保留至dispose，active-scope订阅自动暂停/恢复，不重复注册；外部数据回调不应强持有已dispose实例。

UI tick/定时更新为显式按需订阅，只调度活跃任务；所有控件默认没有逐帧回调。隐藏/失去交互资格/停用/销毁时清理已有capture和焦点，禁用时必要的遮挡与悬停提示由控件策略声明。模态遮挡不依赖背景是否有Click监听器。

## 10. AI 友好能力保留

- schema-first AUI 源资产、主题和模板，稳定 ID 与局部 patch。
- 自动生成 typed View 引用与 ABI Glue；生成产物不作为手写真相。
- 编译错误回指源文件、节点和属性；运行错误提供实例/句柄与修复建议。
- 可查询节点树、属性 owner、布局/命中区域和局部失效原因。
- Off / Summary / Trace 分档；正式运行默认 Off 或功能必需紧凑结果，不能常驻构造 JSON 和大段 trace。
- 复用九项独立工具、普通 Rust 项目代码、RuntimePackage 与现有验证入口，不新增强制编辑器或 UI 专用任务编排层。

## 12. 迁移与交付顺序

建议依赖顺序（不是已激活施工 Gate）：

1. 冻结实例/句柄、Unity风格操作、事件/生命周期、自定义扩展和ABI合同；用设置面板与圆形进度控件贯通生成引用、注册和安全调用。
2. 建立常驻树和样式/布局/文本/绘制/命中增量链；同时覆盖 Renderer 消费，禁止只优化前半段。
3. 接入控件状态、拖放、焦点、列表与可选绑定；完成自定义布局/绘制扩展和三组接口样本，Player/Editor共用运行实现。
4. 迁移塔防 UIBattle，完成真实窗口、性能和独立交付回归。

旧资产通过加载/编译适配到同一新运行实例，旧 snapshot 输入只作为兼容适配器。迁移期允许显式版本开关与回退包，但不得长期维护两套 UI 引擎。资产 schema 与 module ABI 各自版本化；不兼容时构建/加载明确拒绝，不能静默误读。每次交付保留旧包以便回退，不覆盖用户唯一可运行版本。

## 13. 验收要求与性能目标

以下是拟议交付标准，不是已测成绩。施工前固定硬件、分辨率、包身份、构建 profile、场景、输入时间线、预热/采样数量；dev 与 release 分开报告。建议性能主样本预热 120 帧、采样至少 600 帧，并保存 P50/P95/P99、最大帧、CPU/GPU/Present 分段及内存。

| 场景 | 正确性与工作量证据 |
| --- | --- |
| 清洁帧、同值 setter | 无全树 clone/重建；layout、shaping、geometry rebuild 为零，允许必要输入/提交 |
| 单标签、按钮反馈 | 更新受影响属性/节点；无关布局与文字复用 |
| 字牌拖动、移动单位 | 实际位置随输入变化；drop 命中同步；非必要布局与 shaping 为零 |
| 文字撑大、DPI/主题变化 | 必要依赖正确失效，允许有依据的扩大更新 |
| 大列表、隐藏树 | 工作量随可见内容/实际变化变化；回收不串数据，缓存内存有界 |
| down/move/up 同帧、失焦/移除 | 不丢事件、不重复动作、不遗留 capture |
| 多次开关界面 | 无失效句柄误命中，无订阅/缓存持续增长 |
| 塔防完整界面 | 保留实际 UI 和玩法，部署、合成、取消、暂停与三关流程回归 |

性能拟定目标：在冻结的 Windows release 基准机器、1280×720、约 400 节点塔防界面下，AUI CPU P95 ≤ 2 ms，完整帧 CPU P95 ≤ 16.67 ms；GPU 与呈现间隔另报，不能用 CPU 倒数声称显示 FPS。10k 节点是规模测试，不能套用 400 节点预算，也不能把 50 ms clean 当成 60 FPS 合格。

若未达目标，必须报告阶段归因和未达项，不以删掉大量真实 UI、关闭玩法或只跑 release 微基准替代交付。真实窗口必须能观察到连续拖动、即时按下反馈、兵种移动、合法合成与失败反馈；截图只能证明单帧，连续过程需输入/帧时间记录与窗口观察共同证明。

### 13.1 R2必须增加的验收

三组样本均使用普通项目SDK和真实Project Module/Engine DLL链，不允许测试专用入口绕开ABI。

| 样本 | 接口验收 | 效率/错误验收 |
| --- | --- | --- |
| 设置面板 | Button/Text/Slider引用、事件订阅/取消、值通知与无通知赋值、启停 | 反复启用不重复监听，绑定回填无循环，同值赋值无失效 |
| 塔防拖放与合成 | 模板多实例、坐标转换、捕获、父子顺序、落点与取消 | 拖动不重排无关Grid；同帧down/move/up、失焦、节点删除无悬空状态 |
| 扩展与规模样本 | 项目实现圆形进度、径向布局，以及10k数据项虚拟列表；不改Core | 自定义绘制仅按需调用；错误measure/paint被隔离；列表回收不串身份 |

还须验证锚点伸缩、轴心、DPI与嵌套变换；KeepScreen受控布局拒绝；inactive/Hidden/Collapsed/interactable/hit_test_enabled各自行为；dispose后旧句柄与卸载后的旧回调明确拒绝。两个模板实例及两种自定义类型同时运行，证明接口不是单例特例。

规模测量分别采用400/1k/10k总节点的静态树，以及10k逻辑数据项的虚拟列表，不能混淆总数据项与实例节点。对照清洁帧、单节点更新、10%节点更新、整体主题/DPI变化四类负载；固定其它条件检验成本来自实际依赖与可见提交，而非无条件扫描。用两个独立固定布局子树验证一侧变化不触发另一侧measure/paint；祖先自动尺寸变化另设正例验证应有的传播。

ABI负例覆盖缓冲不足、过期generation、属性owner冲突、非法结构事务与回调重入；拒绝后SDK读值、引擎属性、几何/命中必须保持一致。内存测试反复开关、实例化/销毁和滚动，报告稳定后的高水位与缓存回收，不以单次截图证明无泄漏。

2ms目标沿用第13节，不扩大成Unity性能等价结论。缓存容量和交换缓冲硬上限、具体平台分配豁免、各规模预算与测量机器身份必须在施工首阶段冻结；未冻结或未验收不得宣称效率完成。

## 14. 自审结论

本设计遵循用户确认的表现/逻辑分离与直接控件操作；取消强制项目快照层，并保留可选绑定的纯数据边界。通过顶层架构同步明确新方向，历史实施结果不被重写。设计本身不代表性能已达标或完整对标成熟引擎；施工状态见49/54。

尚需在施工合同冻结时确定实际 API 命名、ABI 字段/容量、缓存上限和基准机器身份；这些是实现细节，不改变本文已确认的编程模型。文档完成后仍需单独生成并激活施工文档才能开始引擎施工。

R2已吸收本次审核的五项缺口：扩展接口（5.3/5.4）、普通使用与控件作者的失效职责（1/5.3）、Unity行为合同（5.1/5.2/9.1）、调度/隔离/成本（7.1–7.3）、接口与性能联合验收（13.1）。成熟引擎对应源码见配套对比第6节。模块设计原则落实为小型项目接口隐藏内部更新复杂度，同时为确有变化的布局和绘制提供受控扩展位置；不新增通用插件总线或强制MVC框架。
