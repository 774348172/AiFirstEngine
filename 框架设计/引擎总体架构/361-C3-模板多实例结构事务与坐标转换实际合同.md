# 361 C3：模板多实例、结构事务与坐标转换实际合同

日期：2026-09-27。范围：Project Runtime ABI/SDK、Generated Glue、AUI常驻实例/会话、原生模块适配器及直接Editor/Player consumer。接续[361总施工文档](施工文档/当前/361-AUI-R2-总施工文档.md)的Gate C，不代表自定义measure/layout/paint、绑定ownership或整个Gate C完成。执行证据见[C3记录](施工文档/证据/361/C3-执行记录.md)。

## 1. ABI、wire与SDK合同

Project Runtime ABI由1.4升级为1.5。Host函数表增加独立`ui_structure`入口；属性继续使用`aui-update.v3`，有序结构操作使用`aui-structure.v1`，不把结构屏障塞进属性合并表。结构批次最多256项、wire最多1 MiB，短Host表、旧1.4模块、超限请求、短输出缓冲、未知字段或无效版本均失败关闭。SDK digest包含结构schema，所有生成Glue Host表构造点同步1.5。

`UiWriteBuffer`在结构操作前flush已有属性段，执行结构事务后清空类型缓存，并允许立即使用返回的新handle继续写属性。`instantiate`返回稳定template instance ID、root handle及模板局部ID到handle的引用表；`delete`、`reparent`和`set_sibling_index`均为typed SDK操作。结构调用有副作用且不会因输出缓冲不足而自动重试。

## 2. 模板实例与句柄生命周期

同一已打包AUI模板可同时实例化多次。每个模板实例拥有独立template instance ID和局部ID引用空间，不会与其它实例串用。动态节点使用slot+generation；删除后旧handle永久失效，slot复用必须分配新的全局generation。Canvas root不能删除或reparent。

删除子树先按有效active状态排队Disable，再排队Dispose；生命周期通知耗尽后才释放目标订阅。reparent和结构发布会重算active继承、兄弟顺序及布局/绘制/命中所消费的树结构。

## 3. 回调级结构事务

结构操作进入`AuiSession`当前项目回调的结构草稿。后续query、属性stage和订阅都访问同一草稿；项目回调Accepted后，草稿整体替换正式实例并通过既有AUI document/layout solver重建受影响实例。Rejected、panic、超限或任一结构操作失败都会丢弃该回调中的结构、属性和订阅变化，不发布半棵树，也不引入第二套布局器。

原生Host路径已经覆盖`属性flush -> Instantiate -> 新节点写入 -> Accepted一次发布`。`host_ui_structure`先检查调用期context和输出容量下限，再执行有副作用的结构事务；非法或超限请求会poison当前AUI回调事务。

## 4. reparent、顺序与坐标语义

reparent只允许同一AUI instance、同一canvas root，拒绝自身/后代环、跨实例和不兼容根。`KeepLocal`保留节点局部布局数据与translation；`KeepScreen`记录提交前screen原点，在下一次既有layout提交后以post-layout translation保持屏幕位置。新父节点由Row、Column、Flex、Grid或Overlay控制布局时，`KeepScreen`明确返回`ControlledLayout`，不会伪造不可满足的坐标承诺。

`local_to_screen`与`screen_to_local`扩展既有只读`ui_query`，基于最近提交geometry和祖先translation进行可逆转换；它们不隐式flush、不触发布局。无已提交layout、非有限坐标或过期handle均明确失败。

## 5. 明确未完成

C3不实现自定义measure/layout/paint、绑定ownership、圆形/径向控件、塔防项目迁移、真实窗口、GPU、安装或FPS资格。Gate C尚未关闭；下一整块按完整361方案进入自定义measure/layout/paint扩展，不进入Gate D/E。
