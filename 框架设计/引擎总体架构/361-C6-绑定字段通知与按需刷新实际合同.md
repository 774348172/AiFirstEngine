# 361 C6：绑定字段通知与按需刷新实际合同

日期：2026-09-28。范围：Project Game SDK 的 session-local 绑定状态辅助类型及 Generated Runtime Glue 的真实项目消费。接续[361 总施工文档](施工文档/当前/361-AUI-R2-总施工文档.md) Gate C；执行证据见[C6 记录](施工文档/证据/361/C6-执行记录.md)。本合同不代表项目迁移、真实窗口、性能或 Gate D/E 已完成。

## 1. API 与边界

Project Game SDK 新增并公开 `UiBindingStore` 与 owned `UiBindingRefreshPlan`。普通项目在 session 中持有一个 store：玩法或 Controller 在来源变化处调用 `notify(path)` / `notify_all()`；`resolve_ui_state` 先调用 `prepare_resolve(request)`，只计算 `refresh_paths()` 列出的字段，再把结果交给 `finish_resolve(plan, refreshed)`。

两阶段 API 让项目在 plan 不借用 store 时读取同一 session 的其它玩法字段，不要求额外 snapshot owner、全局 registry 或内部 ECS 访问。`UiBindingStore` 已加入 SDK 符号目录；项目不再手写 active path cache、binding digest、visible revision 或 `Reuse`/`Replace` identity 比较。

Project Runtime ABI 函数表保持 1.6，继续复用既有 `resolve_ui_state`、`ProjectRuntimeUiStateIdentity` 与完整 `Reuse`/`Replace` wire；不增加 Delta variant、Host 回调、每字段 ABI 调用或 RuntimePackage digest 变更。

## 2. 按需刷新语义

首次 `Replace` binding set 或 binding set digest 变化时，plan 列出新 active 字段全集。注册后的 `Known` clean resolve 不携带 replacement paths并返回空 refresh 集；项目不读取字段，SDK 不复制 active paths/set/values、不提交 store 或推进 generation，caller identity 一致时直接输出 `Reuse`。

active 字段通知按 path 合并，同一字段重复通知只产生一次工作；inactive 字段通知返回 `false` 且不保存脏状态，因为它以后被激活时必定走全集刷新。`notify_all` 只在已有 active set 且尚未 force refresh 时推进一次 generation，并用返回值说明是否实际登记工作。

`finish_resolve` 对全部预期字段做原子校验和比较。刷新值相同会清 dirty 但不推进 visible revision；新增、修改或删除任一可见值时，每次 resolve 最多推进一次 revision，并按既有协议输出完整 active values 的 `Replace`。binding set 改变即使值相同也以新 digest 保守 `Replace`。

## 3. 容量与失败关闭

单 store 最多 4096 个 active path，每个 path 的 UTF-8 长度最多 512 字节。producer ID、digest 和 path 必须非空且首尾无空白；`Replace` paths 必须严格升序且唯一。unknown `Known` digest、同 digest 不同 paths、caller identity 超前、缺失/多余/重复 refresh 结果及 stale plan 均明确失败。

所有 refresh 结果验证完成后才替换 values、active registry、identity 和 dirty 状态。失败不清 dirty、不推进 visible revision、不安装半份 cache。store generation 与 visible revision 使用 checked increment；包括 generation 溢出的 `notify` / `notify_all` 也在写 dirty/force 标记前失败，保持原状态。

## 4. 真实 Glue 消费

Generated Glue 编译烟测中的普通项目 session 真实持有 `hp` 与 `UiBindingStore`，注册 `.ui_state(ui_state)`，并只对 plan 请求的 `fixture.hp` 生成值。Smoke 通过生成的 ABI 函数指针验证：首次 active set 得到 revision 1 / hp 3 的 `Replace`；clean `Known` 得到相同 identity 的 `Reuse`；lifecycle 把 hp 改为 2 并通知字段后得到 revision 2 / hp 2 的 `Replace`。

engine native adapter 的 `ProjectUiStateSnapshotCache` roundtrip 和 Player `AuiPresentCache` 直接 consumer 保持既有 identity、last-valid、ownership、virtual list 与 clean-cache 行为。C6 没有修改这些 consumer，只用定向回归证明共享合同未退化。

## 5. 明确未完成

C6 不迁移塔防或其它样例，不运行真实窗口、GPU、安装、FPS 或 Gate D/E，也不实现复杂 custom hit、pressed/hover/drag 主题内部状态、动画属性覆盖层或显式 UI tick/定时订阅。Gate C 尚未关闭；下一整块先冻结 C7 指针捕获/取消与控件内部交互反馈的最小因果范围。
