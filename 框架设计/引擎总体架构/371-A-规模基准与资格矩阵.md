### 3.1 S0 渲染选型探针

先固定同设备/API、分辨率、几何/光源分布、透明比例、预热条件和输入摘要，覆盖简单forward与Clustered Forward+的光源遍历/分桶、透明过绘制、深度方向和阴影资源带宽风险；deferred可用同设备可复现实测参考及成本分析，不要求实现第三套完整管线。允许既有真实wgpu最小场景加局部技术原型，或可复现实测参考；必须标明哪些数据来自本引擎、参考实现、估算及其缺项，不用跨机器FPS直接排序。

报告CPU组织/上传、GPU时间、内存/带宽、所需features与fallback、最坏输入和选择理由。探针不需S2完整PBR/阴影/IBL，不计BM-04通过。S0开工时设定可完成的探针投入上限；超过上限或关键证据缺失时停止该选型分支、保存未决原因，不能为“选型”偷偷完成多套renderer。S2以真实Compiler/Package/生产consumer重验，结论推翻时先回填设计。

### 4.1 几何、材质与真实可见

BM-02/03 K0 将 10,000 个物体放成 100×100、间距2 m 的朝向相机网格，物体投影不得相互遮挡；使用正交视图覆盖220×220 m，维持每对象最小约4×4像素。Android使用50×40网格，同最小覆盖。K0专门证明真实可见数量；K1另用三维层次布局验证透视/裁剪，二者不互相替代。

每 mesh 用相同拓扑复杂度、不同稳定顶点扰动生成；BM-03 禁止内部把独特 mesh 偷换成共享资源。报告导入和消费后的实际 vertex/triangle 数，不用声明字段代替。静态UV包含接缝，正常/镜像/非均匀缩放依合同分合法与拒绝用例。

最终目标一套纹理定义为 baseColor、normal、ORM 三张；PC 2048²、Android 1024²，完整mip；foundation-v1只消费4.0规定的baseColor基础层，不能宣称完整纹理链。格式在S0按backend冻结并记录实际bytes。BM-04另有一个1024²环境cubemap及其派生IBL；Android512²。纹理内容不能全部常量色被编译器折叠；GPU压缩前后bytes分别保存。

BM-04 PC directional总预算为4096² atlas、spot总预算4096²；Android各2048²。主相机固定质量抗锯齿、tone mapping、IBL/雾；S0/S2冻结具体算法/参数与图访问合同。点光首档不投影，不能在结果中写成144盏投影光源。

多视图子档增加一个960×540 PC视图或640×360 Android视图，具有不同camera/layer和render target；单独报告额外CPU/GPU成本、复用和最后使用点。多视图无需沿用单视图60/30 Hz预算，但S0必须冻结明确附加预算，不能无预算记性能合格。

### 4.2 脏比例、动画和模拟

BM-01/02/03的0/1/10/100%变换脏子档使用相同seed选取固定集合，每tick改变位置/旋转；0%档只在初始化写入，视图移动与否分开。以10,000对象计，脏数为0/100/1,000/10,000；不能把“提交意图数”当成“最终发生变更数”。

另测单父节点变化牵动1,000后代、单共享材质影响1,000实例、同tick同对象100次修改合并、1%创建/销毁。记录intent、最终dirty、传播、提取、写入/上传bytes、重新prepare的mesh/material数，避免局部接口后面仍全量重建。

静态0%稳态不得每帧重新创建mesh/material GPU资源、整场序列化或hash；允许相机可见性与必要帧uniform工作。1/10%档不以严格线性时间为硬门槛，但必须证明数据更新范围正确并给出成本曲线；改变比例不允许重新挑最优相机。

SimulationDelta与PresentationDelta单独计数；60 Hz模拟/120 Hz呈现中，零新tick但alpha改变的帧仍须更新活跃插值对象。0%静态基准要求同时无模拟和表现变化，不能把合法插值上传当成无效更新，也不能靠停止插值达到零上传。

BM-05四种子档为全角色可见播放、75%离屏但保留gameplay事件、暂停/单步、10% root motion+10%角色控制切换。皮肤输入、current/previous姿态、bounds、事件次数分别验证；关闭蒙皮或把角色替成静态mesh不算通过。

动画正确性附加子档只需2角色：两段骨骼IK含可达/不可达/极限退化、两个不同骨长rig的显式映射retarget含缺joint负例、4个morph target且最多2个同时非零并与skin组合。S3冻结误差/权重范围与变换顺序；此小档证明首期子集，不假装100角色全开高级功能的性能证据。

呈现频率分别30/60/120 Hz、模拟固定60 tick/s，使用相同tick输入：World/physics变换与gameplay事件应保持同一声明语义；PresentationPose仅影响画面。观察必须关联snapshot tick pair、alpha、frame与origin epoch，render bounds与collision/nav bounds分开。低帧率注入100 ms延迟验证catch-up上限和诊断，不能静默丢tick或慢放玩法。

BM-06分别记录初始落体、稳定堆叠和受持续驱动的≥90% awake段；性能主样本使用持续活动段，静止sleep段独立保留。两角色用固定路径覆盖台阶、坡面、低顶、移动平台、teleport、跨cell；mesh collider限制、触发/接触事件和CCD穿透分别判定。

连续模拟中统计后端重建/全量回灌次数与contact/sleep等私有状态保留：正常tick不得每次重造整个physics world。分别测试“原实例继续”“声明的完整后端状态恢复”“仅项目存档字段恢复”；三者资格独立，Transform恢复不能称物理无损续跑。

BM-07路径请求包含可达70%、不可达20%、跨未驻留tile10%；不能只算成功请求。最短路径允许算法合法差异，以可行性、避障、稳定ID和冻结的路径代价容差验收；动态tile卸载必须使相关结果失效，不复用陈旧路径。

BM-10的角色、刚体、导航可以属于同一批角色实体，但各声明计数须真实执行；禁止把1,000导航代理和1,000刚体都藏在不可见/停更区域。综合档不叠加孤立最坏负载的全部阴影资源，配方差异必须保持显式。

### 4.3 世界驻留与精度

BM-08 PC最多25个resident cell、Android最多9个；全局共享资源也计入预算。K2至少访问40个PC或24个Android独特cell并重访前4个，使累计读取/上传量超过resident上限两倍；不允许“全部预热后只走小圈”代替。

生成时保证一个cell的独特可上传payload至少32 MiB PC/32 MiB Android；每cell mesh/texture/collision/nav字节单列，填充payload必须由真实可见/查询consumer使用，不能塞不可访问空文件制造dataset规模。S1双cell子档只证明生命周期，不宣称超过总预算的完整世界资格。

BM-09目标局部位置差≤1 mm、屏幕位置差≤0.25 pixel；接触距离/形状查询误差≤2 mm，路径端点差≤1 cm；均相对零锚点同配置参考。范围是已规定的1,000 km锚点与≤2 km局部坐标；S0若物理后端要求更小局部域须通过显式重定位满足，不能放大误差掩盖全局f32损失。

BM-15在S0消费上述空间容差的最小子集，绑定真实库版本、构建feature/精度/线程和适配策略；对跨锚点物体的连续接触与sweep、两nav tile接缝路径、卸载后旧路径拒绝均须真调用。失败先修正选型/空间合同，不能以stub通过S0；S3再经SDK/包/Projection真实产品链重复受影响探针并扩到BM-06/07/09。

精度比较在非遮挡、稳定投影探针点执行，重定位前后同时验证previous transform、骨骼、粒子、音源、物理/nav origin epoch；motion vectors不能产生与真实运动不符的跳变。GPU像素差按冻结的抗锯齿容差计算，不要求所有光照像素bitwise一致。

| 资源驻留 | GPU tracked≤2 GiB；CPU decoded/cache≤2 GiB | GPU tracked≤512 MiB；CPU decoded/cache≤768 MiB | 不含driver不可见部分的声明必须明确；RSS仍单独测 |
| 总内存与余量 | S0按所选主机冻结CPU tracked aggregate、进程峰值、GPU总分配和系统保留余量 | S0按真实设备冻结同类总量/进程峰值与平台可测内存压力门槛 | 当前不编造数值；未冻结不得关闭对应性能/容量档，总量与分项同时判定 |
| CPU staging/在途 | 上传staging≤128 MiB，retiring bytes≤256 MiB，最多2提交帧在途 | staging≤32 MiB，retiring≤64 MiB，最多2帧 | 超限背压/拒绝；不能临时无限扩池 |
| 后台资源预算 | 上传≤16 MiB/呈现帧；decode工作内存≤256 MiB、同时解码≤4 | 上传≤4 MiB/帧；decode≤64 MiB、同时≤2 | 大资产分片或拒绝，取消回收；总CPU/GPU预算仍适用 |
| 请求/缓存上界 | 活跃资源请求≤256、ready完成队列≤128、失败缓存≤128 | ≤64/32/32 | 所有其它cache/pool也须列上界；以上不是唯一受控容器 |
| nav服务 | 200请求/秒稳态，P95≤100 ms、P99≤250 ms | 40请求/秒，同deadline | deadline含排队；不可达/未加载也须有界响应 |
| 控制/反馈延迟 | input采样→模拟提交≤2ticks；提交→present≤2显示间隔 | 同2ticks/2间隔 | 可用tick/frame/OS事件关联，不等于光子级输入延迟 |

CPU各阶段、AUI、physics、animation、nav、extract、prepare、submit与wait都报告，但不强制把上表13.3 ms拆成刚性单模块额度。S0按综合配方分配初始份额；总critical path和GPU不达标时，单模块合格不能救总档。

内存账本必须覆盖World/层级/索引、动画、physics/nav私有状态、资产/cache、队列、snapshot、CPU staging和retiring。S0明确互斥分类、包含关系和共享分配去重规则；GPUresident/staging/retiring若重叠不得重复相加，仍同时报告总allocated与各域峰值。初次稳定分配也受总量门槛约束，不能只靠生命周期“没有继续增长”通过。driver/OS不可见部分写明测量缺口，不以tracked总量冒充进程或全显存。

**Admission latency 与 stall 分开**：资源请求到CPU/GPU Ready、cell请求到Active是服务延迟；主模拟/呈现停止是stall。BM-08提前一个cell预取，持续32 m/s移动不得越过未激活必要模拟区域；可控边界等待须记录位置、原因、时长，不能因镜头停住隐藏stall。

冷启动/teleport的候选服务目标：启动到可交互≤10秒PC/15秒Android；一个预定义目标cell闭包的冷请求到Active P95≤2秒PC/4秒Android。场景入口必要闭包Cook bytes固定为≤256 MiB PC/128 MiB Android，磁盘与缓存条件随身份记录；这些目标须S0按真实存储冻结。

超预算时必须区分 `admission_rejected / optional_quality_reduced / backpressure / deadline_missed / failed` 的拟定结果语义，并报告原因和恢复动作；不是要求当前接口已经具有这些字符串。拒绝正确只证明边界安全，不证明主档容量或性能通过。

### 6.2 时间口径

- CPU critical-path frame：该帧需要的CPU工作和依赖等待的wall跨度，排除显式frame pacing/Present阻塞；另报告含全部等待的app-frame elapsed、模拟tick、render CPU、worker总work及各wait。边界与排除项可审计；并行阶段P95不能求和，CPU/GPU不能相加当实际呈现间隔。
- GPU frame：该帧实际提交工作首/末GPU时间戳，跨pass/view/queue范围明确；pipeline bubble、queue backlog及时间戳有效性单列。只测main pass不能标GPU整帧。若设备/API缺时间戳，S0必须选择具有可信整帧GPU测量方法的设备/profile，或冻结可审计的vendor/OS GPU工具及关联范围；仅有busy比例/CPU submit不足，对应资格保持不完整。
- Present：区分应用请求、API返回、OS/compositor提供的presented事件。通过有界token映射FramePacket→submission→swapchain image/present→OS event；新应用帧与compositor重复显示分别计数，旧画面重复不增加有效应用帧率。测不到实际事件时只报告调用节奏；物理屏幕scanout/光子延迟需要专门设备，本文不自动授予。
- 使用原始有效样本的nearest-rank P50/P95/P99、mean、max及阈值超限数量；3轮逐轮通过才主档passed，不把3轮合并掩盖坏轮。不删除异常帧；OS干扰可使整轮invalid并有界补一轮，原轮保留。
- 所有结果给样本数、wall时长、warmup边界、tick与frame范围、有效/无效GPU样本数、采样时钟和分辨率。暂停、失焦、最小化只进入专门窗口，不混入普通稳态。

截图区分offscreen readback、应用backbuffer、OS capture；capture token绑定产生该画面的不可变snapshot，不能拼接最新World。多帧在途或OS丢帧/重复时无法关联的事件标unmatched/unavailable，对应同帧视觉或实际呈现资格不授予；其它已证明维度可保留。

### 6.3 缓存、测量开销与回放

缓存条件分为 source/Cook cache、package IO cache、CPU decoded cache、GPU resident、shader/PSO cache；逐项写明warm/cold/unknown。新进程只证明进程内冷，不能称OS磁盘缓存冷；禁止为了“清缓存”删除用户全局缓存或伪装重启。

BM-14首次Cook与无修改/单资产变化必须保留调用清单、缓存命中/失效和输出bytes；不能只比较总墙钟。首次建pipeline与已预热稳态分别报告，pipeline预热耗时计入启动/prepare成本。

Off、Summary、过滤Trace分别同身份比较：Off/Summary各按6.1对应K0或非K0完整稳态窗口，warmup后同样重置轨迹/事件起点；Trace用固定300帧窗和固定对象过滤。Summary增量CPU P95候选上限为Off的3%或0.2 ms取较大者；Trace成本和截断须展示，不以Trace运行证明正式预算。必要测量探针计数与成本随报告公开。

固定input/replay首先证明同backend/版本/平台/配置/seed/tick输入的状态与事件语义一致；域内bitwise、容差、事件顺序分别声明。跨平台确定性、物理浮点、nav等价路径与GPU粒子不合并承诺；不能拿画面相同证明World确定性。

## 7. 内存、容量与泄漏结论

每次采样分四层：CPU引擎tracked（资产/实例/动画/physics/nav/队列/缓存/retiring）、进程RSS/PrivateBytes或平台对应指标、GPU引擎tracked allocated/resident/staging/retiring、driver/OS能取得的GPU占用。单位统一MiB/GiB并给采样API；不能将tracked之和冒充全进程或全显存。

稳态记录起点/终点/P95/峰值；生命周期在同一“retired且同基准cell active”的状态比较，区分保留cache和未释放对象。池可到达容量后保持，但每个增长必须有owner、上界与策略；RSS不回落也不能直接等同泄漏。

生命周期候选门槛：第5～20轮tracked同状态无未解释的单调增长，live handle/lease/request回到预期计数，峰值不超过预算；PrivateBytes/RSS尾段增长超过较大者(初始的5%，64 MiB PC/32 MiB Android)触发调查。通过只能声明“本窗口无未解释增长/悬挂对象”，不能声明无泄漏或无限世界规模。

压力1.5×/2×档必须报告容纳上限、拒绝点、降级和峰值，必要模拟不可降级为缺失。性能允许不达主档，但不得挂死、无界增长或使用失效句柄；压力安全通过不提升承诺容量。
