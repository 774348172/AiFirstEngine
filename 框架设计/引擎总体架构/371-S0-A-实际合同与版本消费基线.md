# 371 S0-A 实际合同与版本消费基线

日期：2026-10-10。上游为[总合同](371-大型游戏级AI原生3D平台-方案B-v1总合同.md)、[方案B](371-大型游戏级AI原生3D平台-方案B-v1方案.md)和[当前总施工](施工文档/历史/371-大型游戏级AI原生3D平台-方案B-总施工文档.md)。

本块交付可执行的坐标/身份合同内核、当前消费矩阵和后续必须遵守的状态语义。内核不是新 Package、World 流式定位或 SDK 发布接口。基础贯通由 S1 提供；后端可行性由 S0-C 提供；任何未消费字段不能写入产物并宣称支持。

## 1. Owner 与消费边界（D-02）

| 真相/产物 | 唯一 owner 与既有消费链 | 本块处理 |
| --- | --- | --- |

| 资源/世界驻留 | 既有 AssetProjection/缓存，后续同 owner 资源操作与事务 | 不新增第二 loader/Bridge；异步状态在 S1 实际接入 |

## 2. 空间合同（D-03）

- 单位米，右手系、Y 向上、相机默认朝 -Z；列向量、列主序矩阵。
- 局部变换仍用 canonical f32 TRS；四元数顺序 xyzw，单位化与符号规范化继承359。
- 大世界位置由 f64 anchor 和独立 f32 local 表示。严禁先把 local 加到巨大的绝对位置后再相减，或先把 anchor 转成 f32。
- `WorldPosition::relative_to` 用 `(anchorA-anchorB)+(localA-localB)` 的 f64 运算，最后只窄化一次。该函数无 World 写入、无重定位副作用。
- `CoordinateDomain` 必须由消费端显式给出，每轴限制 anchor/local/relative 的绝对范围及绝对误差预算；构造拒绝非有限/非正限制以及不可表示的 local/relative 范围。
- 本块测试内核包络：anchor ±10^12 m，local/relative ±32768 m，每轴转换预算 0.005 m。不是物理/导航或 GPU 全链精度资格，也不是 A 附录设备预算冻结。
- 误差检查含 f32 窄化的实际差值及保守 f64 表示/减法/加法界；不包含资源量化、上游作者输入和后端求解误差。过严预算可以拒绝大 anchor，即使相对位移很小；不静默放宽预算。
- 所有非有限数、超包络和超预算分别返回 `three_d.coordinate.non_finite`、`out_of_range`、`precision_budget` 和字段路径。成功返回规范正零；无 clamp、无部分提交。
- 镜像/非均匀缩放可表示为 TRS；父级组合产生的 affine shear 可用于 mesh 世界矩阵和 bounds，不能静默反解为无损 TRS。当前 wire 不接受 shear 字段，keep-world 的不支持路径必须拒绝；相机继承必须刚性。S1 的 reparent/模拟适配继承这些约束。

## 3. 深度合同及旧 U2 映射（D-07）

首期基础默认固定为 forward-Z：clip/NDC 深度 [0,1]，near→0、far→1，clear=1、比较 LessEqual、当前附件 Depth32Float。`render_contract/camera.rs` 的透视/正交执行矩阵与 `wgpu_backend/real/geometry.rs` 的 clear/compare 为真实对应点。

| 消费 | 当前映射 |
| --- | --- |
| 359 World3d perspective | TestAndWrite，沿用上述 forward-Z |
| 旧 World2d / U2 正交构造 | 默认 Disabled，保持旧层序；显式 TestAndWrite 时矩阵仍 near0/far1 |
| UI overlay | 保持独立 UI pass，无 World3d 深度推断 |
| LegacyMatrix | 保留旧调用输入；不能据此推断它具有新3D能力 |

Reverse-Z 仍是候选，未发布新 policy。S0-C 若有证据要求改变默认，必须同步 policy/投影/clear/compare/深度重建与旧路径映射，不能只换一处 compare。AA 算法与历史成本留给 S2。

## 4. 持久身份、运行身份和写入边界

`PersistentEntityIdentity` 为 `(world, placement-or-spawn-instance, entity-local)` 不可混淆的 tuple。各段非空；相同 Prefab 的两个 placement 必须有不同 instance key，同一 instance 的 replay 必须保持原 key。key 由 World/实例 owner 分配并保存，不能由 Prefab asset ID 代替，也不能用有歧义的分隔符拼接。当前仅为验证内核，不自动生成 key，不序列化为新 schema，不提供 resolve。

运行句柄沿用 `RuntimeEntityId(index,generation)`，只在所属 World/session 内有效；它不是跨 World 引用。`World::try_resolve_runtime_entity` 同时验证槽范围、alive 和 generation；旧句柄不能通过 despawn/respawn 或流式再加载自动重绑。持久引用未来必须经显式 resolve 得到当前句柄。跨 cell 强依赖/层级由共同驻留或事务迁移处理，不凭 ID 偷渡驻留。

项目结构变化进入 deferred mutation/Runtime Spawn/Despawn Request；组件值由现有 World 校验后提交。域后端可以保留连续私有状态，但不是第二份项目真相。Prepare 的 staged 物理/导航对象不能参与 live query/tick；表现插值/视觉姿态不能写回模拟 World 或碰撞状态。这些集成行为由 S1-B/F 和 S3 验证，本块不声称已接通。

## 5. 时钟与资源状态语义（D-09/10）

当前 `RuntimeTime` 的 frame、fixed tick 独立递增；frame 不隐式推进 fixed tick。timeScale=0 冻结 scaled time，unscaled time 仍前进。当前默认 fixed delta=1/60 s，frame delta 上限约1/3 s。它不是完整 catch-up/背压/快照插值实现。

S1 冻结/实现：输入在声明 tick 边界采样，结构提交产生 simulation epoch，表现仅读取完整已提交快照并可插值；追帧次数和 RenderThread 帧滞后必须有界。具体 catch-up 上限、队列容量和调度粒度由 S0-B/C 证据决定，禁止现在编造已测参数。

资源状态约束：共享 LoadOperation 与每消费者独立 Ticket 分离；取消一个 ticket 不得使其余消费者失败；最后订阅释放后的底层取消遵从 owner 策略。资源内容版本与请求 generation/设备 epoch 分离。世界事务 Prepare→所有 required owner ACK→commit epoch；失败/取消回滚 staged 状态，late callback 按 generation/epoch 拒绝，不能覆盖新操作。Render 可以延迟使用旧完整 epoch，不能消费半提交状态。真实错误代码/schema 随 S1 的真实 consumer 冻结，不提前注册空 DTO 或能力位。

## 7. Device lost 策略（D-16）

首期 PC/Android runtime 基础策略选**明确失败退出**，自动重建设备为后续可选能力。S1-D 必须实现：停止接收旧 epoch 提交、标记 Failed/Abandoned、使旧回调无效；经 backend 确认设备失效/销毁后释放其资源，关闭过程有界。正常资源退休必须等真实 GPU completion；lost/超时不能伪造成 fence 成功，也不能无限等待永不完成的 fence。

当前代码没有被本块赋予该完整资格；策略是 S1-D 的明确施工输入，真实故障和跨 epoch 隔离必须在那里验证。

## 8. 验收与失效范围

终验执行当前施工列出的 `platform_3d_contracts` 与 `three_d_contract_a0`。前者覆盖数值/身份/句柄/投影/未来字段/时钟；后者覆盖现有严格 wire、规范化、旧新 reader、Package 版本拒绝等直接消费者。既有 affine shear/刚性相机/结构命令的真实 World 行为另用 `three_d_runtime_a` 中对应测试核实。

不增加依赖、不改 lock、不改 ABI/Package/wire、不运行 GPU/全 workspace/Local CI/安装。CPU 源码合同通过不授设备、后端、大世界生产贯通和性能资格。测试证据及实际源文件 SHA 见对应阶段记录；以后只改文档不使源码测试失效，改变内核/reader/fixtures/依赖则更新其消费证据。
