## 1. 终态与范围

`source_passed_platform_pending`：PC Windows Release实际优化构建、普通3D+AUI包的最短headless启动和源码不可用的独立启动通过；Android正式目标源码链已接入，但本机缺JDK17/SDK35/NDK/Gradle，native构建与真机资格pending。未取得GPU视觉、帧率、容量、商店发布或安装资格。371/S1整体未完成，PC允许继续S1-B；Android的对应平台门禁仍必须补齐，不能因host测试通过而关闭。

## 2. 唯一入口与配置合同

- `TargetProfile`消费`windows-dev/windows-release/android-dev/android-release`，Release配置分别来自leased `BuildProfiles/windows.release.json`、`BuildProfiles/android.release.json`。check/prepare/build保留target lineage；不把live文件替换为准备后的输入。
- 沿用BuildProfile v2的Release字段，增加优化交付布局`compiler-delivery-v1`：Windows x86_64或Android arm64-v8a，reports=true、symbols=false，不携带shipping application metadata。既有237 `portable-directory-v1`校验保持；当前Compiler consumer对不支持的shipping布局明确返回`release_layout_pending`。
- ProjectRuntimePackageAssembler仍为正式装配owner，PreparedRuntimePackage/CompilerSourceView仍为冻结输入。Android owner迁移至`project_authoring_execution::android_export`；可选Editor仅re-export，不成为headless构建前置。
- BuildDeliveryReport的desktop/android报告分别为Option；调用者按目标消费，不假造桌面报告。源Provider typed check/build schema支持上述四target；这不意味着已安装Provider已更新。

## 3. PC优化交付

复用既有Player builder的Release支持与profile/target缓存隔离。桌面导出消费实际选中profile；Release拒绝无Compiler composition的外部/legacy Player，也拒绝非空环境RUSTFLAGS/CARGO_ENCODED_RUSTFLAGS/CARGO_BUILD_RUSTFLAGS。

产品Module与Host/Engine构建均使用`cargo build --release`，opt-level=3、debug assertions=false、overflow checks=false。Host/Engine feature为`runtime_cli/real-window`。包内保存`reports/player-artifact-build-report.json`；runtime_cli的现有包reader核对Release build report、EXE/DLL/Module descriptor及包身份，拒绝Dev改标与错误DLL。报告通过ProjectWriteScope写入。

历史artifact内部`target/debug`只是组装布局名称；实际输入来自Cargo Release输出，不能靠路径名称判定profile。以命令、Cargo artifact profile、二进制哈希和报告共同判断。

## 4. Android源码链与平台边界

正式Compiler build消费prepare后的SourceView，复制leased bytes到run-owned staging，再调用既有ProductionStaging与RuntimePackageBuilder；Generated Glue不从live项目读取源文件。Release只允许arm64-v8a，原生Cargo使用`--release`，Gradle使用assembleRelease且isDebuggable=false。

Compiler Rust check与native build共享NDK linker/CC/CXX/AR/ANDROID_NDK_HOME配置。NDK/API、Rust target和工具链分发锁在昂贵步骤前预检；原生Cargo/Gradle步骤沿既有bounded child owner执行，600秒deadline、退出/截断/进程归属检查及逐步receipt。Library staging创建和Build发布复用ProjectWriteScope；必需最终报告写入失败不能登记Success。单文件原子写入不等于APK与manifest的跨文件事务；一致性reader仍需核对完整包。

APK验证使用JDK `jar tf`枚举真实archive entries，拒绝伪文本APK；检查目标/profile/ABI/APK hash，native输出检查ELF架构。签名为本地android-debug，明确不代表商店签名。设备执行consumer尚未资格化：run/verify明确`android_device_pending`，verify先检查包完整性，不转为Windows执行。

继承工具链候选：NDK28.1.13356709、min API26、SDK/build-tools35、JDK17、Gradle8.11.1/plugin8.9.1。它们不是本轮新测得的native冻结资格。本机Rust arm64 target可用，其余预检项缺失，真实Android请求在Check早拒绝；native/APK/device链仍待实际环境验证。
