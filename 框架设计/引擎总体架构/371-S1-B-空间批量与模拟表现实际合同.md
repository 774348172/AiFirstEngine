## 1. 实际链路与边界

普通项目 `project_game_sdk::DeferredMutationWriter` → `project_runtime_sdk::ProjectRuntimeDeferredMutation::Spatial` → DLL生成胶水JSON → `project_runtime_native_adapter::append_deferred_mutation` → 原session prepare/commit → World final overlay → simulation snapshot → presentation cache → 原RenderExtract/Projection。批量接口复用原DTO集合，不引入第二套bulk wire或独立提交通道。

Runtime SDK schema增加 `spatial-foundation-intents.v1`，使旧Host/新Module等不匹配组合由既有digest门禁拒绝；原ABI调用形状保持。意图tag与字段均camelCase，unknown fields拒绝。SDK不依赖engine_runtime/editor，不向项目暴露World、原始实体索引、renderer内部对象或直接插值缓存。

源文件：`rust/crates/engine_runtime/src/{world.rs,spatial_3d.rs,spatial_3d/timeline.rs,spatial_3d/structure.rs,project_runtime_session.rs,frame_loop.rs,engine_host_loop.rs,render_extract.rs}`及原session/spatial、structural子模块；SDK位于两原crate的spatial模块。Player终止故障消费位于`runtime_player_winit/src/lib.rs`，复用原session report，不新增wire或Runner。新增CPU target为`platform_3d_foundation`、`platform_3d_sdk`，旧`three_d_runtime_a`追加双Prefab用例。

## 2. 项目接口

| SDK方法 | 实际语义 |
|---|---|
| `write_local_transforms3d(&[(EntityHandle,Transform3D)])` | 先检查全部句柄非零generation与全部TRS数值，再追加原Spatial意图；invalid tail不留下SDK半批；宿主仍负责live identity与最终World校验 |
| `teleport3d(handle,transform)` | 新local TRS提交后重置整个子树previous/current；不会从旧位置慢慢插过去 |
| `set_spatial_interpolation(handle,enabled)` | 子树插值策略在成功提交后生效并重置历史；不通过直接修改Render组件实现 |
| `reparent3d(child,Some(parent)/None,preserve_world)` | live父子generation在prepare和commit重复确认；最终层级循环/跨域拒绝；keep-world保留全局姿态，否则保留local |
| `set_world_anchor3d(root,[f64;3],preserve_world)` | anchor属于最终根，finite且abs≤1e12；keep-world重算local displacement，不代表cell生命周期 |

米、右手/Y向上、相机朝-Z、四元数xyzw沿用359/S0合同。结构prepare先捕获普通最终值写入后的旧全局姿态，再按最终父层级计算迁移；结构同实体的最后parent/anchor值组成最终overlay，keep-world策略采用该实体最后结构意图。不会把中间层级公开为完成状态。需要业务逐步迁移时用连续回调提交，不能依赖batch内部的中间World读。

EntityHandle/RuntimeEntityId沿用S0冻结的World/session作用域，带generation；不承诺跨World重建或cell重激活后复用旧句柄。跨cell持久解析与WorldEpoch由S1-F接入。

跨anchor keep-world通过S0 split WorldPosition/CoordinateDomain，affine inverse后分解local TRS；不可表示的shear、奇异矩阵、坐标域/精度失败拒绝整批。单位scale相机及祖先约束仍存在。原typed hydration、Prefab实例owner和source→runtime映射保持。

## 3. 原子提交、容量与dirty

prepare只做校验，不改变World、history、dirty或容量。commit重复确认句柄、剩余tick容量与当前World的最终overlay；全部通过才收费并进行原owner的不可失败提交。非法尾项、stale parent、最终循环、shear及超容量均为零批写入。Prefab prepare/commit复用旧实例owner，与普通及空间结构意图共享容量，失败不发布半实例。

`World::set_spatial_profile(SpatialProfile)` 要求正值且容纳当前已使用量。默认每tick空间值意图16384、结构意图1024；Teleport/模式/主相机等计值，reparent/anchor及Prefab spawn/despawn计结构。多个批次共享计数；prepare和commit都检查，拆批不能规避。结构意图数不等同Prefab内部实体数；总体内存、GPU及大型负载资格仍由后续阶段负责。

最终同实体同组件取最后值；最终值与原值相同不调用dirty路径。根合并按真正继承的transform/visibility/hierarchy变化进行；纯binding变化不遍历/更新子树。传播计算最终矩阵一次，子节点实际矩阵/继承显隐未变时不生成更新。field mask为translation=1、rotation=2、scale=4、visibility=8、binding=16、hierarchy=32、history reset=64；mask是位集合，不可把提交意图数冒充GPU上传数。

`SpatialDelta` 是tick内合并变化：`tick/dirty_roots/affected_count/Arc<[SpatialChange]>`。dirty_roots表示实际传播批的根工作数，affected_count为该tick保留的不同运行身份数，包含删除；跨已发布批次同对象会再次传播，计数不声称CPU工作完全只做一次。`SpatialChange` 携带source EntityId、RuntimeEntityId+generation、field mask与可选共享pose；None是该运行身份的删除。销毁同名重生保留两个不同运行身份的通知。读取`spatial_delta()`不drain，旧Arc不会被新提交改写；两个领域可拿同一Arc。

## 4. 模拟快照与表现

正式FrameLoop以 `begin_spatial_tick`/`finish_spatial_tick` 管理历史。World持有每live空间实体previous/current两个共享不可变pose、当前tick变化表、活跃/待表现集合和一份独立presentation cache；不会每frame复制整个World。旧快照由消费者的Arc lease保留，消费者应按自己的有界在途预算释放；GPU lease与slot retirement由S1-C/D负责，本文不授无限保留快照的内存资格。

`committed_spatial_pose()` 返回runtime_id/tick/local/parent/SpatialWorldState。`spatial_world()`及SDK Transform3D读取仍是simulation。表现用local translation/scale插值、最短四元数归一化插值，再组合父表现矩阵；不对world matrix逐元素混合，180度旋转不会让矩阵坍缩。父引入的affine shear仍由矩阵组合保留。

2026-10-22原owner实现收敛：独立root、相同runtime/generation与anchor、无父级求值cache路径，且**插值/归一化后的**rotation与scale逐bit等于current local时，可复用已提交矩阵的线性部分，仅替换translation；否则保留完整组合。signed zero不按数值相等归并，generation/anchor/parent变化不复用此证明。此为既有数学语义的计算复用，不新增缓存权威、不跳过必要动态求值；真实底层重建计数与1/16/128/1024反例见阶段37的75/78，不能从计数下降推出整帧已达预算。

`prepare_spatial_presentation(frame,alpha)` 仅更新活跃与pending对象，返回/保留共享 `PresentationDelta{frame,tick_pair,alpha,changed}`；`spatial_presentation_delta()`非消耗读取。没有新tick也会因alpha变化更新表现，alpha相同且静态时不产生更新。teleport、模式、anchor/reparent及scale符号转换重置历史；历史settle按tick而非RenderExtract drain推进。

当前单主相机anchor作为表现origin；S0转换域anchor±1e12m、local/relative±32768m、误差≤5mm，在转换边界强制检查。合法远距simulation实体不能被错误转换为GPU f32坐标，超域表现明确失败；表现更新先全部算完，再原子替换缓存，失败保留上一份完整表现。FrameLoop将此错误转为结构化terminal fault。多view独立origin/history、bounds与GPU历史是S1-C，不在本块假称完成。

原RenderExtract/mesh descriptor/主相机消费presentation cache，最终场景仍走原Projection及生产渲染。3D重复Transform/RenderState dirty合并为每实体一次提取；2D路径保持原行为。纯模拟提交与零tick表现变化的计数分别可观察。

兼容：359独立World脏记录调用在tick=0仍维持原一次drain的previous settle；正式FrameLoop进入单调tick后不再依赖此路径。它是旧内部调用兼容，不是新的SDK时序合同。

## 5. 正式帧时序

自动生产3D宿主按60Hz累计scaled时间，30/60/120Hz输入得到60个simulation tick/秒；暂停不推进且保留alpha。每frame最多4 tick，债务保留，alpha限于已有完整snapshot；累计债务超120 tick时在修改World前进入可观察终态，保留已提交状态。delta沿既有maximum_delta_time裁剪，`SpatialSchedule` trace保留ticks/debt_ticks/alpha/clamped_seconds，不能把裁剪和过载隐藏为正常运行。

time_scale改变自动tick频率，每个3D tick的simulation delta为1/60，fixed_time也按1/60推进，避免双重缩放。旧2D/显式固定步语义保持。EditorStep默认走一步，即使frame delta=0；调用者仍可显式选择0步；显式Headless/固定步最多4，超限在前置边界拒绝。

AUI意图参与本frame第一个tick safe point，先开始history边界再执行意图，FixedUpdate不二次reset；因此AUI普通移动不会被错当成已完成历史。无tick frame仍保留既有合法session回调提交行为并按当前完整history产生表现，表现从不反写simulation。正式GPU/呈现计时及Off/Summary成本在S1-D/G验证，本CPU时序成功不证明帧预算。
