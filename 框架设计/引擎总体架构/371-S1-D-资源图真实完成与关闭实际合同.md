## 1. 所有权与实际图编译

沿原 RenderGraph → RhiCommandPlan → 原 wgpu backend；沿原 ProductionGeometrySnapshot → FramePacket → RenderThread。没有第二套 Renderer、资源注册表或加载器。新增子模块分别属于原图编译器与原 GPU backend。

GraphResourceId / GraphPassId、aspect / mip / layer / access kind、尺寸/格式/样本数、显式依赖、external/persistent/frame-local/history 进入中立图合同。编译稳定拓扑、hazard 边、资源首末使用点与兼容 transient slot。显式边先确定访问顺序，再推导读写依赖；不按资源名排序。结构缓存只保留最近一个计划，帧号、颜色和变换不导致重新编译；结构、资源描述与 history identity 改变失效。

循环、缺资源/pass、重复身份、未初始化读取、非法子资源/feedback、attachment 尺寸/格式/采样数冲突、非法 history 在 RHI Submit 前拒绝。显式访问不能把真实 attachment 写操作降为只读；命令写目标必须声明。history identity 包括设备、原点、相机、资源版本和 extent；本块实现身份校验/编译失效，实际 temporal texture/history 算法仍属 S2。

真实首期 backend 只执行单 backing color target、单 mip/层/样本和 Depth32Float。中立图能描述更广访问，**不等于 GPU 已支持这些配置**；多采样/mip/层、Depth24Plus、多颜色目标明确拒绝。独立 render texture 与完整跨目标渲染尚未实现。

实际深度 transient 复用同时检查图 slot 与 RHI command 的最后使用区间；图重叠或下一帧拓扑变化时重建分配关系。新增依赖 DrawGeometry pass 输出左红/右蓝的确定像素：不重叠的两个逻辑深度资源只实际分配一次，重叠时分配两个，同一 backend 从前一种图切到后一种图也正确。

## 2. 资源 lease、提交和退休

RenderResourceManager 在原 handle+generation 上登记弱 lease。ProductionGeometrySnapshot 冻结资源 lease，DrawGeometry 沿同一原生 lease 传递；旧版本 Stale/PendingRelease 仅凭精确 lease 可继续消费，伪造 token、Released/Failed 或新 generation 不获得此权限。serde 不传原生 lease；跨进程/反序列化后需要重新 Prepare，不能延续旧进程的原生所有权。

实际 queue.submit 分配 `(device_epoch, serial, frame_index, content_version)`。on_submitted_work_done 才推进真实 completed serial，并及时释放 CPU lease。CPU end_frame 推进十万帧也不能提前释放仍有 lease 的旧资源。无 lease 的历史路径仍保留 safe_frame_delay；不宣称全部资源域已迁移到 GPU fence。

mesh、pipeline、depth、clear buffer、由 geometry owner 持有的旧纹理沿原 backend 退休，保留到其最后 submission completion。更新仍沿 S1-C 同 queue 的 write→encode→立即 submit；不是任意外部 deferred encoder 的 COW 保证。S1-C 5,505,024B 固定参数/索引 arena 在空帧仍驻留。

当前实现上限：16 个未完成 frame submission；退休预算 128MiB 与 4096 对象；进入退休前检查已有量加本次增量，超限早拒绝。bytes 是 backend 可知分配的保守计数，逻辑 depth alias 可重复计账，pipeline 未知 bytes 以对象数限制；不是 driver 总显存。完整 resident/staging/加载预算由 S1-E/G 继续承担。

GPU submission fence 以 epoch/serial 表示队列完成；帧/内容关联以采集表中的完整 token 精确匹配。不得只凭 serial 的完成状态推断任意修改过的帧 metadata。

## 3. Worker、设备和关闭

原 worker 命令容量 4；最多 8 个未消费 frame 结果和 16 个未消费 fence 结果。满队列明确拒绝 admission，调用者可重试冻结 packet，不伪造 accepted。开始关闭后停止接收新 frame/fence。CPU fence 只证明 RenderThread 编译完成；RHI Submit、GPU Completion、Present 深度没有真实 backend 观测时返回 NotObserved，future CPU frame 也不能标 Completed。

shutdown 满队列/超时请求停止，仅在 JoinHandle 已结束时 join。确定负例持住真正资源锁、填满队列，5ms shutdown 在 100ms 内返回 Timeout；释放锁后 worker 在 2s 内退出。Rust 线程不能强杀，永久不释放的外部锁只能获得有界返回与未完成退出事实，不能冒称线程已终止。

GPU poll/wait、关闭和截图读回有 timeout；Player 最小化零 extent 前仍 poll，resize 沿原深度 owner 重新分配。正常 completion 与 abandonment 分离；timeout/lost 销毁旧设备并收回旧 epoch 分配，不推进 completed。已真实完成的 token 在后来 lost 后仍为 Completed，未完成 token 为 Abandoned。当前恢复策略是明确退出/重建 backend，不是自动恢复游戏会话。

wgpu 每个物理 Device 只有一个 lost callback，共享 viewport owner 共用一个丢失信号。设备键不能使用 wgpu Device Eq：它在不同 Instance 中会碰撞。以只读 HAL guard 地址+backend 区分物理设备，保留 Device clone 到键清理之后；native 地址仅作内部身份，不进入项目 API。未知 native backend fail closed。shared owner 同时失效，新 Instance 的重建设备不会继承旧 lost 信号；旧回调只持旧 atomic/弱信号，不发布新资源。
