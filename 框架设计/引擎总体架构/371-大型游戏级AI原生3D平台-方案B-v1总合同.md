## 1. 产品范围与完成定义

目标：让 AI 通过普通代码、版本化项目资产和现有工具制作、修改、调试、构建复杂 3D 游戏；引擎在资源、实例、角色、模拟和世界规模扩大时仍有清晰成本、正确生命周期和可扩展边界。

“大型”通过明确负载与平台资格表达，不能由类型数量、接口名称、编译通过或单幅截图推导。首期总项目 S0–S5 必须交付：

1. 可扩展的空间、帧调度、任务交接、增量 Projection 与持久渲染数据。
2. 平台化资源 Cook、后台加载、分段上传、驻留预算和分区激活/卸载。
3. 真实 PBR、基础光照/阴影/环境、抗锯齿、多视图、批处理与 LOD/HLOD。
4. 骨骼/蒙皮/动画混合与事件、角色控制、Physics3D、导航完整消费链。
5. 地形/植被、与 3D 视图深度协作的特效、空间音频，以及基础存取状态的稳定身份。
6. AI 创作/修复知识、结构化观察、故障恢复、多类项目和独立交付资格。

首期主性能档按 PC 大场景 + 复杂角色战斗设计；Android 从 S1 开始做真实能力贯通，在同一资产/SDK 语义下用较低质量与规模档。具体设备尚未指定，设备未验证时对应资格必须为 `unqualified`，不得拿模拟或 PC 数据填充。

实时全局光照、虚拟几何、复杂破坏/布料/流体、完整面部系统、电影制作、完整网络复制与多人回滚、所有主机平台不作为首期完成条件。其接入不得绕过资产、任务、Projection、能力与资源规则。高精度坐标和存档身份不自动授予网络确定性资格。

## 4. 身份、数据布局与所有权

### 4.1 身份层级

- **Source identity**：Asset GUID、sub-asset ID、Scene/Prefab entity ID。路径用于定位，不能是长期引用的唯一真相。
- **Persistent world identity**：world persistent ID + 稳定 scene/prefab placement instance ID + 实体局部 ID，标识重复 Prefab 中的具体世界实例；动态持久对象使用写入存档的稳定 spawn ID。原型来源身份不等于世界实例身份。
- **Runtime identity**：world/session、entity index + generation、instance ID。销毁后旧句柄失效；重新加载同一源实体也不能复用旧 generation。
- **Domain identity**：RenderInstance、PhysicsBody、NavigationAgent、AnimationInstance，映射到运行实体；项目不可直接保存后端裸 ID。
- **Allocation identity**：GPU buffer/texture、物理内部对象、任务请求与 staging allocation。独立 generation/epoch，按实际完成点回收。

Source ID 用于构建、观察、持久引用和诊断；热循环用紧凑 ID、typed columns 与预编译绑定。允许按变化生成来源映射，不允许每帧为所有实例重新 JSON 序列化或 SHA 计算身份。

EntityHandle 只指向一次运行 incarnation，不随重新加载自动绑定。Persistent/SoftEntityRef 按持久世界实例身份显式 resolve 为新 handle，是否发起加载由引用策略决定；source ID 只用于来源追踪，不能在重复 Prefab 间猜测目标。普通 handle 不隐式保持 cell 驻留；只有声明的 strong reference/lease 构成驻留依赖。

### 4.2 单一 owner

| Owner | 拥有 | 不拥有 |
| --- | --- | --- |
| Project/Authoring context | 源文件、revision、mutation receipt/rollback | Runtime 可变内存 |
| GameProjectCompiler/Assembler | source lease、导入/Cook、依赖与产物发布 | 帧更新、显卡对象 |
| World/场景生命周期 | 实体、组件、已提交状态、激活规则 | Shader/后端裸句柄 |
| 各领域系统 | 姿态、物理求解、路径等计算状态与其结果 | 第二套项目/Scene authority |
| 既有 Projection adapters | 提交状态到领域表示的变更翻译 | 重复资产库/独立常驻同步主循环 |
| RenderScene/Renderer | 持久实例、视图、可见集合、图与批次 | gameplay 规则或可变 World |
| Asset/资源管理 | 包索引、加载/驻留、依赖占用、上传与退休 | 项目内容临时生成器 |
| Backend | 设备资源与命令执行、真实 fence | 项目路径、自然语言目标 |

这些是职责接缝，不要求一项一 crate。扩展优先落到现有 owner；新 Module 必须说明深能力及其隐藏的复杂度。

World 拥有对 gameplay 可见的已提交语义状态；物理求解器、动画实例可保留跨 tick 的 contact cache、sleep state、采样连续状态等私有数据。它们由唯一领域 owner 持有，不需每 tick 全量导出再回灌。后端重置、存档恢复和回放是否保留这些状态必须分别声明，不能仅恢复 Transform 就宣称无损继续。

## 5. 空间与世界合同

### 5.1 统一约定与高精度定位

沿用 359 的右手、Y 向上、米、秒、相机朝 -Z 和局部四元数语义。新世界定位采用 **高精度世界锚点 + 局部变换**：锚点位置为 f64，局部 TRS 继续用 f32；无锚点的旧场景解释为零锚点。世界差值应先在高精度域计算，再转换为渲染/后端局部坐标。

世界锚点是空间定位合同，WorldCell 是加载与激活单元，两者可以关联但不强制一对一。S0 冻结受支持的锚点间距、局部坐标范围和误差预算；越界必须诊断或显式重定位，不能偷偷截断。不得承诺任意天文尺度精度。

GPU 使用每视图相机相对 f32 空间。当前/前一帧矩阵记录所用 origin epoch，原点转换必须同时处理历史位置、骨骼/粒子/运动矢量，防止假速度。非均匀缩放、镜像、法线逆转置、bounds 和相机刚体姿态继承 359 的明确限制；若放宽需版本化和负例。

PhysicsSpace/NavSpace 明确原点、精度、范围与坐标变换。所选后端可以使用全局高精度或有界局部坐标；origin shift 必须经过后端能力校验，不假设所有后端都支持。分区边界不能自动变成物理墙；一条连续碰撞/路径所需邻域必须就绪。

S0 必须确定首期物理/导航后端及精确版本，并用真实库做空间适配探针：远距局部转换、跨锚点连续碰撞/查询、两个导航 tile 的接缝与卸载失效。探针只证明 `adapter_feasibility`，完整产品链与规模留到 S3；探针失败应调整合同或选型，不能用 stub 推迟。

### 5.2 层级与引用

保留 Scene 为实体树、Prefab 为可复用创作描述。空间索引不是层级树；允许渲染 BVH、物理 broad phase 与导航 tile 分别优化。

跨分区引用分为显式强依赖、软引用与常驻服务引用。强依赖构成驻留闭包，并在 Cook 检测循环组与超大闭包；软引用解析为 Ready/Pending/Unloaded/Missing/Stale 等确定结果，不伪造默认实体。跨 cell 的动态实体迁移使用稳定的本次运行实体身份，换宿主 cell 不等于销毁重生。

跨 cell 父子关系必须采用共同驻留、常驻父级，或迁移时显式保持世界变换的重挂载事务；父级不能先卸载而留下悬空 hierarchy。若变换含无法表示的 shear/尺度，重挂载必须给出明确拒绝或保留仿射表示的版本化策略，不做有损猜测。

持久化描述保存 source/persistent identity 与项目存档字段，不保存 GPU/物理裸句柄。版本迁移、缺失对象策略和加载顺序可验证；不把运行世界整个内存快照当作通用存档格式。

## 6. 帧、任务与变换写入合同

### 6.1 运行时序

每个固定模拟 tick 的语义顺序：

1. 接收输入与已允许提交的异步完成；按固定顺序合并 gameplay/结构意图。
2. 运行玩法与动画逻辑，生成控制目标、根运动增量、力/速度/目标姿态。
3. 角色控制与物理执行；导航任务结果只在约定边界接受，查询读取明确的 snapshot/tick。
4. 提交求解后的变换与事件；会产生再次结构修改的回调排到下一合法提交点，禁止求解中重入。
5. 更新层级/bounds/领域版本，产生增量变更集合。

每个呈现帧在已完成的模拟状态间插值，完成表现姿态/IK 与派生 bounds，再提取不可变渲染输入。离屏角色仍需要的 gameplay 动画事件不能被纯渲染裁剪停止。项目暂停、单步、时间缩放、低帧率补步和 catch-up 上限有显式策略及诊断；不能以每呈现帧固定只走一个 tick 隐式改变游戏速度。

CommittedSimulationSnapshot 按 tick 保存已提交的空间/必要姿态。PresentationPose 从两个已完成 snapshot 和 alpha 派生，不回写 World、PhysicsBody、碰撞 bounds 或 gameplay 事件。影响命中/挂点的骨骼采样属于模拟域，纯视觉 IK 属于表现域。Render bounds 可依据表现姿态保守扩大，不能替换物理/nav bounds。观察记录 tick pair、presentation frame、alpha 和 origin epoch；S1 先用真实变换插值验证，S3 再接骨骼。

增量链区分 SimulationDelta 与 PresentationDelta。后者由 tick pair/alpha、视觉姿态、view origin 等变化驱动，仍归既有 Projection/表现 owner；仅更新活跃插值对象。即使没有新模拟 tick，呈现矩阵/bounds/上传仍可能变化。零脏预算指真实静止且无表现变化，不允许以零模拟 dirty 停止插值。

### 6.2 变换模式

| 模式 | 主要写入来源 | 其他系统如何参与 |
| --- | --- | --- |
| authored/kinematic | gameplay 提交的目标 | physics 做查询/运动约束，动画提供可选择的根运动请求 |
| dynamic body | Physics3D 求解结果 | gameplay 发力/速度/teleport，动画驱动姿态不覆写刚体位置 |
| character motor | 角色控制器接受的移动 | gameplay/根运动提供目标，碰撞决定实际位移 |
| attached/presentation | 父级与表现系统 | 不独立作为动态物理 root；跟随/挂点规则显式 |

模式切换、teleport、root motion 开关和 ragdoll 接管必须是受验证的事务，重置或转换历史插值状态；非法组合在 check/prepare 或提交处拒绝。

### 6.3 并行与交接

任务声明读写数据域、依赖、取消和完成点。以粗粒度批次并行，任务不能持有跨阶段裸 World 引用。渲染包持有不可变数据/版本；资源被替换时在途包继续引用旧版本直至退休。

队列容量、最大 frame lag、CPU staging、worker 数量属于目标配置并在 A 冻结。可靠的创建/销毁/资产变化不能丢失；允许合并的 transform 更新只能在保持生命周期顺序和历史插值的条件下合并。默认采用有界背压；任何丢帧策略必须单独声明，不可借此吞掉 gameplay tick。

停止顺序：拒绝新任务 → 取消可取消工作 → 收拢已提交工作 → 处理/退休在途资源 → 退出线程/设备。worker lost/device lost 返回有界失败及可重建状态，不挂死等待。CPU worker 完成、RHI submit、GPU fence、Present 是不同状态。

禁止持有 World 写权限、队列锁或完成回调必需的平台线程时，阻塞等待依赖同一权限/线程的任务。队列满产生背压时，消费端仍能获取推进所需资源；阻塞边和锁顺序属于任务审查范围。

GPU handle、submission 与 callback 均绑定 DeviceEpoch。正常运行按真实 completion 退休；设备丢失时将旧 epoch 标为 Failed/Abandoned，由 backend 确认设备销毁/失效后整体释放旧资源，不能等待永不完成的 fence，超时也不能伪装成 GPU 完成。旧 callback 只清理旧请求，重建仅消费仍有效的 CPU/cooked lease。

## 7. 资产、Cook 与驻留合同

### 7.1 冷路径

所有 Mesh、Material、Texture、Skeleton、Skin、Clip、AnimationGraph、CollisionShape、NavMesh、WorldCell、Terrain、VFX、Audio 配置均进入既有 Asset DB/Graph。

Cook key 至少包括源依赖摘要、导入设置、schema/cooker 版本、目标能力档、实际消费的依赖派生 key。输出包括压缩/布局/LOD/mip/骨骼绑定/动画采样数据/碰撞与导航块等。构建可取消、失败原子回退；reimport 不因数组顺序变化重命名子资产。GPU Shader/PSO 变体预算与预热属于构建/准备设计，不能首次交战时无限同步编译。

Runtime 只读已打包产物，项目不手写最终包或骨骼/GPU 二进制布局。来源映射随包保存，原源目录不可用时仍可运行。

### 7.2 运行状态

资源请求语义状态：`Requested → Reading → Decoding → CpuReady → UploadQueued → GpuReady`；纯 CPU 资源在 CpuReady 满足消费条件。失败/取消可从允许状态退出；重试创建新 request generation。

就绪必须带 domain，CPU prepare 不得报告为 GPU resident。相同资源/版本请求去重；依赖占用、项目强引用、激活 cell、在途帧分别持有可审计 lease/pin。释放顺序为取消未来使用、解除占用、进入 Evicting/Retiring、实际完成后释放。

去重后的 SharedLoadOperation 按资源版本/消费域组织，每个消费者拥有独立 RequestTicket。取消 ticket 立即取消该消费者发布资格，仅当无活跃消费者且缓存策略允许时取消共享工作。迟到产物可在预算内缓存，不能恢复已取消 ticket。cell 发布还需匹配 world epoch、cell generation、target-state revision、activation transaction ID 与资源/包版本，资源 request generation 不能替代这些检查。

内存、I/O、解码、每帧上传和退休队列分别预算；单资产超过 upload budget 必须分块或明确拒绝，不能无限破例整块上传。缓存和失败重试有上界。低内存先按显式策略降低可选资源/质量或拒绝激活，必要碰撞/导航缺失时不能静默以无碰撞世界代替。

热替换先准备新版本，再在合法边界原子切换；旧版本按在途引用退出。取消迟到、版本不符、设备重建、包卸载均检查 epoch/generation。

## 8. 渲染合同

### 8.1 数据和阶段

RenderScene 持久保存 mesh/material/instance/view 及其版本。脏集合驱动局部修改与删除；相机移动可触发可见性重算，但不使全场景 mesh/material 重新准备。

链路为：增量提取 → 更新实例与空间索引 → 每 view 可见性/LOD → 按 phase 排序/分桶 → 批量上传/实例化 → 图编译 → backend 提交。opaque/mask/transparent、shadow、depth、后处理、UI 保留各自排序与访问规则。透明对象排序不承诺解决所有相交透明面。

批次兼容键考虑 pipeline、材质布局、mesh/submesh、实例格式、视图/阶段等真实依赖；不能为减少 draw 数合并语义不同的对象。批处理跨对象但应能按空间区域裁剪，避免整张地图一个不可裁剪巨批。

S1 必须落地 CPU 正确裁剪与实例批处理；GPU preprocessing/indirect/occlusion 在后续形成同语义能力档与回退。LOD/bounds/骨骼和遮挡状态变化都参与失效。

### 8.2 图与 GPU 生命周期

图输入显式描述 view、pass、资源及 subresource 读写/attachment、访问阶段、clear/load/store、外部/持久/临时/历史资源。编译至少检查依赖顺序、未初始化读、使用冲突、尺寸/格式/采样数和输出可达性，派生生命周期与临时资源复用计划。

在 wgpu 下由其执行必要 API barrier；引擎仍须维护中立访问语义，不能谎称自行控制底层所有 barrier。async compute/多队列可后续扩展，初期正确单队列执行仍必须满足合同。

稳定 mesh/material/pipeline 复用；每帧实例/骨骼数据进入有界池或 ring buffer；实际 GPU completion 决定复用与销毁安全。多 view、shadow 与 history 的最后一次使用共同参与寿命计算。每个 backbuffer/frame slot 的状态独立，resize/minimize/device lost 清理规则可测。

资源存活不等于内容版本正确。每个 FramePacket 必须绑定其消费的 buffer/range/content version；实例、材质参数、skin 和 view 数据的更新不能覆盖尚未编码/提交的旧 packet 所需内容。S0/S1 明确采用按帧版本化区间、copy-on-write 或与 submission 严格有序绑定的上传策略；若复用同一物理区间，必须证明旧读、新写、新读的 GPU 队列顺序。不同策略均受在途内存预算约束。慢 render worker 与连续更新同一实例的多帧 GPU 对照必须覆盖此合同，不能仅凭 lease/handle 未失效通过。

### 8.3 材质、光照与质量

StandardLit 采用 metallic-roughness PBR 语义，定义线性/sRGB、normal/tangent、UV、base color、metallic、roughness、normal、AO、emissive、opaque/mask/blend、cull/depth。Unlit 继续可用；导入 PBR 不默认丢弃语义。

首主路径以 Clustered Forward+ 为首选设计，S0 以多光/阴影/透明/带宽负载作决策冻结；不能把后续 deferred 需要的全部实现提前堆进首期。方向光/点光/聚光、阴影预算与级联/atlas、IBL/sky、雾、HDR/tone mapping、抗锯齿分别声明能力和成本。

S0 的决策证据由固定输入的有限 GPU 技术探针、同硬件可复现实测参考及明确的能力/带宽分析组成，输入与指标按 A 的选型规则冻结；不要求先完成 S2 生产材质、完整阴影或多套正式 renderer。直接后端探针只能取得选型可行性，不能取得 BM-04 或普通项目资格。证据不足则对应决策保持未关闭；S2 真实生产负载推翻选型时先回填设计及受影响资格。

S0 冻结 ViewDepthPolicy 及首期默认的深度方向、clip range、clear/compare、投影/重建规则和旧 U2 映射；S1 按已冻结合同消费。S2 冻结抗锯齿/阴影算法参数及具体 history consumer。若新 3D 使用 reverse-Z，必须以版本化 policy 明确接入；旧 U2 正向深度与 AUI 不被隐式改变。后续更改 policy 需版本化迁移并重验受影响资格，具体选择见 D。

## 9. 动画、物理、导航与环境合同

- Skeleton/Skin/Clip/Graph 是独立可引用资产，绑定在 Cook 校验；运行保存紧凑索引、姿态与 current/previous skin buffer。clip loop 边界、事件、混合、mask、根运动和暂停语义确定。S3 完成播放/混合/蒙皮/事件；IK、retarget、morph 的首期子集由总方案明确，不借名称宣称完整角色系统。
- Physics3D 对外提供碰撞体、刚体、触发器、查询、关节、CCD、角色控制合同；backend 通过既有 PhysicsProjection 思路接入，只有一个首期正式后端。求解器默认精度/步长/线程/排序规则写入运行与回放身份。
- Navigation3D 分离离线 bake、tile 驻留、路径请求、动态障碍与局部避让。卸载相关 tile 必须使受影响路径失效/重算；未加载空间给出显式不完整/等待结果。导航与渲染不强制共享同一索引或 cell 粒度。
- 地形和植被是资源/空间/渲染 consumer；高度场与植被实例首期闭合，其视觉 LOD 与碰撞/nav 表示分别管理。边缘接缝、镜头跨区、物理有效距离和 bounds 必须可验证。
- 粒子与空间音频复用既有 owner；3D VFX 绑定真实 view/depth/空间原点，空间音频定义 listener/source、衰减与停止/卸载行为。可选 GPU 结果不进入需要确定性的 gameplay 真相。

## 10. 分区生命周期

世界分区的目标状态与实际状态分开：`Unloaded → Loading → Loaded → Activating → Active → Deactivating → Retiring → Unloaded`，包含失败/取消支路。

Loaded 表示 CPU 描述及规定依赖已准备，Active 表示激活策略要求的实体/渲染/碰撞/nav 已满足。纯视觉远景可选择更轻策略；可进入的 gameplay 区域必须满足必要模拟依赖。不同策略是明确资源合同，不能由超时隐式降级。

激活事务先校验引用闭包、预算与领域就绪，在提交边界发布实体和领域映射；失败释放本事务持有内容，保留合法旧世界。退场先处理动态实体迁移/持久状态、路径和事件，再解除领域占用，最终等 GPU/任务退休。跨 cell 的强依赖聚组不能超过预算而无诊断。

原子激活指逻辑提交：Prepare → required domain readiness ACK → commit epoch。预备实体/映射不能被 gameplay 枚举、查询或发事件，所有必要领域确认后在 World 边界发布 activation epoch；领域查询只消费已提交 epoch。渲染可按有界 frame lag 显示较旧完整 epoch，不能显示半个激活事务。commit 前失败回滚预备内容，commit 后失效执行明确退场/故障策略。可选安全点暂停方案必须计入停顿预算，不能把不同线程同一时刻更新作为隐含前提。

domain readiness ACK 是 `domain-private prepared-ready`：预备 body/collider 不参与活跃求解、接触/触发缓存或生产查询，预备 nav tile 只做隔离内部验证。支持 inactive/staging 的后端可先准备，其他后端在模拟安全点完成可回退批量接入，再启用并发布 epoch；提交前不得让预备内容改变旧活跃世界。任何失败必须在恢复生产求解/查询前清理，S3 用相邻活跃刚体与路径验证无准备态副作用。

S1 必须用至少两个真实 cell 验证资源后台加载/取消/迟到/激活/释放；此时尚无 Physics3D/Nav 的消费须显式标为未实现。S3 接上真实领域后重验，S4 扩展大范围连续移动。禁止用 stub 通过完整跨区模拟资格。

## 11. AI 创作、观察与版本

### 11.1 公共接口

AI 使用版本化资源描述、命名材质槽/动画参数、typed SDK 和真实 Rust 代码。复杂玩法留项目层；便捷 API 隐藏布局、资源池、后端句柄与提交细节。能力查询投影到既有 inspect/check/observe；不新增 3D 通用 execute 大工具或第二个 catalog。

每种能力分别记录 `design / source / integration / platform-qualified / installed` 的事实与证据引用。包声明 required/optional 能力，target profile 显式选择质量与 fallback；必要能力不支持时在最早检查边界拒绝。

### 11.2 观察与失败

已有 observe 扩展空间、可见性原因、材质/资源驻留、动画状态、碰撞/路径和阶段成本。一个观察结果携带 project revision、package/delivery/run、tick/frame、view/domain、采样口径。CPUReady、GpuReady、可见集、实际遮挡/像素是不同事实。

按需取证维护有界关联：FramePacket → submission → swapchain image/present token → OS presented event/capture token。截图标记 offscreen readback、应用 backbuffer 或 OS capture，并绑定当时不可变 snapshot，禁止用最新 World 拼接旧图。无法映射的事件/截图标 `unavailable/unmatched`，不得取得对应同帧/实际呈现资格；compositor 重复显示旧图不计为新应用帧。

错误至少包含稳定 code、domain/stage、source path/field、相关 source/runtime identity、expected/actual、修复建议、retryability；发生错误才构造必要上下文。Off 不生成全量对象 trace；Summary 保留有界计数/首因；Trace 采用过滤、容量、时间窗和截断标志。

### 11.3 版本与迁移

文档版本、项目/资产/schema、cooked 数据、SDK/ABI、工具协议、观察与 package manifest 分别版本化。新增必需能力必须使旧 reader 明确拒绝；不得靠旧代码忽略字段获得假兼容。

旧项目使用既有语义，新项目显式选用 371 能力档；可兼容扩展保留旧 reader。改变坐标、材质、深度或绑定语义时提供迁移映射、影响分析与回滚，禁止自动重写全项目。S0 生成实际 consumer/version 矩阵，不能预先编造尚不存在的 ABI 版本号。

### 11.4 逐维度验收与诊断经济性（2026-10-14）

按[371-F](371-F-验收依赖与性能反馈链.md)分别证明CPU/GPU/实际显示/资源/工具；缺OS关联仅限制对应实际呈现/同帧资格，不否定有效的其它维度。共同身份/内容/时钟错误仍阻断受影响证据，整体完成义务保持。诊断优先owner与身份明确的已发布包，不将Cook/构建失败归为运行性能失败。
