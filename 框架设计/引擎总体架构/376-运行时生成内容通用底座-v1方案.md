## 1. 目标与依据

让普通 Rust 项目在不修改引擎源码、不直接操作 GPU/Jolt 对象的情况下，提交运行时生成的几何与碰撞，并读写项目自己的字节数据。

能力只有三项：运行时网格、运行时碰撞替换、项目字节存储。请求寿命、预算、取消和结果查询是三项能力的必要合同，不独立建设任务平台。

顶层依据：[权威架构 §5.5–5.9](00-AI-First-Game-Engine-权威架构设计-v1.1.md)、[产品需求 PR-AUTHOR-002/003/004](00-AI-First-Game-Engine-权威产品需求-v1.1.md)。当前基线见[49](49-当前状态与下一步入口.md)，施工归属见[54](54-当前可自动化施工总入口.md)。源码证据与审核见[376-A](376-A-成熟引擎源码对比与方案审核.md)。

体素只是可能的项目消费者。引擎生产接口中不引入 Voxel、Block、Chunk、Biome、WorldGenerator、GreedyMesher、FluidTick 等领域类型。

## 4. 最小公开表面

下列名称已映射到开发源码的Project Game SDK合同，普通项目mutation和能力声明已接通真实owner并完成G5。定义显式增加`.generated_content()`/`.project_storage()`，且须注册FixedUpdate、AUI、UI事件或生命周期等可提交mutation的session回调；只有Rule的定义在检查期拒绝。没有native consumer或缺可信存储绑定的宿主继续明确返回CapabilityGap。项目不手写ABI、descriptor或派生胶水；安装版是否包含这些功能仍按49的实际产物身份判断。

| `abandon_project_bytes` | ticket | 既有deferred mutation内显式放弃未领取数据 |

暂存标识与引擎接纳ticket分开：writer同步返回request_id，后续合法callback通过Request查询取得带session_generation的ContentTicket。尚未接纳的标识返回NotFound；不把项目返回的Applied或成功暂存解释为上传/提交完成。几何与存储共用这一关联方式，存储使用独立结果类型。复用原request_id、generation、回执和mutation模式，不复制全局事务管理器。builder/validate提供ContentError；writer沿原GameError返回本地错误，异步查询将语义ContentError与传输GameError分开保留。

新查询选择器直接扩展原ProjectRuntimeWorldQueryRequest类型化合同，沿原world_query回调分派；不为所有旧查询增加untagged输入中间解码。该修正仅删除中间解码步骤，不以此声明已量测的分配或性能收益。

请求接纳遵循原callback/deferred mutation的校验规则；接纳与异步完成是两件事。组合一致性仅覆盖一次明确提交的同目标几何/碰撞，不扩展为整帧所有对象或“文件写入＋World变化”的事务。项目通过结果回执自行安排跨请求依赖，目标必须先经原生命周期流程成为有效实体。

目标通过现有实体/Prefab创建流程产生。首版每个目标只有一个由本会话拥有的生成几何绑定，资源不能跨会话或跨实体隐式共享。显式释放移除该生成绑定，不自动复活此前 authored mesh；目标销毁或会话退出自动释放其资源。材质等长期资源继续使用 AssetRef。

## 5. 运行时网格合同

### 5.1 创建与拓扑替换

采用现有 TriangleList、Uint16/Uint32、坐标约定、属性格式和材质语义。SDK builder 从安全 Rust 数组生成布局、stride、索引计数和附件描述。首版不扩大到任意拓扑、任意顶点程序或全功能网格编辑库。

创建和拓扑替换共享完整提交路径。顶点数、索引数、布局、子网格变化均使用完整替换。位置、法线、UV、颜色的局部修改使用固定布局更新，不通过属性补丁改变拓扑。

服务端仍校验尺寸乘法溢出、属性重叠、索引越界、非有限值、子网格范围、材质引用、坐标约定和负载预算。SDK 成功构造不替代引擎入口校验。

### 5.2 属性更新与边界

属性补丁必须标明已提交基础修订。基础不同或目标已有待提交更新时明确返回冲突，不将相对补丁隐式接到未知版本。完整替换可以按 §7 的规则替代较旧的待提交请求。

位置变化由引擎在准备阶段从候选位置数据计算AABB与包围球，和该修订一起发布；纯颜色/UV变化复用原边界。SDK可以预计算，但服务端仍验证，不能要求AI记住另调“刷新包围盒”。现有中立合同的边界包含性校验继续使用。

首版只处理CPU可见的位置数据；不增加任意shader位移的边界推断系统。需要额外保守边界时沿现有显式材质/边界能力处理，不得使用旧边界裁掉已移动的生成网格。Bevy本地开发树的实际calculate_bounds已处理AssetChanged更新，不能照搬同树“只创建时自动算”的旧注释（376-A，R02）。

局部更新只承诺修改指定属性，不承诺所有后端都能原地、零复制完成。后端必须保护仍被旧帧使用的数据；需要 COW 或完整替换时按真实成本计费。

### 5.3 CPU 数据寿命

跨 DLL 接纳后数据由引擎持有，项目可以释放自己的提交数组。GPU、碰撞和恢复数据按实际持有 owner 记录；共享 backing 去重计费。

首版保留一份紧凑、已校验的规范几何payload，供属性补丁、边界重算与设备恢复使用；不常驻原始JSON、生成算法中间数组或每帧历史副本。相同payload在准备、碰撞或恢复消费者间尽可能共享，按真实backing去重，派生native形状单独计费。

当前版本与候选版本重叠的峰值必须预留。成功切换后旧CPU数据在无消费者时释放，旧GPU数据按原fence退休。会话/实体释放时清退规范payload。首版不增加RenderOnly/CPU可丢弃模式，避免引入项目回调再生成或恢复失败分支；以后如有实测需求另行设计（376-A，R05）。

## 6. 运行时碰撞合同

首版支持现有中立形状在静态Body上的运行时创建与替换，静态三角网格是必验路径。Replace需携带现有Body3D合同所需的配置，复用enabled、motion、friction、restitution、sensor等实际字段及校验，不另造层/物理材质或体素参数。StaticMesh仅允许Static且不能为sensor的现有限制继续生效。首次绑定与替换已有静态绑定走同一路径。

动态Body、CharacterMotor或关节关联对象的形状变化涉及质量、惯量、接触和唤醒等额外语义，本版返回明确UnsupportedMotionType；不因底层能构造形状就声称全部动态替换已支持。不新增自动凸分解或破坏模拟能力（376-A，R07）。

碰撞与渲染数据可以不同。网格更新不自动推导或重建碰撞。组合替换显式指定 `Keep / Replace / Clear`：Keep保留现有碰撞及其collision_revision，Replace提供形状，Clear明确移除；Replace/Clear才随本次提交更新collision_revision。不能把每次几何修订都误判为碰撞也已更新。

单独替换碰撞复用同一路径，不建第二物理世界。准备阶段不可参与公开查询或模拟。成功后在现有模拟安全点提交；失败保留已生效数据，释放本次准备资源。

需要配套更新时，项目以一次目标替换请求提交网格与碰撞。候选GPU上传必须取得原backend真实Ready，静态碰撞必须在原native owner中Prepared；World在模拟安全点复查目标代次/基础修订/最新候选，并以同一提交修订切换两项绑定。任一准备失败或提交检查失败均释放候选，旧绑定继续有效。

Applied表示新碰撞用于该安全点之后的模拟/查询，新几何已进入同修订的渲染提取输入。已在途的旧帧可以完成；首个消费新修订的实际呈现帧可能稍后到达。Applied不承诺同一OS时刻像素与物理原子改变，视觉验收必须使用实际帧/截图证据。

沿用原prepare/activate/rollback合同，但“替换已存在目标”需要单独验证，不能拿cell首次激活证据替代。首版释放生成绑定同时移除本会话创建/替换后拥有的生成碰撞；Keep留下的非本会话碰撞保持原owner。逻辑目标身份保持，native内部句柄不暴露；旧接触事件按现有代次规则失效。

## 7. 请求、修订与生命周期

首版请求状态为 `Accepted → Preparing → Applied`，以及 `Failed / Cancelled / Superseded` 终态。Ready仅是各内部 owner 的阶段状态，不要求项目再执行手工 activate。Applied只表示合同规定的运行时提交已完成，不表示已经截图或用户看到画面。

身份包含会话代次、目标实体代次、请求 ID、基础修订和候选修订。候选修订由引擎分配，不能由项目伪造 backend ACK。Applied修订与最新请求状态分别查询，失败不能把旧Applied数据标成新版本。

只在完整接纳新请求后才使旧待提交请求 Superseded。新请求在校验或预算接纳前被拒绝时，旧请求仍有效。异步完成时重新检查所有者、代次与候选身份，旧结果只释放资源，不得回挂。

取消是停止发布并回收资源的请求，不承诺强制终止 native worker。CPU内存和预算须保留到任务实际结束，GPU资源须等原 completion/fence 允许回收。

回执采用有界存留；近期窗口被回收返回明确 `ReceiptExpired`，不得误报成功。项目若不确定先查询Applied修订，不自动重放有副作用的操作。

同一目标始终区分applied_revision与pending_revision。完整替换只允许最新已接纳候选提交；候选已Superseded即便先完成也不能短暂覆盖当前有效版本。被拒绝的更新不得取消原候选。基础修订在接纳及提交时各核对一次；接纳后外部绑定变化使请求失败，而非盲目覆盖。

Applied之前的取消禁止发布；Applied之后返回AlreadyApplied，不伪装回滚。目标销毁时先撤销公开绑定、停止接纳，再让在途owner持有引擎自有数据完成退休。项目自身线程须在session销毁回调返回前取消并join；宿主在销毁完成前保持module加载。项目线程不能保存host_context或持有引擎内部对象；禁止detach后卸载DLL（376-A，R03/R06）。

## 8. 二进制数据与预算

在现有 bulk wire 上扩展明确的附件记录：类型、偏移、长度、计数与格式。所有区间在分配前检查，不传裸 Rust Vec/Arc、借用指针或 GPU/Jolt句柄。Host context只在包含它的 module call 内有效，项目工作线程不能保存后调用它。

首版单次封装总字节数沿用现有 `MAX_SESSION_BYTES = 8 MiB` 上限，包含元数据和全部附件；不是每个附件各8 MiB。大内容由项目分成多对象或多key。返回读数据遵守相同有界缓冲语义。旧AIFESB01的变换记录含义不变；新增附件采用显式版本化格式，不能把旧格式中的固定60字节记录悄悄解释为网格。

接纳在module call返回前将借用输入复制/转交为引擎自有有界字节；项目返回后原数组失效也必须安全。跨模块不交换分配器所有权，不承诺零复制。读取结果由调用方提供ProjectRuntimeByteBuffer，短缓冲只报告所需大小，不消费结果；成功复制后才标记已领取。

2026-10-30编码映射：提交沿AIFESB02包装原AIFESB01及其固定60字节变换记录，新增附件表保持显式区间。读取结果采用AIFEPB01：16字节header、结果元数据JSON及原始字节附件，总和仍≤8MiB；字节不进入JSON数组。SDK只接受请求ticket相符的成功读取结果。ProjectStorageAbandon也走原v2 mutation通路。schema摘要覆盖内容与存储合同，HostApi表尺寸及ABI minor保持；未启用owner前不宣告新capability。

复用现有 profile 的 CPU准备、GPU resident/staging、每帧上传与队列预算。若旧版本＋候选版本不能同时容纳，返回明确BudgetExceeded，保留旧版本；不偷偷卸载旧对象，不提高全局预算。

项目请求与资源占用有界，回执窗口复用已有128项模式；活动请求占用窗口且不能被逐出，终态记录才可回收，满时明确拒绝新请求。实际 pending/reserved 仍受现有预算准入，不因窗口数量预分配128份最大payload。取消中的真实占用不能提前归零。

GPU大提交沿原上传owner分帧、在每帧额度内推进，不照搬Bevy“额度耗尽前至少允许一个完整大资产”的宽松预算语义。不可容纳的双版本驻留在接纳前拒绝；临时分帧等待保持Preparing，不能因当帧额度已用完就把合法请求升级成frame_rejected。仍须验证原上传owner真实进展及退出，不能只靠队列有界声称完成性（376-A，R04）。

## 9. 项目字节存储

### 9.1 命名空间与基本操作

宿主根据可信 project identity 和运行 profile 绑定存储根，不由项目传绝对路径。只暴露相对key；拒绝路径逃逸及经链接逃逸。运行包、源工程和用户配置不作为存储根。正常发布持久目录与测试隔离目录分开。

只支持整key读取、完整替换写入、删除。零字节是合法内容，NotFound是明确结果。数据编码、压缩、索引和多key一致性完全归项目。首版没有事务数据库、目录扫描 API、云同步或自动迁移。

同一命名空间由宿主持有单写入租约，另一进程/会话争用时明确返回StorageBusy，不支持未声明的多进程并发写。同key操作包含读/写/删除，均按接纳顺序执行；并行独立key仍受I/O预算。读取不能看到本owner写入中的临时内容。命名空间按稳定project identity绑定，正常版本更新不因包hash变化丢失存档；测试目录由宿主显式隔离。

读结果显式获取一次，缓冲不足返回所需长度但不消费结果。未领取数据继续占用I/O/回执预算且不可当作可逐出的小记录，直至领取、放弃或会话结束；满时拒绝新接纳。缺少受控目录或单写入保证的平台明确capability_gap（376-A，R09/R10）。

2026-10-30 G4实际映射：可信宿主通过原`RuntimeInstanceLoader::bind_project_storage(base, identity, profile)`绑定，不从项目DLL接收绝对根，也不自动选用户目录。identity/profile长度分隔后SHA256为namespace，相对key校验后SHA256为固定叶名；包hash不参与。原loader内单一活跃worker按接纳顺序串行所有key，共享原CPU/I/O额度；读只按实际长度分配，未领取结果持续占用额度。payload上限为原8MiB封装减256字节元数据保留，不修改wire schema；128回执不预分配最大payload。真实FFI查询/领取已接入，普通Player持久根/身份注入和正式mutation仍由G5完成。

### 9.2 写入语义

保证分为三层：受本接口序列化的正常读者只读到完整旧值或完整新值；在支持且验证的平台上进程中断前后目标也不经过“先移走旧目标”的空窗；本版不承诺掉电后的持久事务或多key一致性。

源码审核确认：现有atomic_file_replace先把目标移为随机backup，再提交temp；中断可能使目标路径暂缺。并且提交成功后删除backup失败仍返回Err。该helper不能未经调整就作为上述语义的证明（376-A，R01）。

在原文件替换owner内提供明确的运行时单key提交原语：同目录临时文件完整写入/flush/sync后，使用经平台验证的单步目标替换；目标已存在时不得先rename到随机backup。可以复用原temp/error设施，但保留既有authoring调用的兼容性；共享原语修改须覆盖实际调用方，不自动重测无关全仓。

存储结果区分NotCommitted、Committed、Unknown。提交前已确认失败保留旧值；提交后临时文件清理失败报告Committed并附清理warning，不能谎称未写入。无法可靠判定时返回CommitUnknown，项目先读取核对，不能自动重放。临时残留只由原I/O owner在取得命名空间租约后清理，不建设恢复数据库。

写操作的取消与退出必须区分提交前和提交后，不能把已经落地的数据报告为未提交。临界替换已开始就等待确定结果或报告Unknown；普通退出须先停止接纳并收束该阶段，再释放命名空间租约。存储任务只持有引擎自有字节，不回调已卸载项目DLL。

G4平台落实在原`engine_content::atomic_file_replace::project_storage`子模块，旧authoring helper函数体保持。固定本地NTFS根逐组件`NtCreateFile`相对已打开目录句柄打开，拒绝reparse及叶硬链接，后续I/O和枚举不重走完整路径；固定lease独占打开至真实worker收束。temp完整write/flush/sync后使用`NtSetInformationFile(FileRenameInformationEx)`、REPLACE_IF_EXISTS|POSIX_SEMANTICS、namespace目录RootDirectory一次替换。官方合同、旧新handle/并发open及真实子进程中断组合限定本机Windows11 build26200/NTFS的资格，不外推掉电、多key或其它平台。见[G4完成记录](阶段完成记录/2026-10-30-376-Project-Storage/00-G4项目字节存储与单key提交.md)及其平台原语复核；不新设数据库/Job API/恢复平台。

## 11. AI适配

1. 一次语义提交表达一次完整目标替换；项目不接触上传/physics准备的内部步骤。
2. 安全builder负责stride、offset、计数和附件编码；编译器生成注册与ABI胶水。AI写普通Rust项目代码与资产，不手写最终包。
3. 稳定错误包含 `code / field_path / request_id / expected / actual / next_action`；按失败字段修复，不要求AI猜日志。
4. 观察输出能够回答“已提交哪个修订、碰撞是否同批生效、请求是否终止、资源是否释放”，可直接写断言。
5. Off只保留功能必需的有界状态；Summary按需给计数，Trace才给详细阶段与来源。禁止每帧完整几何JSON、全项目扫描或常驻长字符串。

6. 九工具保持现有职责；check报告capability_gap、run/playtest/observe/build消费相同SDK合同，不新增“生成区块”等工具。
7. Headless、真实窗口Player和打包Player共享语义；headless没有GPU时不得伪造Ready。平台不支持的操作明确拒绝。

实际诊断沿用`RuntimeInstanceLoader.observe_memory`与`ResourceMemorySample.capacities`：固定`generatedContent.*`/`projectStorage.*`聚合receipts、worker、pending、CPU charge及未领取payload；请求/目标代次/修订/错误继续使用原receipt查询。只在显式采样读取，不用动态request key累积历史。charge为既有预算预留，payload为逻辑长度，不能冒称完整heap/driver内存；普通会话Off路径不调用采样。

新增能力通过原SDK schema摘要、capability声明及Compiler/Generated Glue接入。旧产物若不兼容，在prepare/绑定阶段给出RequiresRebuild或CapabilityGap，不进入运行后才越界解码；本方案不承诺跨SDK摘要二进制兼容。不盲目扩大ProjectRuntimeHostApi后要求所有旧表满足新sizeof。查询优先复用现有session请求/结果通路。

观察字段至少包含：ticket、目标及代次、status、applied_revision、pending_revision、commit_epoch、collision_revision、紧凑error_code；存储额外含commit_state、byte_count和结果是否已领取。资源计数按需使用既有观测owner，不为每个请求新建常驻日志账本。field_path和next_action沿源映射按需生成，顶点数据绝不进入默认观察输出。

AI标准用法：生成数组 → builder → 一次语义提交 → 查询必要结果/断言。SDK文档给出完整替换、固定布局更新、静态碰撞配套替换、字节保存四个短例与对应错误修复；示例是代码，不建设另一套DSL或操作编排语言（376-A，R08）。

## 12. 验收需求

以下需求已由G0–G5逐项验证；完整用例、失败oracle、复用身份和实际平台范围见[最终验收映射](../../.artifacts/376/integration-20261030-110437/g5-requirement-map.md)。表内是功能合同，不能外推正式性能、其它平台或安装可用性。

| ID | 失败可捕获的验证 |
| --- | --- |
| V01 | 普通项目创建生成网格、改变顶点/索引数量后真实窗口像素改变 |
| V02 | 位置补丁使网格移出旧边界仍正确可见；颜色/UV补丁不改变拓扑 |
| V03 | 越界索引、错误stride、非有限值、错误基础修订被拒绝，旧对象保持 |
| V04 | 异步A/B乱序完成、目标销毁和会话退出后旧结果不能生效 |
| V05 | 原始native碰撞准备不参与查询；替换后射线/角色消费新形状 |
| V06 | 组合几何/碰撞替换任一owner失败不出现半提交 |
| V07 | 原预算内重复替换/销毁后pending/reserved与GPU退休资源回基线 |
| V08 | 字节保存后退出进程，独立重启读回一致；零字节与NotFound可区分 |
| V09 | 存储故障发生在提交前后，回执与旧/新数据实际可见性一致 |
| V10 | 项目身份、key隔离及测试目录不写入真实用户存档 |
| V11 | 同一SDK经真实项目DLL、普通Compiler导出、独立Player消费；旧ABI明确兼容或拒绝 |
| V12 | Off路径不生成大报告；Summary/Trace能定位具体请求、修订与字节占用 |

V02还须覆盖纯属性更新边界不变及位置变化边界同修订发布；V04覆盖“新请求准入失败不取消旧请求”；V06覆盖Applied后第一模拟步与首次新修订呈现帧的区别。V07须含CPU规范payload与设备恢复重传，不能只查包装计数。V09至少验证写前失败、替换期间进程中断、已提交后清理失败、提交未知四种回执语义；不外推掉电资格。V11包含静态碰撞范围外的明确拒绝、真实ABI短缓冲不丢结果和模块任务退出后才卸载。

只建设小型通用几何consumer：地板、立柱或曲面生成与修改，碰撞替换，参数字节存取。不同几何形状用于证明通用性，不建设完整体素游戏。各验证复用不变输入的既有证据，只补本次影响面。
