# 可直接实现落地路线

> 状态提示：本文档是历史落地路线，多数任务已经完成或被新的 Native Editor / Rust Runtime 路线覆盖。当前是否继续施工，先看 `49-当前状态与下一步入口.md`。

本文档用于从当前代码状态继续开工。

它只列出“现在可以直接实现”的任务，不讨论长期方向，不把尚未确认边界的大模块塞进施工队列。

## 选择标准

一个任务进入本文档，必须同时满足：

```text
已有上游架构文档支撑。
不会改变长期技术路线。
不会把 TypeScript prototype 固化成最终 runtime。
不会提前锁死 Rust Runtime / Rust AOT / Native RHI 的底层设计。
可以在当前代码库内小步实现。
可以写自动化测试。
测试通过后能直接更新文档状态。
```

如果实现中发现需要改变以下边界，必须暂停讨论：

```text
Project Schema 核心结构
Canonical Rule IR 核心语义
RuntimeBackend 核心接口
Asset DB 核心语义
Build Graph 阶段语义
Rust Runtime / Rust AOT / Native RHI 正式路线
AI 自动绕过用户确认修改项目
构建脚本自动删除、替换、移动用户资源
```

## 任务 1：Asset DB 与 AI 资源生成注册闭环

当前状态：

```text
已完成数据层 v1。
Asset Candidate 可以生成 AssetRegistrationPlan。
AssetRegistrationPlan 可以生成 asset.meta proposal 和 register-generated-asset patch candidate。
第一版仍然 report-only，不写文件，不自动进入 Asset DB，不自动替换项目引用。
```

### 目标

把当前 AI 资源生成候选接到 Asset DB 注册前的可审查流程。

正式链路：

```text
Asset Candidate
  -> Asset Registration Plan
  -> asset.meta proposal
  -> Patch Plan candidate
  -> 用户确认
  -> Asset DB
```

### 为什么现在可以做

已有基础：

```text
28-AI-Asset-Generation-MVP.md
25-Asset-DB-Importer-MVP.md
src/asset-generation/assetGeneration.ts
src/asset-generation/assetEditPlan.ts
src/engine/assetDatabase.ts
scripts/test-asset-generation-mvp.cjs
scripts/test-asset-edit-plan.cjs
scripts/test-asset-db.cjs
```

缺口很明确：

```text
AI candidate 还不能形成 Asset DB 可审查注册计划。
Asset DB 不应该直接吃 AI candidate。
用户确认前不能写入项目资源真相。
```

### 实现范围

可以做：

```text
定义 AssetRegistrationPlan v1。
从 Asset Candidate 生成 AssetRegistrationDraft。
从 Draft 生成 asset.meta proposal。
从 meta proposal 生成 Patch Plan candidate intent。
校验缺失 source / lineage / type / usageSlot / dependencies。
保留 report-only，不自动写文件。
```

第一版不做：

```text
不调用真实 AI 模型。
不写入最终资源文件。
不自动进入 Asset DB。
不自动替换 Scene / Prefab / Component 引用。
不自动应用 Patch Plan。
```

```text

```
