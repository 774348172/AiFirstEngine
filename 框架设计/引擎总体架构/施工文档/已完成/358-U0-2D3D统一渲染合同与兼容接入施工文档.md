## 2. 施工目标与完成声明

U0 要交付的是**真实接入旧 Sprite 生产链的统一合同基础**：

1. 一个中立、可序列化、可校验的 `render-contract.v1` 合同，覆盖资产引用视图、坐标/Transform metadata、View、Visibility、RenderPolicy、Provenance 和 Diagnostic。

3. 旧 2D 可表达子集的无损转换与行为保护；无法还原的新语义明确返回 `unsupported`。
4. AI 能从按需输出的结构化错误中定位 source/entity/asset、expected/actual 和 next action；不依赖猜日志，不新增 Agent 工具。

最终只允许声明 `u0_source_contract_and_2d_compat_passed`。该声明表示源码合同与 headless 消费兼容通过，不表示新二进制 GPU 画面、默认安装、3D rendering 或完整 358 已通过。

## 5. U0 合同冻结规则

### 5.1 版本、序列化与能力状态

- 新合同 envelope 使用 `schemaVersion: "render-contract.v1"`；只属于内部 render 合同/诊断及 fixture，不使 RuntimePackage、Scene、SDK、ABI 或工具协议跟随升版。
- 新 tagged union 必须显式区分 domain/kind。新字段使用 camelCase，未知版本/未知 tag/拼错字段返回结构化错误；内嵌旧 `RuntimeAssetRef` 保持旧键名。
- 为每个新字段写明类型、是否必需、默认值或显式 unknown/not_evaluated、来源、非法输入和兼容方向。禁止以零、identity matrix 或 `true` 代替未知来源。
- 新 schema 严格校验与旧 decoder 是两个入口。不得给旧结构添加 strict 规则导致旧项目不可读；旧输入先按旧规则解释，再带 legacy 标识投影。
- U0 的 typed 3D/View 描述是 `contract_only`：可解析、校验、报告，不可被报告成可执行 3D。请求旧 consumer 执行无法表示的内容时明确 `unsupported`，禁止测试三角形替代成功。
- 不增加“将来可能有用”的全字段万能 optional 对象。Geometry buffer、named Material binding、资源 Ready 状态由 U1 定义/实现；U0 不预造空 handle 或虚构 cooked digest。

### 5.2 类型与来源冻结表

| 对象 | U0 必须落实的语义 | 兼容/延后边界 |
| --- | --- | --- |
| AssetRef typed view | 复用 `RuntimeAssetRef { id, type, guid?, sub_asset? }`；期望类型受控；source/revision/digest 从既有 record/调用上下文读取 | 不新建身份库；Project path 不是 ID；无 index 时只能记录 unresolved，不能声称 resolved/Ready |
| Asset validation | 有 index 时调用 `RuntimeAssetIndex::resolve`；补充本合同入口的 expected kind 和 id/guid 一致性校验，错误带原始身份 | 不全局重写 resolver，不改变已有非 render 路径；缺 source/cook 信息显式 unknown |
| Transform metadata | 区分 `legacy2d` 与新的 typed `world3d`；保留 local/world/previous 的来源和 evaluated 状态 | U0 不重写 ECS Transform/Hierarchy，不声称完成 world 传播 |
| Coordinate convention | 新 3D 为右手、Y-up、米、camera -Z；authoring 角度使用 degrees；目标 canonical quaternion/world matrix | 旧 2D 原值/单位不迁移；U0 只冻结 metadata，不实现通用 Euler/quaternion/import 转换 |
| RenderView | identity、source camera、domain、projection、viewport、target、layer、clear/depth policy 和 provenance | 内部 `LegacyMatrix` 原样承接旧矩阵和 view kind；新 Orthographic/Perspective 验证参数但不生产矩阵或 depth target |
| Visibility | authored 与 inherited 分开；未计算 inherited/culling 用 `not_evaluated`；view 结果带 `(view_id, instance_id)` | 不新增场景遍历/culling 系统，不用某个 view 的 bool 覆盖实例共享状态 |
| Bounds | 区分来源、space 和精度；旧 `Bounds::from_transform` 标为 `legacy_approximation` | 不把 scale 近似解释成真实 Mesh world AABB |
| RenderPolicy | domain-specific tagged policy；Sprite 保留排序和 alpha 语义；新 3D policy 只描述执行意图 | 不在 U0 把 2D 排序重写成 3D depth sort；UI 只引用既有 composition domain |
| Provenance | source entity/component、producer stage；可用时关联 project revision/path、asset、operation | 现有 World 没有的 project/path/operation 信息不可编造，不为此引入第二上下文缓存 |
| Diagnostic | compact code/domain/stage；Summary/Trace 可输出 expected/actual、source、dependency、fallback、retryability、next action | 复用既有诊断约定；新码只为 U0 实际失败，不新增独立 diagnostic registry |

新的 Perspective 验证 finite、`0 < fovYDegrees < 180`、`0 < near < far`；Orthographic 验证 finite、正 size 和 `near < far`。新 viewport 的尺度与策略必须明确定义并验证；旧 raw matrix/viewport 按旧合同保留，不能逆推相机参数。U0 不冻结未实现 backend 的矩阵内存布局或反向深度算法为现行行为。

### 5.3 旧 Sprite 和 View 的不可变行为

1. Sprite payload 完整保留 `sprite_ref/material_ref/color/flip_x/flip_y/sorting_layer/order_in_layer/sort_z`，descriptor 保留 visible/layer/payload kind；`None` 与 `Some("")` 不能混同。
2. 旧 Sprite 几何把 scale 用作 half-extents，rotation.z 使用 degrees，原 consumer 对 x/y rotation 的处理保持；不自动归一化 scale、颜色或排序值。
3. `sort_z == 0` 使用 transform.z，既有千分量化与最后的 proxy ID tie-break 保持；浮点容差只用于浮点几何，身份、枚举、整数和 command 次序精确比较。
4. source/runtime/proxy ID 及 generation 生命周期各归原 owner。新投影尚未有 proxy ID 时显式未分配，不造假 ID；despawn 后继续使用现有 scene 映射完成 RemoveProxy。
5. 旧 RenderView 的 view kind、source camera、identity matrix 与 placeholder 区别、viewport、target 和 layer mask 原样保留。真实相机给出的 identity matrix 不可误当“没有相机”。
6. 旧缺纹理引用继续由现有 Sprite pipeline 跳过并报告 `sprite_missing_ref`；Adapter 不静默吞实体、不 panic、不引入测试几何 fallback。

### 5.4 转换的无损范围

- 旧 Sprite/descriptor、旧 Transform metadata、旧 View 和旧 AssetRef 的已声明字段组成 legacy 可表达子集；`legacy -> neutral -> legacy` 必须保持字段和值，以及旧 decoder 的默认语义。
- `neutral -> legacy -> neutral` 只对明确标记为 legacy-compatible 的 canonical 值承诺等价；来源附件不会自动成为旧结构新增字段。必须由显式投影 API 返回兼容 payload 与转换结果，不能宣称附件也经过旧格式持久化。
- 任意 Perspective、新 3D 变换语义、多层集合、新资产限定信息等不能在对应旧目标中无损表达时，返回 typed unsupported/error；禁止取第一个 layer、删除新字段、猜 FOV 或吞掉 source metadata。
- 旧 JSON 对比的是已声明字段、键名、默认语义与 canonical 输出，不承诺空白、属性顺序或旧 decoder 本就忽略的未知字段的字节级 round-trip。
- 新合同可序列化正反例与旧 fixture 应拥有独立固定预期，不让生产 converter 同时生成 expected 和 actual。

### 5.5 运行时开销与 AI 诊断

Runtime 默认 `Off`：成功路径不生成完整 report/trace/JSON/文件；错误保留功能所需的 compact code，不将 Off 解释为吞错误。Summary/Trace 按需输出，Summary 条数/依赖链有上限，Trace 才展开详情。优先复用现有等级和报告类型，确实无法复用时仅增加本模块局部策略。

Provenance 尽量借用/共享既有身份，只在 dirty 投影或显式诊断时物化；不得在每帧扫描整个 World 或复制整个 Asset DB。测试应验证 Off 不走详细报告构造分支，不能只检查最后返回空数组。

报告的 unknown 必须给出实际缺失原因；例如旧 ECS 只有字符串 asset key 时，不伪造 GUID、路径和 digest。U0 不改 `inspect/check/observe` 工具 surface；未来在既有工具中展示合同属于后续阶段。

## 6. 正式生产接入点

```text
World dirty records
  -> RenderExtractContext（既有 owner）
  -> render_proxy_descriptor 的 Sprite 优先分支
  -> RenderProjectionAdapter<SpriteRenderer2D>
  -> 中立 Sprite projection / legacy-compatible policy
  -> 旧 RenderProxyDescriptor
  -> 旧 AddProxy / UpdateRenderState / UpdateTransform / RemoveProxy
  -> RenderSceneState -> RendererFeatureBuilder -> Sprite2D pipeline
  -> 既有 RenderGraph -> RhiCommandPlan -> Headless/WGPU backend
```

Adapter 直接消费 Sprite component 与必要上下文；不能先创建旧 descriptor 再每帧转换来回、仅为让新合同看似被使用。逆转换 API 供兼容边界和测试使用，不新增第二个逐帧同步回路。

既有 Transform-only 更新可继续走原 UpdateTransform 分支；新增类型不要求把所有 dirty 类型改写为全量重建。Sprite 与 Renderable 同时存在仍取 Sprite，移除 Sprite 后仍按原规则回退 Renderable；Add/Update/Remove 与 command merge 都归原 owner。

本阶段允许 Adapter 内部中立值立即 lowering 成旧 descriptor；这是明确限于 U0 的兼容接缝。U1/U2 再逐个迁移 consumer，不能在本阶段额外维护一份永久 neutral scene state。
