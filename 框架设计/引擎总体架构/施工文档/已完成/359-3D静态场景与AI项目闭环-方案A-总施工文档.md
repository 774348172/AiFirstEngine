## 2. 总施工目标与交付范围

把 358 U0–U2 的真实几何、材质、相机、depth、RenderGraph/RHI 底座接入普通项目，交付以下完整链路：

```text
Scene / Prefab / Transform3D / Camera3D / MeshRenderer3D / Visibility3D
  + generated cube/plane / Unlit / glTF-GLB import
  + Rust Project Module / typed SDK / AUI
  -> 同一 AuthoringProjectContext / Compiler / RuntimePackage
  -> HydrationProjection / World / Hierarchy / RenderProjection
  -> U1 Prepare / U2 GeometryFrame / 原 Renderer / WGPU
  -> 九工具中的 check / run / playtest / observe / build / delivery verify
  -> Windows dev 独立交付与可追溯的语义、像素证据
```

交付物包括实际实现、普通样例 `samples/three_d_lab_project/`、可执行 SDK/资产/错误修复示例、支持矩阵、原始证据及总完成记录。“静态 3D”限制网格内容，不限制相机移动、实体变换、显隐、材质替换、Prefab 实例化/销毁。

不施工 PBR/Light3D/阴影、skin/morph/动画、Physics3D/导航/碰撞控制器、3D 编辑器、Picking、大世界、GPU instancing 优化、多相机堆叠、共享粒子深度、World-space UI、Android 或 release 性能资格。不修改默认 Provider/真实宿主配置，不恢复 Tower P1-2，不改变已验收项目玩法。

## 7. A0：合同、版本与兼容边界

### 7.1 施工任务

激活复核补充：旧 Compiler 会保留未知组件，且旧 Prefab reader 不检查 envelope。新 3D 源项目必须显式使用 `aife-project.v3`；既有 v2 项目不迁移。A1 输出任何新 spatial Scene/Prefab 的项目均以 `runtime-scene.v2` 作为活动场景，确保旧加载器在 Scene 检查处拒绝（仅升级 Prefab 不足）。包外壳保持 v2。A0 提供合同解码/验证，不接运行消费；check 对合法新源报告 contract-only，prepare 和运行加载明确拒绝未接通的执行链。此处细化方案 6.5 的最小版本保护，不将 A1/A2 提前计为完成。

1. 落实正式方案第 6–8/10 节的严格 schema：Transform3D、Visibility3D、MeshRenderer3D、Camera3D、scene mainCamera、mesh-asset.v2、material-asset.v2、model-import.v1。保持普通文件可创作，不要求 AI 手写渲染矩阵/字节。
2. 冻结单一 spatial 真相、同域父子、RH/Y-up/米/-Z、Euler `Rz*Ry*Rx`、列主序、quaternion xyzw、非零 scale、material slot 名称与 AssetRef 原键。

- 故意错误 near/far 或材质槽 → check 字段诊断 → 正常字段 patch → 新 revision → build/playtest/observe/capture；旧 run 在当前源码修改后仍回读旧封存结果。
- 示例文档、schema fixture、SDK 示例与普通项目一起验证，不能只有口头工具用法。

```powershell

cargo test -p runtime_player_winit --locked --lib semantic_outcome
```

视觉要求与判定：

- 透视：同尺寸对象放在不同相机距离，投影尺寸与数学预期一致；正交对照大小不随深度改变。
- 深度：交换前后实体距离，内部 ROI 颜色随遮挡关系交换；near/far clipping、layer/visibility 隔离各有对照。
- 几何/材质：方向纹理检查上下左右，negative scale 与 back/front/none cull 有镜像对照，Unlit 颜色/alpha 与 double-sided 符合声明。
- 组合：BeforeWorld、旧 Sprite、native world、旧 Particle、ScreenOverlay/Modal 依据实际顺序检查；不声称旧粒子共享 Mesh 深度。
- 固定 backend 下内部纯色 ROI 每通道容差不超过 3/255；边缘几何容差 1px，采用远离抗锯齿边缘的 probe。纹理样本按实际 sampler/颜色空间算预期。不同 backend 不套逐字节 golden，若需更改容差先说明依据并回填，不能因失败任意放宽。

有限规模固定 1/100/1000 个共享 Mesh 实例，1280×720、Windows dev；每组预热 30 帧、采样 120 帧，记录 CPU mean/P95、draw、prepare、geometry/texture upload 与资源占用。不设未经基线证明的 60FPS 门槛，也不将 CPU 倒数当显示 FPS。

确定性硬门槛：clean 帧不重复上传未变几何；材质/相机修改不重做 Mesh cook/upload；Off 无详细报告，Summary/Trace 遵守上限；8 次场景卸载/重开与 resize 后无该场景残留的有效 handle/引用，缓存回到其声明保留上限。资源计数可证明的内容与 OS working set 测量分开，不能仅凭 RSS 短期稳定宣称无泄漏。
