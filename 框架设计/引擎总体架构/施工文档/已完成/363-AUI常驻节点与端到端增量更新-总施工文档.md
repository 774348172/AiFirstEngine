## 1. 目标、边界与责任

目标是让已知 UI 属性变化直接进入生产布局、命中、持久绘制和上传，完整 `Replace` 只在入口比较真实绑定变化；保留 361 的公开 API、控件/交互/扩展能力。最终以塔防三关 Windows Release 真正交战的 AUI CPU P95 <= 2 ms、完整 CPU P95 <= 16.67 ms 验收，不能仅凭微基准宣称达标。

引擎 owner：`rust/crates/engine_runtime/src/aui_instance.rs`、`aui_present_cache.rs`、`aui.rs`、`aui_layout_runtime.rs`、`aui_geometry_cache.rs`、`aui_drawing_cache.rs`，必要时触及现有 UiProjection/Renderer/RHI 的受影响实现与 owner 测试。项目 owner：`samples/tower_defense_project/Projects/hezi_shoucheng/RuntimeModule/src/sdk.rs`、项目 UI 资产和项目测试。跨 DLL 只用普通 SDK/Glue/正式导出链。新公开 wire/schema/ABI 不作为默认前提；若实测证明必需，先修订 363 正式方案和本施工合同、独立版本化后再实施。

不做 Provider 安装、默认宿主配置替换、Editor 全面改造、每节点 Canvas/离屏纹理、通用渲染线程重构、删减塔防 UI 或降低交互刷新率。候选包输出独立于既有可运行包。工作区已有大量用户改动，尤其 `aui.rs` 与若干未跟踪的 361 源文件；保留原状，定向编辑与验证，不清理或覆盖。

## 2. 必要性与验证经济性审计

请求与确认失败：361 专项 400 节点负载达标，但真实 415 节点塔防 Release 第一波 AUI P95 约 9.57 ms；240/240 帧 Presenter 重建，并有大量测量/几何工作。该事实证明真实项目链路仍有重复工作，尚未精确分摊每段毫秒数。

## 3. Gate A：变化源和生产协调

1. 冻结有界变化记录、版本/cursor、溢出和恢复策略；一个 owner 记录提交变化，多个只读消费者不争抢 destructive `drain_invalidations`。记录只携带稳定句柄/属性/原因；常驻实例仍是属性真相。失败不能推进消费版本，实例更换/结构提交/自定义输出/slot 复用使相关缓存安全回退。保留事件顺序和 8 轮稳定化上限。
2. 将生产 `AuiPresentCache -> AuiC2Runtime::observe_retained` 接到已知变化；清洁帧 O(1)，单叶变更不重枚举整个 `presentation_properties`、不做二次嵌套比较。变更集合按 slot/property 合并，撤销和绑定 owner 转换正确。首轮/落后版本按有原因的完整基线恢复。
3. 最小定向红测先验证两消费者独立观察、跳过帧、容量溢出、同值/失败不变、结构和 disposal 代际；再测真实 Presenter consumer，保留首次失败断言。计数区分首次基线与稳态；与 fresh 路径比较结果。

## 4. Gate B：兼容绑定与局部准备

1. 构建/挂载时建立 path -> 类型化目标 slot/property 索引；完整 Replace 依现有协议验证字段、缺值/fallback、身份与 owner，并在入口和最近成功基线比较。只有成功安装输入/下游结果才能推进成功身份；错误不留下半份文档或错误的 Reuse 基线。
2. 对真实变化批量更新常驻属性或受控派生值，未变绑定不克隆整份 Document、不触发布局/整形/绘制；替换/解绑/恢复显示有正反例。传输/解码/入口比较的 O(B) 明确计时，不把它算成端到端稀疏传输。
3. 保留 typed 高频接口与旧项目 Replace 共存；测试混合 Translation、文本及 HUD 完整输入。400/1k/10k 总节点单叶变化测 visited、copied、allocated、solver rebuild；初次可见文字另测。

关闭口径：本 Gate 冻结并验证绑定准备工作量，完整链路分段计时由 Gate D 的统一测量边界实现；不得因此漏掉 Replace 入口的 O(B) 比较、文本预检或错误恢复成本。`allocated` 的可审查豁免是暂不引入进程级 allocator/分配字节追踪，改为记录实际重新克隆并绑定的源节点对象数 `prepared_binding_nodes_rebuilt`；它不是 malloc 次数，不证明零堆分配。`source_nodes_compared` 只计几何源比较，`source_nodes_loaded` 只计 solver 载入，均不能冒充全链 visited。Gate D 的完整工作量计数和 Gate E 的生命周期内存/真实性能验收仍为必做项。rect targets 与 Canvas 根更新保留经过 fresh/失败测试的安全回退，局部依赖传播属于 Gate C。
