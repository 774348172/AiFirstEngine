## 筛选标准

可以自动化实现的任务必须满足：

```text
已有明确架构规则。
不改变核心架构边界。
不接真实 Rust Runtime。
不接真实 Native RHI。
不接真实 AI Provider。
不做真实 Android / iOS 签名打包。
不自动删除、移动、替换用户资源。
能写自动化测试。
失败时能停止，不进入下一个任务。
```

必须暂停的情况：

```text
需要修改 Project Schema 核心结构。
需要修改 RuntimeBackend 接口。
需要让 AI 自动绕过用户确认。
需要开放任意本地文件读取。
需要把 TypeScript Runtime 继续扩展成正式 runtime。
需要接入真实平台 SDK / 编译器 / 签名。
```

## 第三批：暂时不要自动化实现

### Rust Runtime MVP

原因：

```text
会进入真实底层 runtime。
需要先明确 crate layout、Runtime Package、Golden Scenario 文件格式。
可以讨论和写施工文档，但不应直接开工。
```

### Native Editor Host MVP

原因：

```text
依赖 Rust Runtime MVP。
涉及 Native Rust Editor Host、Editor Core 加载、UI Backend、Rust Runtime direct boundary 决策。
```

### 真实 WgpuBackend / Native RHI

原因：

```text
涉及真实 GPU API。
需要单独 renderer backend 施工文档。
```

### 真实 AI Provider 接入

原因：

```text
涉及模型供应商、密钥、安全、版权、成本。
需要单独权限和 Provider 策略。
```

### 真实 Android / iOS 编译签名

原因：

```text
涉及 SDK / NDK / Xcode / signing。
需要平台环境和签名策略。
```

## 推荐自动化执行顺序

建议第一轮自动化执行：

```text
1. Input System MVP
2. Golden Scenario Test 数据层
3. Editor Core 最小数据层
4. Build Report 受控历史读取 A1
```

理由：

```text
Input System 和 Golden Scenario 是 Rust Runtime MVP 的前置验收结构。
Editor Core 数据层能降低后续 Native Editor Host 迁移成本。
Build Report A1 已确认 legacy Electron 路径安全规则，建议放在纯数据任务之后。
```

如果只想做最稳的一批：

```text
1. Input System MVP
2. Golden Scenario Test 数据层
3. Editor Core 最小数据层
```

这三项都不接 UI、不接 Rust、不改当前运行行为。
