## 2. 成熟引擎对照

| 引擎 | 对应路线 | 本阶段借鉴 | 本阶段不复制 |
|---|---|---|---|
| Unity | AssetDatabase / Importer / Refresh / AssetPostprocessor / BuildPipeline / Native Renderer upload | 文件变化必须进入统一 Asset DB / Importer；编辑器导入期间有明确状态；资源最终进入 runtime 可加载格式 | 不复制 Unity 黑盒 AssetDatabase，不开放用户直接操作底层 GPU resource |
| Unreal | AssetRegistry / AssetTools / DerivedDataCache / Cook / Pak / Render Resource 初始化 | watcher / registry / cook / render resource 分层；Cook 和 Runtime 消费物分离；报告可追查 | 不做完整 DDC、Pak、Nanite/Lumen、复杂异步加载系统 |
| Bevy | notify_debouncer_full FileWatcher / AssetServer / RenderAsset extract-prepare | watcher debounce 分类；runtime asset 和 render asset 分层；wgpu backend 可 headless / real 分离 | 不引入 Bevy Schedule / RenderWorld 复杂度给项目默认层 |
| Godot | FileSystem dock / ResourceImporter / `.import` artifact / RenderingDevice | 源文件、导入产物、运行时资源分离；编辑器能识别外部文件变化 | 不采用 Godot Node / Resource 全套体系 |

项目路线：

```text
Unity-like AssetDatabase / Importer 心智
+ UE-like AssetRegistry / Cook / Runtime package 边界
+ Bevy-like Rust watcher / asset server / render asset 分层
+ AI-first report / diagnostics / deterministic headless tests
```

## 4. 全局硬规则

### 4.1 大阶段，但不混乱

```text
本阶段只有一个施工文档。
实现时可以分 A/B/C/D 子阶段提交。
每个子阶段必须有最小测试。
每个子阶段完成后可以写阶段子记录，但不再新开小施工文档。
如果某个子阶段发现方案冲突，先回填正式方案文档，再继续本施工文档。
```

### 4.2 Headless 默认，真实能力 feature / smoke

```text
默认测试不能依赖真实文件系统常驻 watcher。
默认测试不能依赖真实 GPU / driver / window。
真实 watcher、真实 GPU upload、真实 Bundle 文件可以有本机 smoke gate。
所有 smoke gate 失败必须输出 report / diagnostic，不允许 panic。
```

### 4.3 编辑器导入占用态

沿用已确认规则：

```text
大批量导入 / 外部文件同步期间，编辑器进入全局导入占用态。
占用态期间用户不能读写项目。
ProjectDock / Inspector / Console 只能读取导入前 snapshot 或导入完成后的新 snapshot。
```

### 4.4 不绕过既有边界

```text
FileWatcher 不直接导入资源。
FileWatcher 不直接写 AssetPipelineDatabase。
ImportWorker 不直接更新 AssetRegistry。
ImportWorker 只能通过 ImportTransaction 提交。
Build / Cook 不直接读编辑器临时状态，只读 Asset DB / Registry / Runtime Package 输入。
Runtime Asset Type Loader 不直接扫描文件系统。
GPU Upload 不直接读源文件，只消费 typed runtime resource / cooked asset。
RuntimeRenderer 不绕过 RDG / RHI。
```

## 5. 子阶段 A：真实 OS File Watcher / Import Worker

### A1. 数据结构

新增或落地：

```text
RawFileEvent
FileEventKind: created / modified / deleted / renamed
DebouncedFileEventBatch
ClassifiedFileChange
FileChangeBatch
FileWatcherReport
ImportWorkerRunReport
ImportOccupancyState
```

### A2. Watcher 规则

```text
真实 watcher 只产生 RawFileEvent。
RawFileEvent 必须 debounce。
debounce 后按 project asset root / meta file / unknown file 分类。
重命名必须尽量保持 GUID；无法判断时转为 delete + add。
大批量变化超过阈值时走 full scan reconcile，不逐条事件无限处理。
```

### A3. Import Worker 规则

```text
FileChangeBatch -> ImportBatchPlan。
ImportBatchPlan -> ImportQueue。
ImportQueue 第一版单队列。
ImportWorker 第一版单 worker 串行。
ImportWorker 成功只通过 ImportTransaction 更新 AssetPipelineDatabase。
ImportWorker 失败保留旧资源状态并写 report。
```

### A4. 最小测试

```text
raw_file_events_are_debounced_and_classified
created_file_generates_import_unit
modified_file_generates_reimport_unit
deleted_file_generates_mark_missing_unit
renamed_file_preserves_guid_when_meta_moves_together
large_file_batch_enters_import_occupancy_state
import_worker_commits_only_through_transaction
import_worker_failure_keeps_old_asset_state
```

## 6. 子阶段 B：Runtime Asset Type Loader / Render Asset Bridge / GPU Upload C-min

### B1. 数据结构

新增或落地：

```text
RuntimeTypedAsset
RuntimeAssetTypeLoaderReport
RenderAssetBridgeReport
GpuUploadRequest
GpuUploadResult
GpuResourceHandle
GpuUploadReport
```

### B2. Type Loader 规则

沿用 `06-资源系统架构.md`：

```text
Runtime Asset Loader 负责 bundle mount / load / release。
Runtime Asset Type Loader 负责 model / texture / material / audio typed resource。
Render Asset Bridge 负责把 typed model / texture / material 转为 renderer 可消费 binding。
GPU Upload 只消费 typed runtime resource，不读源文件。
```

第一版只做 C-min：

```text
texture: metadata + bytes length + format placeholder -> GPU texture handle placeholder
mesh: primitive / minimal vertex buffer descriptor -> GPU buffer handle placeholder
material: material params + texture binding -> material instance handle placeholder
```

### B3. GPU Upload 规则

```text
GPU Upload 默认 headless backend 产生 deterministic GpuResourceHandle。
real wgpu upload 只作为 feature-gated smoke gate。
失败输出 GpuUploadReport，不 panic。
GpuResourceHandle 不进入项目数据，只进入 runtime / render resource cache。
```

### B4. 最小测试

```text
runtime_type_loader_decodes_texture_metadata
runtime_type_loader_decodes_mesh_metadata
runtime_type_loader_decodes_material_metadata
render_asset_bridge_combines_mesh_material_texture
headless_gpu_upload_creates_texture_handle
headless_gpu_upload_creates_mesh_buffer_handle
headless_gpu_upload_creates_material_handle
gpu_upload_failure_reports_asset_and_layer
render_thread_consumes_uploaded_resource_handles_without_reading_asset_db
```

## 7. 子阶段 C：真实 Asset Cook / Bundle Pack 二进制最小闭环

### C1. 数据结构

新增或落地：

```text
CookedAssetFile
CookedAssetIndex
BundleBinaryManifest
BundleBinaryFile
BundlePackBinaryReport
RuntimeBundleMountReport
```

### C2. Cook 规则

沿用 `07-Build-Export-Pipeline.md`：

```text
Asset Cook 扩展 cook-assets 阶段。
Bundle Pack 扩展 pack-bundles 阶段。
Cook / Pack 不改变源文件。
Cook / Pack 不绕过 Asset DB / Bundle Plan / Runtime Package。
第一版只做 loose-directory + manifest + deterministic binary blob。
压缩 / 加密 / 热更差分后续再扩展，不改变 manifest 边界。
```

### C3. Bundle 规则

```text
AssetSet 是语义集合。
Bundle 是构建产物。
Bundle 分包由 Build Graph 自动生成。
用户只配置策略，不手动管理底层包。
第一版二进制 Bundle 可以是单文件 manifest + blob table。
```

### C4. 最小测试

```text
cook_assets_writes_cooked_asset_index
cook_texture_writes_deterministic_cooked_file
cook_mesh_writes_deterministic_cooked_file
bundle_pack_writes_binary_manifest
bundle_pack_writes_blob_file
runtime_bundle_mount_reads_binary_manifest
runtime_asset_loader_loads_from_binary_bundle
build_report_links_cook_bundle_runtime_diagnostics
```
