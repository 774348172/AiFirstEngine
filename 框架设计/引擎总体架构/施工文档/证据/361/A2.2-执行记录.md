## 首次失败与修复

1. 引擎lib测试编译失败：`E0063 missing field ui in initializer ReadOnlyWorldHost`，原`project_runtime_native_adapter/spatial_tests.rs:212,282`两处测试夹具未补新字段。补`ui:None`，保持空间查询断言。
2. DLL已构建和加载，但测试包被正式加载器拒绝：`output_staging_preload_failed: rules.rules[0].irHash: enabled rust-aot rule requires irHash`。补规则fixture所需irHash/irSource；随后`artifactId must be rule-artifact:rule.fixture:fixture`揭示irHash和生成模块artifactId须相同，改为使用生成模块descriptor的aot_content_digest。没有放宽加载器。
3. 包可加载后，解析settings/label返回`UiError {kind:UnknownNode}`。夹具只写了AUI文档体，未在RuntimeAuiManifest中声明，正式loader正确没有加载它。补正式manifest的documentId/path与统计字段，继续验证真实挂载，不直接向session塞测试实例绕过。
4. 产品缺陷：DLL运行mode103主动panic，下一次创建会话报`project_runtime.session_factory_failed / project runtime ABI call failed with status 7`。现有Glue持有全局sessions锁时运行用户回调，panic到外层FFI才截获，造成共享锁poison。

第4项最小修复：在`with_session`内部、锁仍存活时catch_unwind，标记该StoredSession.faulted并返回PANICKED。外层FFI仍保留；不忽略poison、不重放回调、不恢复出错项目状态。真实DLL回归验证panic后新建会话以及原先存活的另一个会话仍可正常更新UI。正常测试中的`project UI panic`stderr是主动负例，不是最终测试失败。
