## 变更与发现

C6 在 Project Game SDK 增加 session-local `UiBindingStore` / `UiBindingRefreshPlan`，把普通项目手写的 active set、dirty paths、visible revision 和 identity 比较收进 SDK。项目只在来源变化处通知 path，并只计算 plan 指定的首次激活或 dirty active 字段；clean resolve 不计算字段，沿既有 ABI 输出 `Reuse`。

Generated Glue 的临时普通项目已真实注册该 handler，并通过 ABI 函数指针完成 `Replace(hp=3) -> Reuse -> lifecycle notify -> Replace(hp=2)`。施工末审发现 generation 溢出时原实现会先写 dirty/force 再返回错误，且 clean plan/finish 仍复制 active paths 与 values；已分别改为“先 checked increment 再改变标记”和不携带 replacement paths、不提交 store 的 clean 常量快路径，并用 owner 测试证明失败原子性与 generation 不变。

## 已证明的行为

- 首次/切换 binding set 只刷新 active 全集；clean frame 的 refresh paths 为空并返回 `Reuse`。
- active 单字段通知合并且只刷新该字段；inactive 通知零工作；相同值不推进 revision。
- 新增、修改、删除可见值输出完整 active `Replace`，每次 resolve 最多推进一次 revision。
- unknown digest、非 canonical path 集、容量超限、caller identity 超前、missing/extra/duplicate refresh、stale plan 和两个计数器溢出均失败关闭。
- refresh 或 notification 失败不清 dirty、不改 force 标记、不推进 identity、不安装半份 cache。
- ABI 函数表与 wire 保持 1.6/既有 resolve 合同，没有 Delta、反向 Host 通知或第二 snapshot owner。
