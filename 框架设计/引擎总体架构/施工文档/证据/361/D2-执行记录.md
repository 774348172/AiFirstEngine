## 4. 生产阻塞首因

### 4.1 Custom Layout measured-size 为零

两组径向实例得到了不同坐标，证明 Layout callback 已被生产 Runtime 调用且实例属性相互隔离；但九个直接子项的最终 `width`/`height` 全是零，即使 cooker 已保留项目声明的 `46×34` slot。

只读定位到 `rust/crates/engine_runtime/src/project_runtime_native_adapter.rs:808`：初始 Layout 请求构造把 `measured_size` 硬编码为 `[0.0, 0.0]`。这次零尺寸输出随即进入 runtime identity/cache，后续稳定化 frame 再读取已经被覆盖为零的 child geometry，无法恢复真实 slot measured size。这违反 C4“Layout 收到直接子项实际 measured size”的合同。项目回调硬编码 `46×34` 会掩盖引擎缺口，未采用。

### 4.2 多 face 字体包 Runtime glyph lookup 全量失配

构建侧字体包已经含两个 face、中文/Arabic/ASCII glyph 和 14/16/18 至 32px bitmap，且 `fallbackUsed = true`、`qualityGateEligible = true`。生产 Runtime 仍报告：

- `fontAtlasId = virtual-list-font`
- `fontAssetStatus = incomplete`
- `glyphPresent = false`
- `requestedGlyphCount = 183`
- `renderedGlyphCount = 0`
- `unsupportedGlyphCount = 461`
- `nextActions = [runtime_text_glyph_present]`

截图因此显示 legacy/static 字样和圆形 mesh，但两份虚拟列表内容不可见。单 face 的历史 `hezi-font` 可正常渲染，缺口位于多 face bundle 的 Runtime paragraph/shaping/glyph lookup 消费链；相关 owner 为 `aui_paragraph.rs`、`text_shaping.rs`、`aui.rs` 和 `font_bundle.rs`。本块没有修改这些引擎文件。
