## 当前不能直接做

当前不要直接做：

```text
Rust Runtime MVP
IR -> Rust AOT Codegen
Rust Runtime 与编辑器桥接
真实 Native RHI / D3D12 / Vulkan / Metal Backend
真实 WgpuBackend 高级渲染
真实 AI 模型供应商接入

真实热更差分包

```

原因：

```text
这些会改变底层边界。
不能在当前 TypeScript prototype 中仓促固化。
需要先讨论架构规则、模块边界、测试策略和迁移路径。
```

## 当前剩余直接施工项

当前结论：

```text
当前没有新的“无需确认架构边界即可继续实现”的任务。
```

也就是说，继续写代码前，需要先确定下一块要进入的架构边界。

## 最推荐的下一步讨论

当前最自然的下一步是：

```text
是否需要实现 Build Report Panel 历史构建报告浏览？
```

如果需要，需要先确认：

```text
Electron bridge 是否允许只读读取历史 Build Report JSON。
允许读取哪些目录。
允许读取哪些文件名。
BuildService 是否负责报告读取。
Build Graph 是否要生成正式 summary。
Evidence Index 是否成为未来统一入口。
```

这不能直接实现，因为它涉及编辑器与本地文件系统安全边界。

## 执行纪律

后续继续施工仍按以下顺序：

```text
1. 先确认需求是否会改变核心架构边界。
2. 如果不会，写最小实现。
3. 每个需求新增或更新测试。
4. 先跑本任务测试。
5. 再跑必要回归测试。
6. 测试通过后更新对应文档。
7. 如果实现中发现要改核心架构，立即暂停。
```

## 当前结论

本轮直接实现阶段已经收敛。

下一轮不应该继续“找能写的代码硬写”，而应该先选择一个架构模块进入：

```text
Build Report 历史浏览与路径安全
Rust Runtime / IR AOT 边界
真实 Asset DB 与文件同步
真实 Renderer / RHI MVP
真实 AI Provider 接入边界
```

其中 Build Report 历史浏览是最小但会触碰边界的一项，适合作为下一次架构确认入口。
