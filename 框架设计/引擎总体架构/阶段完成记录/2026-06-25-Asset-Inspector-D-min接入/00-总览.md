# Asset Inspector D-min 接入完成记录

## 需求目标

按照 `施工文档/已完成/65-当前可自动化施工文档-Asset-Inspector-D-min接入.md` 实现 Asset Inspector D-min 接入。

目标是完成资源详情面板的最小闭环：

```text
ProjectDock selected asset
  -> Inspector asset mode
  -> AssetPipelineSnapshot
  -> AssetInspectorViewModel
  -> identity / importer / dependencies / referencers / reports / actions
```

## 框架定位

本阶段落地 `25-Asset-DB-Importer-MVP.md` 和 `20-编辑器工程结构.md` 中已经确认的规则：

```text
Asset Inspector 只读 AssetPipelineSnapshot / AssetInspectorViewModel。
ProjectDock 只负责选择资源。
Asset Inspector 不直接写 Asset DB / AssetRegistry。
低风险动作直接 UI callback。
高风险动作只生成 AssetActionRequest placeholder，不执行真实资源写入。
```

## 已实现能力

```text
AssetInspectorViewModel v1
AssetActionRequest v1 placeholder
createAssetInspectorViewModel
createAssetActionRequest
InspectorMode = asset
Inspector Asset tab
Asset / Importer / Dependencies / Referencers / Reports / Actions 面板
ProjectDock 选择资源后切换 Inspector asset mode
Locate / Copy GUID / Open Report 低风险 callback
Request Reimport / Create AI Repair Candidate 高风险 request placeholder
```

关键行为：

```text
no-selection 返回 emptyReason = no-selection。
asset-not-found 返回 emptyReason = asset-not-found。
importing / rebuilding / unreadable snapshot 返回 asset-pipeline-busy，不暴露半成品 registry。
dependencies 只展示直接依赖。
missingDependencies 从直接依赖中派生。
referencers 只展示直接反向引用。
reports 只筛选当前 asset 相关 import / batch / registry issue。
actions 明确 low / high risk 分类。
```

## 当前结论

Asset Inspector D-min 已经形成可测试闭环。
