# AssetPipelineState v1 完成记录

## 需求目标

按照 `施工文档/已完成/64-当前可自动化施工文档-AssetPipelineState-v1.md` 实现 Asset Pipeline State v1。

目标是建立正式资源管线运行时状态层：

```text
AssetPipelineState
  -> AssetPipelineSnapshot
  -> AssetPipelineEvent
  -> AssetPipelineController
```

并保证 ProjectDock / ConsoleDock / Inspector / AI 后续只读取 Snapshot / ViewModel，不持有资源真相。

## 框架定位

本阶段落地 `25-Asset-DB-Importer-MVP.md` 和 `20-编辑器工程结构.md` 中已经确认的规则：

```text
AssetPipelineState 是 Editor Core / Native Editor Host 内部状态。
AssetPipelineSnapshot 是 UI / AI 只读输入。
AssetPipelineEvent 是刷新通知，不是资源真相。
active import 期间不暴露半成品 registry。
```

## 已实现能力

```text
AssetPipelineStatus
AssetPipelineState
AssetPipelineSnapshot
AssetPipelineEvent
AssetPipelinePanelSnapshotInput
createAssetPipelineState
getAssetPipelineSnapshot
beginAssetPipelineImport
updateAssetPipelineImportProgress
completeAssetPipelineImport
failAssetPipelineImport
rebuildAssetPipelineRegistryState
createAssetPipelinePanelSnapshotInput
```

关键行为：

```text
初始 stateVersion = 1。
begin / progress / complete / fail / rebuild 都递增 stateVersion。
active import 期间 Snapshot.readable=false。
active import 期间 Snapshot 不暴露 registry。
complete import 提交新的 database / registry。
failed import 保留旧 database / registry。
reports 默认最多保留 50 条。
report trimming 会生成 reports_trimmed event。
Event 不承载完整 database / registry。
PanelSnapshotInput 只从 Snapshot 派生，不暴露 AssetPipelineState。
```

## 当前结论

AssetPipelineState v1 已经从架构规则落地为可测试代码。

下一步如果继续 Asset Pipeline，优先级建议：

```text
1. Inspector 接入 Asset Pipeline importer setting / dependencies / referencers。
2. Native Editor Host 接入 AssetPipelineState Snapshot。
3. 真实 OS file watcher / Import Worker。
4. Library/Reports/AssetPipeline 持久化 IO。
```
