# ProjectLogicRunner / LogicExecutor / Rust ECS 接入 v1

日期：2026-06-27

## 目标

按 73 号施工文档实现项目逻辑正式进入 Rust Runtime 的最小闭环：

```text
FrameLoop
  -> ProjectLogicRunner
  -> LogicExecutor
  -> WorldReadApi / WorldWriteApi
  -> ECS Transform write
  -> DirtyRecord
  -> RenderExtract
  -> RuntimeTrace
```

## 完成内容

新增 Rust Runtime 模块：

```text
rust/crates/engine_runtime/src/project_logic.rs
rust/crates/engine_runtime/src/logic_executor.rs
rust/crates/engine_runtime/src/world_api.rs
```

修改模块：

```text
rust/crates/engine_runtime/src/frame_loop.rs
rust/crates/engine_runtime/src/runtime_trace.rs
rust/crates/engine_runtime/src/lib.rs
```

已实现能力：

```text
RuleExecutionPlan / RuleCall
ProjectLogicRunner
LogicExecutor trait
RustAotExecutor generated-like function registry
IrInterpreterExecutor structured unsupported result
LogicContext
WorldReadApi / WorldWriteApi
Transform local_position 受控写入
RuntimeTrace logic result record
FrameLoop 在 RenderExtract 前执行 ProjectLogicRunner
```

## 关键边界

```text
业务顺序由 RuleExecutionPlan 数组顺序显式决定。
引擎不根据业务语义自动重排规则。
项目逻辑不直接访问 ECS raw storage。
项目逻辑不直接 mark dirty。
项目逻辑不直接生成 RenderCommand。
TypeScript Runtime 没有新增正式能力。
IR -> Rust AOT codegen 未在本阶段实现。
```

## 当前结论

Project Logic 已经有 Rust Runtime 正式入口。

现在最小游戏循环中，“项目逻辑推动一帧 -> ECS 写入 -> DirtyRecord -> RenderExtract -> RenderCommand / RenderSceneState”这条 headless 数据链路已经跑通。
