# 真实 OS RenderThreadWorker / Fence / FrameLag D-min

## 目标

落实 `82-真实OSRenderThreadWorker-Fence-FrameLag方案.md` 与对应施工文档。

本阶段把上一阶段的 `DedicatedThread` 队列边界升级为真实 OS render worker 线程，并建立最小可测试的 fence / flush / shutdown / frame lag 报告闭环。

## 已完成能力

```text
RenderThreadWorker
RenderCommandDispatcher
RenderThreadCommand
RenderFence / RenderFenceResult
RenderFenceSyncDepth
FrameLagController
RenderWorkerReport
EngineHostLoop -> RenderCommandDispatcher
Dedicated worker submit -> flush -> poll -> shutdown
```

## 架构边界

```text
EngineHostLoop 不再直接持有 RenderThread。
EngineHostLoop 持有 RenderCommandDispatcher。
RenderThreadWorker 独占 RenderThread。
Game / Runtime 侧不直接接触 RenderThreadWorker / RenderFence。
InlineDeterministic 继续用于 headless / CI / deterministic tests。
DedicatedWorker 真实 spawn OS worker thread。
```

第一版仍不实现：

```text
UE TaskGraph
RHIThread
RenderCommandPipe recording
GPU timeline semaphore
lock-free queue
项目侧 RenderFence API
```

## 关键结论

```text
DedicatedThread 通过 RenderCommandDispatcher / RenderThreadWorker 路径已经是真实 OS worker。
底层 RenderThread 仍只是单帧渲染执行器，不直接表达 OS thread ownership。
旧 raw RenderThread::new(DedicatedThread) 测试保留 diagnostic，用于说明绕过 dispatcher 时不会自动获得真实 worker。
AI 调试默认读取 RenderSubmissionReport / RenderWorkerReport / RenderFenceResult。
```
