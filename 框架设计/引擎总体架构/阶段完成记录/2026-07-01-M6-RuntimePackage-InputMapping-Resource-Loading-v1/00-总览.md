# 2026-07-01 M6 RuntimePackage InputMapping Resource Loading v1 完成记录

## 1. 本阶段目标

本阶段按照 `136-M6-RuntimePackage-InputMapping-Resource-Loading-v1方案.md` 和施工文档完成：

```text
RuntimePackage 中的项目 InputMappingAsset
  -> input manifest
  -> RuntimePackage Loader
  -> Runtime Player default mapping
```

`InputMappingAsset::gameplay_default()` 现在只作为测试 fixture 和显式 fallback 使用，不再是 Runtime Player 正式路径的唯一真相。

## 2. 代码改动

### 2.1 engine_runtime::runtime_package

新增 RuntimePackage 输入资源结构：

```text
RUNTIME_INPUT_MANIFEST_SCHEMA_VERSION
RuntimeManifestInputIndex
RuntimeInputManifest
RuntimeInputMappingManifestEntry
RuntimePackage.input_manifest
RuntimePackage.input_mappings
RuntimePackage.default_input_mapping
```

`load_runtime_package` 现在会：

```text
读取 manifest.input。
读取 input/input-manifest.json。
读取 enabled InputMappingAsset。
验证 defaultMappingId。
调用 InputMappingAsset.validate。
在缺失 input index / manifest / default mapping 时显式 fallback 并写 warning。
```

### 2.2 engine_runtime::runtime_package_builder

RuntimePackageBuilder 现在会：

```text
写入 input/{mapping.id}.json。
写入 input/input-manifest.json。
在 RuntimePackageManifest 中写入 input index。
没有项目 mapping 时写入 engine default fallback mapping。
```

### 2.3 runtime_player_winit

Runtime Player 现在：

```text
headless path 使用 package.default_input_mapping。
real-window path 加载 package 后使用 package.default_input_mapping。
NativeInputSummary 输出 mappingSource / mappingId / mappingStatus / mappingPath。
```

正式路径不再直接硬编码 `InputMappingAsset::gameplay_default()`。

## 3. 测试覆盖

新增 / 更新测试覆盖：

```text
RuntimePackage loader 读取项目 default InputMappingAsset。
RuntimePackage loader 缺失 input index 时 fallback 并报告 warning。
RuntimePackageBuilder 写入合法 input manifest 和 mapping。
Headless Runtime Player report 显示 runtime-package mapping source。
```

## 6. 当前结论

M6 已完成。

当前 Runtime Player 输入来源已经从“窗口层硬编码默认 mapping”收敛为：

```text
RuntimePackage input manifest
  -> project InputMappingAsset
  -> default_input_mapping
  -> Runtime Player
  -> InputResolver
```

fallback 仍然保留，但现在是显式可报告的异常路径。
