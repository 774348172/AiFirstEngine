# AI-first Editor Command Framework C-min 阶段完成记录

## 目标

完成 `150-AI-first-Editor-Command-Framework-C-min方案.md` 的第一阶段施工：把编辑器 UI 命令从分散映射收敛到可登记、可验证、可执行的 C-min 命令框架，降低后续 UI 功能重复注册和难以追踪的风险。

## 实际修改

```text
editor_core
  - 新增 editor_command.rs，定义 EditorCommandRequest / Descriptor / Category / OwnerDomain / PayloadKind / Availability / Context。
  - 新增 editor_command_registry.rs，集中登记内置命令 descriptor，并验证 command id 唯一性。
  - 新增 editor_command_executor.rs，作为 EditorSession 业务命令执行入口。
  - EditorSession::execute_command 保持旧 public API，内部转为 EditorCommandRequest 再进入 executor。
  - 保留 execute_ui_command_direct 作为兼容执行点，供 executor 调用。
  - AI proposal accept 先更新 review state，再把 proposal payload 重新提交到统一命令通道。

editor_ui_model
  - 新增 ui_command_id_for_payload 纯 helper，作为 payload -> command id 的唯一完整映射真相。

editor_input / authoring_workspace / property_editing
  - 移除各自维护完整 payload -> command id match 的做法，统一委托 editor_ui_model helper。

editor_window_winit
  - 更新 AI proposal accept 测试预期：最终 last_command_id 记录实际业务命令，而不是 ai_accept_proposed_command 壳命令。
```

## 设计边界

```text
本轮是 C-min，不是完整 UE Slate Command Framework。
不做插件命令系统。
不做完整菜单 / 快捷键编辑器。
不做大规模 EditorSession service 拆分。
不改变 UI 视觉和窗口布局。
不改变 Runtime / Build / RHI 主流程。
```

## 暴露问题

```text
1. EditorSession 仍然聚合较多领域状态，本轮只先收敛命令入口，没有完成 service 化拆分。
2. editor_window_winit 仍承担较多 shell / route / present 编排职责，本轮通过命令框架减少业务侵入，但没有做文件级大拆分。
3. command id 仍保留旧 snake_case 兼容格式，后续如需 canonical dot id，应单独做兼容迁移方案。
```
