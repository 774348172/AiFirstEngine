# M10 Input Mapping Authoring Runtime Productization v1 完成记录

## 目标

完成输入映射从编辑器创作到 Runtime Player 生效的第一版产品化闭环：

```text
Editor Input Mapping Authoring
  -> Project InputMappingAsset
  -> Validate / Save
  -> Workspace / AssetBrowser summary
  -> DesktopExportPipeline input collection
  -> RuntimePackage default input mapping
  -> Runtime Player / ActionSnapshot verification
```

本阶段不重做 M5 / M6 输入底层，不新增项目玩法 API。

## 实际修改

### Gate A: UI Model / Commands

修改：

```text
rust/crates/editor_ui_model/src/lib.rs
```

新增 `InputMappingAuthoringModel`、action/context/binding summary、validation/report/diagnostic 模型，并新增输入映射相关 `UiCommandPayload`。

### Gate B: EditorCore InputMappingAuthoringService

修改：

```text
rust/crates/editor_core/Cargo.toml
rust/crates/editor_core/src/input_mapping_authoring.rs
rust/crates/editor_core/src/lib.rs
rust/crates/editor_core/src/authoring_workspace.rs
```

新增 `InputMappingAuthoringService`，支持 create default、load、save、validate、add/remove action、add/remove binding、set binding device path、build authoring model。

`EditorSession` 已接入 create/edit/validate input mapping 命令。

### Gate C: DesktopExport / RuntimePackage 接入

修改：

```text
rust/crates/editor_core/src/desktop_export.rs
```

DesktopExport 现在会扫描 `ProjectRoot/Input/*.json`，把合法 `InputMappingAsset` 写入 `RuntimePackageBuildInput.input_mappings`。非法输入映射会进入 `DesktopExportDiagnostic`。

### Gate D: Workspace / AssetBrowser 集成

修改：

```text
rust/crates/editor_core/src/lib.rs
rust/crates/editor_core/src/asset_browser.rs
rust/crates/editor_core/src/authoring_workspace.rs
rust/crates/editor_ui_model/src/lib.rs
```

Workspace Input domain 现在显示 mapping count、default mapping id、validation status、error / warning count。

AssetBrowser 已识别 `Input/input.default.json` 为 `AssetKind::InputMapping`。

## 暴露问题

旧测试曾用 `{}` 伪造 input mapping 文件。M10 后 Input domain 会真实加载和验证输入映射，因此该测试已改为写入合法 `engine_input::InputMappingAsset::gameplay_default()`。

这说明新规则已经生效：Input 文件不再只是“存在即可”，而是必须能被 Runtime 链路理解。
