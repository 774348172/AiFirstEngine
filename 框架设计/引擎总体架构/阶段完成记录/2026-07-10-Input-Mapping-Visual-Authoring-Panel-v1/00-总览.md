## 1. 完成范围

本轮把 Input Mapping 从 schema/service 基线推进到可视化编辑、保存、预览和运行时消费闭环：

```text
InputMappingAsset
  -> InputMappingEditorState working copy
  -> Native Input Mapping Workspace
  -> InputMappingEditCommand
  -> validate / conflict / impact
  -> source-hash guarded save
  -> RuntimePackage
  -> InputResolver / ActionSnapshot
```

已完成：

```text
Input Mapping schema 升级为 input-mapping.v2，并新增稳定持久化 binding_id。
旧 v1 资产可确定性迁移到 v2，legacy binding_index 调用仍兼容。
新增只发布 runtime resolver 真正支持路径的 InputControlCatalog。
新增 editor-only working copy、选择、dirty、Save、Discard 和 source hash 冲突保护。
Context、Action、Binding、Trigger、Processor 可通过结构化命令编辑。
Native Workspace 提供稳定 hit target、键盘/鼠标 capture 和 gamepad catalog 选择。
capture 会先于编辑器快捷键和 GameView 消费输入，并支持 Escape/失焦取消。
新增冲突、类型、遮挡和外部 action 引用影响诊断。
Preview 复用真实 InputResolver；Report Panel 支持 Off / Summary / Trace。
ProjectPatch 的 Input 批次会在 Build/批次结束前显式保存。
复杂打飞机样例已迁移到 v2，并形成 complex-shooter-input-mapping-visual-authoring-report.v1。
E2E 已证明未保存 draft 不进入包、保存后 mapping 进入 RuntimePackage 且 runtime resolver 生效。
```

## 2. 关键边界

```text
InputMappingAsset 仍是唯一持久化项目真相。
InputMappingEditorState 只是编辑器 working copy，不进入 RuntimePackage。
Preview 与 runtime 共用 InputResolver，不存在第二套输入求值器。
binding_id 是 UI/AI 的稳定身份；binding_index 仅保留兼容用途。
Runtime 默认不生成 Visual Authoring report。
本轮不提供真实物理手柄 capture，只提供受支持目录选择和 synthetic preview。
本轮不新增 Input Graph、ControlSchemeAsset、runtime rebinding 或多人设备所有权。
```
