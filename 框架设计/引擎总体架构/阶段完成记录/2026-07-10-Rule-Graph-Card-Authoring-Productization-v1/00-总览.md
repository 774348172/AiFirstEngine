## 1. 完成范围

本轮把 Rule Authoring 从结构化服务和 raw document 推进到可读、可编辑、可报告的产品面：

```text
RuleAuthoringModel
  -> RuleCardAuthoringModel / RuleCardModel / RuleCardFieldModel
  -> RuleAuthoringService / RuleAuthoringEditCommand
  -> Gameplay Rule Asset / RuleSlot
  -> validate / build / report
  -> Generated read-only RuleGraphPreviewModel
```

已完成：

```text
RuleAuthoringModel 新增 card_authoring 派生子模型。
RuleCardAuthoringModel 可从 ProjectRuleAsset / RuleAuthoringDocument 派生 trigger / statement / operation / diagnostic cards。
RuleGraphPreviewModel 可从 rule asset 派生只读 nodes / edges / source mappings。
新增 SelectRuleCard / SetRuleCardField / AddRuleCard / RemoveRuleCard / SelectRuleGraphNode / RefreshRuleGraphPreview 命令。
Card edit 会降低到既有 RuleAuthoringEditCommand，不新增持久化 RuleCardPatch。
Graph node selection 只改 editor selection，不修改规则资产。
ManualWalkthrough / Workflow / Report Panel 能看到 Rule Card / Graph Preview 能力。
project_e2e_gate 新增 complex-shooter-rule-card-authoring-productization-report.v1。
复杂打飞机样例 3 条规则可生成 cards/graph，并验证 card edit -> validate/build -> graph refresh。
```

## 2. 关键边界

```text
Gameplay Rule Asset / RuleSlot 仍是编辑真相。
Canonical Rule IR 仍是内部规范语义和构建输入。
Rule Cards 是可编辑产品面，不替代 RuleAuthoringService。
Rule Graph Preview 是 editor-only 只读派生视图，不是第二规则真相。
Runtime 执行链路仍走 RuntimePackage.rules -> RuleModuleRegistry -> ProjectLogicRunner。
本轮未新增 Blueprint / Lua / VisualScript 式通用脚本系统。
DuplicateRuleCard / MoveRuleCard 未启用，避免在缺少 reorder/duplicate 语义时制造第二套规则修改路径。
```
