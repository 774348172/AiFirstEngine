## 完成结论

238 已完成。编辑器现在可以把用户 prompt、canonical strict `ProjectPatchDocument` schema 和脱敏的 authoring context 发送给真实 OpenAI-compatible Chat Completions provider；响应仍必须经过既有 Import、Validator、Review、用户 Confirm 和 transaction Apply，LLM 没有直接写文件或绕过验证的权限。

首次候选若命中稳定 diagnostic allowlist，可在相同 request/context 下执行最多一次受控 repair。修复候选不能提高风险、增加 capability、扩大 destructive/Build scope 或超过 operation 上限；无进展、上下文过期、取消和越界都会终止，不产生可 Apply proposal。

## Gate A-F 实现范围

```text
Gate A：schemars 派生 canonical ProjectPatch strict schema、确定性 schema hash、sanitized semantic context hash 与 stale guard。
Gate B：ureq OpenAI-compatible HTTP transport、HTTPS 或 loopback HTTP policy、URL credential/redirect 拒绝、2 MiB request/response/candidate 上限、typed status 与一次 transient retry。
Gate C：可编辑 prompt、Submit/Cancel、std::thread + mpsc background worker、frame pump 与每 EditorSession 单 active request。
Gate D：exact-code repair allowlist、一次 repair、diagnostic fingerprint、risk/capability/operation/destructive/Build scope guard。
Gate E：initial/repaired candidate 统一走 ProjectPatchImportService 与 PatchValidator；proposal 保持 requires_confirmation；project.patch 复用 Off/Summary/Trace evidence。
Gate F：complex shooter 本地 fake HTTP E2E 覆盖一次 repair、全域 Asset/Prefab/AUI/Rule/Build candidate、确认前不修改和事务 Apply。
```
