## 完成结论

CQ-04 已完成。active project 的相对路径写入权限已统一收敛到 `ProjectWriteScope`：调用方提交严格的 `ProjectRelativePath`，scope 持有 project root capability，并在同一 capability 下完成 read、目录创建、原子文件替换、删除和原子目录发布。Scene、AI image、ProjectPatch 及其余 production project-write consumers 不再依赖“先验证绝对路径、再用 ambient filesystem 写入”的安全假设。

Windows 真实文件系统 Gate 已证明 junction、hard link、并发换链和 ProjectPatch rollback 换链不能修改项目根外 sentinel。当前进程没有创建文件 symlink 的 Windows 特权，该 fixture 以 OS error 1314 显式跳过；junction/reparse 必需覆盖已执行并通过，聚合报告仍为 `passed`。

## Mutation Inventory 分类

| 分类 | 范围 | 结论 |
|---|---|---|
| capability path | Project launcher child files、Scene、AI image/metadata、Input、Prefab、AUI、Template、Rule、BuildProfile、ProjectPatch、Preview/GameView/consistency reports、默认 Build/Preview/Report | 通过 `ProjectWriteScope`，或在进入既有 staging/publisher 前由 scope 对 project-owned parent 做 capability preflight |
| typed external output | 用户选择的 desktop/release export root、外部 consistency report | 只能由 `ExplicitExportOutput::from_user_selected` 授权；项目相对路径和 LLM patch 不能构造该权限 |
| owned staging | desktop/release/RuntimePackage staging 内部的 copy/write/remove/publish | staging 目录由已授权 project subtree 或 typed external root 创建，内部 mutation 不重新解释项目相对路径 |
| bootstrap | 新项目 root 创建、打开 root capability 之前的 manifest 初始化入口 | 只接受 launcher 明确提供的 root；root 建立后所有 child writes 立即进入 scope |
| fixture-only | module 内 `#[cfg(test)]`、project_e2e_gate、临时 OS filesystem fixture | 仅用于测试输入、故障注入、link/junction/hard-link/race 证据，不是 production write authority |

复扫未发现 241 范围内存在 containment failure 后回退 `std::fs` 的路径，也没有新增平行 path validator。

