# 246 施工耗时复盘与通用提速规则

## 1. 为什么持续时间长

246 同时跨越 policy、AST inventory、历史 debt/coverage、change scope、AI transport、artifact verifier、Editor report 和 CI，代码面广；更主要的时间来自权威验证，而不是 Provider。

```text
最终真实 Provider review：约 6-10 秒。
最终 EngineStrict QualityGate：1183843 ms，约 19.7 分钟。
最终 authoritative Local CI：898896 ms，约 15.0 分钟。
两项最终完整证据合计：约 34.7 分钟。
```

EngineStrict 和 Local CI 都串行运行 default/all-features workspace；398 个 editor_core tests、50 个 project_e2e_gate tests、PE/export/window/build fixture 与 doc tests 构成长尾。Provider 并不是主要瓶颈。

## 2. 可避免时间

```text
Provider 兼容问题在真实 Gate 才发现：base URL /v1/、strict schema、标准 envelope 可由无源码 smoke 提前覆盖。
canonical request/context 生成器在 Gate G 才补：应在 Gate E CLI 设计时与 review 命令同时完成。
warm 定向测试掩盖 loopback 500 ms 调度假设：应在 cold/parallel workspace 等价 target 预检。
临时 worktree 放进仓库内部，污染主 Git status：所有施工 worktree 应建在仓库外固定根。
验证 worktree 被 E2E 改写 tracked fixture 后又尝试作为 Local CI source：两个角色必须物理分离。
外层 timeout 1000 秒小于实际 Runner 1184 秒：包装层必须按内部总预算加 cleanup 余量设置。
EngineStrict 与 Local CI 重复完整矩阵：当前合同正确但存在约 15-20 分钟可合并空间。
```

## 3. 之后所有施工采用的规则

### 3.1 外部 Provider 四层预检

```text
1. GET /models：验证认证、base URL 与 model ID。
2. minimal chat：验证最小消息请求。
3. strict schema smoke：不发送源码，验证 response_format/json_schema/envelope。
4. canonical source review：只在用户授权、exact clean commit、预算和脱敏全部成立后执行。
```

前三层任一失败都禁止进入真实 source review。

### 3.2 Worktree 角色隔离

```text
主工作树：允许用户未跟踪/并行文档，不承担 authoritative source clean。
Provider/EngineStrict worktree：允许测试改写 fixture，不复用为 Local CI source。
Local CI source worktree：fresh exact commit，只负责启动 LocalCiRunner。
LocalCiRunner isolated worktree：由 Runner 创建并强制 cleanup。
```

所有临时 worktree 放在仓库外；创建和删除前验证绝对路径。

### 3.3 验证顺序

```text
schema/parser/unit -> loopback/affected crate -> suppression/Clippy -> same-target cold/parallel cumulative failures -> Provider -> EngineStrict -> Local CI
```

任何新增 `allow/expect/cfg_attr` 在完整回归前先跑 suppression inventory。网络测试不得依赖 500 ms 一类紧调度窗口；使用显式 readiness 或覆盖 cold client 初始化的 deadline。

### 3.4 Timeout 与可观测性

外层 timeout 取内部各 stage timeout 总和加 checkout、artifact、cleanup 余量，不能按历史平均值设置。长 Runner 应输出 stage started/completed 轻量事件或增量状态文件；无输出不等于 hang，但必须能定位当前 stage。

### 3.5 单一权威矩阵

新方案如果同时要求 strict artifact verification 与 Local CI，应优先让 LocalCiRunner 接收 trusted artifact/expectation，在同一次 isolated matrix 中完成 EngineStrict 与 exact-commit/cleanup 验证。只有合同确实不同，才允许连续跑两套完整 workspace。

## 4. 预期收益

```text
Provider 兼容失败从分钟级真实 Gate 前移到秒级无源码 smoke。
dirty source/worktree 角色错误在毫秒级预检解决，不触发完整矩阵。
suppression 与 loopback 环境问题在受影响域阶段解决，避免 5-20 分钟权威失败。
统一 EngineStrict + Local CI 后，单次施工最终阶段预计减少约 15-20 分钟重复矩阵。
stage progress 不直接缩短测试，但显著减少误判 hang、错误中断和由此产生的完整重跑。
```
