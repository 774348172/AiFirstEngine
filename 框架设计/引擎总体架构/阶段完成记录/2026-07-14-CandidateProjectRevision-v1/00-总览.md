## 1. 结果

250 Phase 2 已完成。新增深 `CandidateProjectRevisionStore` Module，公开 Interface 为：

```text
stage(request) -> CandidateProjectRevision
verify_base(revision, project_root) -> CandidateBaseVerification
discard(revision, candidate_store_root) -> CandidateDiscardReceipt
```

`stage` 在项目外的候选 store 中先创建 staging sibling，复制基线、应用受控文件变更并复核基线摘要，最后以 rename 发布唯一 revision root。真实项目在整个流程中不被修改；失败会清理本次 staging，不发布 Ready 候选。

revision、request、file change、verification、discard receipt 和 error 均有严格 serde schema。base/candidate digest 绑定 schema version、规范化项目相对路径与文件字节；`changed_paths` 由基线和候选的实际字节差异计算，不把同内容覆盖或删除不存在文件误报为变更。

Module 排除 `Library / Build / target / .git / .aife-candidates`，拒绝非 UTF-8 路径、symlink、Windows junction/reparse、根目录互相包含、目录逃逸和非规范 revision record。`verify_base` 同时 fail closed 检查 base drift 与 candidate tampering；`discard` 只删除指定 store 下与 revision id 精确匹配的候选根，并保持幂等。
