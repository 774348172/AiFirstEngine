## 1. 结果

250 Phase 3 已完成。新增深 `ControlledSourcePatch` Module，公开 Interface 为：

```text
prepare(request) -> ControlledSourcePatchCandidate
validate(candidate, validation_request) -> ControlledSourcePatchValidationReport
apply(approved_candidate) -> ControlledSourcePatchApplyReceipt
rollback(apply_receipt, project_root) -> ControlledSourcePatchRollbackReceipt
```

`prepare` 是 AI/用户 SourcePatch 文本进入 `CandidateFileChange` 的唯一 policy seam。v1 只允许 `project.aife.json`、`RuntimeModule/Cargo.toml`、`RuntimeModule/src/**/*.rs` 和 `RuntimeModule/tests/**/*.rs`；限制 64 operations、单文件 1 MiB、总文本 4 MiB，并拒绝非规范/大小写碰撞/Windows 保留路径和三个必需文件删除。

候选发布前结构化解析 `aife-project.v2` 与 Cargo TOML，要求显式 `ProjectRust`、固定 Cargo manifest、package 对齐和精确 Engine SDK 版本；拒绝 workspace inheritance、build.rs/package.build、target/build/dev dependency、git/path/registry dependency、动态 crate type 和非 Engine dependency。没有新增玩法专用 Engine Core Interface，也没有扩大 Rule IR。

`validate` 重新检查 base/candidate/changed-path binding，在 candidate store 内建立短路径 validation copy，通过 trusted `EngineSdkLocator` 生成 validation-only Cargo patch config，并用既有 bounded child process 顺序执行 `fmt --check -> check --all-targets --offline -> test --no-run --offline`。只有显式 `TrustedLocalExecuteTests` 才追加真正的 `cargo test`。`CARGO_TARGET_DIR` 和 offline 环境显式注入，Windows 子进程路径去除 `\\?\` verbatim 前缀，所有终态清理 validation root。

`apply` 要求 approval 精确绑定 passed validation digest，使用 `ProjectWriteScope` 和候选真实 changed paths。写入前在 candidate store sibling 持久化带内容摘要的 before snapshot；写入、摘要复核或候选复核失败统一反向恢复，并再次验证 before digest。`rollback` 校验 receipt、record 和 snapshot 摘要，拒绝 applied project drift，成功后恢复 before digest 并删除 record。

事务自审还在矩阵前补齐 rollback snapshot 内容摘要、写入后任意复核失败的自动恢复、恢复后 before digest 复核，以及 generated `RuntimeModule/target` 排除。所有修改都在冻结前重跑累计失败集和受影响域，因此没有用旧矩阵冒充最终证据。
