## 1. 结果

250 Phase 4 已完成。新增深 `ProjectAssetImport` Module，正式 Interface 为：

```text
prepare(request) -> ProjectAssetImportCandidate
validate(candidate) -> ProjectAssetImportValidationReport
apply(candidate + passed validation + approval) -> ProjectAssetImportApplyReceipt
rollback(apply receipt) -> ProjectAssetImportRollbackReceipt
```

首个真实 importer 为 PNG texture。外部或受信生成的 PNG 只有通过该 Module，才能进入 `Assets`，并获得稳定 GUID、descriptor、`*.asset.meta.json`、AssetDB 记录及确定性重建的 AssetGraph / AssetRegistry。记录保留 source provenance 和 license declaration；`unknown` 会产生 warning，但引擎不冒充法律授权判断。

`RejectExisting` 拒绝目标路径、assetId、GUID 和大小写折叠冲突；`ReplaceMatching` 只有 expected GUID 与 source hash 都精确匹配才保留身份并替换。candidate、validation、approval、source/base/derived state 都有摘要绑定。

Apply 使用独占 import lock、二进制 before snapshot 和 `ProjectWriteScope` 原子写入。任意写入或复核失败都会补偿恢复；显式 rollback 会复核 receipt、record、snapshot 和当前 applied state，遇到漂移或篡改 fail closed。

本次验证发生在共享混合脏工作树。工作树包含用户已有修改、249/250-A/B/C 结果以及测试会改写的 sample build artifacts；250-D 没有重置、清理或覆盖这些内容。因此本记录不声称 clean checkout，也不声称 exact-commit 通过，只声明上述冻结文件、隔离 target 和当前工作树上的实际结果。
