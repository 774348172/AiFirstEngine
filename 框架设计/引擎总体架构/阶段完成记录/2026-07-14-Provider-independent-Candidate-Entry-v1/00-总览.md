## 1. 结果

250 Phase 5 已完成。新增深 `ProjectCandidateEntry` Module，统一入口为：

```text
Built-in Provider / Imported Codex / Imported file / Test fixture
  -> ProjectCandidateEnvelope
  -> prepare
  -> validate
  -> explicit approval
  -> apply
  -> rollback
```

v1 每个候选只承载一种 typed payload：`ProjectPatch`、`ControlledSourcePatch` 或 `AssetImport`。共同合同绑定 active project id/root、base project digest、source/envelope/payload/candidate digest、ProjectPatch semantic context、validation digest、显式 approval、apply receipt，以及外部文件 path/digest 漂移检查。

Apply/rollback 只调度既有 ProjectPatch、250-C 和 250-D transaction；没有复制三套 lowering，也没有绕过各自 validation、approval、containment、rollback 或 receipt 检查。内置 Provider 与 imported Codex 的 ProjectPatch 已共用同一 candidate schema、prepare/validate/approve/apply 路径；Provider transport 失败不再阻止 imported candidate 独立进入项目生产流程。

## 2. Consumer 与兼容性收敛

```text
EditorSession：原来的多组 ProjectPatch proposal vector 收敛为单一 ProjectCandidateProposal store。
```
