## 1. 结果

253 已完成。引擎新增小而稳定的 AI Capability Tool Kernel，开放式任务不再以 `ProjectProductionRun / candidatePlanSteps / AdvanceRun` 作为默认执行真相。AI 可以自行选择工具、读取 receipt 和 diagnostics、重新规划并继续工作；引擎负责项目事实、有限授权、安全 mutation、验证、回滚和可审计结果。

```text
Tool Kernel interface：catalog / inspect / execute / observe / cancel
首批工具：project.inspect / project.mutate.candidate / project.rollback.candidate / project.preview
授权：CapabilityGrant 绑定项目、domain、mutation kind、删除、依赖、网络、费用、时间、次数和过期时间
连续修改：同一 Grant 通过 receipt lineage 继续，不要求每一步重新批准
持久化：Library/AiCapability/tool-kernel-journal.json
长期记忆：IntentJournal / WorkItem / Diagnosis 保留为可选输入，不拥有工具执行顺序
```

ProjectRust Preview 现在必须使用正确项目的 RuntimeModule binding，禁止静默回落到 empty runtime。旧 Workflow Preview 复用同一个 project-owned Preview 工具；Previewing 不占 mutation lane。无效或越权 Grant 在创建 Operation 和写 journal 前完成 preflight，拒绝路径没有未授权副作用。

## 4. 施工中发现的问题

1. Tool Kernel journal 中的 action 文本被旧输入引用扫描器当作项目源码，导致 Candidate rollback 失败。扫描器现排除 `Library`、`Build`、`target`、`.git`、`.aife-candidates` 等生成目录；rollback diagnostic 透传首个真实逆补丁错误。
2. 无效 Grant 原先会先写 Running Operation 再校验。现已改为无副作用 preflight 和工具级授权检查先执行。
3. `architecture_review` loopback fixture 原先只读取一次 16 KB 请求就响应并关闭。strict-schema POST 可能超过 16 KB，Windows 因未排空请求体产生 TCP RST，表现为偶发 Transport failure。fixture 现在显式等待 server readiness，并按 `Content-Length` 完整、有界地排空请求体后响应。精确失败集连续运行 50 次通过。

修复 loopback fixture 前，default workspace 曾通过 661.6 秒；修复中间版本 all-features 曾通过 285.8 秒。这两次不是最终源码权威结论。只有最终源码的 265.8 秒和 280.6 秒两轮计入最终 Gate。
