# 295 Windows Player Continuous Portrait Presentation/Input Minimal Repair v1 完成记录

状态：已完成并归档。

## 完成范围

- Windows Player 改为持久化 `RuntimePackage`、World、Host 与 GPU 会话；winit 每个
  `RedrawRequested` 只推进一帧，并持续请求下一帧，不再在首帧跑完整个会话后退出。
- Windows build profile 的可选 `gameViewTarget` 进入 RuntimePackage；Tower Windows dev profile
  使用 `720x1280 + contain`。
- Renderer 与 AUI 指针反解共享同一份 `ResolvedGameViewPresentation`；Windows DPI 指针坐标先进入
  physical client space，再映射到 target space。
- Player 把 AUI active binding paths 传给 Tower producer；可选 FPS session 缺失不再丢弃整个 HUD
  snapshot。
- Player 窗口按请求的物理像素创建；当窗口超过当前显示器工作区时，扣除非客户区后等比缩小并居中，
  虚拟 target 仍保持 `720x1280`。

## 诊断说明

旧底部黑区不是 Renderer viewport 裁切。旧窗口使用 `LogicalSize(720,1280)`，在 125% DPI 下客户区
变成 `900x1600`，超过显示器物理工作区；桌面捕获把屏幕外部分记录为黑色。改用物理窗口尺寸并增加
工作区适配后，完整 `720x1280` 客户区位于工作区内。

前三次外部 smoke 失败分别属于坐标原点、DPI virtualization 和 `SendInput` 路由的 harness 问题，证据
保留在 `evidence/attempt-*`；最终使用 Per-Monitor-V2 DPI 捕获和目标 HWND 窗口消息通过，不需要继续修改
Renderer。
