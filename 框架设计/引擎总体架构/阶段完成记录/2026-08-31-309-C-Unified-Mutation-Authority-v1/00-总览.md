# 309-C Unified Mutation Authority v1 完成记录

## 结果

309-C 已完成 Gate A-D 与受影响终态验证，结论为 `Unified Mutation Authority sourceAvailable`。
`authoring_project_context` 现在提供唯一、领域无关的 project-scoped mutation lane：结构化
`ProjectMutation` 在同一 OS 生命周期锁中执行 expected revision CAS、write-ahead journal、before
material、确定文件操作、未知外部写入检测、sealed receipt 与 exact-revision rollback。

`ControlledSourcePatch` 和 `ProjectAssetImport` 已迁入该 lane。它们继续负责 prepare/validate 与旧 public
API/receipt 兼容，不再拥有独立 commit、compensation、rollback transaction 或 lock authority。

本次只完成 309 Stage C 源码纵切。Stage D crash recovery/finalize/compensate、Editor/Gateway/Compiler/
Provider 接入、旧 authority 全面 retirement、daemon、production 和安装态均未施工。

## 实现

- 新增 `ProjectMutation` create/replace/delete/move 合同、declared read/write set、expected before hashes、
  validation digest 与 expected revision CAS；
- 新增 `.aife/authoring/authority.lock` project-scoped OS lifecycle lock，Windows 使用
  `LockFileEx`/`UnlockFileEx`，Unix 使用最小 advisory `flock`；
- 新增 write-ahead journal、before material、sealed mutation receipt 与 rollback receipt；
- write set 外未知 canonical write 只补偿 own writes，同路径未知 bytes 或 material tamper 进入
  `recovery_required` 并阻断后续 commit；
- rollback 要求 current revision 精确等于 receipt after revision，并验证 receipt、journal 与 before material；
- `ControlledSourcePatch` 与 `ProjectAssetImport` 通过 Context commit/rollback，旧 receipt 字段形状不变；
- 删除 Asset Import 独立 `import.lock`，删除 `ProjectWriteScope::acquire_lock` 与旧 lock owner；
- candidate store 与 `ProjectWriteScope` 继续只承担隔离 prepare/validate 和原子文件能力。
