# 309-D Crash Recovery v1 完成记录

## 结果

309-D 已完成 Gate A-C 与受影响终态验证，结论为 `Crash Recovery sourceAvailable`。
`AuthoringProjectContext` 现在会在Headless open读取manifest、发布handle和首次refresh之前，使用309-C同一
project-scoped OS authority lock检查sealed journal，并把可证明的崩溃状态确定收敛为`aborted`、`committed`
或`restored_before`。未知touched-path bytes、journal/material/receipt tamper与冲突事务保持fail-closed。

本次只完成309 Stage D与G6源码纵切。Stage E EditorProjectAdapter、Stage F Gateway authority retirement、
Provider/Compiler接入、daemon、production、安装态、真实断电和文件系统损坏恢复均未施工。

## 实现

- 保持`open(...) -> ProjectHandle`兼容，新增`open_with_report(...) -> OpenReport`；
- recovery在manifest读取和handle发布前取得`.aife/authoring/authority.lock`，调用方不编排内部步骤；
- 新增structured project/transaction recovery report与`DiagnosticStage::Recovery`；
- journal新增terminal `aborted`，commit新增prepared与committed-before-receipt最小checkpoint；
- all-before标记aborted；exact before/after mixture只恢复own after；all-after先排除write-set外漂移再确定commit；
- committed journal缺receipt时，只有after bytes与after revision全部可证明才补发同一确定receipt；
- unknown bytes不覆盖，journal/material/receipt tamper与冲突nonterminal journal拒绝自动恢复；
- 恢复动作再次进程退出后，下一次open仍从sealed disk facts幂等收敛。

五个child exit checkpoint为：prepared journal sealed、applying before first operation、after one operation、
after all operations before verification、committed journal before receipt publication。每个场景均再次open，证明
terminal journal、receipt、bytes和revision稳定；OS lock在child退出后由生命周期释放。

`project_asset_import`首次终态回归有1项失败：consumer篡改统一journal后，309-D在open阶段先返回底层decode
类别，而旧consumer期待309-C的`rollback_journal_invalid`。recovery owner将journal/receipt decode失败归一到
既有兼容类别，同时保留Recovery stage；定向失败用例通过后，owner和两个完整consumer suite均重跑通过。

ignored项是既有`local trusted workspace Engine SDK smoke`。`cargo check`只报告既有`engine_runtime`三项
dead-code warning：`IrInterpreter`、`validation_only_ir_interpreter`、`remove_sprite_renderer2d`。
