# 327-R3 Stable Engine Runtime DLL + Project Public API v1 施工文档

状态：施工完成，Gate A-B、C、D、E、F、F2（Engine DLL 真实 Runtime execution owner）通过；受影响回归通过。完成记录与证据：`.artifacts/327-r3-gate-d-delivery-formal.json`、`.artifacts/327-r3-failure-matrix-20260913/327-r3-failure-matrix.json`。对应方案：`327-R3-Stable-Engine-Runtime-DLL-Project-Public-API-v1方案.md`。

## 施工目标

以最小 Windows vertical slice 证明稳定 Engine DLL 与 Project Module 的编译、加载和版本边界，验证项目修改不会触发 Engine DLL 重编译。施工不迁移整个 `project_runtime_sdk`，不改项目玩法和 AI 工具面。

## 过量施工约束

- 只实现最小 `engine_public_api` facade：版本/能力查询、生命周期、时间/输入和有界诊断。
- 不暴露 Rust trait、泛型、内部 ECS/Renderer 类型或项目语义。
- 不迁移全部 Engine API，不做 Android、Editor UI、热更新、脚本 VM 或 DLL 插件市场。
- 不把 Engine DLL 直接替换到用户安装宿主；只在 run-owned staging 中验证。

## 必要性与验证经济性审计

- 请求目标：获得 Unity 式稳定 Engine Runtime/DLL + Project 层公开 API 边界。
- 最小因果变更：一个 ABI facade、一个最小 DLL 构建目标、一个 Project Module 加载测试。
- 明确排除：全量 SDK 迁移、完整渲染 API 重构、发布渠道改造、真实宿主安装替换。
- 证据经济：每个 Gate 只验证一个边界风险，优先 owner-level deterministic test；只有加载/交付声明需要时才进入集成测试。

## Gate A：ABI 边界基线

盘点现有 `engine_runtime` 与 `project_runtime_sdk` 的直接依赖，冻结首期 facade 的类型、内存所有权、版本和能力字段。输出 `.artifacts/327-r3-gate-a-abi-baseline.json`。

停止条件：若首期合同需要项目语义、未定义所有权或暴露 Rust 内部类型，停止并修订方案。

## Gate B：Engine DLL 最小构建

新增最小 Windows `cdylib`/C ABI facade 构建目标，Engine 自己编译并产出带版本 manifest 的 DLL。运行 ABI layout、版本查询、错误码和释放 owner 测试。

证据：`.artifacts/327-r3-gate-b-engine-dll.json`。

当前进度：Gate A 已通过；Gate B 最小 facade vertical slice 已通过。Gate B 仅证明独立 cdylib 目标、固定布局版本查询和生命周期状态接口可构建，尚未宣称完整 engine_runtime 已迁移。

Gate C 已通过最小项目客户端合同测试；经用户授权 Runtime 重构后，Gate D 已通过最小 `engine_runtime.dll` 迁移切片。完整 staged Game Host 组合仍属于后续独立施工，不在本轮扩大范围。

## Gate E：Staged Engine DLL Loader

在 run-owned staging 中由 Game Host 加载 `engine_runtime.dll`，校验公开入口、ABI major/minor、能力位和 DLL 身份；缺失或不兼容时结构化 fail-closed。

证据：`.artifacts/327-r3-gate-e-loader.json`。

## Gate F：Project Module 真实运行链

使用最小 Project Module 和 RuntimePackage 通过公开 API 启动一次 staged run，记录 Engine DLL、模块和 package identity；不迁移完整服务，失败则停止扩展。

证据：`.artifacts/327-r3-gate-f-staged-run.json`。

当前进度：首次 staged run 捕获并修复了静态 `engine.empty.runtime` 绑定问题；接入 Project RuntimeModule DLL 后，Engine DLL probe、module identity/AOT digest 校验和 8 帧 headless run 全部通过。成功证据：`.artifacts/327-r3-gate-f-staged-run-success.json`。原首因失败保留于 `.artifacts/327-r3-gate-f-staged-run.json`。

## Gate F2：Engine DLL 真实 Runtime execution owner

新增 `engine_runtime_host` cdylib（产物名保持 `engine_runtime.dll`），由 DLL 持有 `runtime_player_winit` 的 headless 执行入口。Host 在 `AIFE_REQUIRE_ENGINE_DLL` 下只负责加载 DLL、传递有界 C ABI request、读取 DLL 写入的结构化 native report；不再静态调用 Player runtime。DLL 内部负责 RuntimePackage 加载、Project RuntimeModule 选择/加载和实际帧循环；空模块仅对明确的 `engine.empty.runtime` package 允许显式 fallback，其它项目缺失模块 fail-closed。

已通过：`cargo check -p engine_runtime_host`、`cargo check -p runtime_cli`、`cargo build -p engine_runtime_host`；CLI 的 DLL execution branch 已接通并保留 `FreeLibrary` 生命周期。曾先以缺失模块运行验证 fail-closed，随后从当前 complex shooter 源重新生成 Generated Runtime Glue 并完成真实 8 帧 staged run。最终 run-owned staging 证据：`.artifacts/327-r3-gate-f2-staged-run.json`；报告同时包含 `native_host.engine_runtime.execution_owner`、module identity/AOT digest 和 `framesCompleted=8`，execution owner 路径为 `.artifacts/327-r3-staged-runtime/engine_runtime.dll`。早期非 staging 成功报告保留于 `.artifacts/327-r3-engine-dll-execution-success.json`，缺失模块失败证据保留于 `.artifacts/327-r3-engine-dll-execution.json`。

## Gate C：Project Module 独立编译与加载

让一个现有样例 Project Module 通过公开 API 调用 Engine DLL；改变项目源码后只重编译 Project Module，加载时校验 ABI major/minor、能力位和 module identity。不得依赖 Engine 私有 crate 符号。

证据：`.artifacts/327-r3-gate-c-project-module.json`。

## Gate D：单一交付组合与失败闭环

在 run-owned staging 中组合 Engine DLL、Project Module、RuntimePackage 和 Game Host，执行 run/build/delivery verify；验证 DLL 缺失、ABI 不兼容、模块身份漂移均 fail-closed。确认九项 AI 工具和 334 内部缓存语义不变。

证据：`.artifacts/327-r3-gate-d-delivery-formal.json`。正式 Windows dev 包含 `Game.exe`、`engine_runtime.dll`、`data/bin/sample_complex_shooter_runtime.dll`、`package-manifest.json`、`data/runtime_package/` 和报告目录；8 帧 packaged process verification 退出码为 0，Engine DLL 为实际 execution owner。失败矩阵 `.artifacts/327-r3-failure-matrix-20260913/327-r3-failure-matrix.json` 覆盖 Engine DLL 缺失、Project RuntimeModule 缺失、module identity 漂移和 ABI major 不兼容，均非零退出、有结构化报告且无静态回退。Project Player artifact 在构建阶段固化 Generated RuntimeModule DLL，DesktopExport 在交付阶段放入 `data/bin/<moduleId>.dll`。

## 测试与成本控制

- Gate A：`cargo metadata --locked --no-deps --format-version 1` 与依赖扫描。
- Gate B：facade owner 单元测试 + `cargo check` 目标 crate。
- Gate C：Project Module 定向编译/加载测试。
- Gate D：正式 Windows dev 交付组合、packaged process verification 和失败矩阵均已通过；不把完整 workspace 或真实安装宿主作为开发循环。

若任一 Gate 的实际成本明显超过预估，停止昂贵分支并重新评估 DLL 边界，不追加永久步骤。
