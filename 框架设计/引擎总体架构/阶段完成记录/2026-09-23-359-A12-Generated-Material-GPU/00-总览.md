## 1. 实际完成

高层 `mesh-asset.v2` / `material-asset.v2` 已接入原 Compiler.prepare → neutral_assembler → render_asset_cook → RuntimePackage → loader / Prepare 链。v3 项目同时装配 Assets 下的 `.asset` 与 `.json`；旧项目的 `.asset` 规则保持，依赖解析与实际装配资格一致。生成器只在构建侧执行，Runtime 不扫描源目录或生成图元。

Cube 的 size 是完整 XYZ 边长，中心为原点，24 顶点 / 36 个 u16 索引；plane 的 size 是完整 XZ 尺寸，位于 XZ 平面，正面 +Y，4 顶点 / 6 索引。顶点包含 position3、normal3、UV2，stride 32，offset 为 0/12/24；CCW 绕序、AABB、包围球、`surface` 槽和 RH/Y-up/米制合同齐备。Plane U 向 +X、V 向 +Z；cube 各面的 UV 和法线按面独立生成。

Unlit 高层参数映射到原有 shader owner、CookedMaterial 和命名纹理绑定。缺少纹理声明时为纯色；声明但引用缺失或身份不匹配时失败。原 RuntimeRenderAssetProducer 新增 `prepare_mesh_renderer` 接缝，按 Mesh 的真实命名槽准备材质，只有全部 PreparedGeometry 验证成功才返回完整快照；继续使用原 ResourceManager，不新增资源注册表。

材质 RGBA 为线性值；base-color 纹理 RGB 用 sRGB 解码，alpha 保持线性。独立 min/mag nearest/linear 与 S/T repeat/clampToEdge/mirroredRepeat 共 36 种组合实际传入 WGPU。采样和格式变体使用原资源键的 usage 区分，同一纹理的不同采样方式可同时驻留；相同变体复用，变体内的像素版本变化仍使旧句柄失效。

DrawGeometry 依据完整 world affine 矩阵的 determinant 派生正面方向，并写入实际 pipeline identity；WGPU 分别使用 Cw/Ccw，材质 back/front/none 策略不变。真实 GPU 测试验证单轴镜像、shear、双重反射、正反面观察。相同 Mesh 的多个实例与材质共享实际 GPU buffer；改变颜色、相机或帧不会重复上传 Mesh，改变生成尺寸会改变网格数据和可见轮廓。

## 2. 实际合同与后续消费接缝

新增 Cook recipe 为 `render-native.generated-static.v1`；旧 `render-native.v1` 仍受支持。包外壳、`render-contract.v1`、源 Mesh/Material v2、SDK/ABI 均没有版本升级。CookedMaterial 增加可选 `baseColorTextureSampling`，内容为严格 typed 的 minFilter/magFilter/wrapS/wrapT；缺省不序列化，旧 U1 材质保持原纹理元数据语义。采样字段存在时必须有 `baseColorTexture` 引用。

TexturePayload 沿用原字段，不新增纹理 authority。原 `nearestClamp` / `linearClamp` 保留；其它组合编码为规范的 `min:mag:wrapS:wrapT` 字符串。Prepare 和后端拒绝未知或非规范标签，不再根据字符串是否包含 nearest 猜测。当前纹理仍为单 mip，不宣称 mipmap/各向异性功能。

`PreparedMeshRenderer` 只保存验证后的 geometry/textures 快照。A1.3 应在资产或材质绑定变化时准备和缓存它，使用现有上传 owner 注册 textures；实例与后续帧复用 PreparedGeometry。按 A1.1 已确定的顺序先 extract/apply dirty，再 project_main_camera，最后由 MeshProjection 创建 GeometryInstance，并将 GeometryFrame 接入真实 RenderFramePacket/RenderThread。相机变化不触发图元重新 Cook。
