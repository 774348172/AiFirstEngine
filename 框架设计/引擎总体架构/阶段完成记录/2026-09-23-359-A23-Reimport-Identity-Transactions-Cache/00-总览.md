## 1. 已接通的行为

### 1.1 映射预览与文件事务

现有 `engine_project_inspect` 新增可选 `modelImport:{descriptorPath,maxEntries}`，从同一operation snapshot返回 `modelImportInspection`。报告包括源locator/fingerprint、重名、提交的key/GUID/entityId/slot、候选与歧义、cooked路径，以及结构化JSON引用位置和源实例ID。默认256、上限4096；对象、映射、引用和候选总量受限，并报告truncated。

候选不自动分配或选择长期身份。重命名、重排、删除和歧义由AI/用户审查并显式修改原descriptor；首次映射也沿原文件事务提交。`engine_project_mutate.expectedRevisionId` 将修改绑定预览revision，在既有Context CAS之前拒绝过期计划，成功后仍使用原receipt/rollbackRef。测试通过真实v3项目验证两文件重导入及两级精确rollback，同时保留事务外的game.rs修改。

预览的 `buildable` 只表示所选导入解码及映射装配通过，不能替代整个项目check。引用影响是Assets/Scenes/Prefabs/AUI/Rules中JSON的保守匹配；不承诺发现任意Rust动态引用。源码事务成功与新包成功发布是不同结果。

### 1.2 真正消费静态Prefab实例覆盖

旧legacy bake不能覆盖本轮的空间实例要求，因此在原neutral assembler中接入既有 `engine.prefab_instance` 源组件形状，没有增加runtime envelope或registry。Scene实例引用使用严格AssetRef，导入Prefab必须匹配id/GUID/`sub_asset`；展开命名空间沿用源Scene实体ID，根放置由其Transform3D定义。

覆盖按持久节点entityId和具名材质槽定位：支持 `MeshRenderer3D.materials.<槽名>`、Transform3D translation/rotation/scale、Visibility3D.visible和已有project.*字段。两个实例分别展开，不修改共享Prefab；重排后覆盖仍指向原身份。删除节点/槽、错误引用、重复覆盖和展开ID碰撞均失败。公开canonicalize仍拒绝未展开实例，Compiler展开完成后才输出RuntimeScene。

本阶段支持完全3D的静态Prefab；嵌套空间实例、混合域Prefab源实例明确拒绝。根Transform不能同时另设override。运行期空间实例化、控制和SDK属于A3。

### 1.3 真实缓存和独立失效

沿用 `ProjectAssemblyArtifactCache`：整模型producer为 `model-import`，几何/图片子producer为 `model-import-geometry` / `model-import-image`，recipe为 `gltf-static.import-cache.v1`。依赖索引只帮助确定精确已读取源文件，不作为产物命中数。

| 输入变化 | 本轮实际验证 |
| --- | --- |
| 无变化、仅改相机 | 整模型命中，跳过decode/assemble，不执行几何子producer |
| 仅改材质颜色 | 整模型重装配，几何/图片解码命中；Mesh产物字节保持 |
| 改buffer几何 | 几何重新生产，图片命中；材质产物保持 |
| 改图片 | 图片重新生产，几何命中；Mesh/材质产物保持，纹理payload更新 |
| 改profile/平台/profile文件 | 实际cache key隔离；不冒充对应平台运行验证 |
| recipe过期、缓存损坏 | 重新生产，不返回陈旧产物 |
| 缺依赖或超预算 | 失败且旧完整包字节不变，不能借旧缓存通过 |

Cook wrapper的sourceDigest按各自产物数据和recipe计算，避免整模型源摘要污染无关Mesh/Material身份。图片变化额外经过真实Runtime loader/Prepare：材质cookedDigest相同，新像素仍取得新的纹理handle/generation，旧binding失效。命中报告来自真实lookup/produce/skip，不填写预设统计。

### 1.4 取消与原子发布

Compiler新增 `prepare_cancellable`，在开始、导入工作安全点与返回prepared前检查，取消时不返回成功prepared revision。RuntimePackageBuilder新增 `build_cancellable`，沿原atomic publish owner在staging完成/校验后、rename临界区前响应；临界区开始后完成或回滚。

测试覆盖prepare早期/中途/末端取消、发布三个安全点、缺依赖/预算以及原发布故障注入，确认旧包字节保留、不残留半成品staging。没有第二事务owner。九工具仍声明 `supports_cancellation=false`；这是源码合作式取消接口，不是宿主异步取消已接入。

使用方式见[样例重导入说明](../../../../samples/three_d_lab_project/REIMPORT.md)，合同补记见[A0附录第7节](../../359-A0-3D场景资产与版本合同附录.md)。
